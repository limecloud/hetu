# 插件生态、开源许可与商业化

## 专业扩展按需采用

核心优先服务小说和剧本的持续修改，叙事视频按需接续。插件提供专业表达与工具，不强制安装整套，不拥有第二份正式稿或独立作者决定；退出插件仍保留可读取交付。

产品定位与任务分流见[01](01-产品需求PRD.md#1-产品定义)。

创作插件覆盖数据、动作、视图、方法和适配器，以套件服务小说、剧本、导演预演等任务；完整分类、需求、用例与生态路线见[插件系列](plugin/README.md)。标准插件栈为JS/TS＋React，Electron/TS负责宿主与生命周期，Rust负责作品内核。FR-17仍专指可选商业多媒体调度，不代表全部插件；Codex接入包、创作能力和算力服务分别管理。

## 1. 组件与能力边界

新增第一方和第三方创作能力通过共同贡献合同接入；安装、启用、作品绑定与Agent可调用性分开。下表为基础和外部协作的分工，创作能力不限于多媒体，也不要求购买云服务。

| 类型 | 作用 | 是否生成内容／产生算力费 |
| --- | --- | --- |
| Hetu Core／CLI／MCP | 本地事实、规则与交付；向外部Agent提供可选固定计划封装 | 不自主生成；显式调用的服务费用按所选渠道结算，不是离线核心前置 |
| Codex Plugin／其他宿主适配包 | 分发专用 Skills、MCP 连接定义与局部 UI | 自身不生成；作者在宿主对话，Agent 使用其宿主能力 |
| 独立多媒体调度插件 | 适配用户选择的图片／音乐／视频供应商 | 可代表用户调用生成服务，费用直接归供应商 |

接入插件不能把核心偷偷改成内置 Agent；多媒体服务不进入默认安装、默认网络链路或核心必需依赖。与 `axi` 的研究及组合方式见[27](27-Agent与Codex插件集成设计.md)。

## 2. 多媒体调度插件边界

插件独立仓库、独立进程与版本，只接收作者明确选择的设定集片段、线索和参考素材，不读取整个 IP 或系统凭据。结果通过受限素材／草稿导入入口进入对应内容包，不能直接改设定集、定稿指针或版本记录。

本节独立仓库要求针对商业多媒体调度插件。免费宿主接入、专用 Skill 方法、MCP Apps 与按需 Node.js 局部页面属于河图洛书 Monorepo 的协作能力，不因此变成必购增值包；具体布局见04。封面通过外部 Agent 自身工具生成时无需安装商业调度插件，河图固定任务、接收候选并展示验收；可选模型工具按作者授权执行固定计划，不运行自主生成循环。

提供方适配负责参数、任务 ID、状态、取消、费用与结果元数据；核心只检查来源、文件、引用和审核状态。首期不建立任意native动态库热加载或在线交易市场。已安装的JS/TS包在受管宿主和明确权限下执行，不执行作品文件里的任意脚本；插件后端的OS隔离另行验收。

## 3. 授权、费用与未知结果

生成前展示供应商、模型、输入材料、数量、预计费用及内容外发目的地。用户自带 Key，Key 存插件的系统安全存储，供应商直接向用户结算。河图洛书不代收算力费，不保证供应商可用性、结果版权或可商用性。

超时后沿原 provider task ID 查询，不自动重复提交付费任务；供应商无幂等／查询能力时保持未知并交由用户处理。取消是尽力请求，不能承诺退款或任务未执行。

渠道返佣必须显式披露，不影响作者默认选择、不隐性改变价格或路由。订阅控制商业插件能力，不限制作者访问、编辑、导出已有作品。

## 4. 开源与私有范围

核心免费开源，完整手工流程、基础 MCP 和标准交付不依赖付费服务。商业调度插件可独立收费，私有源码不作为开源构建和测试前提。第三方扩展消费版本化合同，不导入核心内部数据库或私有对象布局。

GitHub 仓库可见性按仓库控制，不能通过目录或分支隐藏商业源码。此原则不预先决定未来仓库数量，按实际团队、许可和发布边界建立。

## 5. 许可证

核心仓库按 `LICENSE` 中的 Apache License 2.0 授权。许可证变更须核验权利归属、既有贡献、依赖与发布影响，由权利方明确决定。

第三方库、编辑器、格式转换器、字体、图标与测试材料分别核验许可，分发时保留必要通知与 SBOM。不能因为核心选 MIT／Apache 就认为所有插件与素材可同许可分发。

## 6. 作者 IP 与数据权利

软件许可证不改变作者对小说、设定集和素材的权利；用户内容不因被工作区管理而自动开源。Bundle 记录作者声明和来源，既不提供版权登记，也不替代合同或供应商条款核验。

商业假设通过付费插件试点、续费、使用成本与支持成本验证；本设计不预测未经调研的市场规模、收入或版权风险已经隔离完毕。
