# macOS 原生实施方案

V1 支持 macOS 14+、Apple Silicon arm64。其他架构按独立的原生验证与分发要求扩展。

## 1. 工程与职责

| 层 | 技术与职责 |
| --- | --- |
| App | SwiftUI 场景、窗口、菜单、导航与依赖组装 |
| Presentation | Swift 状态、任务、选择、编辑缓冲与错误投影 |
| Native Platform | AppKit 编辑器、系统目录选择、文件访问、Keychain |
| Core Bridge | `bindings/swift/` 对 C ABI 的生命周期、安全类型与异步包装，供 App 和跨平台 CLI 共用 |
| Shared Core | 共享 Rust 设定集、规则、存储、Git、审核与导出 |

Swift 不重新实现剧情规则或持久化审核状态机。桥接不暴露裸指针给 View；以明确 `close` 与析构兜底管理句柄，取消和回调遵循 ABI 合同。

## 2. 原生编辑与窗口

优先 SwiftUI 组织布局，长文本 Markdown／Fountain 编辑使用 `NSTextView`／TextKit 适配，以满足中文输入法、撤销栈、大文档、查找与精确定位。编辑器按中文输入法、长文性能与来源定位要求验收。

AppKit 适配应保留 marked text，输入法组合期间不得重设全文；差量更新避免丢失选区和撤销历史。原文以 UTF-8 保存，`NSRange` 与字节范围经修订绑定映射转换，不能只按字符个数推导。

采用原生打开／保存面板和最近文档行为。一个窗口绑定一个工作区上下文；多窗口编辑由内核跨进程锁和 CAS 处理。切换项目立即清除旧项目的敏感预览与临时授权。

工作台首次打开按所在屏幕可用区域设置宽敞的初始尺寸，内容宽度约占92%、高度约占94%，扣除系统标题栏和边缘留白；小屏下不超出可用区域。标准屏幕最小内容尺寸为1180×740，小屏按可用区收敛。保留原生标题栏、拖动边缘、系统绿色按钮和全屏，书库与作品顶栏另提供“放大或还原窗口”。缩放使用窗口所在屏幕的完整可用区域，再次操作恢复原大小；初始化不反复重设已调整的窗口。

## 3. 文件与系统权限

系统选择器明确授权工作区；是否采用 App Sandbox 在 M0 结合独立 MCP 的文件访问原型决定。若启用 sandbox，安全作用域书签与 stale 更新只保存在应用用户目录，使用期间成对开始／结束访问。

桌面 sandbox 授权不会自动传给独立 stdio MCP 进程。MCP 由宿主按其权限启动并自行打开用户明确选定的路径；无权访问时返回权限错误，不要求关闭系统保护或读取桌面私有书签绕过。

Keychain 保存 Git HTTPS Token 引用；SSH 优先用户已有系统 agent，不复制私钥。系统访问权限与业务批准不同：能读目录不等于可以替作者推送、解锁或定稿。

## 4. 并发与桥接

UI 主线程仅处理视图和轻量状态。内核任务由串行工作区写队列与有界读任务执行，回调携带任务 ID 和当前上下文；Swift 在 MainActor 更新 UI，过期窗口回调不得写入新项目状态。

取消为协作式：Core 定期检查取消标识，已经持久化的草稿保留，正在提交的原子阶段不被硬杀；最终结果说明取消发生于提交前还是后。关闭窗口时分离短任务取消与持久操作查询，不能直接释放仍被回调引用的对象。

## 5. 构建与交付

工具链采用 Swift 6 系列、Xcode 与 Rust 2024 Edition；精确 Xcode、Swift、Rust 和 macOS SDK 组合记录在构建锁定清单。Cargo 产出内核及 C ABI 库，Xcode／Swift Package 只消费稳定头文件和固定构建产物，避免两套独立编译配置漂移。

目标交付 `.app` 与独立 CLI／MCP 二进制。正式分发需签名、Hardened Runtime、公证、嵌入库加载验证与干净用户安装；是否 DMG 或 PKG 在发行原型后确定。签名密钥不进入源码、工作区或日志。

Mac 开发构建入口为 `python3 "tools/build-native.py" --test`，生成 `build/native/Hetu.app`。SwiftPM 组织 `HetuCore` 桥接、`HetuNative` 表现层、`HetuMac` 应用与独立测试程序；Rust 动态库和文案资源嵌入开发包，移除开发机的绝对库搜索路径。开发包使用 ad-hoc 签名，正式签名与公证独立验收。

共享文案来源为 `assets/localization/native.json`。构建前生成 JSON 资源与 String Catalog，核对双语键、具名参数和代码引用。恢复副本位于应用用户目录 `Hetu/Recovery/`，以工作区、文档和窗口标识隔离；保存请求在调用内核前持久化原操作键、基线与正文，结果不确定时重放原输入。

剧情节点编辑器提供事实、能力与实际／梦境／假设／转述语境标注；作者确认后参与内核规则检查。“一致性诊断”面板按固定剧情修订执行检查，显示覆盖、缺失前提、过期状态及逐条原文证据，支持按规则、严重程度、确定性和处置筛选。核对原文使用固定正文修订的 UTF-8 范围映射，不替换当前编辑缓冲。误报、知悉与例外另存有理由的处置历史，冲突就地显示并保留输入。

“短剧骨架”面板选择固定剧情修订和分集起始节点，创建独立候选；作者可编辑集／场标题、地点、内外景、日夜、人物和改编说明，调整来源映射及顺序，拆分、相邻合并或跨集移动场次。历史列表按确切修订读取，编辑仍需当前 head 的 CAS；过期结构保留原文证据。结构对比报告与骨架分别留存，显示映射和来源变化；对白及镜头内容由独立 Fountain 正文承载。

结构写请求在调用内核前保存工作区、动作、原操作键和固定输入到本机恢复目录。成功或确定阻断后清理恢复记录，未知结果保留；重新打开工作区显示恢复入口，重放完整原请求而不新建键。未确认的结构操作阻止在该面板新建结构写请求，恢复成功后更新对应骨架或报告。

作者在所选骨架修订中“建立可编辑剧本”，填写标题并选择中文／英文模板，创建后直接打开独立 Fountain 文档。建立剧本同样持久化原请求，恢复不会重复建稿。编辑器中的“结构来源”展示初稿场景标题、缺项及原著证据，精确定位固定初稿；正文改写或上游变化后明确标为历史映射，不把旧范围高亮到新文本中。

“审核工作台”按状态分页查询草稿，展示固定正文、来源、当前性、报告与决定历史。已保存正文可在编辑器提交审核；返工编辑器保留手工内容并明确显示当前设定与骨架基线。报告可定位草稿原文、核对剧情标注、生成新报告及记录具体处置，较早报告通过翻页访问。差异预览逐侧最多3000行、展示前400处增删，超出预算明确提示使用完整正文并排核对；不做语义合并或自动移动批注。

参考稿通过、要求修改和驳回记录公开理由，私密批注与定稿覆盖说明分别处理。“采纳到写作稿”打开固定差异，支持局部选择并保存来源，不能更新定稿。编辑器对当前已保存修订提供独立“确认定稿”；手工稿无需先提交参考稿。界面保存完整决定快照及原键，未知结果通过恢复入口确认；撤回定稿保留当前稿、参考稿与历史记录。

“线索与素材”以类别与权利状态呈现作者材料。导入先通过系统文件面板检查固定文件摘要，再明确保存来源与权利声明；使用平台图片／AVKit 控件预览已有媒体，不自动播放或联网。线索编辑器复用只读 TextKit 选区，转换为固定修订 UTF-8 来源；元数据和线索支持历史修订、归档及 CAS 冲突提示。导入与修订请求复用本机原操作恢复；未知结果可重启后沿原键确认，不重复登记素材。

作品资料中的“封面”通过 `CoverSession` 管理手工图片和外部设计。文件面板先完整解码并等比预览，作者点击“用作封面”才导入受管素材。外部设计先预览可编辑 Prompt，再保存固定请求并复制给所选 Agent；请求历史、部分候选、实际尺寸与来源在同一面板展示。选用以封面修订及摘要 CAS，成功后更新作品与书库缩略图，重启沿原操作恢复。文字叠加和图片裁切只影响展示，原件保持；封面错误独立显示，不阻断作品正文打开。

“导入导出”由 `DeliverySession` 管理导入、正文导出和交付包。作者选择本机 TXT、Markdown、Fountain 或 DOCX 文件后先核对转换预览，再确认标题、语言和分卷；一次导入建立一份正文，不依据标题自动拆章，也不设置定稿。正文导出选择保存修订及格式，Fountain 一次选择一部剧本；“使用已定稿版本”必须找到有效定稿，不能静默回退到写作稿。正式交付包默认固定所选正文的有效定稿，允许继续写作后的旧定稿；审阅包使用已保存写作稿。骨架、诊断、改编差异、线索和素材按需选择，改编差异按对应骨架查询，素材许可不足仅交付资料。确认前列明正文修订、文件、格式变化和阻断，产物可在访达显示，交付包可再次核验。

长时间导出使用独立 Core 句柄，释放编辑器的工作区队列；固定预览和原操作先持久化，导出结果不替换编辑缓冲。切换作品后不把旧任务结果投影到新作品。重新打开作品从原请求恢复，文件已发布但回执未知时读取既有结果，不重新分配产物或操作键。

## 6. 验收范围

必须在目标 macOS 与架构上验证：中文输入、文件选择与授权撤销、路径包含中文和空格、符号链接逃逸、崩溃恢复、多窗口冲突、Keychain、SSH、离线完整任务、VoiceOver、浅暗主题、签名安装及 CLI／MCP 独立启动。

Swift 类型检查、内核单测、App 编译、原生 UI 旅程与签名分发分别登记。Linux 或 Windows 的 Rust 结果不能替代 macOS 文件与 UI 证据。

## 7. 外部协作与局部网页

Settings Scene 的“AI 协作”管理默认客户端、扩展引导及分项能力，不包含模型登录、API Key 或聊天。建书表单可保存没有书名的 CreationProject；任务页根据选择的客户端提供 Prompt 预览及 NSPasteboard 复制，作者自行在客户端发送，软件不做键盘注入或自动启动 Agent。

`NewWorkspaceSheet` 通过 `CreationProjectSession` 管理筹备。默认在用户 Application Support 的 `Hetu/CreationProjects/` 下保存独立目录，新建窗口列出未完成筹备，也支持作者选择已有筹备目录。书名、笔名、类型、简介和大纲保持可编辑；候选按字段填入并保留来源，接收结果不创建小说。原生端展示封面缩略图，正式封面导入和选用另行确认。

筹备资料保存使用修订与摘要检查。另一窗口更新资料时保留作者表单，比较磁盘资料后才能确认最新基准；刷新不能默默解除冲突。作者选择正式目录并点击“创建小说”后才调用创建动作。创建请求在 `RecoveryStore` 保留原键和目标，直到新作品身份核验并登记书库后清理；重启沿原操作恢复，不重新分配书名、目录或作品身份。

候选列表按固定任务与批次刷新，窗口激活时有界检查 MCP／inbox 结果。对回调同时核对 scope、task_id 和 request_revision，避免切书后迟到结果串入新作品。正文采纳经 TextKit 编辑事务保留选区及撤销行为，输入法组合期间不更新全文。

需要较大局部视图时按需启动随产品分发的 Node.js 页面服务，可在 WKWebView 或外部 Agent 内置浏览器使用。WKWebView 只加载受管回环来源，外链显式交系统处理，不注入任意文件桥接；它不替代核心 NSTextView 编辑器，也不承载 AI 对话。浏览器会话由原生端配对，权限和生命周期遵守18与27；本地会话或撤权连接中断时清空页面内容，Node.js 退出不丢已保存的业务记录。

本节验收包括首次无作品接入、复制后无生成请求、候选展示、局部采纳、手工独立定稿、原任务恢复、Apps 回退、WebView Origin 隔离及 Node.js 打包／停止；不能以网页能打开代替这些业务证据。
