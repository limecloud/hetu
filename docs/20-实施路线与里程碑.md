# 实施路线与里程碑

按业务依赖组织实施阶段，每个阶段以可执行的退出条件验收；阶段划分不构成固定日期承诺。实施顺序为 macOS 优先：先完成 Mac 内核、客户端、CLI、MCP 和完整创作交付旅程，再开始 Windows 实现与平台验收。

## 1. 阶段与依赖

| 阶段 | 输入与范围 | 退出条件 |
| --- | --- | --- |
| M0 技术原型与决策 | Rust、Swift CLI、Mac 桥接、编辑器、格式、MCP 规范 | Mac 最小 ABI／CLI 路径运行，锁定依赖与验收基准 |
| M1 书库、作品与设定集 | M0；FR-01／02／03／15／21 | 多作品登记、独立资料与卷章、手工封面导入、保存、锁定、来源与恢复可用 |
| M2 抽取与校验 | M1；FR-04／05／06 | 来源定位、候选校正、覆盖与误报评测完成 |
| M3 改编、采纳与定稿 | M2；FR-07／08／09 | 骨架、手工剧本、参考稿局部采纳、来源、独立定稿与过期保护贯通 |
| M4 外部 Agent 协作 | M1～M3；FR-13／14／20／22～25 | 软件接入引导、专用 Skills、建书筹备、Prompt 复制、MCP 候选、Apps 与本地浏览器局部交互、权限和恢复通过真实宿主验收 |
| M5 协作与交付 | M3；FR-10／11／12／18 | Git 冲突与未知恢复、标准格式及 Bundle 核验通过 |
| M6 macOS 发布收口 | M1～M5；FR-16／19 | Mac V1 门禁、签名、安装、升级、辅助功能及离线旅程通过 |
| M6-W Windows 实施与发布 | Mac 完整验收；跨平台内核与合同 | Windows 原生客户端、CLI、分发及完整旅程独立通过 |
| M7 可选商业生态 | 核心稳定；FR-17 | 多媒体调度插件单独授权、费用与故障验收 |

阶段表示依赖与可独立验收的工作包，不是固定日期承诺。共享内核保持平台边界，Windows 风险记录在平台设计中；Windows 实施不抢占 Mac 完整闭环。

## 2. 技术准入条件

1. Rust + Cargo + git2/libgit2 在目标系统的依赖、许可和打包是否闭合。
2. 同一 Swift CLI 能否在 macOS／Windows 原生构建、运行 C ABI、处理中英文管道、确认、取消与干净系统部署。
3. 原生编辑器能否稳定支持中文 IME、10 万汉字及 UTF-8／UTF-16／Swift 定位转换。
4. 文件事务与进程锁在支持的文件系统上能否通过中断与外部改写测试。
5. 无模型的中文提取规则能提供何种可量化覆盖，哪些明确交给作者／Agent。
6. MCP 当前规范、Rust 实现路线、宿主版本和 Apps 信任边界是否可验证。
7. Fountain、DOCX／PDF 导入导出依赖及中文模板是否满足实际接收方要求。
8. 依赖与分发产物符合 Apache-2.0 及第三方许可要求。

原型失败必须更新决策与风险，不可用临时脚本或手工复制充当已完成产品。

## 3. 最小产品切片

第一个切片在作者书库登记两部独立小说，分别维护资料、封面和设定；其中一部包含可选分卷、两章正文、一集两场改编骨架与定稿剧本。全部内容可手工提供，保存、校验、独立定稿、导出及切书不依赖 Agent。第二切片从河图选择客户端开始，覆盖无书名筹备、专用 Skill、复制 Prompt、候选、局部采纳、编辑及独立定稿，并加入 Apps 和本地浏览器的同任务交互及回退。第三切片加入 Git 冲突、批量内容与格式交付。

每个切片先完成 Mac 共享内核、CLI 与原生界面的贯通验证。Mac 验收不能表述为 Windows 支持；后续 Windows 阶段执行独立验收。

## 4. 每阶段交付清单

- 所属需求、机器合同、最小可运行功能和失败恢复一致。
- 用户故事到测试的映射完整，示例不依赖私有相邻仓库。
- 当前源修订／树摘要、构建产物、平台与实际结果可追溯。
- 必要指南只写已落地命令，未实现内容留在本路线和专项设计。
- 用户数据、原操作记录与未保存缓冲均受到保护。

## 5. 服务端演进与准入顺序

实施优先级为 Mac 完整创作与本机 MCP → 外部 Agent／局部交互验收 → Mac 发行及 Windows 独立实施。官网可独立建设，不改变本机软件的离线前提；不将云账号或公共服务列为 M1～M6 的依赖。

| 顺序 | 交付目标 | 准入与退出条件 |
| --- | --- | --- |
| 本机核心 | M1～M3、M5 的书库、创作、校验、采纳、定稿及交付 | 无网络与 Agent 完成作者全程；保护中文输入和本机数据 |
| 本机协作 | M4 的插件／Skills、独立 stdio MCP；Apps 与按需本地网页 | 分别验收真实宿主、权限、原任务恢复及无增强界面的回退 |
| 桌面发行 | M6、M6-W | Mac 先完成；Windows 独立验证，不用云后端替代缺失平台能力 |

服务端业务须有明确用户场景和必要性后单独立项，并补齐需求、故事、数据归属、权限、API 及验收。当前路线不预设服务端业务功能，不预建账号体系、微服务、云数据库、常驻中继或同步双写。商业插件按自身需求评估，不依赖服务端立项。
