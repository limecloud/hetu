# 实施路线与里程碑

按业务依赖组织实施阶段，每个阶段以可执行的退出条件验收；阶段划分不构成固定日期承诺。实施顺序为 macOS 优先：先完成 Mac 内核、客户端、CLI、MCP 和完整创作交付旅程，再开始 Windows 实现与平台验收。

## 1. 阶段与依赖

| 阶段 | 输入与范围 | 退出条件 |
| --- | --- | --- |
| M0 技术原型与决策 | Rust、Swift CLI、Mac 桥接、编辑器、格式、MCP 规范 | Mac 最小 ABI／CLI 路径运行，锁定依赖与验收基准 |
| M1 书库、作品与设定集 | M0；FR-01／02／03／15／21 | 多作品登记、独立资料与卷章、手工封面导入、保存、锁定、来源与恢复可用 |
| M2 抽取与校验 | M1；FR-04／05／06 | 来源定位、候选校正、覆盖与误报评测完成 |
| M3 改编、采纳与定稿 | M2；FR-07／08／09 | 骨架、手工剧本、参考稿局部采纳、来源、独立定稿与过期保护贯通 |
| M4 外部 Agent 协作 | M1～M3；FR-13／14／20／22～26／31～34 | 稳定接入、按需上下文、持续参考稿、公开反馈接续、场景 Skills 与真实宿主旅程；Apps 及无增强能力路径分别验收 |
| M5 协作与交付 | M3；FR-10／11／12／18 | Git 冲突与未知恢复、标准格式及 Bundle 核验通过 |
| M6 macOS 发布收口 | M1～M5；FR-16／19 | Mac V1 门禁、签名、安装、升级、辅助功能及离线旅程通过 |
| M6-W Windows 实施与发布 | Mac 完整验收；跨平台内核与合同 | Windows 原生客户端、CLI、分发及完整旅程独立通过 |
| M7 可选商业生态 | 核心稳定；FR-17 | 多媒体调度插件单独授权、费用与故障验收 |

阶段表示依赖与可独立验收的工作包，不是固定日期承诺。共享内核保持平台边界，Windows 风险记录在平台设计中；Windows 实施不抢占 Mac 完整闭环。

### 1.1 本期实施顺序

先统一需求、领域、数据、API、交互、图示与验收；文档检查通过后，按第6节切片推进：稳定接入与随包 CLI → 固定上下文的窄读取 → 工作副本及提交 → 反馈接续与场景 Skills → Mac 界面和真实 Codex 全程验收。每片同时完善 Core 事务、机器 Schema、能力目录、入口与错误恢复，不先做一个不可调用的页面。资料、设计、候选和固定使用归入 M1／M4，原创与改编分集及语义编辑归入 M3，片段交接不引入内置生成 API。

每个切片同时提供手工路径和 Agent 合同，不能先做仅可点选的界面再补 Agent 入口。保留现有作品并对格式变化提供预演和迁移；不得以重建测试数据掩盖兼容或引用问题。Windows 后置，服务端、商业插件和完整三维编辑器不列为本期前置。

## 2. 技术准入条件

1. Rust + Cargo + git2/libgit2 在目标系统的依赖、许可和打包是否闭合。
2. 同一 Swift CLI 能否在 macOS／Windows 原生构建、运行 C ABI、处理中英文管道、确认、取消与干净系统部署。
3. 原生编辑器能否稳定支持中文 IME、10 万汉字及 UTF-8／UTF-16／Swift 定位转换。
4. 文件事务与进程锁在支持的文件系统上能否通过中断与外部改写测试。
5. 无模型的中文提取规则能提供何种可量化覆盖，哪些明确交给作者／Agent。
6. MCP 当前规范、Rust 实现路线、宿主版本和 Apps 信任边界是否可验证。
7. Fountain、DOCX／PDF 导入导出依赖及中文模板是否满足实际接收方要求。
8. 依赖与分发产物符合 Apache-2.0 及第三方许可要求。

原型失败必须更新决策与风险，不可用临时脚本或手工复制充当已完成产品。

## 3. 最小产品切片

第一个切片在作者书库登记两部独立小说，分别维护资料、封面和设定；其中一部包含可选分卷、两章正文、一集两场改编骨架与定稿剧本。全部内容可手工提供，保存、校验、独立定稿、导出及切书不依赖 Agent。第二切片从河图洛书选择客户端开始，覆盖无书名筹备、专用 Skill、复制 Prompt、候选、局部采纳、编辑及独立定稿，并加入 Apps 和本地浏览器的同任务交互及回退。第三切片加入 Git 冲突、批量内容与格式交付。

每个切片先完成 Mac 共享内核、CLI 与原生界面的贯通验证。Mac 验收不能表述为 Windows 支持；后续 Windows 阶段执行独立验收。

## 4. 每阶段交付清单

- 所属需求、机器合同、最小可运行功能和失败恢复一致。
- 用户故事到测试的映射完整，示例不依赖私有相邻仓库。
- 当前源修订／树摘要、构建产物、平台与实际结果可追溯。
- 必要指南只写已落地命令，未实现内容留在本路线和专项设计。
- 用户数据、原操作记录与未保存缓冲均受到保护。

## 5. 服务端演进与准入顺序

实施优先级为 Mac 完整创作与本机 MCP → 外部 Agent／局部交互验收 → Mac 发行及 Windows 独立实施。官网可独立建设，不改变本机软件的离线前提；不将云账号或公共服务列为 M1～M6 的依赖。

| 顺序 | 交付目标 | 准入与退出条件 |
| --- | --- | --- |
| 本机核心 | M1～M3、M5 的书库、创作、校验、采纳、定稿及交付 | 无网络与 Agent 完成作者全程；保护中文输入和本机数据 |
| 本机协作 | M4 的插件／Skills、独立 stdio MCP；Apps 与按需本地网页 | 分别验收真实宿主、权限、原任务恢复及无增强界面的回退 |
| 桌面发行 | M6、M6-W | Mac 先完成；Windows 独立验证，不用云后端替代缺失平台能力 |

服务端业务须有明确用户场景和必要性后单独立项，并补齐需求、故事、数据归属、权限、API 及验收。当前可选模型服务以 hetu website 为产品接入层，复用 Cloud 身份、文字与图片模型及 Console 费用入口；不另建云端书库、常驻本机中继或同步双写。商业插件按自身需求评估，不依赖服务端立项。

场景适配 FR-30 贯穿 M1、M3～M5：引导／新建 → 原著与权利记录 → 四种导入用途 → 小说或分集工作台 → 外部任务 → 分材料交付检查。各场景独立完成手工、Agent 可选、失败恢复及真实 UI 旅程，不把单一小说夹具通过视为全部场景适配。

## 6. 持续协作的实施准入

本节集中记录设计与实现的差距及退出证据；产品需求、图示和 API 描述目标合同，安装版本只以实际能力目录为准。以下基线核对日期为2026-11-14，源码与分层检查的进展不构成整条持续协作链路或真实宿主已经通过的声明。

| 切片 | 实现基线与缺口 | 实施范围与退出条件 |
| --- | --- | --- |
| 稳定接入 | 当前 Codex 会话已通过随包 `--client` CLI 打开两个独立作品任务，验证精确引用、串书拒绝及逐任务撤权；新会话自动发现与真实宿主 MCP 连接另行验收，插件缓存不作为接入证据 | 随软件稳定助手入口、私有任务授权映射、精确 open；真实 Codex 新会话读写隔离测试任务及两作品，后续任务无需改连接 |
| CLI 分发 | Swift CLI 源码包含单任务／筹备定位及稳定接入，构建入口装配随包 CLI；源码或构建脚本不证明干净用户环境可运行 | 随 Mac 制品装配可独立启动 CLI，和 MCP 共享单筹备／任务授权；无 Xcode、开发目录和桌面进程可执行任务读写，版本及摘要可核验 |
| 上下文 | 源码包含请求记录1.1.0的固定清单、目录／字面检索／片段读取，以及较大设定集的分类和实体窄读取，均从不可变修订回读；缺项请求、作者补充及请求升级仍待实现 | 固定清单、目录／摘要／检索／片段、具体缺项和作者补充；大作品不靠扩大单次返回预算，越权及请求升级负例通过 |
| 资料影响核对 | 独立同版 Core 链接及专项集成通过；隔离原生弹窗的中文切换、旧稿定位、未保存提示、刷新与关闭通过，英文文案及布局已截图核对。英文后续操作因 CUA 超时未完成；生成文案与当前源一致，统一 App 装配和安装仍待完成 | 19第3.4节；保留固定旧版、错误拒绝、空锚点、归档、分页及缓冲保护；最终 App 使用同版 Swift／Core 并核验符号和资源，再补齐英文操作、筛选、失败恢复、键盘及最小窗口验收，不自动改稿或确认关联 |
| 持续参考稿 | 当前 Codex 已在同一任务连续保存两版原创首章、分别固定提交、重放原键并回读旧候选；请求版本发布及可选检出导入仍待实现 | WorkingCopy／WorkingRevision、CAS、原键、可选检出导入、固定候选；旧请求失效、作者并发、旧候选不可改及正文隔离通过 |
| 反馈接续 | 当前 Codex 已回读针对确切成果的作者意见，沿原参考稿返工并关联后续成果；隔离作者驱动验证局部采用与独立定稿。原生端可复制继续提示词，Apps 消息的实际宿主接续另行验收 | 明确反馈目标、保存后继续、宿主消息与复制回退；三个结果分别可见，Agent 回读原任务返工，无重复任务和未知重发 |
| 场景方法 | 共用方法包含同任务参考稿、意见返工及原创／改编分流，按唯一源生成分发；当前 Codex 已提交并回读无原著、无骨架的原创 Fountain，原生小说起草与原创剧本任务入口测试通过 | 共用原创小说／原创剧本／改编／素材方法，按需加载资料；生成脚本同步全部分发包，真实原创剧本不要求原著 |
| 完整验收 | 当前 Codex 的真实 CLI 创作与返工、原生状态、协议及整书驱动分别取证；当前会话不替代新安装发现或真实 Apps 宿主，预制内容不作为真实 Agent 创作证据 | 执行19第3.3节，保存新会话筹备至首章反馈返工、局部采纳、恢复、撤权、原创剧本与素材的真实证据 |

各切片先实现共享 Core 与精确机器合同，再装配 CLI／MCP／Skills 和 Mac 界面，最后用同一制品验收。发布设计动作前更新合同修订、兼容读取与迁移预演；不能修改已有请求或候选摘要伪装升级。现有手工创作、保存、独立定稿和历史查看持续可用。

资料影响核对的本轮分层复核及资源摘要记录于 `build/requirements-audit/resource-impact-integration-2026-11-14/`；该专项记录不替代真实 Agent 全旅程或安装 App 的界面验收。

Mac 本期完成须同时满足 FR-31～34 的能力与负例，以及 E2E-18～21 中所声明宿主路径；未执行能力标 not_run／blocked，不由本节文字判通过。Windows、云端会话观察、服务端、商业生成插件均不抢占本期本机协作闭环。

## 7. 全软件 Agent 联动的实施准入

产品与交互按 FR-35 组织：外部 Agent 操作全软件，桌面端首先用于可视化 review 与审核，其次用于作者编辑优化；作者不承担资料及操作表单的重复填写。本节记录实现差距，不能以文档目标替代安装版本能力。

2026-11-14 复验：稳定 CLI／MCP 已开放无任务筹备，有限新建仅分配独立受管目录。Agent 可保存筹备资料、明确返回的新目录、创建小说或原创剧本、建立空章节／分集并准备首任务；管理引用与 TaskGrant 分开，Agent 身份和审计保持不变，不能采纳或定稿。新建作品只派生本客户端、本范围的管理引用；作者可撤销管理授权及其派生任务。任意已有目录接入、完整操作提案、全页交接及设置等仍按下表分别验收，不能由该切片推定已完成。

由本对话 Codex 通过公开 CLI 完成小说与原创剧本两条从零旅程：筹备、资料、创建、空章／分集、首任务、实际创作、同稿多版、固定提交、公开反馈返工及原键重放。隔离测试作者通道独立验证局部采纳、采纳不等于定稿、独立定稿及撤权；未用作者驱动或 GUI 补齐业务步骤。原生客户端已只读核对两部演示作品的定稿状态与选用正文。[本轮证据](research/evidence/current-codex-acceptance-2026-11-14.json)保留安装版和此前源码缺入口的首次失败，以及修复后的分步回执、制品摘要和验收边界；原始材料位于 `build/current-codex-acceptance-20261114/`。这只确认源码 CLI 的上述旅程及隔离作者合同；真实 MCP 宿主安装发现、Apps、签名安装包和全软件页面仍须分别验收，不以 Core、stdio 或源码 QA App 替代。

| 实施顺序 | 交付切片 | 退出证据 |
| --- | --- | --- |
| 1 | 拆分发现、读取、草稿维护、操作准备、获权执行及作者决定；定义确切对象与范围 | Core 拒绝自批和范围扩大；无需通用作者模式，已有任务隔离、CAS 及撤权保持 |
| 2 | 无作品筹备→Agent 填资料→新建预览及执行→新作品定位→首任务 | E2E-22；无 GUI 或预建任务，不覆盖既有目录，原键恢复及原创剧本分支通过 |
| 3 | 作品目录、资料、设定提案、导入、检查、版本、交付及设置的机器用例 | 用例逐项有 Schema、CLI/MCP、预览／执行／回读／恢复；需要决定时审阅完整提案，无需重填 |
| 4 | 书库及全部工作页的精确交接、待审成果和提案展示，手动编辑保留 | E2E-23～24、AC-50～54；机器新建作品进入原生书库并打开同一作品与任务供 review，无需作者重填；中文与英文、空／只读／无权／冲突／未知状态覆盖 |
| 5 | Skills 从实际能力完成全旅程，真实 Codex 机器验收，再做 GUI 验收和安装 | 同一制品证据；机器步骤不靠 Computer Use、作者夹具或受管文件直写补齐，不冒称未验证宿主可用 |

发生接口缺口时修正应用用例与权限，不能增加固定“回 GUI 填表”步骤。保留已完成的作品、修订、任务及作者决定；格式变化须有明确迁移和旧记录读取测试。Windows、云端和新生成服务接入不扩大本切片。
