### 1.1 本期实施顺序

先统一需求、领域、数据、API、交互、图示与验收；持续协作基础按第6节核对，本轮重构按38的R0～R5推进：既有分集可读→创作库三类入口与固定关联→一集资产及预演→真实视频与音画→局部返工、工程交付和全剧覆盖。每片同时完善 Core 事务、机器 Schema、能力目录、入口与错误恢复，不先做一个不可调用的页面。资料、设计、候选和固定使用归入 M1／M4，原创与改编分集及语义编辑归入 M3，制作由外部客户端或桌面托管的所选Agent经工具或固定计划适配器推进；Core不自建推理或未经授权的生成循环。

## 2. 技术准入条件

1. Rust + Cargo + git2/libgit2 在目标系统的依赖、许可和打包是否闭合。
2. 独立Rust CLI能否保持公开语义，在macOS／Windows处理中英文管道、权限、取消与干净系统部署；Swift CLI只作对照。
3. Web编辑器能否稳定支持中文IME、10万汉字、撤销和UTF-8／UTF-16来源定位；原生编辑器提供行为对照。
4. 文件事务与进程锁在支持的文件系统上能否通过中断与外部改写测试。
5. 无模型的中文提取规则能提供何种可量化覆盖，哪些明确交给作者／Agent。
6. MCP 当前规范、Rust 实现路线、宿主版本和 Apps 信任边界是否可验证。
7. Fountain、DOCX／PDF 导入导出依赖及中文模板是否满足实际接收方要求。
8. 依赖与分发产物符合 Apache-2.0 及第三方许可要求。

原型失败必须更新决策与风险，不可用临时脚本或手工复制充当已完成产品。

## 3. 最小产品切片

既有文本基础切片在小说分类登记两部独立小说，分别维护资料、封面和设定；其中一部包含可选分卷、两章正文、一集两场改编骨架与定稿剧本。全部内容可手工提供，保存、校验、独立定稿、导出及切书不依赖 Agent。第二切片从河图洛书选择客户端开始，覆盖无书名筹备、专用 Skill、复制 Prompt、候选、局部采纳、编辑及独立定稿，并加入 Apps 和本地浏览器的同任务交互及回退。第三切片加入 Git 冲突、批量内容与格式交付。

每个新切片先完成Mac共享内核、CLI与插件工作面的贯通验证。Mac 验收不能表述为 Windows 支持；后续 Windows 阶段执行独立验收。

## 4. 每阶段交付清单

- 所属需求、机器合同、最小可运行功能和失败恢复一致。

### 7.1 全页面 AI-first 机器链路

页面按同一责任边界组织：Agent 准备资料和完整操作，作者阅读、比较并作出必要决定，Agent 执行获批事务，客户端显示同一领域结果。每项交接包含实际对象、固定修订、允许能力和恢复引用；不以复制提示词、源码盘点或按钮存在替代执行证据。

| 页面与场景 | 机器入口与成果 | 作者决定 |
| --- | --- | --- |
| 书库、新建与接入 | 稳定客户端连接；从零筹备、资料保存及受管新建；小说和原创剧本保持独立身份，书库自动接纳 | 已有作品精确授权；删除作品仍由作者确认完整作品名 |
| 作品资料、卷章、大纲 | 读取当前修订并准备完整结构或资料方案；固定对象身份、差异和执行回执 | 审阅确切方案，不重新填写 Agent 已准备的内容 |
| 正文、搜索、批注 | 精确文档与 UTF-8 选区交接；持续参考稿、公开反馈及固定候选；排除未保存缓冲和私密批注 | 自行编辑、局部采用和定稿分别决定 |
| 设定、人物、地点 | 固定设定与实体交接；未锁定设定维护走方案，资料整理走独立任务 | 解锁、设定采用与人物图片选用保持独立 |
| 剧情、短剧项目、分集和场次 | 抽取、检查、剧情校正、骨架修改、项目及空分集方案；当前骨架和场次单独固定版本 | 确认改编取舍；台词与正文仍由参考稿交付 |
| 资料、图片、封面 | 资料任务、素材导入、来源权利、线索及引用关联方案；图片按人物、地点、正文和图库展示 | 权利确认、封面一键选用和模型费用批准 |
| 诊断、意见、审核 | 固定报告、问题和处置修订；Agent 可保存建议，持续返工保留原任务及旧批次 | 问题正式处置、采纳与定稿不由 Agent 代替 |
| 版本、冲突和同步 | 固定快照及分支、合并、远端方案；历史内容有界读取，推拉目标固定，原键恢复 | 确认具体提交、合并选择和网络操作；保留当前正文、领域状态及未保存稿 |
| 导入、导出和交付 | Agent 提交明确文件字节，预览格式损失，准备固定导入或选集交付；回读并核对产物摘要 | 审阅转换结果、固定选集和交付内容；正式交付继续要求有效定稿 |
| 本机设置、扩展和关于 | local_settings 读取白名单、准备偏好或所选套件安装方案，独立本机 Owner 执行；安装和会话发现分开核对 | 密钥、账号登录和私密配置由作者掌握，不通过普通交接回读 |
| 空、只读、无权、冲突与未知 | 使用当前对象交接或精确恢复引用；权限、版本和能力错误明确返回 | 不扩大范围、不换键重发；需要的决定只出现在对应结果和风险处 |

作品管理使用带修订的 management_ref；任务维护使用独立 task_ref。批准创建任务后，为同客户端派生 task_locator；撤权再授权不能复活旧任务。固定方案维持 Agent 身份，不开放通用作者调用、正文直接覆盖、采纳、定稿、解锁或费用自批。

导入的机器入口使用 inline_source 文件内容与摘要，作品授权不能用于读取任意本机 file_path；作者手动文件选择仍可用。固定字节、输入预算、审阅预算、版本冲突和原键重放由 Core 校验。设置和扩展使用独立本机方案，不借作品授权扩权。MCP Apps 操作视图只读方案及状态，不能批准或执行。

验证按源码盘点、Core、公开 CLI／stdio MCP、原生集成、SDK Apps 浏览器集成与真实 GUI 分层记录。[0.7.0统一装配验收](research/evidence/ai-first-complete-2026-11-15.json)记录 Core194项、MCP stdio20项、原生全量、浏览器29项及工具17项通过；公开 CLI 的111条回执及跨领域51条组合回执覆盖具体机器事务。当前 Codex 会话实际 MCP 的固定原著读取、参考稿保存、提交与回读通过，既有[页面交接证据](research/evidence/ai-first-pages-2026-11-15.json)保留此前缺口和界面观察范围。安装版位于 `/Applications/Hetu.app`，包内 CLI／MCP／Core／Skills 及资源摘要一致，安装版 stdio20项通过；旧应用备份按作者要求清理。

外部 Codex／Claude Code／WorkBuddy 的真实 Apps 宿主、各宿主可信批准、真实 Gitee／GitHub 鉴权同步、签名公证安装包及首次加载性能分别验收。SDK 浏览器集成和本地 bare remote 测试不能推导这些能力已通过；本机测试工具不可用时保留明确失败记录，不把 GUI 项记为通过。

## 图片资产验收边界

## 小说导入与改编接续

`hetu-import` 提供原稿快照、阅读文本、目录与范围核对以及可恢复 CLI 编排。TXT、Markdown、DOCX、EPUB 和 HTML 按实际格式处理；复杂或无法解析的文件由 Agent 选择明确转换方法。普通小说导入由 Agent 整理完整输入，作者审阅结果；章节重号、同名和原文中的转义文本保持来源，不按章名合并。

`hetu.documents.import_batch` 在固定目录基线下原子导入有界的一批章节，保存每章原字节、转换报告及不可变修订。脚本固定作品、计划摘要、方案、执行键和校验进度，遇到未知结果沿原记录恢复，不重建作品或换键重复导入。正式作品及导入快照不使用构建目录。

《持械入宋》使用作者指定的本机文件作为真实导入与改编来源。[整书导入及开篇改编验收](research/evidence/novel-import-adaptation-2026-11-15.json)记录510章和1篇作品说明、5组目录，全部511篇已逐一回读；原稿、计划和恢复记录存于作者的持久目录。开篇6集独立 Fountain 参考稿、13份人物／场景／道具及改编资料已写入，当前 Codex 经真实 MCP 和 CLI 执行，安装版书库自动接纳同一作品。原生只读专项核对全部目录和固定成果，不将开篇六集称为全书改编完成。
