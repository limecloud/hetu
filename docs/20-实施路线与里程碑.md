### 1.1 本期实施顺序

先统一需求、领域、数据、API、交互、图示与验收；持续协作基础按第6节核对，本轮重构按38的R0～R5推进：既有分集可读→创作库三类入口与固定关联→一集资产及预演→真实视频与音画→局部返工、工程交付和全剧覆盖。每片同时完善 Core 事务、机器 Schema、能力目录、入口与错误恢复，不先做一个不可调用的页面。资料、设计、候选和固定使用归入 M1／M4，原创与改编分集及语义编辑归入 M3，制作由外部Agent经工具或固定计划适配器推进，不引入内置Agent或自主生成循环。

每个切片同时提供手工路径和 Agent 合同，不能先做仅可点选的界面再补 Agent 入口。保留现有作品并对格式变化提供预演和迁移；不得以重建测试数据掩盖兼容或引用问题。Windows 后置，服务端、商业插件和完整三维编辑器不列为本期前置。

## 2. 技术准入条件

1. Rust + Cargo + git2/libgit2 在目标系统的依赖、许可和打包是否闭合。
2. 独立Rust CLI能否保持公开语义，在macOS／Windows处理中英文管道、权限、取消与干净系统部署；Swift CLI只作对照。
3. Web编辑器能否稳定支持中文IME、10万汉字、撤销和UTF-8／UTF-16来源定位；原生编辑器提供行为对照。
4. 文件事务与进程锁在支持的文件系统上能否通过中断与外部改写测试。
5. 无模型的中文提取规则能提供何种可量化覆盖，哪些明确交给作者／Agent。
6. MCP 当前规范、Rust 实现路线、宿主版本和 Apps 信任边界是否可验证。
7. Fountain、DOCX／PDF 导入导出依赖及中文模板是否满足实际接收方要求。
8. 依赖与分发产物符合 Apache-2.0 及第三方许可要求。

原型失败必须更新决策与风险，不可用临时脚本或手工复制充当已完成产品。

## 3. 最小产品切片

既有文本基础切片在小说分类登记两部独立小说，分别维护资料、封面和设定；其中一部包含可选分卷、两章正文、一集两场改编骨架与定稿剧本。全部内容可手工提供，保存、校验、独立定稿、导出及切书不依赖 Agent。第二切片从河图洛书选择客户端开始，覆盖无书名筹备、专用 Skill、复制 Prompt、候选、局部采纳、编辑及独立定稿，并加入 Apps 和本地浏览器的同任务交互及回退。第三切片加入 Git 冲突、批量内容与格式交付。

每个新切片先完成Mac共享内核、CLI与插件工作面的贯通验证。Mac 验收不能表述为 Windows 支持；后续 Windows 阶段执行独立验收。

## 4. 每阶段交付清单

- 所属需求、机器合同、最小可运行功能和失败恢复一致。
- 用户故事到测试的映射完整，示例不依赖私有相邻仓库。
- 当前源修订／树摘要、构建产物、平台与实际结果可追溯。
- 必要指南只写已落地命令，未实现内容留在本路线和专项设计。
- 用户数据、原操作记录与未保存缓冲均受到保护。

## 5. 服务端演进与准入顺序

实施优先级为 Mac 完整创作与本机 MCP → 外部 Agent／局部交互验收 → Mac 发行及 Windows 独立实施。官网可独立建设，不改变本机软件的离线前提；不将云账号或公共服务列为 M1～M6 的依赖。

| 顺序 | 交付目标 | 准入与退出条件 |
| --- | --- | --- |
| 本机核心 | M1～M3、M5 的书库、创作、校验、采纳、定稿及交付 | 无网络与 Agent 完成作者全程；保护中文输入和本机数据 |
| 本机协作 | M4 的插件／Skills、独立 stdio MCP；Apps 与按需本地网页 | 分别验收真实宿主、权限、原任务恢复及无增强界面的回退 |
| 桌面发行 | M6、M6-W | Mac 先完成；Windows 独立验证，不用云后端替代缺失平台能力 |

服务端业务须有明确用户场景和必要性后单独立项，并补齐需求、故事、数据归属、权限、API 及验收。当前可选模型服务以 hetu website 为产品接入层，复用 Cloud 身份、文字与图片模型及 Console 费用入口；不另建云端书库、常驻本机中继或同步双写。商业插件按自身需求评估，不依赖服务端立项。

场景适配 FR-30 贯穿 M1、M3～M5：引导／新建 → 原著与权利记录 → 四种导入用途 → 小说或分集工作台 → 外部任务 → 分材料交付检查。各场景独立完成手工、Agent 可选、失败恢复及真实 UI 旅程，不把单一小说夹具通过视为全部场景适配。

## 7. 全软件 Agent 联动的实施准入

产品与交互按 FR-35 组织：外部 Agent 操作全软件，桌面端首先用于可视化 review 与审核，其次用于作者编辑优化；作者不承担资料及操作表单的重复填写。本节记录实现差距，不能以文档目标替代安装版本能力。

2026-11-14 复验：稳定 CLI／MCP 已开放无任务筹备，有限新建仅分配独立受管目录。Agent 可保存筹备资料、明确返回的新目录、创建小说或原创剧本、建立空章节／分集并准备首任务；管理引用与 TaskGrant 分开，Agent 身份和审计保持不变，不能采纳或定稿。新建作品只派生本客户端、本范围的管理引用；作者可撤销管理授权及其派生任务。任意已有目录接入、完整操作提案、全页交接及设置等仍按下表分别验收，不能由该切片推定已完成。

由本对话 Codex 通过公开 CLI 完成小说与原创剧本两条从零旅程：筹备、资料、创建、空章／分集、首任务、实际创作、同稿多版、固定提交、公开反馈返工及原键重放。隔离测试作者通道独立验证局部采纳、采纳不等于定稿、独立定稿及撤权；未用作者驱动或 GUI 补齐业务步骤。原生客户端已只读核对两部演示作品的定稿状态与选用正文。[本轮证据](research/evidence/current-codex-acceptance-2026-11-14.json)保留安装版和此前源码缺入口的首次失败，以及修复后的分步回执、制品摘要和验收边界；原始材料位于 `build/current-codex-acceptance-20261114/`。这只确认源码 CLI 的上述旅程及隔离作者合同；真实 MCP 宿主安装发现、Apps、签名安装包和全软件页面仍须分别验收，不以 Core、stdio 或源码 QA App 替代。

### 7.1 全页面 AI-first 机器链路

页面按同一责任边界组织：Agent 准备资料和完整操作，作者阅读、比较并作出必要决定，Agent 执行获批事务，客户端显示同一领域结果。每项交接包含实际对象、固定修订、允许能力和恢复引用；不以复制提示词、源码盘点或按钮存在替代执行证据。

| 页面与场景 | 机器入口与成果 | 作者决定 |
| --- | --- | --- |
| 书库、新建与接入 | 稳定客户端连接；从零筹备、资料保存及受管新建；小说和原创剧本保持独立身份，书库自动接纳 | 已有作品精确授权；删除作品仍由作者确认完整作品名 |
| 作品资料、卷章、大纲 | 读取当前修订并准备完整结构或资料方案；固定对象身份、差异和执行回执 | 审阅确切方案，不重新填写 Agent 已准备的内容 |
| 正文、搜索、批注 | 精确文档与 UTF-8 选区交接；持续参考稿、公开反馈及固定候选；排除未保存缓冲和私密批注 | 自行编辑、局部采用和定稿分别决定 |
| 设定、人物、地点 | 固定设定与实体交接；未锁定设定维护走方案，资料整理走独立任务 | 解锁、设定采用与人物图片选用保持独立 |
| 剧情、短剧项目、分集和场次 | 抽取、检查、剧情校正、骨架修改、项目及空分集方案；当前骨架和场次单独固定版本 | 确认改编取舍；台词与正文仍由参考稿交付 |
| 资料、图片、封面 | 资料任务、素材导入、来源权利、线索及引用关联方案；图片按人物、地点、正文和图库展示 | 权利确认、封面一键选用和模型费用批准 |
| 诊断、意见、审核 | 固定报告、问题和处置修订；Agent 可保存建议，持续返工保留原任务及旧批次 | 问题正式处置、采纳与定稿不由 Agent 代替 |
| 版本、冲突和同步 | 固定快照及分支、合并、远端方案；历史内容有界读取，推拉目标固定，原键恢复 | 确认具体提交、合并选择和网络操作；保留当前正文、领域状态及未保存稿 |
| 导入、导出和交付 | Agent 提交明确文件字节，预览格式损失，准备固定导入或选集交付；回读并核对产物摘要 | 审阅转换结果、固定选集和交付内容；正式交付继续要求有效定稿 |
| 本机设置、扩展和关于 | local_settings 读取白名单、准备偏好或所选套件安装方案，独立本机 Owner 执行；安装和会话发现分开核对 | 密钥、账号登录和私密配置由作者掌握，不通过普通交接回读 |
| 空、只读、无权、冲突与未知 | 使用当前对象交接或精确恢复引用；权限、版本和能力错误明确返回 | 不扩大范围、不换键重发；需要的决定只出现在对应结果和风险处 |

作品管理使用带修订的 management_ref；任务维护使用独立 task_ref。批准创建任务后，为同客户端派生 task_locator；撤权再授权不能复活旧任务。固定方案维持 Agent 身份，不开放通用作者调用、正文直接覆盖、采纳、定稿、解锁或费用自批。

导入的机器入口使用 inline_source 文件内容与摘要，作品授权不能用于读取任意本机 file_path；作者手动文件选择仍可用。固定字节、输入预算、审阅预算、版本冲突和原键重放由 Core 校验。设置和扩展使用独立本机方案，不借作品授权扩权。MCP Apps 操作视图只读方案及状态，不能批准或执行。

验证按源码盘点、Core、公开 CLI／stdio MCP、原生集成、SDK Apps 浏览器集成与真实 GUI 分层记录。[0.7.0统一装配验收](research/evidence/ai-first-complete-2026-11-15.json)记录 Core194项、MCP stdio20项、原生全量、浏览器29项及工具17项通过；公开 CLI 的111条回执及跨领域51条组合回执覆盖具体机器事务。当前 Codex 会话实际 MCP 的固定原著读取、参考稿保存、提交与回读通过，既有[页面交接证据](research/evidence/ai-first-pages-2026-11-15.json)保留此前缺口和界面观察范围。安装版位于 `/Applications/Hetu.app`，包内 CLI／MCP／Core／Skills 及资源摘要一致，安装版 stdio20项通过；旧应用备份按作者要求清理。

外部 Codex／Claude Code／WorkBuddy 的真实 Apps 宿主、各宿主可信批准、真实 Gitee／GitHub 鉴权同步、签名公证安装包及首次加载性能分别验收。SDK 浏览器集成和本地 bare remote 测试不能推导这些能力已通过；本机测试工具不可用时保留明确失败记录，不把 GUI 项记为通过。

## 图片资产验收边界

图片成果由外部 Agent 经 Skills + CLI/MCP 提交，原生端提供角色、地点、封面、正文关联视图及统一图片资产库。批次接收不等于采用。2026-11-15 的《归宋守渡》实际调用使用单一自定义图片模型：封面、场景和插图已回传；人物和道具的原计划结果未知，未重复请求，不能登记为五类全部通过。

作者另行批准一次沈砚三视图请求后，当前 Codex 经 MCP 成功生成并收集完整三视图，从原图无缩放裁出正面、侧面和背面，四张固定候选已提交并回读。该图组绑定沈砚及设定修订3，裁切记录含原图与各文件摘要。角色主图只取单人形象或正面，图组与多人情节插图分别展示；新请求不改变原人物超时计划的未知状态，也不证明道具生图成功。

本次实际作者批准来自当前会话的明确授权，经限定固定计划摘要的可信本机 SDK 记录；没有新增通用 author CLI、自报 approved 字段或自动批准。普通任务中的模型操作表单已移除；各外部宿主的通用可信批准桥接仍需单独实现及验收，不能以本次 SDK 记录代替宿主确认能力。

本轮[图片生成与本地展示证据](research/evidence/image-generation-codex-2026-11-15.json)固定了7张候选、生成与裁切来源、原生界面核对范围及统一开发包摘要。最终新进程已核对中英文角色图组与封面详情、等比三视图、角色关联插图、服装空态及图片意见目标；已有未提交意见不会随切图改投。Core 图片相关20项、MCP stdio 17项和原生图片库／封面专项通过；214个既有作品文件摘要保持不变，未选用封面或修改定稿。当前插图关联人物与地点，正文关联仅由专项集成验证，不宣称演示作品某章已经显示插图。

本地图片读取已加入有界缩略图缓存、对象页共享状态及开发包优化；缓存命中仍核验原图完整摘要和当前权限。相同作品的常驻 Core ABI 测量中，7图首次／重复读取由24.64／25.92秒降为7.81／1.89秒，该数值不代表软件启动。完整原生 SDK 在本机严重负载下仍测得打开作品11.89秒、首次图库26.69秒、刷新11.63秒；测量时8核／16 GB机器负载超过100，交换空间使用约18 GB。保留构建期间及结束后的全部样本，首次完整打开性能仍未验收通过；现有事务历史检查与首次解码开销须继续按19第4节测量，不能以缓存收益替代启动目标。

## 小说导入与改编接续

`hetu-import` 提供原稿快照、阅读文本、目录与范围核对以及可恢复 CLI 编排。TXT、Markdown、DOCX、EPUB 和 HTML 按实际格式处理；复杂或无法解析的文件由 Agent 选择明确转换方法。普通小说导入由 Agent 整理完整输入，作者审阅结果；章节重号、同名和原文中的转义文本保持来源，不按章名合并。

整书导入的会话授权由 `hetu.import_authorizations.register/get/revoke` 固定作品、原稿、完整目录与实际用户指令；批次执行携带原授权引用，在范围内连续运行，不依赖桌面逐批批准。实现与真实安装版验收分别记录，未通过的结果不登记完成。

`hetu.documents.import_batch` 在固定目录基线下原子导入有界的一批章节，保存每章原字节、转换报告及不可变修订。脚本固定作品、计划摘要、方案、执行键和校验进度，遇到未知结果沿原记录恢复，不重建作品或换键重复导入。正式作品及导入快照不使用构建目录。

《持械入宋》使用作者指定的本机文件作为真实导入与改编来源。[整书导入及开篇改编验收](research/evidence/novel-import-adaptation-2026-11-15.json)记录510章和1篇作品说明、5组目录，全部511篇已逐一回读；原稿、计划和恢复记录存于作者的持久目录。开篇6集独立 Fountain 参考稿、13份人物／场景／道具及改编资料已写入，当前 Codex 经真实 MCP 和 CLI 执行，安装版书库自动接纳同一作品。原生只读专项核对全部目录和固定成果，不将开篇六集称为全书改编完成。

用户实用复核发现前六集从分集页面不能阅读已提交参考稿。此前原生专项仅核对任务候选，漏掉项目到分集的阅读入口，因此本书可用性交付判定为未通过，不能用下层测试代替。修复范围包括固定目标关联、分集阅读投影、参考稿直读与原任务接续、Skills 交付回读及原生界面验收。全书改编、完整设定与制作素材仍须继续完成，不以开篇样稿代替。

导入中发现的 TXT 摘要比较错误、锁屏恢复记录不可读及隔离书库误接纳真实作品已修复并复验。结果未知沿原计划、原方案和原键接续，未重建作品或重复导入。外部 Agent 的剧本和资料保持待作者审阅，不修改或定稿原著，不从本机导入推断公开传播权；当前本书 GUI 排版验收因 CUA 初始化资源错误仍为 blocked。
