# 品牌视觉与原型规范

产品交互以外部 Agent 操作、作者可视化 review 与审核为主，作者手动编辑优化为第二作用。原型必须覆盖全页 AI 交接、Agent 已填好的完整方案、成果与差异、必要作者决定及执行结果，不以手工录入表单代表默认旅程；具体页面覆盖以[10第2.1节](10-原生客户端与交互设计.md#21-每页的-ai-操作入口)为准。官网以具体创作例子表达这一最终产品分工，内部实施差距由20维护。

河图洛书的视觉以“作者拥有自己的故事世界”为主题。中文名称为“河图洛书”，英文为 Hetu Luoshu；中文界面使用“设定集”，英文使用 Story Bible。品牌表达为：**设定有据，创作有序。**

品牌叙事遵循[产品核心价值](01-产品需求PRD.md#1-产品定义)：**让越来越强的 AI，围绕作者持续积累的作品工作；让每一次生成，都有机会成为可理解、可选择、可继续创作的成果。** 宣传优先用具体创作例子表现来源、候选比较、作者取舍及继续修改；价值观在创作主张和产品介绍中完整表达，操作界面通过实际行为体现，避免重复口号挤占写作空间。

## 1. 品牌角色

吉祥物“小图”是一只玉青色的小龙马：暖玉白的卷轴鬃毛、短圆角、三枚横向金点、墨色眼睛与朱砂印章吊坠。卷轴连接设定与创作，印章表达作者确认；角色保持友善、安静，不使用战斗表情或复杂鳞片。

3D 表面采用柔和陶瓷与黏土质感，保留适度高光和柔影。Logo 与宣传插画共用母图，不对每个场景重新发明角色。母图见[透明 PNG](../assets/brand/mascot-master.png)，展示入口见[品牌与产品设计](../design/index.html)。

## 2. 颜色与文字

界面颜色采用 Radix Colors 的语义色阶，按浅色、暗色分别映射；不继续维护近似手写色板。品牌插画的光影材质不作 UI 颜色来源。

| 色组／色阶 | 用途 |
| --- | --- |
| Sage 1～2 | 画布、纸面及低层级表面 |
| Sage／Jade 3～5 | 悬停、低强调选中与交互表面 |
| Sage 6～8 | 分隔、边框与焦点所需边界 |
| Jade 9～10 | 实心主操作及其交互态，文字对比单独核验 |
| Sage 11～12 | 次要文字与正文 |
| Jade 11～12 | 可读强调文字，不用浅背景色作文字 |
| Amber／Red 3、6、11～12 | 警告与错误表面、边界和文字，状态不只依赖颜色 |

工作区允许克制地使用 Jade、Blue、Violet 的低阶背景渐变，正文纸面保持稳定。每个页面最多四档字号且不小于12px，优先三档；通过字重、颜色与间距补层级。界面边框为0.5px，嵌套圆角按内外边距保持同心；减少阴影和动画，必要过渡采用 ease-out、约250ms，并遵循减少动态效果偏好。

产品 UI 使用平台中文无衬线字体；阅读区可采用系统宋体类字体。标题、文案和操作始终使用真实文本，避免把生成图片中的文字当成唯一的可访问内容。英文版共用语义层级，按文本长度调整布局。

官网和原生界面的交互颜色采用 Radix Colors，品牌插画保留原始资产。背景使用色阶1–2，交互底色使用3，边框使用6–8，实心操作使用9–10，文字使用11–12；小号操作文字选择满足对比度的较深色阶。官网首页桌面使用56、24、14、12px四档，手机主标题与大数字调整为40px；其他页面保留40、24、14、12px四档。原生首页使用20、14、12pt三档。分隔和边框为0.5px，按需使用小圆角，不添加装饰眉题或中点分隔，不以动画表达必要状态。

### 4.1 官网逐页设计

页面设计覆盖信息组织、版式、图文关系、导航、操作和响应式，不以更换背景代替重设计。首页的环境背景承担品牌识别；内页按作者来访的目的组织，长文与目录保持稳定纸面。

| 页面 | 信息顺序与版式 | 图形及操作 |
| --- | --- | --- |
| 首页 | 居中价值主张与主要操作 → 创作主张 → 具体痛点、市场与创作路径 → 演示与深入阅读 | 纸桥河谷独立构图；图表注明时间、来源和统计边界；主操作进入示例工作台 |
| 创作流程 | 创作起点 → 四个连续步骤 → 原文与参考稿的实际比较 → 作者确认边界 | 首屏使用稿本与设定概念图；步骤直接链接对应指南；审核区使用注明来源的首页演示截图 |
| Agent 接入 | 三方分工 → MCP、CLI、Skills → 一次协作的步骤 → 可筛选的 Skills 目录 | 用真实文本与 CSS 表达 Agent、河图、作者之间的往返关系；方法详情进入原生模态弹窗，不在目录展开长文 |
| 使用指南目录 | 入口说明与写作实图 → 开始创作、改编交付、协作管理、开发者四组任务 | 分组标题与任务链接对齐；普通作者与源码构建分组；截图链接到对应指南 |
| 使用指南正文 | 分组导航、正文、本文目录三栏；手机改为可展开的指南导航和单栏正文 | 当前指南同时以位置、字重和背景标识；正文图片可放大；页尾保留前后篇导航及演示范围说明 |
| 博客目录 | 创作者主张作为主文章 → 改编与工作方式的两篇文章 → 体验入口 | 主文章用横向图文版面，后续文章用双栏；封面各自独立，不重复排列相同素材 |
| 博客正文 | 标题与封面 → 文章目录和阅读正文 → 相关论述 → 体验入口 | 桌面目录随阅读固定，手机收为原生折叠目录；标题锚点由正文生成；改编文章提供可核查的数据图表；不添加虚构作者、日期或软件结果 |
| 常见问题 | 创作与 AI、获取与费用、作品与交稿三组 | 桌面左侧分类导航、右侧原生折叠问答；手机顺序排列；问题、展开状态和跳转均可键盘操作 |
| 品牌与设计 | 小图身份 → 资源下载 → 字标图标 → 故事空间与界面 → 品牌延展 | 下载显示资源名称及格式；品牌插画、首页演示和移动概念分别说明；不以旧网页效果图展示当前官网 |
| 404 | 明确找不到页面 → 中文首页、英文首页和使用指南 | 品牌角色作轻量陪伴；不把错误路径渲染成首页成功响应 |

内页桌面使用40、24、14、12px四档；手机标题通常使用24px，数据大数保持40px。图文分栏使用等高视觉中心，长图不拉伸；图片圆角8px，截图容器边框0.5px。字标及吉祥物作为品牌资源允许在资源页展示，叙事宣传图不在同页反复裁切充数。博客和指南采用各自的阅读布局，中英文逐页检查长标题、来源、换行与导航。

页面组成由 `apps/website/src/components/` 维护；首页视觉归 `foundation.css`，内页组成归 `pages.css`，共用的颜色与基本控件归 `global.css`，Skills 与演示交互各自维护样式。页面图形采用语义 HTML 与 CSS 时，应保留可读取的角色、关系和操作文字，不为装饰增加依赖或动画。

含文字资源按 `zh-CN` 与 `en` 分开交付，英文版使用 `-en` 文件名。中英文桌面演示、网站与移动端概念图均由对应语言的可编辑页面导出，来源保存在 `output/design/`；移动端源页面为 `design/mobile.html`，明确标注设计概念。周边展示按语言分别精修字样与排版，英文版为 `brand-merch-en.webp`。无文字插画共用原图；界面语言切换不改变小说内容，不得引用另一语言的界面图。

`assets/manifest.json` 保存实际尺寸、摘要、语言及派生来源。`tools/export-localized-assets.py` 导出字标、分享卡、图标总览与原型资源，`tools/export-brand-merch.py` 导出双语周边展示。图中文字按本地字体精确排版；生成式插画保留母图与 Prompt，不用生成文字替代产品字标。Web manifest 中的产品名与字标一致，平台图标文件名和技术标识保持稳定。

周边图是材质与品牌应用展示，印刷出血、刀模、Pantone、3D 网格及量产打样另按制造流程提供，不能把渲染图直接称为制造源文件。

## 6. 资产维护

修改角色身份需统一更新母图、图标、插画与界面示意，不能在单一场景产生不同脸型或配饰。裁切、优化和版式派生不得覆盖原始图；最终资源需核验透明度、实际尺寸、小尺寸辨识与浅暗背景。

官网和原型不引用在线字体或第三方 CDN。宣传文案与功能范围保持一致，不用下载按钮、商店徽章或兼容标志暗示未发布的应用或平台认证。

## 7. 交互设计验收

原型用于检验具体布局和交互，不承担领域或 API 事实源。评审以10的页面合同、15的采纳与定稿语义、23的图示及26的用户用例为共同依据。

| 评审范围 | 必须体现的设计 |
| --- | --- |
| 多作品入口 | 书库与单部作品分别导航，封面、资料、卷章和当前作品持续可辨 |
| 首次建书 | 无书名也能保存筹备；手工填写和外部构思均可完成，不用虚构资料替作者建书 |
| 外部协作 | 软件提供可复制 Prompt 和固定结果入口，不展示内置聊天或虚构生成进度 |
| 编辑与验收 | 作者正文为默认工作面；AI 改稿按需进入，参考候选独立呈现，可只读或选择性采纳，定稿为独立操作 |
| 局部交互 | Apps、WebView 与内置浏览器仅承载当前任务，正式决定回原生作者入口 |
| 持续协作 | 稳定接入只在设置或缺能力时出现；参考稿编辑、固定候选、公开意见及待补资料分组展示，“按此修改”按真实宿主能力继续或复制提示词 |
| 失败与恢复 | 未保存、冲突、部分结果、过期证据和未知操作具有明确状态及原任务恢复入口 |
| 中文与英文 | 默认中文、英文完整；文字为真实可访问文本，作品内容不随界面语言改变 |
| 图片与排版 | 封面按2:3展示窗口等比容纳，人物和插画不拉伸；裁切意图不改原始素材 |

用户指南讲可执行的作者任务，产品设计文档维护研发合同；网站导航不以 PRD、领域模型或内部 API 替代使用帮助。静态界面图、可点击原型、实际软件与跨宿主验收分别标注证据范围，不能互相充当完成证明。

## 8. 设计系统与原生实现

设计顺序为作者任务及状态 → 语义颜色、字体与间距 → 可复用组件 → 多作品书库和单书写作台 → 建书、短剧、参考稿与设置 → 原生实现及验收。颜色变量区分画布、正文纸面、分隔、选中、操作和错误；同一语义覆盖浅暗主题，不将整页背景渐变延伸到长文阅读纸面。装饰服务于层级，不能覆盖章节操作、正文或状态提示。

| 设计对象 | 必须覆盖的变体与行为 |
| --- | --- |

### 8.1 可编辑设计与组件映射

研发使用 Figma 时先检索已采纳组件、变量与素材，再逐区组装。真实文本、Auto Layout、组件实例和可检视属性构成界面设计；生成的整页位图用于氛围参考，不能替代可编辑原型或正文控件。品牌母图与封面资源按原比例引用，不能从界面截图反复裁切派生。

每个需还原的关键页面记录设计文件与节点、修订或采集时间、窗口尺寸、语言、主题和业务状态，并映射实际代码组件。共享视觉语义归 `assets/design/`，平台资源按04生成；Figma 是协作视图，采纳的规则须回写本仓库。Code Connect 如使用，采用经核验的模板方式；不将其设为构建原生客户端的前置条件。

macOS 按 SwiftUI/AppKit 的窗口、菜单、列表、TextKit 及辅助功能实现，Windows 按 WinUI 3 实现。Figma 返回的 React／CSS 不直接变成原生绝对坐标布局；原生字体、系统控件及键盘行为以对应平台规范与实际用例为准。

### 8.2 还原与行为验收

设计与实现按相同尺寸、语言、主题、数据及状态比较，检查导航层级、布局、字体、语义色、图标、封面比例和截断。逐页记录截图、源码及制品身份和差异处置；“已运行提醒 hook”不能作为视觉检查通过的依据。

行为验收另行检查中文输入与组合状态、撤销重做、窗口缩放、键盘和辅助功能、保存失败与恢复、作品切换、局部采纳和独立定稿。HTML 预览、Figma 原型及原生软件分别验收，不把网页截图作为 Mac 或 Windows 的实现证明。方法依据见[Figma 插件研究](research/08-Figma插件与设计协作研究.md)。

资料工作台采用[35第8节](35-资料素材与短剧制作资产.md#8-原生界面与中文表达)的三栏结构；短剧以项目和分集编辑为主。文字资料优先列表，图片保持比例，不将生成片段、骨架表格或大图卡片作为所有作者的默认首页。锁定时保持详情、历史和原文入口可读，写操作单独禁用。
