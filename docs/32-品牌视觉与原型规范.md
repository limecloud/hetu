# 品牌视觉与原型规范

河图的视觉以“作者拥有自己的故事世界”为主题。中文名称为“河图”，英文为 Hetu；中文界面使用“设定集”，英文使用 Story Bible。品牌表达为：**设定有据，创作有序。**

## 1. 品牌角色

吉祥物“小图”是一只玉青色的小龙马：暖玉白的卷轴鬃毛、短圆角、三枚横向金点、墨色眼睛与朱砂印章吊坠。卷轴连接设定与创作，印章表达作者确认；角色保持友善、安静，不使用战斗表情或复杂鳞片。

3D 表面采用柔和陶瓷与黏土质感，保留适度高光和柔影。Logo 与宣传插画共用母图，不对每个场景重新发明角色。母图见[透明 PNG](../assets/brand/mascot-master.png)，展示入口见[品牌与产品设计](../design/index.html)。

## 2. 颜色与文字

| 颜色 | 值 | 用途 |
| --- | --- | --- |
| 玉青 | `#1E6B5E` | 主操作、选中态、品牌文字 |
| 纸白 | `#F8F6EF` | 网站、展示页与图标背景 |
| 墨色 | `#20312B` | 正文与标题 |
| 浅玉 | `#E8F0E9` | 低强调选中与状态背景 |
| 朱砂 | `#CF765A` | 品牌配饰，避免替代危险状态语义 |
| 暖金 | `#AD823C` | 小面积装饰与材质，不作浅底小字 |

产品 UI 使用平台中文无衬线字体；阅读区可采用系统宋体类字体。标题、文案和操作始终使用真实文本，避免把生成图片中的文字当成唯一的可访问内容。英文版共用语义层级，按文本长度调整布局。

周边图是材质与品牌应用展示，印刷出血、刀模、Pantone、3D 网格及量产打样另按制造流程提供，不能把渲染图直接称为制造源文件。

## 6. 资产维护

修改角色身份需统一更新母图、图标、插画与界面示意，不能在单一场景产生不同脸型或配饰。裁切、优化和版式派生不得覆盖原始图；最终资源需核验透明度、实际尺寸、小尺寸辨识与浅暗背景。

官网和原型不引用在线字体或第三方 CDN。宣传文案与功能范围保持一致，不用下载按钮、商店徽章或兼容标志暗示未发布的应用或平台认证。

## 7. 交互设计验收

原型用于检验具体布局和交互，不承担领域或 API 事实源。评审以10的页面合同、15的采纳与定稿语义、23的图示及26的用户用例为共同依据。

| 评审范围 | 必须体现的设计 |
| --- | --- |
| 多作品入口 | 书库与单部作品分别导航，封面、资料、卷章和当前作品持续可辨 |
| 首次建书 | 无书名也能保存筹备；手工填写和外部构思均可完成，不用虚构资料替作者建书 |
| 外部协作 | 软件提供可复制 Prompt 和固定结果入口，不展示内置聊天或虚构生成进度 |
| 编辑与验收 | 作者正文为默认工作面；AI 改稿按需进入，参考候选独立呈现，可只读或选择性采纳，定稿为独立操作 |
| 局部交互 | Apps、WebView 与内置浏览器仅承载当前任务，正式决定回原生作者入口 |
| 失败与恢复 | 未保存、冲突、部分结果、过期证据和未知操作具有明确状态及原任务恢复入口 |
| 中文与英文 | 默认中文、英文完整；文字为真实可访问文本，作品内容不随界面语言改变 |
| 图片与排版 | 封面按2:3展示窗口等比容纳，人物和插画不拉伸；裁切意图不改原始素材 |

用户指南讲可执行的作者任务，产品设计文档维护研发合同；网站导航不以 PRD、领域模型或内部 API 替代使用帮助。静态界面图、可点击原型、实际软件与跨宿主验收分别标注证据范围，不能互相充当完成证明。

## 8. 设计系统与原生实现

设计顺序为作者任务及状态 → 语义颜色、字体与间距 → 可复用组件 → 多作品书库和单书写作台 → 建书、短剧、参考稿与设置 → 原生实现及验收。颜色变量区分画布、正文纸面、分隔、选中、操作和错误；同一语义覆盖浅暗主题，不将整页背景渐变延伸到长文阅读纸面。装饰服务于层级，不能覆盖章节操作、正文或状态提示。

| 设计对象 | 必须覆盖的变体与行为 |
| --- | --- |
| 书库与作品卡 | 真实封面、默认封面、无作品、路径不可达、长书名与多部独立作品 |
| 单书工作台 | 当前作品持续可辨；分卷、章节、剧本及作品资料分别组织；常用操作键盘可达 |
| 正文编辑器 | 中文标点和首行缩进的显示设置、焦点、选区、IME、撤销、未保存与冲突；视觉排版不改正文字符 |
| 稿件状态 | 参考稿、当前写作稿、旧定稿及证据过期分别呈现；审核、采纳和定稿各有明确动作 |
| 图片与局部比较 | 保留原图比例、原尺寸与放大入口；缺图／加载失败、长文字、候选切换和选择保存 |
| 设置及接入 | 中文／英文、浅暗主题、排版和 AI 客户端选择；未安装、未连接、权限不足分别提示 |

### 8.1 可编辑设计与组件映射

研发使用 Figma 时先检索已采纳组件、变量与素材，再逐区组装。真实文本、Auto Layout、组件实例和可检视属性构成界面设计；生成的整页位图用于氛围参考，不能替代可编辑原型或正文控件。品牌母图与封面资源按原比例引用，不能从界面截图反复裁切派生。

每个需还原的关键页面记录设计文件与节点、修订或采集时间、窗口尺寸、语言、主题和业务状态，并映射实际代码组件。共享视觉语义归 `assets/design/`，平台资源按04生成；Figma 是协作视图，采纳的规则须回写本仓库。Code Connect 如使用，采用经核验的模板方式；不将其设为构建原生客户端的前置条件。

macOS 按 SwiftUI/AppKit 的窗口、菜单、列表、TextKit 及辅助功能实现，Windows 按 WinUI 3 实现。Figma 返回的 React／CSS 不直接变成原生绝对坐标布局；原生字体、系统控件及键盘行为以对应平台规范与实际用例为准。

### 8.2 还原与行为验收

设计与实现按相同尺寸、语言、主题、数据及状态比较，检查导航层级、布局、字体、语义色、图标、封面比例和截断。逐页记录截图、源码及制品身份和差异处置；“已运行提醒 hook”不能作为视觉检查通过的依据。

行为验收另行检查中文输入与组合状态、撤销重做、窗口缩放、键盘和辅助功能、保存失败与恢复、作品切换、局部采纳和独立定稿。HTML 预览、Figma 原型及原生软件分别验收，不把网页截图作为 Mac 或 Windows 的实现证明。方法依据见[Figma 插件研究](research/08-Figma插件与设计协作研究.md)。
