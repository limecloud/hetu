# 持续创作定位与任务分流研究

日期：2026-11-24。来源为作者本次定位讨论、现有PRD、用例、Skills与官网内容的源码盘点。本篇记录采纳理由和待验证问题，不构成外部产品实测或用户收益研究。

## 1. 问题与取舍

通用Agent与文件可以完成临时创作。河图需要在跨会话接续、保留表达、比较修改与固定交付中证明收益。现有Core与来源、修订、意见和作者决定相符；主要冲突在设定先行、默认首任务、完整流水线和过量保存叙事。

采纳：从当前需要开始、选择性积累、只读可以完成任务、充分委托、独立创作判断和可取回成果。产品合同归[01](../01-产品需求PRD.md#1-产品定义)，设计决定归[24](../24-文档治理架构决策与风险.md#持续创作定位决定)。

不采纳：所有任务都进河图、用关键词决定是否值得保存、内置意图规划Agent、全量记忆对话、用检查分数裁决审美。创作者表达“保留”后仍应完整保存，不借选择性积累丢掉所需内容。

## 2. 研究资料如何继续使用

| 既有研究 | 本轮采用与局限 |
| --- | --- |
| 01 MCP协议、02 Codex插件、03 AXI | 保留机器入口、发现与恢复；协议存在不代表每次需要调用 |
| 04 浏览器原生能力、05参考工程 | 技术分工与可移植性；参考布局不能决定创作路径 |
| 06开源工作台、14编辑阅读 | 连续阅读、编辑与来源对照；还原外观不能证明持续创作收益 |
| 07外部Agent、08设计协作 | 外部理解和按需工作面；不以可见会话替代实际作品接续 |
| 09改稿边界 | 固定原稿、限制范围及比较；作者有意差异不由校验擅自消除 |
| 10写作方法 | 按当前卡点用方法；不强制题材安装或完整设定先行 |
| 11资产管理 | 选用素材与固定来源；避免默认生成和收录全部变体 |
| 12市场与作者价值 | 保留作者表达中心；市场规模不能证明单个作品收益 |
| 13预演与审阅 | 用足以回答当前问题的最简单材料；预演与生成均非每任务前置 |

旧研究保留原采集日期、制品和未验证状态，不把历史观察改写成当前兼容结论。

## 3. 验证设计

使用相同原稿、模型、上下文与目标，比较Agent＋文件夹＋Skills与河图接续的解释次数、找稿耗时、误改及返工。先保存原始任务和结果，不预设收益百分比。文学质量、作者认可、工具执行和文件核验分别记录。

负例同样重要：只讨论名字不创建作品，只查人物不建立任务，已知素材不重复生成，停用扩展后仍能取回通用稿件。对应验收归[19](../19-测试策略与验收矩阵.md#持续创作的价值与分流验收)。

完整模型创作与长期作者试用仍需独立证据，不能由本轮文档或交接测试推导。
