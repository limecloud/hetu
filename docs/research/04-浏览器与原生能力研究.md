# 浏览器与原生能力研究

资料版本日期：2026-11-12。研究范围为文件、离线、扩展生命周期、native host 与 Git 的平台能力。

| 一手来源 | 核对结论 | 河图洛书设计含义 |
| --- | --- | --- |
| [Chrome 扩展生命周期](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle) | service worker 会因空闲等条件终止，应持久化状态；并非所有扩展都随标签关闭 | 不将长期任务状态只放浏览器内存 |
| [Chrome Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging) | 扩展可与注册的独立 native host 经标准流通信 | 浏览器并非绝对不能调本地程序，但需要另行安装与授权 |
| [MDN File System API](https://developer.mozilla.org/en-US/docs/Web/API/File_System_API) | 支持的环境可读写文件与目录，受安全上下文和授权等限制 | 原生文件管理是本产品选择，不说 Web 完全无文件能力 |
| [MDN Service Worker](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API) | 缓存与请求拦截可提供离线体验 | “浏览器断网即瘫痪”不作为选型依据 |
| [isomorphic-git 快速上手](https://isomorphic-git.org/docs/en/quickstart) | 浏览器 Git 可运行；跨源远端可能需要代理处理 CORS | 选择 libgit2，但性能与功能差异需实测，不以概括代替基准 |
| [OpenAI 插件 UI](https://developers.openai.com/plugins/build/chatgpt-ui.md) | UI 可按能力采用不同展示模式 | 不把所有插件都描述为狭小弹窗 |

采用理由是河图洛书要求原生长文编辑、明确的文件和 Git 集成、独立 CLI／MCP 与本地恢复。native 同样受权限、依赖、升级和进程生命周期约束；其优点需对应原生验收证明。

平台能力不等于具体产品的性能或可靠性。功能比较需固定版本、授权方式、工作负载和基准；本研究不提供市场占比、文学语义准确率或版权认证结论。
