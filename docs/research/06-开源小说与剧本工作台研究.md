# 开源小说与剧本工作台研究

采集日期：2026-11-13。研究对象是作者使用的小说创作、作品管理与剧本编辑工具；Star 为 GitHub REST API 的采集值，会随时间变化。仓库、默认分支提交、README、许可正文和部分界面图片的固定来源见[来源清单](sources.json)。

## 1. 检索范围与评价方法

通过 GitHub 仓库搜索，按 Star 降序检索 `novel`、`novel writing`、`小说`、`写作`、`topic:novel-writing`、`manuskript`、`writerfly`、`screenplay`、`screenwriting` 与 `ebook reader`，再逐个读取候选仓库的元数据、默认分支 README 和许可文件。检索包含项目名称、简介及主题，辅以 README 搜索；排除无关算法、资料合集、小说下载器和视觉小说游戏引擎。

综合评价采用以下顺序，不将不同类别的 Star 相加，也不编造综合分数：

1. 作者任务适配：多作品、封面、作品资料、卷章组织、设定、版本与导出。
2. 创作模型：纯手工路径是否成立，小说与剧本是否拥有各自结构。
3. 工程适配：本地存储、可读文件、维护情况、原生平台交互参考。
4. 社区关注与复用条件：Star、默认分支提交和实际许可正文。

本文给出本次检索的候选比较，不宣称是 GitHub 全站穷尽排名。功能描述来自固定版本的项目资料；没有把 README 声明当作运行验收、性能证据或中文排版标准。

### 2.1 novelWriter：卷章结构与可读文件

README 明确将小说组织为多个较小的纯文本文件，并提供批注、梗概和交叉引用。官方仓库文档进一步定义：

- `#` 对应部／分区，`##` 对应章节，`###` 对应场景，`####` 对应更小的片段。
- 章节编号可在构建稿件时插入，序号和正文标题分开处理。
- Novel、Plot、Characters、Locations、Timeline、Objects 等根目录各有语义。
- 项目树呈现字数／字符数、状态和是否参与输出。

可借鉴其层级、状态、资料引用与稿件构建的分工。上述标题语法属于 novelWriter 自身格式，不直接作为河图洛书文件标准。

### 2.2 NEO：作者书库与多种作品

README 明确描述书架分组、封面、拖拽排序和字数目标；数据采用每书一个目录、章节 HTML、元数据 JSON。小说章节与剧本场景分别组织，剧本可以导出 Fountain、Final Draft 和 PDF。

对河图洛书最有价值的是作者书库模型、每部作品的独立身份与封面、小说和剧本的类型区分。其连续回车创建章节、英文弯引号、首字下沉等编辑习惯，不能直接作为中文编辑默认行为。README 列出的界面语言未包含中文，中文适配需要河图洛书自行设计和验证。

### 2.3 51mazi：中文作者的多书入口

README 明确写明“支持创建、编辑、删除多本书籍”和“每本书都有独立的数据目录结构”，并列出本地封面选择与自定义颜色。官方仓库截图可见多本封面及书名字数信息，进入作品后提供独立编辑器。

可借鉴书架入口、封面识别、书籍资料与作品数据隔离。此次资料未确认分卷管理的完整实现，不将“有章节编辑器”推断为“有卷章全流程”。README 中的密码保护说明也不能替代加密实现和安全性验证。

### 2.4 Pagekin：多作品概览与单章工作流

README 与书房截图展示多部作品；选中封面后先查看该书的概览和进度，再进入作品。单章工作流区分草稿、审稿、修稿、定稿，修订差异由作者逐段确认，历史恢复形成新草稿。

可借鉴书库和编辑窗口的分层、单书进度、版本对比与定稿状态。其模型任务、自动生成按钮和创作阶段门槛不作为河图洛书纯手工写作的前置条件。其通过 Tab 写入全角空格的实现也不构成中文出版规范；河图洛书的显示缩进与源文字节保持规则见[格式设计](../25-小说与剧本标准格式.md)。

## 6. 对河图洛书的参考结论

优先对照 **NEO、51mazi、novelWriter、Manuskript、Pagekin、Beat**。它们分别覆盖多作品入口、中文封面书架、卷章结构、故事规划、修订审核和 Mac 剧本编辑；Star 作为关注度参考，任务贴合程度决定研究优先级。

### 6.1 作品与内容层级

- **作者书库**：登记多部独立作品，提供封面、书名、笔名、题材、创作状态、字数、最近编辑和搜索筛选。
- **小说作品**：拥有自己的简介、封面、分卷、章节、大纲、设定集、素材、修订和导出选择。分卷可选，单部短篇无需建立空卷。
- **卷与章节**：顺序、编号和稳定身份分离；支持序章、正文、番外等类型，明确单章草稿／定稿状态。
- **短剧项目**：拥有分集、场次、剧本及修订；改编项目明确关联原著和固定来源。剧本采用适合场次和台词的编辑结构。
- **系列分组**：作为可选组织信息，由作者主动建立，书库中各部作品具有独立身份。

软件源码 Monorepo 管理内核、CLI、原生应用、网站和共享合同；作者书库管理作者的独立作品；作品工作区承载对应文件、授权和版本边界。界面应分别表达这些概念。

### 6.2 封面与排版

封面应区分原始图片、书库缩略图、裁切参数和投稿／交付用版本；保留原图比例，按具体平台 profile 检查尺寸。无封面作品使用书名与笔名构成的本地占位设计，手工导入始终可用。

外部封面设计采用河图洛书提供 Prompt、配套 Codex Skill 生成并写回固定目录、河图洛书核验显示与作者选用的流程，正式合同见[34](../34-小说封面与Agent协作.md)。

编辑排版应区分小说阅读、中文码字、剧本编辑和导出 profile。首行缩进、行距和标点处理必须有独立依据及中文输入法验证；英文工具的回车行为、自动英文引号和首字下沉不直接成为中文默认值。

### 6.3 证据与采用范围

本次直接查看了官方仓库中的 novelWriter 编辑／稿件构建截图、51mazi 多书首页截图、Pagekin 多作品书房截图；图片来源、固定提交和摘要记录在来源清单中。它们用于核对页面确实呈现的结构，没有据截图推算可交互行为，也没有直接复制其品牌、插图或界面资产到河图洛书。

参考以信息架构、用户任务和公开格式为主。若采用第三方源码或资产，按具体文件许可处理；MIT、Apache-2.0、GPL、AGPL 和自定义许可分别核对。研究结论用于设计决策，河图洛书的已实现行为仍以应用代码、合同和验收结果为依据。
