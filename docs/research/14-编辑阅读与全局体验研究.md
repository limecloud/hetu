## 3. 字体与排版：必须形成共同模型

Ulysses 官方文档直接说明：编辑器中的变化不影响导出。novelWriter 固定源码中，`Document font` 明确同时作用于编辑器和阅读器，而界面字体单独设置；行高使用相对值。iA Writer 也把编辑器字体、字号、行宽与打印／PDF 设置分开。

据此建议河图分别定义：

| 层次 | 控制什么 | 不应连带改变什么 |
| --- | --- | --- |
| 全局界面 | 界面外观、控件字号与密度、导航、弹窗和插件公共表面 | 原文字节、文稿样式和交稿模板 |
| 文稿排版 | 字体、基础字号、行高、段距、缩进、最大行宽 | 目录字体、按钮尺寸和导出版式 |
| 文稿缩放 | 在当前排版基础上放大阅读文字 | 内容、正式字号、定稿修订和导出页数 |
| 阅读位置 | 固定对象、修订、原文锚点和屏幕内偏移 | 作品事实和其他窗口的阅读位置 |
| 交付版式 | 纸型、页边距、字体、分页和制片方模板 | 编辑器主题和个人阅读偏好 |

中文行宽不能直接使用西文 `ch` 的数字当作汉字数。原型应比较 CJK 字形单位或实测字宽，设置最大可读宽度并受可用视口约束。工作面铺满与文字行宽受控可以同时成立。

[W3C 中文排版需求](https://www.w3.org/TR/clreq/)覆盖行首行尾禁则、标点、缩进和中西文混排。它提供排版问题与要求，不是河图现成的浏览器实现；浏览器、CodeMirror、只读阅读器和 PDF 的实际支持需要分别验证。不要使用 `word-break: break-all` 或逐字插入空格粗暴模拟中文排版。

中文正文、英文段落、数字、全角标点、破折号、成对引号、罕见字与 Emoji 必须共同进入字形样本。不能仅验证常见汉字后宣称字体完整，也不应全局开启连字、压缩标点或自动两端对齐。

## 4. 主题：颜色一致还不够

[Ulysses 主题说明](https://help.ulysses.app/en_US/styles-themes/editor-themes)区分编辑器背景、文字、标记、高亮以及浅暗版本；CodeMirror 的[样式说明](https://codemirror.net/examples/styling/)区分主题与基础主题，并要求编辑背景、选区、光标等状态协调。

河图应以语义变量统一全局控件与文稿表面，覆盖普通、悬停、选中、禁用、聚焦、错误、警告、搜索命中、意见及差异。只把背景变黑会遗漏选区、浮层、原稿、比较、插件和导出预览。界面主题和文稿纸色可以分开，但组合数要受控。

保留已确认的纸色、玉色与山水灰、连续静态渐变及轻透导航。正文表面稳定实色，主题不改变作者图片和视频的颜色，不把纸张纹理铺在文字下面。下一版不需要开放任意脚本或 CSS 的主题市场。

## 5. 缩放、聚焦与文字操作

“全屏”至少涉及工作面铺满、收起导航的专注模式、操作系统全屏和外部宿主显示模式；它们不能用同一个模糊的按钮表达。文稿缩放也不应通过 `transform: scale()` 放大整块编辑 DOM：布局尺寸、选区、输入法候选位置和浮标仍需要正确度量。

CodeMirror [参考文档](https://codemirror.net/docs/ref/#search)提供搜索状态、上下结果、大小写、整词、正则、替换命令与快捷键。河图可复用这些能力，并自行负责只读状态、当前缓冲／已保存全作品范围、中文语义、替换预览、撤销及版本核验。默认的西文整词行为不能直接命名为中文“完整词”。

文字操作需要区分显示设置和内容事务。切换字体无需进入撤销栈；加粗、插入引号、转换段落或替换文本则必须进入原文事务，并可撤销。Fountain 的下划线表示强调中的下划线，不能与 Markdown 斜体语法随意互换，见[官方语法](https://fountain.io/syntax/)。

聚焦和打字机模式适合部分创作阶段；默认阅读、比较和反馈时应保留完整上下文。IME 组合期间不改变排版或重建编辑器；用户拖选、查找跳转、批注定位或查看历史时不自动抢回光标。

ProseMirror 的[官方指南](https://prosemirror.net/docs/guide/)明确采用受 Schema 约束的文档模型；这不是其缺陷，而是与河图当前原文字节合同不同的设计选择。Tiptap 核心许可与商业扩展分别评估，不能用核心 MIT 推定所有配套服务免费。此次不复制外部源码。

## 7. 无障碍依据及常见误读

| 来源 | 可核实的要求 | 河图如何使用 |
| --- | --- | --- |
| [WCAG 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) | AA：普通文字对比至少 4.5:1，大号文字例外为 3:1 | 校验主题、选区、意见及差异；不因低对比“柔和”损失可读性 |
| [WCAG 1.4.4](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html) | AA：文字可放大到 200%，内容和功能不丢失 | 正文和控制界面分别检查，浮层及工具也必须可达 |
| [WCAG 1.4.10](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) | AA：普通纵向内容按 320 CSS px 等效视口重排，存在需二维布局的例外 | 窄 App、较大字号和比较视图提供可读重排，不把桌面最小窗口等同此标准 |
| [WCAG 1.4.12](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html) | AA：用户调整文字间距至指定条件时不丢内容与功能，存在语言适用说明 | 测试覆盖，而不是要求所有默认正文都使用该行段距 |
| [WCAG 1.4.8](https://www.w3.org/WAI/WCAG22/Understanding/visual-presentation.html) | AAA：包括不强制两端对齐、80 字符／CJK40 字形等视觉呈现条件 | 作为可选阅读档案参考；不误写成 AA 强制或全球唯一最佳行宽 |

上述文档是规范解释材料。本次没有完成河图的 WCAG 符合性审计，也未证明 VoiceOver、Narrator 或所有宿主的辅助功能已通过。

## 9. 参考编辑器的具体参考与复刻边界

参考编辑器 官方样式概览区分文字级和页面级样式；格式说明进一步区分文字格式、块结构和页面设计。查看的官方图呈现选区上方的格式浮条、页头 `Aa` 格式面板及样式缩略预览。它们证明公开展示的结构，不证明本机安装版拥有相同尺寸或完全相同的交互。

| 研究点 | 官方依据 | 河图的产品判断 |
| --- | --- | --- |
| 即时预览与精选样式 | 样式快速指南有当前样式预览、预设库及颜色分项重置 | 用真实正文预览纸色与字体，先提供少量可用预设，不要求作者调色 |
| 默认样式 | 默认页面样式说明按空间保存默认，并允许单文档覆盖 | 借鉴默认和重置语义；河图阅读偏好由本机设置拥有，不自动成为作品内容 |
| 应用与文稿字体 | App Styles说明文稿颜色可延伸到编辑器周围，UI仍用系统字体 | 全局视觉协调，不将小说宋体用于按钮和目录；保留河图自己的共享色板 |
| 选区操作 | 格式工具和包围选区说明就近格式和成对括号 | 常用意见与AI交接靠近选区，格式命令可键盘操作且可以撤销；中文成对标点另验 |
| 缩放与专注 | 快捷键分别列出Zoom、Actual Size、Focus和文字大小 | 采用语义区分，快捷键仍按当前宿主核对，不整套照抄 |
| 搜索范围 | 查找替换明确macOS、Windows和Web的子页／表格范围差异 | 河图必须准确展示范围和覆盖，不能只因共用页面就宣称能力完全相同 |
| 意见 | 意见与通知描述共享文档的块意见及行内回复 | 借鉴内容附近反馈，保留河图固定修订与精确选区；不据此引入云共享和通知系统 |

复刻目标覆盖参考软件的整体布局、风格、排版、控件和操作，不能仅以借鉴层级和补齐功能作为完成。先采集实机状态，再将实际差异映射到河图的共享工作台；河图作品、固定来源和作者决定沿现有内核处理。品牌、私有内容、代码和商业字体文件不进入河图制品。
