# Agent 改稿边界与交互研究

资料日期：2026-11-13。研究范围为 Figma 的选区、锁定与分支，以及代码编辑器的改动审阅。以下事实来自官方正文，不表示已完成第三方账号、插件或宿主互操作验收。来源、响应表示与摘要见[来源清单](sources.json)。

## 1. 可参考的产品机制

| 来源 | 已核实的行为 | 河图洛书采用及限制 |
| --- | --- | --- |
| [Figma selection](https://developers.figma.com/docs/plugins/api/properties/PageNode-selection/) | 当前页选区返回新的只读数组，数组内节点仍是现有节点的引用 | 用明确选区指定任务对象；选中哪些对象不能证明插件只能操作这些对象 |
| [Figma locked](https://developers.figma.com/docs/plugins/api/properties/nodes-locked/) | 锁定限制画布上的部分选择、拖动；官方明确不影响插件写属性 | “不改这段”须转化为 Core 核验的范围，不能仅靠锁图标、禁用控件或提示词 |
| [Figma branching](https://help.figma.com/hc/en-us/articles/360063144053-Guide-to-branching) | 可在分支探索、请求评审、比较和处理合并冲突；主文件编辑权限与评审有独立规则，功能受计划与席位限制 | 采用独立参考版本和比较入口；每次 AI 改稿无需创建 Git 分支，不照搬 Figma 云端和席位体系 |
| [VS Code 改动审阅](https://code.visualstudio.com/docs/agents/run/review-code-edits) | 可逐处或逐文件 Keep／Undo；待审编辑已写盘；Keep 不表示 Git 提交；检查点不撤销外部网络等副作用 | 借鉴逐处比较、保留和撤销的交互。河图洛书的候选先单独保存，作者采纳才生成正文修订；不能把“候选已收到”当成正文已更新 |
| [Zed Inline Assistant](https://zed.dev/docs/ai/inline-assistant) | 作者显式选择文本或行并输入要求；使用 Zed 配置的 LLM provider，文档明确 external agents 不适用于该功能 | 借鉴选区旁的任务入口和上下文呈现；河图洛书仍交由外部 Agent 对话，不采用编辑器内直接调用模型的实现 |

Figma 的锁定正文为：“Does not affect a plugin's ability to write to those properties.” 这是交互锁与授权的明确区别。Figma 分支可不经评审直接合并的条件也说明：不能从“存在评审界面”推断所有写入都必须经过作者批准。

## 2. 河图洛书采用的边界

改稿任务分别固定参考资料、可改范围和作者决定。参考资料是显式选择的已保存章节、设定及作品资料；可改范围是其中一个文档固定修订的选区或整章，章末续写使用明确的空插入点。未列入可改范围的段落只供参考，不允许补丁越界。语气、视角、人物动机等要求属于创作约束，不能伪装成规则引擎能完全判断的语义保证。

Agent 在本任务中提交独立候选，不获得正文保存、设定修改、章节重排、定稿、正式封面选用或 Git 操作权。Apps 与局部网页只记录候选选择和意见；作者在原生端比较并确认采纳，随后仍可自行编辑。整章授权表示允许提出整章改稿，不表示允许自动覆盖整章正文。

作者继续写作时不锁住编辑器。旧基线候选可保留参考；合并须比较任务原文、当前写作稿及候选，基线变化时重新预览。未保存缓冲不自动外发，结果到达不替换缓冲或改变焦点。实际权限矩阵及页面流程见[交互设计](../10-原生客户端与交互设计.md#10-已有正文的外部改稿)。

## 3. 技术与验证边界

范围限制由 Rust Core 的任务上下文、输入合同和补丁核验执行，不能只靠 Skill 遵守。UTF-8 偏移、原文引句、任务修订、同任务操作恢复和撤权均需负例；中文、Emoji、组合输入及 CRLF 分别验证。

本机 MCP 的限制只适用于受管入口。外部 Agent 若同时获授同用户 Shell 或整库文件写权限，仍可能绕过业务 API；产品应提供受限 MCP 配置和独立结果目录，不宣称能用应用内锁抵御相同 OS 权限的进程。详见[安全边界](../18-安全与隐私.md#3-权限模型)。

研究未依赖付费功能开通、安装第三方插件或实际调用其生成接口。第三方机制用于设计参考，河图洛书的验收以自身内核、原生交互及所声明宿主的真实证据为准。
