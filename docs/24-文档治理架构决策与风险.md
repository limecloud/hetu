# 文档治理、架构决策与风险

产品范围由[01](01-产品需求PRD.md)维护，阶段退出条件由[20](20-实施路线与里程碑.md)维护，外部来源与适用边界由[research](research/README.md)维护。

## 1. 文档与合同治理

每项事实只有一个维护位置，其他章节通过链接引用。产品需求使用 FR，故事使用 US，用例使用 UC，贯通旅程使用 E2E；新增范围同步对应验收，不通过复制表格制造不同结论。

`contracts/` 拥有机器 Schema、工具和正负夹具。Markdown 示例是说明或设计样例，新增和变更时由真实校验器验证；生成类型、帮助、文案及设计资源不可手工改生成副本。输入字段与版本以能力目录及其引用 Schema 为准，文档不得另造一套同名动作的输入。

设计文档定义稳定的需求、边界和验收合同。实现进度、测试执行结果、排查记录与会议讨论进入对应工程记录，不混入规范正文。需求变更须更新拥有该事实的文档及引用，不保留过时结论或对话过程。

在仓库根目录执行 `uv run "tools/verify-docs.py"`，校验本地文件与标题锚点、FR／US／UC／AC／E2E 引用、逐用例追踪覆盖、JSON 示例及共享 Schema。图示修改后还需使用实际 Mermaid 渲染器检查布局、标签及分支；静态检查与图示渲染均不能证明产品功能已完成。

## 2. ADR 摘要

| ID | 决定 | 理由与限制 |
| --- | --- | --- |
| ADR-01 | 核心无模型与生成 API | 本地工程化为主体，外部 Agent 可选 |
| ADR-02 | 共享 Rust Core 与 C ABI | 复用规则、版本与存储，付出跨语言构建和 ABI 测试成本 |
| ADR-03 | SwiftUI/AppKit + WinUI 3 | 原生编辑和系统集成；双端 UI 分别开发验收 |
| ADR-04 | 跨平台 Swift CLI 薄入口 | 共用命令编排与 macOS 桥接，Windows runtime／TTY 在 Windows 阶段独立准入 |
| ADR-05 | 源码与 IP 内容工作区分离 | 软件开源不导致作者内容自动开源 |
| ADR-06 | 文件为正文事实，数据库仅可重建索引 | Git 和可读性优先，不否认 SQLite 的价值与可靠性 |
| ADR-07 | Agent 仅草稿，设定集与定稿归作者 | 受管入口强制，不宣称能阻止同用户任意文件写入 |
| ADR-08 | stdio MCP 独立进程 | 无本机 HTTP 服务前提，生命周期由宿主管理，操作记录持久化 |
| ADR-09 | AXI 0.2.1 作为设计采用基线 | 复用任务、回执与恢复；草案非行业认证，无运行依赖 |
| ADR-10 | 小说 Markdown、剧本 Fountain、profile 导出 | 可编辑源与外部交付分开；中文互操作需验证 |
| ADR-11 | Codex 接入与多媒体插件分开 | 方法／连接不承担生成服务，商业插件独立授权和收费 |
| ADR-12 | 软件入口、用户复制 Prompt、外部 Agent 对话 | 河图洛书只做任务上下文与展示验收，不建设 Agent Runtime 或自动对话循环 |
| ADR-13 | 建书筹备独立于作品 | 无书名可构思，作者确认才创建；原筹备授权不自动扩为新作品 |
| ADR-14 | 参考稿采纳与定稿拆分 | 来源、编辑与作者确认分开；支持纯手工稿独立定稿，语义变化需合同升级 |
| ADR-15 | Apps 与按需本地网页共享用例 | 支持局部交互和大视图，Node.js 不持有第二份业务数据；回环、配对和生命周期单独验收 |
| ADR-16 | 本机 MCP 随桌面分发，服务端业务单独立项 | 创作及外部 Agent 本机协作不依赖公网服务；官网提供静态内容，服务端业务由明确需求决定 |
| ADR-17 | 先建立设计组件与状态，再实现并核验原生界面 | 固定设计节点、双语主题与实际状态；设计截图和网页原型不能代替原生行为验收，Figma 不成为产品运行依赖 |

## 3. 技术准入与变更约束

| 事项 | 准入门槛 | 约束 |
| --- | --- | --- |
| 工具链精确版本 | Mac Rust／Swift 原型；Windows 阶段单独验证 WinUI 与 native 组合 | 版本和依赖必须可复现 |
| Rust MCP SDK 与协议适配 | 规范、维护与许可、宿主测试 | 采用官方 Rust SDK 路线，逐版本核对协议覆盖 |
| legacy MCP 支持 | 目标 Codex／WorkBuddy 版本真实能力 | 仅声明已验收协议组合 |
| macOS sandbox | 桌面与独立 stdio 权限原型 | 不假定权限跨进程继承 |
| 编辑器与格式转换库 | 中文、大文档、跨平台、许可与回环 | 不保证任意富文本无损 |
| Intel／ARM64 扩展 | 对应 native 依赖与实机证据 | 不纳入 V1 默认支持范围 |
| Apps／浏览器局部交互 | 固定任务、受限会话、CAS、真实宿主及回退 | 保存选择或意图，正式采纳、设定／封面和定稿回原生确认 |
| Node.js 页面服务 | 签名制品、回环绑定、配对、Host／Origin／CSRF 及停止 | 不全局安装、不自动开隧道、不将普通 URL 当授权 |

## 4. 风险与处理

| 风险 | 影响 | 应对与触发条件 |
| --- | --- | --- |
| 中文自由文本提取覆盖有限 | 作者期待自动理解全部 OOC | 明示候选、未知与覆盖，独立标注集评测 |
| Swift Windows 依赖／runtime 分发 | CLI 看似通用但用户不能启动 | Mac 完整验收后，在 M6-W 先验干净 Windows，再扩命令 |
| Rust 解析与 unsafe ABI 错误 | 崩溃、越界或数据损坏 | 小边界、模糊测试、sanitizer、所有权和错误检查 |
| 多文件与 Git 并发 | 丢改动或混合版本 | 进程锁、CAS、恢复日志和原 index 保护 |
| 宿主与插件规范变动 | 安装／工具／UI 不一致 | 冻结来源、制品与兼容矩阵 |
| 格式转换损失 | 对白、分页或批注丢失 | 导入预览、转换报告、独立阅读器与渲染 |
| 团队锁被误解为权限控制 | 未授权者改写内容 | 明确本地范围，V1 不声称团队 ACL |
| 素材版权／秘密外发 | 交付或供应商风险 | 权利元数据、最少外发、作者确认、凭据隔离 |
| 本地页面被误认为公网服务 | 作品意外外发或远端获得本机权限 | 区分本机回环与公网部署；数据外发单独确认，远端身份不继承本机授权 |
| 插件示意被当作运行能力 | 设计、Apps 或自动验收承诺失真 | 分别核对制品、当前工具、官方资料和真实运行；静态 HTML 与提醒 hook 不作完成证据 |

研究资料记录外部规范的来源、版本与适用边界，采用的设计决定进入对应架构合同。插件集成见[27](27-Agent与Codex插件集成设计.md)，技术原则见[02](02-架构选型与设计原则.md)。

官方资料也有版本边界：保存链接、采集日、摘要、适用范围及证据边界；外部资料更新不自动改写已采纳合同。新增硬约束同步 PRD、契约、消费者、故事和验收。
