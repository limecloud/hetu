# 国际化与中文体验

河图采用 Chinese first 策略：简体中文 `zh-CN` 为默认语言，英文 `en` 完整支持。中文创作者的长篇写作、短剧改编与本地协作是主要设计场景；国际化覆盖界面、CLI、人类可读诊断、帮助与交付模板。

## 1. 语言与内容分离

| 对象 | 规则 |
| --- | --- |
| 应用语言 | 首次启动默认 zh-CN；用户可切换 en，偏好保存在本机 |
| 工作区内容语言 | `.heturc.json` 的 locale 描述作品默认语言，不随界面语言改变 |
| 文档语言 | 文档可声明 language_tag，支持中英混排；未声明时继承作品语言 |
| 导出语言 | 作者选择 delivery profile 的语言与版式；不自动翻译正文或名称 |
| 机器合同 | JSON 字段、ID、错误码、规则键、CLI 子命令与 MCP 工具名保持稳定英文标识 |

语言切换立即更新导航、表单、帮助与状态，不关闭文档、不丢失选区和未保存缓冲。批注、作者姓名、小说正文、人物名与历史记录的原始内容保持不变。

V1 不将繁简转换作为保存步骤。简体、繁体、异体字及拉丁字母均按作者输入保留；界面语言不限制创作语言。

## 2. 作者术语

| zh-CN | en | 语义 |
| --- | --- | --- |
| 书库 | Library | 作者在本机登记和管理的多部独立作品，不要求属于同一 IP |
| 作品 | Work | 一部小说及其设定、封面、改编和素材的管理范围 |
| 作品资料 | Book Details | 书名、笔名、题材、简介、创作状态等基本信息 |
| 分卷 | Volumes | 小说的可选章节分组，不使用“包”或“工程”作为作者操作名 |
| 章节 | Chapters | 正文写作单元，标题与目录次序分别管理 |
| 设定集 | Story Bible | 作者确认的角色、世界观、时间线及创作规则集合 |
| 角色设定 | Characters | 人物身份、关系、事实与性格描述 |
| 世界观 | World | 地点、势力与世界运行约束 |
| 锁定设定 | Lock Story Bible | 暂停作者设定编辑，不扩大 Agent 权限 |
| 剧情梳理 | Plot Outline | 从已有正文提取并校正的剧情结构 |
| 分集大纲 | Episode Outline | 短剧的分集与分场组织 |
| 建书筹备 | Book Planning | 无需书名即可保存的想法、资料候选和创建准备 |
| AI 协作 | AI Collaboration | 接入外部客户端、复制任务提示词及接收候选，不是内置聊天 |
| AI 参考稿 | AI Reference Draft | 外部 Agent 提交的候选，默认不进入正式正文 |
| 写作稿 | Working Draft | 作者当前正在编辑的正文修订及缓冲 |
| 采纳到写作稿 | Apply to Working Draft | 采用选定内容并保留来源，不设置定稿 |
| 参考稿审核 | Reference Draft Review | 对固定候选及证据的作者决定 |
| 确认定稿 | Finalize Revision | 作者独立确认确切已保存修订，与平台发布分开 |
| 交付包 | Delivery Bundle | 带版本、格式与来源清单的导出材料 |

界面使用作者用语，技术标识 `blueprint.json`、`blueprint_id`、`hetu_read_blueprint` 保持稳定；技术文档首次出现时给出中文含义，普通创作页面不暴露实现字段。中文术语不直译英文技术隐喻。

同一对象在导航、按钮、提示、帮助及任务提示词中保持一致。正文一律区分“参考稿”“写作稿”“定稿”，不以“草稿”笼统表示三个状态；作者提交的待审副本称“参考稿”，确认由外部 AI 生成的内容才加“AI”。“保存”“通过审核”“采纳到写作稿”“确认定稿”分别命名，不互换。

面向作者的表单使用“本段叙述的事实”“原稿版本”“重新读取原稿”“文件校验值”等具体表达。`assertion`、CAS、摘要算法、JSON 字段只用于技术合同或展开的技术详情；不得用技术标识作为作品、人物、章节的默认名称。

## 3. 文案与资源来源

`assets/localization/` 为共享文案唯一来源，由确定性工具生成 macOS String Catalog、Windows RESW、Swift CLI 和 MCP Apps 资源。业务代码只引用语义键，禁止分散硬编码中文或英文。

本地 Node.js 页面与 Apps 复用局部交互文案，按当前用户界面语言展示。任务 Prompt 语言、作品语言和封面文字语言独立设置；客户端／Skill 技术标识保持原名，不翻译作者原书名。中文界面默认“复制到 Codex”等具体动词，英文使用“Copy for Codex”；复制后提示到外部客户端继续，不能翻译成开始生成或发布。

每个键包含 zh-CN、en、用途、占位符名称和必要的翻译上下文。插值使用具名参数，不拼接可翻译句子。英文复数、数字及日期用对应 locale 的格式化能力；两端共享参数语义。

```json
{
  "review.approval_stale": {
    "zh-CN": "设定集已更新，请重新校验后审核。",
    "en": "The story bible has changed. Validate again before reviewing.",
    "parameters": []
  },
  "draft.saved": {
    "zh-CN": "已保存参考稿“{title}”。",
    "en": "Reference draft “{title}” saved.",
    "parameters": ["title"]
  }
}
```

缺少运行时翻译时按“用户选择语言 → zh-CN → 可操作的通用错误”回退并记录资源缺陷，不能把原始键或异常堆栈显示给作者。发行门禁要求所有必需键双语齐全，回退不替代翻译验收。

## 4. 中文输入、排版与编辑

- 支持系统拼音、五笔与常见第三方 IME；组合输入期间保留 marked text，不重新设置全文，不触发补全覆盖。
- 支持中文引号、破折号、省略号、全角空格与标点；字体和换行按原生文本排版处理，不在保存时统一替换。
- 章节标题识别覆盖“第一章”“第十二回”“卷一”等模式，结果必须预览，正文中相同词句不能误切章节。
- 搜索支持中文分词与精确匹配两种模式；人名、别名和同名人物通过设定集 ID 消歧，不使用拼音相同作为自动合并依据。
- 简繁、大小写或 Unicode 规范化仅用于明确标注的搜索投影，不改变源字节、摘要或 SourceRef。
- 默认字体使用平台中文字体回退；导出 PDF 明确字体许可、嵌入与缺字检测，不依赖在线字体 CDN。

中文／英文统计分别显示。中文“字数”统计 Han 字符，英文“词数”按声明的词边界规则统计；总字符数按 Unicode 扩展字素簇计数，另显示是否包含标点与空白。不能用 UTF-8 字节数或 UTF-16 code unit 冒充字数。规则版本随统计结果记录，目标平台投稿口径由 profile 配置。

## 5. 导入、剧本与交稿

UTF-8 为内部编码。TXT 导入支持 UTF-8／BOM 与 GB18030 等常见中文编码识别候选，预览乱码、换行、章节和不可映射字符，由作者确认后转换。保留原文件摘要和编码选择；不以替换字符静默修复。

Fountain 解析与输出覆盖中文人物、场景及中英混排，保留强制人物／场景标记以消除大小写启发式歧义。用户界面显示“内景／外景”“日／夜／未知”等中文术语；内部枚举不本地化。

中文短剧 DOCX／PDF 模板包含集号、场号、内外景、日夜、地点、人物、动作与对白，按制片方 profile 输出。英文模板采用对应的场景标题和人物／对白排版；切换模板不是内容翻译，不能擅自更改专有名词。

## 6. 本地与协作体验

核心离线运行，默认无境外账号、在线字体、CDN、模型服务或遥测前置。GitHub 与 Gitee 同时作为可选远端，均由用户选择和管理凭据；网络失败可继续本地编辑、快照与导出，不隐式切换镜像或代理。

文件选择、路径、分支显示和导出名支持中文及空格；路径规则独立处理跨平台保留名称和长度限制。时间持久化为 UTC，界面按用户时区显示；审计详情与导出来源同时提供明确时区，机器时间不采用模糊本地字符串。

主界面优先显示作品、人物和章节名称，技术 ID 放在详情／复制入口。首次使用提供中文术语说明与最小示例；英文界面具有相同入口与功能，不将英文版缩减为只读模式。

## 7. 诊断、CLI 与 MCP

Finding 保存 `message_key`、安全参数与证据，按界面语言渲染；原文引用保持原语言。已导出的报告固定其 locale 和模板版本，语言切换不能改写历史报告。

CLI 支持 `--locale zh-CN|en`，优先级为显式参数 → 本机偏好 → zh-CN。`--json` 字段与枚举不翻译，人类 message 可本地化，脚本必须消费稳定错误码。错误输出与帮助双语覆盖，长英文文案不破坏终端对齐。

MCP 工具名保持英文，说明与面板文案按宿主能力提供本地化；不支持语言协商时使用中英可理解的说明。协议中的语言提示不成为角色授权，也不能改变作品语言。

## 8. 验收要求

FR-19 覆盖双端原生 App、Swift CLI、基础 MCP 的人类可读输出和交付模板。门禁包括双语键完整、占位符一致、英文膨胀布局、中文输入法连续写作、Emoji 与组合字符、混排搜索、字数口径、中文路径、GB18030 导入及缺字检测。

完整旅程分别使用 zh-CN 与 en 执行；切换语言前后内容摘要、ID、SourceRef、审核决定与原操作键保持一致。语言包故障不允许覆盖正文或伪造业务成功。
