# 工作区与持久化设计

## 选择性持久化

临时讨论和只读访问不创建作品内容文件。用户指定保存、固定返工或恢复所需内容使用原有事务；会话草稿、界面缓存和诊断日志不成为作品事实，不全量复制聊天进入项目。

产品定位与任务分流见[01](01-产品需求PRD.md#1-产品定义)。

内容工作区是文件、事务与权限边界，可自行初始化为 Git 仓库；创作库登记小说、剧本和视频的独立身份与类型。同一根可持有多个对象，也可通过固定来源关联不同根，不要求小说前置、同一 IP 或为每个类型新建仓库。目录与河图洛书软件源码仓库分别管理。

书库登记项与 OS 文件授权保存在当前用户的原生应用数据目录。登记目录不授予 Agent 对整座书库的访问权限；稳定接入后的每次业务调用仍以作者批准的具体任务及单作品范围为准。更换书名不改变作品身份，目录失效时显示需重新定位，不自动扫描同级作品。

## 1. 内容目录

```text

  .heturc.json
  shared/
    blueprint.json                # 既有单设定工作区的设定集，保留身份和路径
```

`document.json` 维护格式、当前与定稿修订指针；修订正文不可原地覆盖。`draft.json` 维护格式、草稿属性与审核状态，提交后正文不可修改；返工产生新草稿并引用旧草稿。小说源为 Markdown，剧本源为 Fountain，详见[25](25-小说与剧本标准格式.md)。删除缓存不能丢失作品或操作结果。

`shared/blueprint-revisions/` 与 `.hetu/blueprints/` 保留该根小说的设定历史和摘要。剧本、视频的自身设定由 `shared/work-canons/` 唯一持有；其摘要索引核对所属 WorkRef、设定身份、修订和内容，不将相同数字修订解析成小说设定。两类受管历史均可进入 Git 内容选集，交付按选定设定修订读取。历史内容与摘要记录不一致时停止依赖该修订，不覆盖历史文件修复摘要。旧记录和 revision-only 引用保持原义；旧项目建立自身设定是明确事务，不在读取时迁移。绑定语义见[29第24节](29-数据字典与Schema设计.md#24-独立创作对象与视频数据)。

剧情保存以固定正文修订与设定集修订为输入，内容、索引、原操作回执与审计在同一可恢复事务中写入。预览提取不创建剧情文件、索引或操作回执。作者校正追加新 `plot_revision_id`，保留原节点 ID、来源与父修订；历史可形成分支，不覆盖其他作者的校正。读取时校验内容摘要、索引和输入来源；当前正文或设定集变化只计算 `stale_reasons`，不修改历史结果。

以上目录保留既有持久化路径；独立创作入口不以搬目录实现。视频及跨对象关系采用以下新增布局，精确记录经相应 Schema 修订发布；下方已有配置样例仍按其发布合同读取，不向旧版本注入新字段。

```text
my-workspace/
  work-links/<link_id>/<revision>.json        # 固定来源关系，不存授权秘密
  packages/video/
    projects/<video_project_id>/             # 项目头、有序分集及不可变修订
    episodes/<video_episode_id>/             # 分集与各阶段成果引用
    storyboards/<storyboard_id>/             # 镜头与剧本固定场次／制作简述
    previs/<previs_id>/                      # 预演清单、实际视频及外部工程引用
    generations/<plan_id>/                   # 固定计划、调用记录与结果引用
    edits/<edit_id>/<edit_revision_id>/      # 剪辑、音画字幕、时间映射与渲染
    media/<artifact_id>/                     # 实际不可变媒体与流信息
    decisions/<decision_id>.json             # 预演认可／选用／成片确认
```

媒体只保留一份受管原字节，资料候选与制作记录通过固定引用共用；缩略图和代理视频可重建，不能取代原文件。大媒体按需使用 LFS 或完整附件策略，Git 指针不能冒充已交付内容。外部工程登记工具版本和依赖清单；回传不自动运行脚本、加载插件或下载远程附件。

跨根关联通过分别获权的读取与目标写入保存必要来源快照，不假装跨根原子事务。目标记录原身份、固定摘要和来源；相同原键恢复同一关系，不重新复制、覆盖或自动追随源头。单项目删除先核对所有权和被引用位置，可恢复归档／删除；只有明确“删除工作区”才能列出全部对象后移动整根。移除创作库登记不删除内容。

## 2. 项目配置样例

```json
{
  "schema_version": "1.0.0",
  "workspace_id": "workspace_33333333-3333-4333-8333-333333333333",
  "title": "示例小说",
  "work_type": "novel",
  "locale": "zh-CN",
  "blueprint_path": "shared/blueprint.json",
  "novel_path": "packages/novel/novel.json",
  "packages": ["novel", "drama", "music-cue", "visual-prompt"]
}
```

原创短剧使用 `work_type=drama`，不要求 novel_path 或空 Novel；作品类型字段升级须显式迁移旧配置。V1 固定上述包根与设定集路径，不接受配置指向工作区外部。配置不存绝对路径、Token、SSH 私钥、供应商 Key 或系统访问凭据。最近打开路径与系统授权保存在当前用户的原生应用数据目录，不随内容工作区提交。

## 3. 新建与打开

新建只允许用户明确选择的不存在目录或空目录，预演标准目录后创建。已有同名文件、部分目录或无权访问时停止并保留原状，不把已有目录当模板覆盖。Git 初始化为独立可选动作，需要明确确认。

打开时检查工作区身份、配置版本、设定集及引用、未完成事务和真实路径边界；损坏时进入只读诊断与恢复模式。不得遍历同级目录寻找“相似设定集”。网络共享盘、云盘占位文件及不支持可靠锁与原子替换的文件系统，V1 默认只读，支持范围经原生验收后再开放。

## 4. 保存与事务

小说资料和卷章目录以 `packages/novel/novel.json` 为事实源，内含独立 `novel_id`、作品身份、修订、`metadata`、有序 `volumes` 与 `chapters`。资料与目录共享修订校验；作者新建章节及采纳候选创建新章时，在正文首次落盘的同一事务中追加章节引用。候选到达和参考稿通过均不自动建立章节。目录重排不改变正文 ID、正文修订或 SourceRef，不允许丢弃章节或更换章节身份与正文的绑定。

未分卷章节在前，其余章节按分卷数组顺序连续排列。作者明确选择卷组时，新章追加到该卷组尾部；volume_id=null 表示未分卷。未提供归属的普通建章入口使用最后一个章节所在分组作为默认，确认界面须显示实际归属。参考稿新章采纳必须显式固定标题、卷组及小说目录修订，不能暗取默认分卷。既有作品缺少小说资料时，读取返回 `initialized=false`，作者确认资料后显式初始化，只收录既有小说章节；大纲、改编笔记与剧本保持独立。

Mac 本机书库保存于用户应用数据目录 `Hetu/Library/library.json`，包含作品身份、目录书签、资料摘要、章节数量、创建／更新时间缓存及独立的最近打开时间，不限制为最近十部。刷新只读取已登记作品，不改变最近打开时间。登记采用跨进程锁与原子写入；进入作品时内核重新核对身份。相同身份的另一可用目录不会静默替换既有登记。书库不读取未登记作品、不扩张 Agent 的授权范围。

作品时间由 `.hetu/workspace-properties.json` 维护，独立于配置身份。`created_at` 固定，`updated_at` 在成功持久化业务变更的同一事务中推进，不因查看、失败或同键重放改变，也不因系统时间回拨而倒退。旧作品缺少记录时，从初始设定集与审计恢复已知时间，未知返回 `null`；读取不补写文件，下次业务写入才保存。时间记录不进入 Git 内容快照，避免提交回执自身产生待提交内容。正文保存、资料修改和定稿各有独立时间，不能拿作品更新时间替代。

书库右键删除只由作者输入完整作品名确认，整个目录移入系统废纸篓后再移除登记。执行时核对当前标题、作品身份、目录身份与写入锁，目录移动、替换或仍在写入时拒绝。书库先持久化删除意图；移动完成而登记写入失败时，使用原书签、目录身份和废纸篓位置恢复登记，不因原路径消失而盲判成功，不删除同路径后来出现的目录。旧 Core 句柄在写入锁内核对根目录身份，作品移走后拒绝继续写入。放回废纸篓中的目录后，作者可重新打开并登记作品。

1. 取得工作区跨进程排他写锁，检查当前工作区身份和未完成事务。
2. 读取当前文件摘要，核对调用方的预期版本与摘要；不匹配返回 `revision_conflict`。
3. 在同卷 staging 写新修订和待替换清单，校验 Schema、引用、摘要与容量。
4. 写入并刷新恢复日志，记录旧值、新值、操作 ID 及提交意图。
5. 安装新文件、原子替换各清单，写入操作结果与审计后标记事务完成。
6. 释放锁，再发应用内状态变化通知。

多文件操作不能仅靠几次 rename 宣称整体原子性。受管读入口取得一致性读锁；发现未完成事务必须先恢复或拒绝读取混合状态。外部程序直接读目录不具有该一致性保证。

读取及恢复的事务检查须枚举当前事务目录，不能因已读过历史日志而跳过新增事务。每个已完成日志可使用进程内有界缓存减少重复解析，但每次须以受管目录描述符重新打开独立普通日志文件，核对设备、文件身份、长度和纳秒级修改／变更时间；身份或属性变化后重新解析。未完成日志不缓存为可读，仍核对全部目标及payload后恢复；损坏、未知版本、链接及冲突继续拒绝。缓存不写入作品、不删除历史日志，也不持有授权或代替正文摘要验证。

候选采纳、新当前修订、来源记录和审计属于同一可恢复事务；独立定稿则保存 FinalizationRecord、定稿指针及审计，不与采纳合并。草稿提交先持久化，诊断独立执行，避免超时导致候选不可查。用户编辑缓冲通过独立自动保存恢复，不能冒充参考稿提交或定稿。

草稿提交冻结正文、身份、设定、语言、写回基线与可选骨架引用，状态修订独立 CAS。只读草稿证据通过虚拟 Document／Revision 指向同一份 `content.<ext>`，供剧情、报告和精确原文定位复用；不创建待审内容的正式正文副本，也不允许保存该虚拟文档或将其作为其他草稿的写回目标。固定凭据、草稿状态及双索引不一致时拒绝读取，不通过重新计算摘要修复。

参考稿决定、采纳记录及定稿记录分别保留不可变历史与摘要。撤回定稿只清除仍属于该 FinalizationRecord 的指针，保留当前正文。返工将新提交与旧稿的接替状态一并落盘。客户端在调用前保存原动作、输入和操作键，未知结果先回读原请求；重启不新建草稿、报告或批准。

## 5. 崩溃、并发与外部编辑

启动时按原操作 ID 核对日志、旧摘要、新摘要和已安装文件；可确定则完成或恢复原状态，存在第三方改动则隔离冲突副本并请求作者处理，不能覆盖新编辑。对外在恢复完成前返回 `recovery_required`。

原生锁由 OS 持有，不能仅凭一个可能陈旧的 PID 文件判断占用。其他进程的写入串行化；两个编辑器基于同一旧修订保存时只有第一个成功，第二个进入差异合并。

外部修改经文件事件与用例前的摘要核对双重发现；文件事件仅作提示，不能替代写入前检查。原始修订被改写时保存损坏证据并阻止依赖定稿，不自动重新计算摘要洗掉历史。

## 6. 格式升级与备份

升级先只读预演受影响文件、空间和版本，再由作者确认生成完整备份；在副本验证后切换，失败保留原项目。未知主版本不降级写回。V1 不实现自动云备份服务；用户可使用本地副本、Git 或自行选择的备份工具，Git 不包含未提交缓冲和忽略文件。

路径安全见[18](18-安全与隐私.md)，Git 跟踪与排除见[16](16-Git版本与协作.md)，封面任务、候选识别和选用事务见[34](34-小说封面与Agent协作.md)。

## 7. 建书筹备与任务目录

尚无作品时，筹备保存在用户应用数据目录下的 `Hetu/CreationProjects/<project_id>/`，包括 `project.json`、不可变项目修订和 `collaboration/`。后者与作品内协作目录使用同样的任务／候选布局，scope 明确为 creation_project。书名可空，目录使用稳定 ID，不以临时书名或列表位置定位。

作者确认创建时冻结筹备修订和最终资料，保存固定创建意图，再在用户选定的目标根创建独立工作区；已有目标内容一律核验，不覆盖。跨卷不声称文件系统原子提交：目标工作区的可恢复创建事务保存 project_ref、固定 workspace_id 及原操作回执，筹备中的创建关联可据此恢复。应答丢失时回查原目标和原键，不生成新 workspace_id。

创建后仅把作者选择的候选来源、实际采用字段及相关摘要快照导入作品 `collaboration/imports/`，不用本机绝对路径作永久引用。旧筹备请求保持原 scope；访问新作品需另行授权。筹备、旧候选和未采用资料不自动加入作品 Git 或 Bundle。

## 8. 外部结果与页面生命周期

外部交接先写候选完整文件，最后原子提交结果清单；只有内核核验后的 submission 可供采纳。外部修改已登记候选时返回冲突，不重新计算摘要掩盖改写。文件监听只触发重新核验，应用启动、重新激活和手动检查有有界补查。

Node.js 页面、MCP Apps 和原生端均读取同一 task／submission／decision；页面 localStorage 和 widgetState 只可保存非敏感视图偏好。授权会话、配对秘密、监听端口及 IPC 句柄留在本机会话存储或内存，不进入协作目录、提示词或 Git。页面关闭不删除任务，不替外部 Agent 取消生成。


## 9. 资料、制作资产与工作副本

资料头、设计头、候选文件组、作者选用和使用记录分别拥有版本，目录语义见[35](35-资料素材与短剧制作资产.md)。媒体原字节沿用对应包的 assets，不因资料分类再复制一份；文字资料不依赖媒体存在。索引只负责检索和当前性，不充当可编辑故事事实或剧本文字。

Agent 的媒体文件交接只写本任务 inbox；文本工作副本优先通过 MCP／CLI 保存，需要文件编辑时使用 Core 显式检出的任务临时目录。Core 校验清单和实际文件后，在事务中登记不可变媒体、参考修订与候选。提交过程中使用临时文件，发布前不进入候选列表。模型生成不在工作区事务内执行，不能用本机事务回滚宣称已取消或退还外部任务。

跨作品导入先冻结来源清单、摘要与权利，创建新身份映射和独立受管副本，最后事务公开；失败保留原操作供恢复，不留下可见的半份资料。备份须包含 resources、相关包的媒体、项目与分集、固定历史和来源；可重建缩略图不要求备份。

## 10. 请求版本与参考稿保存

协作目录保存获权任务的固定请求、上下文清单、工作修订、候选和公开反馈，不保存整段 Agent 聊天。请求 head、观察状态、工作副本 head 和摘要索引均由 Core 维护，不能把客户端 localStorage、文件 mtime 或最后打开的窗口当作事实。建书筹备使用相同布局，不借作品目录定位筹备。

作者补充上下文或改变范围时，先核验外发差异与固定来源，再用可恢复操作发布新请求及本机授权版本；恢复完成前不允许新旧版本混用。旧请求、已提交候选和工作修订保留，旧请求停止新写入。相同目标的普通反馈只追加记录，不复制任务或重写原 Prompt。

任务根 `.hetu/tasks/<task_id>/` 下，`context/<manifest_id>.json` 保存请求1.1.0固定的获权资料目录，request.json 中的 context_manifest_ref 锚定其摘要。目录只保存明确来源、原始字节摘要和元数据，正文回读已有不可变文档修订；不复制整书，也不跟随当前头。1.0.0内联任务保留原始字节与摘要。

`working/<working_copy_id>/head.json` 保存参考稿头，同一参考稿目录内的 `revisions/<working_revision_id>.json` 和 `content/<working_revision_id>.txt` 分别保存不可变修订记录与正文；`feedback/<feedback_id>.json` 保存公开意见。任务状态锚定参考稿头摘要和意见引用，不以目录扫描或文件修改时间判断已保存状态。

工作副本保存先查授权和原键，再检查 expected、请求当前性、内容／补丁范围及预算；新修订、head、操作回执和审计同事务提交。作者与 Agent 同时改同一副本时保留冲突内容，不能自动以最后写入者覆盖。提交候选固定已保存工作修订，候选清单与来源同事务登记，后续编辑不修改旧提交或作者正文。

文件检出写入 `.hetu/task-checkouts/<task_id>/<checkout_id>/`，只包含获权参考内容及安全清单，不包含授权秘密、正式文档写路径或其他任务文件。检出不是 OS 沙箱；宿主文件权限仍由用户控制。导入核对 checkout 身份、固定基线、实际普通文件、摘要和当前副本 CAS，再形成新修订；文件未稳定、已变化、超限、越界或请求升级则拒绝，不登记半稿。临时文件可丢弃，已保存修订必须可恢复。

文件编辑宿主必须另获该任务临时根的 OS 访问权限，才能解析 Core 返回的安全相对位置；交接引用和 MCP 连通不自动授予文件权限。无该能力时使用 MCP／CLI 内容保存，不要求放宽到作品根或整座书库。

稳定连接的目录映射、主体、TaskGrant、配对秘密及消息发送回执保存在本机私有应用数据或内存中，不进入作品、Prompt、Git 或 Bundle。它们与可备份内容分别管理；搬迁作品到新机器不自动取得原客户端授权。工作副本、公开反馈及上下文清单可随作品备份；正式 Bundle 只按交付 profile 显式选取，不把协作目录整包外发。

## 插件优先重构的接入边界

插件安装、运行授权、偏好与作品权威分开；专有对象和修订经受管用例落盘，不能由TS插件直接写作品目录。首期JSON标题投影可重建，SQLite设计用于后续规模评估，包卸载不删除作品。目标分工见[39](39-Electron与插件优先重构架构.md)，详细扩展合同见[插件系列](plugin/README.md)，实际进度归38。
