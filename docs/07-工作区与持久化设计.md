# 工作区与持久化设计

一个内容工作区对应一个 IP，可自行初始化为 Git 仓库；它与河图软件源码仓库无包含关系。

## 1. 内容目录

```text
my-ip/
  .heturc.json
  shared/
    blueprint.json
  packages/
    novel/
      documents/<document_id>/
        document.json
        revisions/<revision_id>.md
      drafts/<draft_id>/
        draft.json
        content.<ext>             # markdown 为 md，剧本为 fountain
      outlines/
      annotations/
      plot/
    drama/
      documents/                 # 同一清单结构，正文 revisions/<revision_id>.fountain
      drafts/
      skeletons/
      comparisons/
      reports/
    music-cue/
      cues/
      assets/
    visual-prompt/
      cues/
      assets/
  exports/
  .hetu/
    audit/                       # 可版本化、已脱敏的操作与审核记录
    operations/                  # 持久操作结果和幂等记录
    transactions/                # 本机恢复日志，不加入 Git 或导出
    cache/                       # 可重建索引，不加入 Git 或导出
```

`document.json` 维护格式、当前与定稿修订指针；修订正文不可原地覆盖。`draft.json` 维护格式、草稿属性与审核状态，提交后正文不可修改；返工产生新草稿并引用旧草稿。小说源为 Markdown，剧本源为 Fountain，详见[25](25-小说与剧本标准格式.md)。删除缓存不能丢失作品或操作结果。

## 2. 项目配置样例

```json
{
  "schema_version": "1.0.0",
  "workspace_id": "workspace_33333333-3333-4333-8333-333333333333",
  "title": "示例 IP",
  "locale": "zh-CN",
  "blueprint_path": "shared/blueprint.json",
  "packages": ["novel", "drama", "music-cue", "visual-prompt"]
}
```

V1 固定上述包根与设定集路径，不接受配置指向工作区外部。配置不存绝对路径、Token、SSH 私钥、供应商 Key 或系统访问凭据。最近打开路径与系统授权保存在当前用户的原生应用数据目录，不随内容工作区提交。

## 3. 新建与打开

新建只允许用户明确选择的不存在目录或空目录，预演标准目录后创建。已有同名文件、部分目录或无权访问时停止并保留原状，不把已有目录当模板覆盖。Git 初始化为独立可选动作，需要明确确认。

打开时检查工作区身份、配置版本、设定集及引用、未完成事务和真实路径边界；损坏时进入只读诊断与恢复模式。不得遍历同级目录寻找“相似设定集”。网络共享盘、云盘占位文件及不支持可靠锁与原子替换的文件系统，V1 默认只读，支持范围经原生验收后再开放。

## 4. 保存与事务

1. 取得工作区跨进程排他写锁，检查当前工作区身份和未完成事务。
2. 读取当前文件摘要，核对调用方的预期版本与摘要；不匹配返回 `revision_conflict`。
3. 在同卷 staging 写新修订和待替换清单，校验 Schema、引用、摘要与容量。
4. 写入并刷新恢复日志，记录旧值、新值、操作 ID 及提交意图。
5. 安装新文件、原子替换各清单，写入操作结果与审计后标记事务完成。
6. 释放锁，再发应用内状态变化通知。

多文件操作不能仅靠几次 rename 宣称整体原子性。受管读入口取得一致性读锁；发现未完成事务必须先恢复或拒绝读取混合状态。外部程序直接读目录不具有该一致性保证。

审核通过、定稿指针更新和审计属于同一可恢复事务。草稿提交先持久化，再派生诊断任务，避免诊断超时导致草稿不可查。用户未提交的编辑缓冲通过独立自动保存草稿恢复，不能冒充定稿。

## 5. 崩溃、并发与外部编辑

启动时按原操作 ID 核对日志、旧摘要、新摘要和已安装文件；可确定则完成或恢复原状态，存在第三方改动则隔离冲突副本并请求作者处理，不能覆盖新编辑。对外在恢复完成前返回 `recovery_required`。

原生锁由 OS 持有，不能仅凭一个可能陈旧的 PID 文件判断占用。其他进程的写入串行化；两个编辑器基于同一旧修订保存时只有第一个成功，第二个进入差异合并。

外部修改经文件事件与用例前的摘要核对双重发现；文件事件仅作提示，不能替代写入前检查。原始修订被改写时保存损坏证据并阻止依赖定稿，不自动重新计算摘要洗掉历史。

## 6. 格式升级与备份

升级先只读预演受影响文件、空间和版本，再由作者确认生成完整备份；在副本验证后切换，失败保留原项目。未知主版本不降级写回。V1 不实现自动云备份服务；用户可使用本地副本、Git 或自行选择的备份工具，Git 不包含未提交缓冲和忽略文件。

路径安全见[18](18-安全与隐私.md)，Git 跟踪与排除见[16](16-Git版本与协作.md)。
