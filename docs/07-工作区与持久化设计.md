# 工作区与持久化设计

内容工作区是单部作品的文件、授权与版本边界，可自行初始化为 Git 仓库；作者书库登记多部独立作品。每部小说拥有自己的正文、设定、封面及关联改编项目，目录与河图软件源码仓库分别管理。

书库登记项与 OS 文件授权保存在当前用户的原生应用数据目录。登记目录不授予 Agent 对整座书库的访问权限；每次接入仍以作者选定的单个作品工作区为范围。更换书名不改变作品身份，目录失效时显示需重新定位，不自动扫描同级作品。

## 1. 内容目录

```text
my-novel/
  .heturc.json
  shared/
    blueprint.json
    blueprint-revisions/<revision>.json  # 不可变设定集修订
  packages/
    novel/
      novel.json                  # 小说资料、稳定分卷及有序章节引用
      documents/<document_id>/
        document.json
        revisions/<revision_id>.md
        adoptions/<adoption_id>.json       # 参考内容采纳及结果修订
        finalizations/<finalization_id>.json # 独立定稿与撤回记录
      drafts/<draft_id>/
        draft.json
        content.<ext>             # markdown 为 md，剧本为 fountain
        submission.json           # 不可变提交属性与只读证据身份
        reviews/<review_id>.json  # 不可变决定，含父决定摘要
      outlines/
      annotations/
      plot/<plot_revision_id>.json # 不可变剧情抽取与校正修订
    drama/
      documents/                 # 同一清单结构，正文 revisions/<revision_id>.fountain
      drafts/
      skeletons/
      comparisons/
      reports/
    music-cue/
      cues/
      assets/
    visual-prompt/
      cues/
      assets/
      covers/
        requests/<request_id>.json # 作者确认的不可变封面请求
        inbox/<request_id>/       # 外部 Skill 候选图及 result.json
        cover.json                # 作者选用记录，引用受管素材
  collaboration/
    requests/<task_id>/<request_revision>.json # 固定外部任务，不含凭据
    inbox/<task_id>/<submission_id>/           # 外部候选及最后写入的 result.json
    submissions/<submission_id>.json          # 内核核验后的候选记录
    decisions/<decision_id>.json              # 局部选择和意见
    imports/                                 # 作者选取的建书筹备来源快照
  exports/
  .hetu/
    novel-head.json              # 小说当前修订与摘要
    novels/<revision>.json       # 不可变小说资料与卷章目录修订
    blueprints/<revision>.json    # 设定集修订路径、身份与原始字节摘要
    plots/<plot_revision_id>.json # 剧情修订身份、输入、统计与内容摘要
    draft-heads/<draft_id>.json   # 草稿状态修订与摘要
    draft-submissions/<draft_id>.json # 固定提交凭据索引
    draft-sources/<document_id>.json # 草稿只读虚拟文档入口
    reviews/<review_id>.json      # 决定归属、路径和摘要
    review-heads/<draft_id>.json  # 草稿最近决定与摘要
    adoptions/<adoption_id>.json  # 采纳记录归属、路径与摘要
    finalizations/<finalization_id>.json # 定稿／撤回记录归属、路径与摘要
    audit/                       # 可版本化、已脱敏的操作与审核记录
    operations/                  # 持久操作结果和幂等记录
    transactions/                # 本机恢复日志，不加入 Git 或导出
    cache/                       # 可重建索引，不加入 Git 或导出
```

`document.json` 维护格式、当前与定稿修订指针；修订正文不可原地覆盖。`draft.json` 维护格式、草稿属性与审核状态，提交后正文不可修改；返工产生新草稿并引用旧草稿。小说源为 Markdown，剧本源为 Fountain，详见[25](25-小说与剧本标准格式.md)。删除缓存不能丢失作品或操作结果。

`shared/blueprint-revisions/` 与 `.hetu/blueprints/` 保留设定集历史和摘要；正文与报告可据此回溯确切设定。历史内容与摘要记录不一致时停止依赖该修订，不覆盖历史文件修复摘要。

剧情保存以固定正文修订与设定集修订为输入，内容、索引、原操作回执与审计在同一可恢复事务中写入。预览提取不创建剧情文件、索引或操作回执。作者校正追加新 `plot_revision_id`，保留原节点 ID、来源与父修订；历史可形成分支，不覆盖其他作者的校正。读取时校验内容摘要、索引和输入来源；当前正文或设定集变化只计算 `stale_reasons`，不修改历史结果。

## 2. 项目配置样例

```json
{
  "schema_version": "1.0.0",
  "workspace_id": "workspace_33333333-3333-4333-8333-333333333333",
  "title": "示例小说",
  "locale": "zh-CN",
  "blueprint_path": "shared/blueprint.json",
  "novel_path": "packages/novel/novel.json",
  "packages": ["novel", "drama", "music-cue", "visual-prompt"]
}
```

V1 固定上述包根与设定集路径，不接受配置指向工作区外部。配置不存绝对路径、Token、SSH 私钥、供应商 Key 或系统访问凭据。最近打开路径与系统授权保存在当前用户的原生应用数据目录，不随内容工作区提交。

## 3. 新建与打开

新建只允许用户明确选择的不存在目录或空目录，预演标准目录后创建。已有同名文件、部分目录或无权访问时停止并保留原状，不把已有目录当模板覆盖。Git 初始化为独立可选动作，需要明确确认。

打开时检查工作区身份、配置版本、设定集及引用、未完成事务和真实路径边界；损坏时进入只读诊断与恢复模式。不得遍历同级目录寻找“相似设定集”。网络共享盘、云盘占位文件及不支持可靠锁与原子替换的文件系统，V1 默认只读，支持范围经原生验收后再开放。

## 4. 保存与事务

小说资料和卷章目录以 `packages/novel/novel.json` 为事实源，内含独立 `novel_id`、作品身份、修订、`metadata`、有序 `volumes` 与 `chapters`。资料与目录共享修订校验；作者新建章节及采纳候选创建新章时，在正文首次落盘的同一事务中追加章节引用。候选到达和参考稿通过均不自动建立章节。目录重排不改变正文 ID、正文修订或 SourceRef，不允许丢弃章节或更换章节身份与正文的绑定。

未分卷章节在前，其余章节按分卷数组顺序连续排列。作者明确选择卷组时，新章追加到该卷组尾部；volume_id=null 表示未分卷。未提供归属的普通建章入口使用最后一个章节所在分组作为默认，确认界面须显示实际归属。参考稿新章采纳必须显式固定标题、卷组及小说目录修订，不能暗取默认分卷。既有作品缺少小说资料时，读取返回 `initialized=false`，作者确认资料后显式初始化，只收录既有小说章节；大纲、改编笔记与剧本保持独立。

Mac 本机书库保存于用户应用数据目录 `Hetu/Library/library.json`，包含作品身份、目录书签、资料摘要、章节数量和最近打开时间，不限制为最近十部。登记采用跨进程锁与原子写入；进入作品时内核重新核对身份。相同身份的另一可用目录不会静默替换既有登记。书库不读取未登记作品、不写入内容仓库，也不扩张 Agent 的授权范围。

1. 取得工作区跨进程排他写锁，检查当前工作区身份和未完成事务。
2. 读取当前文件摘要，核对调用方的预期版本与摘要；不匹配返回 `revision_conflict`。
3. 在同卷 staging 写新修订和待替换清单，校验 Schema、引用、摘要与容量。
4. 写入并刷新恢复日志，记录旧值、新值、操作 ID 及提交意图。
5. 安装新文件、原子替换各清单，写入操作结果与审计后标记事务完成。
6. 释放锁，再发应用内状态变化通知。

多文件操作不能仅靠几次 rename 宣称整体原子性。受管读入口取得一致性读锁；发现未完成事务必须先恢复或拒绝读取混合状态。外部程序直接读目录不具有该一致性保证。

候选采纳、新当前修订、来源记录和审计属于同一可恢复事务；独立定稿则保存 FinalizationRecord、定稿指针及审计，不与采纳合并。草稿提交先持久化，诊断独立执行，避免超时导致候选不可查。用户编辑缓冲通过独立自动保存恢复，不能冒充参考稿提交或定稿。

草稿提交冻结正文、身份、设定、语言、写回基线与可选骨架引用，状态修订独立 CAS。只读草稿证据通过虚拟 Document／Revision 指向同一份 `content.<ext>`，供剧情、报告和精确原文定位复用；不创建待审内容的正式正文副本，也不允许保存该虚拟文档或将其作为其他草稿的写回目标。固定凭据、草稿状态及双索引不一致时拒绝读取，不通过重新计算摘要修复。

参考稿决定、采纳记录及定稿记录分别保留不可变历史与摘要。撤回定稿只清除仍属于该 FinalizationRecord 的指针，保留当前正文。返工将新提交与旧稿的接替状态一并落盘。客户端在调用前保存原动作、输入和操作键，未知结果先回读原请求；重启不新建草稿、报告或批准。

## 5. 崩溃、并发与外部编辑

启动时按原操作 ID 核对日志、旧摘要、新摘要和已安装文件；可确定则完成或恢复原状态，存在第三方改动则隔离冲突副本并请求作者处理，不能覆盖新编辑。对外在恢复完成前返回 `recovery_required`。

原生锁由 OS 持有，不能仅凭一个可能陈旧的 PID 文件判断占用。其他进程的写入串行化；两个编辑器基于同一旧修订保存时只有第一个成功，第二个进入差异合并。

外部修改经文件事件与用例前的摘要核对双重发现；文件事件仅作提示，不能替代写入前检查。原始修订被改写时保存损坏证据并阻止依赖定稿，不自动重新计算摘要洗掉历史。

## 6. 格式升级与备份

升级先只读预演受影响文件、空间和版本，再由作者确认生成完整备份；在副本验证后切换，失败保留原项目。未知主版本不降级写回。V1 不实现自动云备份服务；用户可使用本地副本、Git 或自行选择的备份工具，Git 不包含未提交缓冲和忽略文件。

路径安全见[18](18-安全与隐私.md)，Git 跟踪与排除见[16](16-Git版本与协作.md)，封面任务、候选识别和选用事务见[34](34-小说封面与Agent协作.md)。

## 7. 建书筹备与任务目录

尚无作品时，筹备保存在用户应用数据目录下的 `Hetu/CreationProjects/<project_id>/`，包括 `project.json`、不可变项目修订和 `collaboration/`。后者与作品内协作目录使用同样的任务／候选布局，scope 明确为 creation_project。书名可空，目录使用稳定 ID，不以临时书名或列表位置定位。

作者确认创建时冻结筹备修订和最终资料，保存固定创建意图，再在用户选定的目标根创建独立工作区；已有目标内容一律核验，不覆盖。跨卷不声称文件系统原子提交：目标工作区的可恢复创建事务保存 project_ref、固定 workspace_id 及原操作回执，筹备中的创建关联可据此恢复。应答丢失时回查原目标和原键，不生成新 workspace_id。

创建后仅把作者选择的候选来源、实际采用字段及相关摘要快照导入作品 `collaboration/imports/`，不用本机绝对路径作永久引用。旧筹备请求保持原 scope；访问新作品需另行授权。筹备、旧候选和未采用资料不自动加入作品 Git 或 Bundle。

## 8. 外部结果与页面生命周期

外部交接先写候选完整文件，最后原子提交结果清单；只有内核核验后的 submission 可供采纳。外部修改已登记候选时返回冲突，不重新计算摘要掩盖改写。文件监听只触发重新核验，应用启动、重新激活和手动检查有有界补查。

Node.js 页面、MCP Apps 和原生端均读取同一 task／submission／decision；页面 localStorage 和 widgetState 只可保存非敏感视图偏好。授权会话、配对秘密、监听端口及 IPC 句柄留在本机会话存储或内存，不进入协作目录、提示词或 Git。页面关闭不删除任务，不替外部 Agent 取消生成。
