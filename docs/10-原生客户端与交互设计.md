# 原生客户端与交互设计

两端共享用户任务与业务语义，遵循各自原生控件与系统习惯。界面和内容的语言规则见[31](31-国际化与中文体验.md)。

## 1. 信息架构

作者书库独立于作品编辑窗口，管理多部小说的封面、书名、笔名、题材、状态、字数与最近编辑；提供搜索、筛选、创建及登记已有作品。选书后进入该作品的编辑窗口，书库和作品切换入口持续可达。

作品编辑区采用内容导航、卷章树、正文和可收起检查器。正文占主要宽度，窄窗口折叠检查器及次要导航。顶部持续显示当前作品、设定集锁状态、保存状态和编辑对象；切换作品后清除前一作品的诊断、临时选区与 Agent 授权投影。

默认工作面是作者正文，支持按照个人风格直接写作和修改。AI 改稿是作者按需发起的外部协作任务，入口放在当前章节的次要操作中；未发起任务时不展开候选比较或安装引导，不用 AI 面板挤占正文。同一编辑器支持自主写作与选择性参考，无需切换全局创作模式。

一级导航为设定集、小说、短剧、乐律线索、视觉线索、审核、版本、交付。MCP 授权与远端连接放设置，不抢占创作主入口。窄窗口隐藏检查器并提供原生详情入口，不能遮挡正文或审核状态。

“AI 协作”设置管理客户端和扩展接入；具体任务入口留在建书、资料、大纲、封面和编辑器的当前对象旁。它们打开任务准备与结果页，不打开河图洛书内的聊天界面。用户始终在所选外部客户端与 AI 对话。

## 2. 页面与主要动作

| 页面 | 主要内容 | 主操作及边界 |
| --- | --- | --- |
| 作品入口 | 作者书库、目录授权、恢复提示 | 新建／登记作品；没有作品不扫描全盘 |
| 作者书库 | 多部独立小说、封面、状态、字数和最近编辑 | 选定作品继续创作；目录失效时重新定位 |
| 建书筹备 | 作者想法、书名／简介／大纲候选、选择来源、待填写资料 | 复制到所选客户端，作者确认后创建；书名未知可先保存筹备 |
| 外部协作任务 | 当前作品或筹备、客户端、专用 Skill、Prompt、范围、候选与回执 | “复制到 Codex”等具体按钮；复制不显示为生成中 |
| 作品资料与封面 | 书名、笔名、简介、题材、创作状态、当前封面和候选 | 保存资料、导入封面；外部设计使用 Prompt 与配套 Skill，见34 |
| 设定集 | 角色、势力、地点、时序、世界规则 | 保存或锁定；锁定态先明确解锁 |
| 小说 | 可选分卷、章节顺序、Markdown 编辑、批注与修订 | 新建／重排卷章、保存当前版本；抽取为显式任务 |
| 剧情节点 | 原文与结构并列、歧义与未确认列表 | 确认所选节点，不强迫逐个接受 |
| 短剧 | 分集／场次、来源、缺项、剧本 | 建立骨架或保存草稿，显示结构版本 |
| 诊断 | 级别、确定性、覆盖与原文定位 | 跳转和处理；没有问题不显示“全书无 OOC” |
| 审核 | AI 参考、待审候选、来源、差异、报告与批注 | 采纳到写作稿；要求修改提供可复制 Prompt，定稿为独立操作 |
| 线索 | 叙事引用、情绪／视觉描述、既有素材 | 新增线索或导入文件，不出现核心生成按钮 |
| 版本 | 工作树、文件 diff、分支、远端状态 | 创建快照或同步；范围和方向可见 |
| 交付 | 章节、剧本、线索、问题与排除项 | 导出选定版本的 Bundle |
| 设置 | 通用、写作、AI 协作、版本与关于 | 管理默认客户端、扩展来源／版本、连接与能力；本机偏好不修改作品正文或全局配置 |

## 3. 视觉层次与插画

书库使用浅色与深色两套背景插画，未选封面的作品使用三套通用书封底图。底图不包含文字，书名与笔名使用原生字体叠排；中文与英文界面共享插画，正文标题保持原语言。默认书封按作品身份稳定分配，改书名与重启不换图；默认插画不代表作者选定封面，也不写入作品素材目录。全部位图等比缩放，封面保持 2:3，原图、生成提示词与摘要登记在 `assets/manifest.json`。

原生窗口以玉青、雾蓝、淡紫的连续渐变承托导航与工作面板。浅色使用柔和雾色，深色使用低亮度墨色；标题栏与侧栏透出同一背景，避免每个区域各自形成不相接的色块。正文保持独立纸面，诊断警告与风险颜色遵守语义，不使用装饰色代替状态。

| 区域 | 视觉规则 |
| --- | --- |
| 书库 | 山水横幅、2:3 封面、资料卡、状态标签；网格与列表显示同一作品事实 |
| 作品资料 | 封面与资料并列，简介独立成段；不将占位插画标记为作者封面 |
| 导航与卷章树 | 选中背景与侧边标记共同指示当前位置，悬停只改变表面，不移动条目 |
| 小说正文 | 无插画覆盖正文；纸面外沿使用细边框与轻阴影，窄窗口优先正文宽度 |
| 设定、短剧、审核与素材 | 标题、说明、操作、内容分层；空状态以对应主题插画说明下一步 |
| 剧情、诊断与版本 | 来源、修订与业务状态优先；装饰插画不暗示校验已通过或版本已保存 |

工具页内容固定从顶部开始排布，空状态仅占据剩余内容区，不将标题与操作组整体推到窗口中部。相同页面不重复展示同一装饰插画。工作页共享背景、面板、按钮和标题组件，颜色以 `WorkbenchPalette` 为唯一原生语义来源。

工具主题插画分别提供浅色与深色资源，随外观切换，避免浅色画布在深色面板形成亮块。插画不包含中英文文字、按钮或伪造内容；界面文案始终由本地化资源绘制。装饰不接收点击、不进入 VoiceOver，系统增强对比度或减少透明度时收敛光晕并使用实色面板。背景没有持续动画。macOS 的“显示 → 外观”提供跟随系统、浅色、深色三个选项，仅改变河图洛书的外观。

书库与作品窗口的顶部提供齿轮设置入口，macOS 应用菜单和 `Command+,` 打开同一个原生设置窗口。通用、写作、AI 协作、版本与关于集中管理偏好及接入；界面语言、外观、书库布局和正文排版同步应用到各窗口。Git 作者信息与快照表单使用同一本机偏好，不设置全局 Git 身份，不执行提交或远端同步。作品内容与本机偏好独立保存。

## 4. 正文编辑体验

提供中文输入法、选区、撤销／重做、搜索替换、字数与章节顺序。编辑显示名与磁盘 ID 分离，重排章节不重命名稳定对象。大文档增量布局、后台索引，避免每次键入全量重排或扫描。

查找区明确区分“当前文档”和“本作品已保存正文”，显示精确匹配／中文分词模式、命中数量、查询中、部分覆盖及无结果；未索引章节不能被算作零命中。当前文档搜索包含未保存缓冲，全书搜索结果固定命中修订，定位前核验原文；遇到新修订展示历史引用并提供重新检索入口，不覆盖当前编辑缓冲。替换及全部替换作用于当前编辑器，预览确切变更并形成一次撤销，不自动保存或定稿；跨章节先定位再编辑，见[UC-28](26-用户故事与用例.md#31-uc-28-中文全文检索与当前章替换)。

写作设置提供宋体、苹方和系统字体，字号为 14–30 pt，额外行间距为 0–16 pt。小说默认采用 18 pt 宋体、5 pt 额外行间距和两字首行缩进；Fountain 剧本不应用小说首行缩进。设置包含只读排版预览，修改偏好时保留原文字节、来源定位、选区和撤销栈，中文输入组合期间延后排版更新。

自动保存只保证编辑缓冲可恢复；显式保存生成可引用的修订。状态区区分“编辑中”“已自动保存”“已保存修订”“保存失败”“外部修改冲突”。切换文档或关闭窗口遇到未保存内容时提供保存、保留恢复副本、取消，不静默丢弃。

诊断高亮不改变正文格式。点击问题定位对应源修订；当前正文变化后显示过期标记和重算入口。Emoji 与中文偏移使用内核 SourceRef 转换，禁止按 UTF-16 长度直接解释字节偏移。

## 5. 审核与风险呈现

正文、设定集差异、来源与确定错误优先于摘要评分。提交 Agent 的名称标为调用方声明，审核人显示本地作者身份。批注引用确切修订；要求修改产生可查询的审核结果，不显示虚假的“Agent 正在重写”。

通过前展示当前输入版本及未解决的确定错误、启发式警告和覆盖不足。不可豁免的数据损坏与引用错误阻止定稿；可接受的业务例外需作者说明理由，见[15](15-人工审核与审计.md)。

Git 提交、分支切换、合并、拉取、推送、导出含待审内容等操作分别预览确切影响。普通编辑与受限草稿提交不反复弹确认；已变化的输入使原确认失效。

## 6. 异步与故障状态

所有异步任务具备稳定布局、进度、取消与逐项结果。明确展示空内容、没有访问权限、工作区占用、离线、部分结果、失败、过期和成功，不能依靠整页重载隐藏状态。

取消抽取不会删除源文；取消导出清理自身临时包并保留诊断；Git 推送发出后取消不能保证远端未更新，显示“结果待核实”。对未知状态先查询原操作，不提供自动重试。

## 7. 原生与可访问性

- macOS 使用原生菜单、快捷键、文件选择器、窗口恢复与 VoiceOver；Windows 使用 Fluent 控件、键盘焦点、Narrator 与高对比主题。
- 编辑区支持字号调整；状态不只靠颜色表达，图标有可访问名称与 tooltip。
- 支持系统浅暗主题、缩放与减少动态效果，不将 Web 组件套壳作为核心 UI。
- 键盘可完成打开、编辑、校验、处理问题、审核与导出；焦点在异步更新后保持可预测。
- 渐变用于窗口背景，面板用于承载内容；正文、表单与诊断不使用高对比装饰底图，不以卡片层层包裹同一信息。

目标支持 1024×768 及以上桌面可用布局，较窄窗口采用折叠导航；最终最小窗口、字号和间距须经双端原型验证后冻结，不直接照抄参考项目尺寸。

## 8. AI 协作任务与验收界面

建书表单把“我已有资料”和“先帮我构思”作为可互相切换的填写方式，不增加一条强制 AI 流程。未知书名保持空字段及清晰提示，筹备标题仅用于本机识别，不自动写成正式书名。候选按书名、简介、大纲等字段展示，选择只填入表单，底部“创建小说”仍由作者执行。

任务准备页显示当前筹备或书名、客户端、专用 Skill、目标、上下文清单、Prompt 语言和完整可编辑提示词。主要按钮为“复制到 Codex／WorkBuddy／Claude Code”，复制后反馈“提示词已复制，请到所选客户端继续”，并提供重新复制和查看结果。该页不包含对话气泡、模型选择、Token 用量或虚构生成进度。

结果页显示候选批次、来源、版本、核验结果及下一步；书名与简介按字段选择，大纲按结构比较，图片保持原比例并可放大。文本候选与当前写作稿并排或逐行比较，支持局部采纳；主操作为“采纳到写作稿”。需要改写时作者勾选可外发批注，复制补充 Prompt，不自动通知 Agent 重写。

作者也可以只阅读参考稿，返回原编辑器自行撰写，或关闭结果页而不采纳。对既有正文请求 AI 改稿时，任务准备页明确所选范围、修改目标与希望保留的语气、视角或表达；正文保存、输入停顿和打开章节均不自动发起改稿。外部结果到达只更新参考列表，不切走焦点或替换编辑缓冲。

编辑器同时提供“写作稿”和“定稿”查看入口，显示当前保存状态及是否存在相对定稿的新修改。来源以独立标签或详情呈现，不给整篇内容贴不可消除的 AI 标记；采纳及后续修改可从修订历史追溯。手工作者直接编辑、检查和确认定稿，不经过 AI 收件列表。

Apps 和本地网页只承载当前任务需要的选择、预览和批注。界面持续显示任务所属作品或“建书筹备”，切换上下文清空旧临时数据。最终采纳、作品创建、设定修改、正式封面选用和定稿提供“回河图洛书确认”入口；浏览器环境不能将自动化点击作为作者批准。

## 9. 接入与任务状态文案

| 场景 | 展示 | 可执行的下一步 |
| --- | --- | --- |
| 尚未选择客户端 | 选择用于本次任务的客户端 | 选择或改用手工 |
| 用户完成安装但未技术检查 | 用户已确认安装，连接尚未验证 | 复制只读接入检查说明 |
| Prompt 已复制 | 提示词已复制，等待外部结果 | 到客户端粘贴、重新复制、查看输入 |
| 收到部分候选 | 已收到部分结果，并列出缺项 | 预览合法候选、复制补全说明 |
| 文件出现但回执不完整 | 已发现文件，等待完整结果 | 保留现有稿件、重新检查 |
| 目标基线已变化 | 当前稿已有修改 | 查看三方差异后重新选择 |
| 本地网页未配对 | 等待在河图洛书确认本任务访问 | 回原生端核对，不展示私密正文 |
| Apps 或浏览器不可用 | 当前客户端无该交互能力 | 回河图洛书预览，使用文本结果继续 |

这些状态来自本机可观察事实，不能从复制或用户点击推断外部任务正在运行。内容来源、外部交接状态、审核状态和文档定稿状态分别表达。

## 10. 已有正文的外部改稿

作者从当前章菜单或选区菜单进入“请外部 AI 改稿”。界面使用“允许改动”“仅供参考”“不在本次范围”表达权限，不要求作者理解角色、ACL 或 token。没有选区时要求明确选择“整章改稿”或“在此续写”，不能把空选区解释为整书授权；整章含章末插入点，指定位置续写只允许在该点插入。

### 10.1 权限与内容矩阵

| 对象 | 外部 Agent 在本任务可做什么 | 作者操作 |
| --- | --- | --- |
| 明确授权的正文选区／整章／插入点 | 读取固定原文，提交范围内的改动候选 | 比较、选用部分或全部改动、自行改写或放弃 |
| 添加的其他章节、设定及作品资料 | 仅供参考，不获得这些对象的修改权 | 单独编辑；需要外部改稿时另建对应任务 |
| 本章未授权修改的段落 | 原文可作为已确认的上下文；补丁必须保留这些字节 | 在范围预览中排除不想改的段落，或重新划定可改范围 |
| 未保存正文与输入法组合内容 | 不自动读取，不作为提交结果的写入目标 | 先保存修订再发起；也可取消任务准备，继续写作 |
| 定稿及历史修订 | 可把明确选择的版本作为参考，不能覆盖或移动定稿指针 | 修改写作稿，满意后另行确认新定稿 |
| 设定锁、目录结构、正式封面、版本及交付 | 无本任务写入权限；可以在意见中提出建议 | 回到对应原生界面单独处理 |
| 其他作品、其他任务、本机凭据与应用设置 | 不在本次任务的读取或写入范围 | 新任务重新选范围；凭据不外发 |

“不改这段”是本次任务范围的排除，不给文档增加永久只读状态，也不阻止作者自己改稿。文风、人设和情节走向要求可写入“需要保留”，这些语义由作者审阅及诊断辅助判断；范围外字节不变则由内核确定校验。

### 10.2 准备、交接与验收

1. **固定原文**：完成中文组合输入并保存当前修订；若保存失败、外部冲突或作者选择取消，则留在编辑器，不自动复制缓冲。选区在保存后重新核验，避免把旧坐标套到新稿。
2. **确认范围**：预览“允许改动”的高亮段落或插入点，另列“仅供参考”的章节、设定和作品资料。作者可以缩小范围、排除段落、移除上下文；上下文扩展不扩大可改范围。V1 单任务修改一个文档，多章分别建任务，不默认读写整本书。
3. **表达要求**：输入修改目标及需要保留的语气、视角、称谓等，预览提示词、资料清单和固定回传位置，再复制到所选客户端。安装引导按需出现，不在河图洛书中启动对话或生成。
4. **继续写作**：复制后作者可正常编辑；状态只显示“等待外部结果”。收到候选仅更新任务提示，不抢焦点、不改变当前选区或撤销栈。关闭任务撤销后续访问，历史候选保留。
5. **逐处比较**：展示作者原文、AI 改稿及当前写作稿；将改动按段落分组，每处提供“采用这处”“保留原文”，支持作者继续改写。首次全部未选，不默认全采纳；被保留的原文不能被一次“采纳所选改动”带走。
6. **确认落稿**：主按钮显示“采纳所选改动”，附选中数量；未保存稿先由作者处理。只写选中的结果并形成可追溯新修订，不移动旧定稿。当前稿变化时保留用户选择，重新比较并预览；不按旧行号自动套用。放弃候选不回滚作者后来写的内容。

结果中的越界补丁、错引句或拆分中文字符应整批拒绝，并说明“改动超出本次允许范围”等原因；不裁掉越界部分后假报成功。合法的迟到候选显示“基于较早版本，仅供参考”，作者可选择重新发起或与当前稿重新比较。只读参考与正式采纳走不同动作，MCP Apps／本地网页上的勾选仅保存偏好。
