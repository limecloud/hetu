# 测试策略与验收矩阵

以用户行为、失败及恢复验证合同；内核、跨端桥接、原生界面、协议与分发分别提供证据。

## 1. 验证层级

| 层级 | 验证目标 | 不能代替 |
| --- | --- | --- |
| 文档／Schema | 链接、ID、示例与约束一致 | 功能实现 |
| Rust 单元／夹具 | 设定集、引用、规则、状态与来源 | 原生文件系统及 UI |
| 存储／Git 集成 | 真实文件、跨进程、事务、仓库恢复 | 真实远端和用户旅程 |
| C ABI／Swift／C# | 生命周期、编码、取消与错误 | 原生编辑、签名和安装 |
| CLI／MCP 协议 | 机器输入输出、权限、断线、幂等 | 特定宿主与人类审批 |
| 原生 UI | 中文输入、焦点、权限及完整任务 | 其他 OS 或架构 |
| 格式互操作 | 文件有效性、第三方打开、语义回环 | 所有阅读器和制片模板 |
| 分发 | 干净系统、签名、依赖与升级 | 未测试平台支持 |

### 2.1 专项验证责任

本节规定测试应证明的合同，不记录某次构建通过了什么。自动化夹具、原生 UI、真实宿主及签名分发分别保留执行证据，不能互相替代。

| 专项 | 核心及协议断言 | 原生交互或外部验收 |
| --- | --- | --- |
| 剧情与诊断 | 中文／Emoji／CRLF 精确来源、候选隔离、事实有效期、梦境／转述／假设、覆盖与预算、处置 CAS、摘要篡改拒绝 | 作者标注、报告筛选、固定原文定位、具体处置和双语切换 |
| 分集与骨架 | 稳定 ID、空对白、未知日夜、拆合重排、跨集移动、来源不可伪造、历史与快照游标 | 分集选择、结构表单、原著对照和方案隔离 |
| Fountain 剧本 | 模板语言、结构标题、不可表达项、初稿 UTF-8 映射、正文改变后的当前性 | 建稿、手工编辑、来源定位、标准阅读器及交付渲染 |
| 参考稿审核 | 固定候选与报告、返工接替、公开／私密投影、撤回审核不改正文或定稿 | 比较候选、批注、通过／驳回／要求修改及历史查看 |
| 采纳与独立定稿 | 精确选区及 replacement、目录 CAS、来源链、定稿保持、手工稿零 Draft 定稿、旧决定不能撤新指针、原键恢复 | IME、局部采纳、一次撤销、继续编辑、独立理由和覆盖确认、重启恢复 |
| Git | 上级仓库隔离、原 index 保护、固定选集及 HEAD、批准失效、禁止 hooks、未知状态查询 | diff 评审、快照确认、分支／合并；测试远端的 SSH／HTTPS 同步 |
| MCP 与 Apps | 官方 Schema 与 SDK Client 双向验证、实际协议、工具封装、范围、分页、EOF／取消后的原键恢复、越权拒绝 | 所声明客户端版本实际安装与调用；Apps 局部选择和无 Apps 回退 |
| 素材与封面 | 流式字节复制、类型及限额、来源声明、权利修订、历史许可不能绕过撤回、跨作品候选拒绝 | 文件面板、等比预览、选区关联、封面作者选用及书库刷新 |
| 导入与交付 | 编码和结构损失、原文件变化、目录同事务、固定计划、ZIP 路径及摘要、发布与回执恢复 | 转换预览、中文排版、第三方阅读器、独立解包及接收方核验 |

核心夹具入口见 `core/tests/`，stdio 互操作夹具见 `apps/mcp/tests/stdio.rs`，原生状态与桥接夹具见 `tests/native/`。官方协议 Schema 固定来源修订和摘要，原始许可位于 `tests/mcp/LICENSE`；测试执行绑定该版本，不根据 SDK 列名推断兼容性。各专项均包含正常、失败、并发和恢复断言，实际覆盖由对应执行记录证明。

封面专项入口为 `core/tests/covers.rs` 与原生 `CoverTests.swift`。核对手工图片检查、空白请求拒绝、固定回执及部分候选、伪摘要和损坏图拒绝、作者权限、历史链、双窗口 CAS、书库缓存重建及未知选用的原键恢复；原生文件面板与真实图片的视觉布局另行验收，状态测试不替代界面证据。

## 3. 贯通旅程

- E2E-01 纯手工：断网 → 建项目 → 设定集 → 写小说 → 节点校正 → 骨架 → 手工剧本 → 校验及作者处置 → 对保存修订独立定稿 → 导出。
- E2E-02 Agent：作者主动选择原文范围、修改目标及风格要求并复制 Prompt → 外部客户端对话与 Skill 生成 → 提交独立参考稿 → 原生对比 → 分别验证只读后自行改写、放弃及局部采纳 → 继续编辑 → 独立检查与定稿；软件无生成请求，接收结果不改正文或抢焦点。
- E2E-03 并发恢复：两进程打开 → 同基线写入 → 第二个冲突 → 提交中断 → 重开恢复 → 旧审核不能沿用。
- E2E-04 版本协作：本地快照 → 测试远端 → 两作者改同设定集 → 冲突 → 人工解决 → 重新校验 → 单次推送。
- E2E-05 格式交付：导入中文稿 → 章节／人物人工确认 → Fountain 互换 → DOCX／PDF 制片稿 → Bundle manifest 核验。
- E2E-06 国际化：中文创作 → 切换英文界面 → 读取同一诊断 → 英文帮助与模板 → 核对原文、摘要及批准记录未变；两端分别执行。
- E2E-07 首次建书：软件选客户端 → 无书名筹备 → 对应扩展安装 → 筹备范围只读接入 → 复制 Prompt → 外部构思 → 候选按字段采纳 → 作者创建 → 关联封面任务；创建未知不重复建书。
- E2E-08 Apps：真实支持宿主加载任务 → 选择候选／批注 → 保存并回读 → 原生端显示同一结果 → 切任务不串数据 → 不支持 Apps 的客户端完成原生回退。
- E2E-09 本地浏览器：作者按需启动 → 实际内置浏览器回环可达 → 配对 → 查询和选择 → 原生验收 → 撤权并释放端口；非法 Origin、过期和云端不可达均有明确结果。
- E2E-10 编辑主权：纯手工保存与定稿 → 接收 AI 候选 → 局部采纳、撤销及手工改写 → 定稿保持旧修订 → 作者另行确认新定稿 → 默认交付仅选定稿。

## 4. 性能与规模目标

以下为性能验收目标。基准分别记录 OS、CPU、内存、磁盘、构建模式、冷／热缓存与 p50／p95；以 macOS arm64 和 Windows x64、16 GB 内存、本地 SSD 的明确机器为基线。

| 场景 | 初始目标 |
| --- | --- |
| 编辑 10 万汉字单章 | 输入到显示 p95 ≤ 100 ms；IME 不丢组合状态 |
| 1000 章、约 1000 万汉字项目 | 冷打开首屏 ≤ 5 s，全文索引异步不阻塞编辑 |
| 10 万汉字规则检查 | ≤ 5 s，结果清楚标识覆盖与预算 |
| 全书后台任务 | UI 可操作，取消请求响应 ≤ 1 s，原子提交阶段单独记录 |
| 1 GB 已选交付材料 | 流式打包，额外峰值内存目标 ≤ 256 MB，不把媒体全部读入内存 |

性能目标未达时先调查瓶颈；任何调整需记录理由与产品影响，不能在失败后静默降低门槛。

## 5. 质量样本与故障注入

核心夹具覆盖中文重名、化名、时间跨期、梦境、插叙、说谎、心理活动、群体角色、未闭合引号及无标点文本。抽取 precision／recall 使用独立作者标注集，M0 先冻结数据与评分方式，再确定数值门槛，不虚构通用 OOC 准确率。

在每个事务阶段注入崩溃、磁盘满、权限撤销、锁竞争、文件替换与进程终止；分别核对未写入、已写入、部分结果和 unknown。网络失败注入测试远端，禁止自动访问真实作者仓库。所有破坏性夹具只操作本次生成的临时项目。

## 6. 证据与发布门禁

证据记录 `requirement_ids, case_id, source_revision, build_digest, os, architecture, toolchains, fixture_digest, steps, expected, actual, status, limitations`。状态为 `pass|fail|skipped|blocked|not_run`；未跟踪工作树使用源码树摘要，不要求为测试自行提交。

V1 P0 业务及安全用例双端通过、Swift CLI 干净系统运行、基础 MCP 至少完成所声明宿主版本验收、标准交付样例第三方可读、无数据完整性关键缺陷，才可声明对应范围完成。MCP Apps、扩展架构和可选插件单独验收。

MCP Apps 资源执行 `npm run test:task-view`：用官方 SDK 桥接渲染受沙箱限制的页面，并经真实原生 stdio 获取资源、保存选择及回读持久化决定；同时覆盖中英浅暗布局、封面比例、候选文本注入、任务切换拒绝、未保存意见、旧修订和未知保存结果沿原键恢复。资源与源码摘要由构建入口核验。该自动化宿主只证明资源、桥接与本机服务的集成，不替代指定 Codex／WorkBuddy／其他客户端版本的实际加载和交互验收。

同一命令包含本地页面测试：真实任务、原生侧私有 IPC 适配、浏览器请求配对、精确 Host／Origin／CSRF、跨任务与非白名单拒绝、原键恢复、过期及父进程 EOF 后端口释放。`python3 "tools/build-native.py" --test` 使用装配后的 Node.js，另验证 Swift 父进程管理、原生批准、真实 Core 保存与关闭任务后撤权。浏览器自动化保存成功不替代作者定稿或实际宿主兼容证据。

完成原生构建后，`swift run --skip-build hetu-native-tests --creation-projects` 单独执行筹备状态集成用例，覆盖空书名持久化、重启恢复、受限任务候选、作者修改及来源、CAS 冲突、非空目录保护和创建回执恢复；`--local-task-view` 单独执行本地 Node 子进程、配对、WebKit 沙箱页面与任务关闭撤权用例。两项也包含在完整原生测试中，单项结果不替代完整用户界面旅程和真实外部客户端验收。

`swift run --skip-build hetu-native-tests --agent-integration` 在隔离目录验证逐作品关联、随包文件与版本、Codex 官方安装及回读、WorkBuddy 方法包安装与配置保留，不使用作者真实客户端缓存。发布前还须比较源包、Swift 资源及 App 内资源的完整文件集和每个文件摘要，并核对签名；隔离安装通过不能代表当前客户端会话已加载扩展。

## 7. 关键业务场景验收

以下场景将用户目标转为可执行断言。每项分别记录正常、失败与恢复结果；字段名和错误码由能力目录及动作合同取得，不通过 UI 文案猜测业务完成。

| 场景 ID／用例 | 给定 | 当 | 则 |
| --- | --- | --- | --- |
| AC-01／UC-15／23 | 两部独立小说存在同名角色、章节和不同设定 | 在 A 编辑后切到 B，并用 A 的 Agent scope 请求 B | B 内容与设定不受 A 修改，跨作品访问被拒；A 缓冲与修订仍可恢复 |
| AC-02／UC-21 | 离线，无 Agent 扩展和草稿记录 | 手工建章、中文编辑、保存、检查并独立定稿 | 定稿引用确切正文修订，Draft 数量仍为零，流程无外网依赖 |
| AC-03／UC-05 | 当前正文已有定稿，收到待审参考稿 | 作者通过参考稿审核 | 仅决定和草稿状态变化，正文当前／定稿指针及章节目录不变 |
| AC-04／UC-17 | 候选包含中文、Emoji、CRLF，目标已有定稿 | 仅采纳两个不重叠且 quote 匹配的范围 | 结果字节仅含选定变更，保存 AdoptionRecord，旧定稿指针不变；越界、重叠或错 quote 整次拒绝 |
| AC-05／UC-11／17 | 作者已预览基于 R1 的采纳，另一窗口保存 R2 | 提交原预览 | 返回冲突，不覆盖 R2，不产生部分采纳记录；作者选择保持可重新比较 |
| AC-06／UC-06 | 正文及报告已冻结，之后设定或问题处置变化 | 确认旧预览的定稿 | 旧确认失效，历史报告仍可读，需重新检查；输入摘要损坏不能由例外说明放行 |
| AC-07／UC-06／21 | R1 已定稿 | 保存 R2，再独立确认 R2，最后尝试用 R1 的旧决定撤回 | 保存 R2 不改变 R1 定稿；新确认后定稿指向 R2；旧决定不能撤回新持有者 |
| AC-08／UC-11／17 | 采纳事务已提交但成功回执丢失 | 重启并以相同键和相同输入恢复，再尝试同键异输入 | 返回原修订和原采纳 ID，不新增业务记录；同键异输入明确冲突 |
| AC-09／UC-18／19 | 固定候选已通过 Apps 或配对网页展示 | 保存局部选择，再尝试调用正式采纳、设定写入、封面选用或定稿 | 选择可在原生端回读，作者动作被拒；不支持 Apps 时同一候选可回原生端处理 |
| AC-10／UC-13／25 | 原生编辑器存在组合输入、选区、撤销记录和旧定稿 | 修改阅读样式并切换中文／英文界面 | 组合输入按编辑合同处理，内容摘要和定稿不变；选区、撤销及功能入口可用 |
