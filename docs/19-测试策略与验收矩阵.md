# 测试策略与验收矩阵

## 无额外插件的默认产品门禁

以隔离、空的创作插件安装目录启动，核对随包基础清单、独立CLI/MCP和Electron使用同一核心能力。小说完成卷章、正文、参考稿、意见、第二版及导出；剧本完成独立项目、分集正文和返工；视频完成分集、固定媒体接收与播放、旧新版比较、固定区间意见及基本文件交付。本机器入口专项中，业务经CLI/MCP准备和执行，GUI用于作者审阅及界面验收；独立桌面对话与执行另按第17节验证，不能由本专项通过推定支持。

视频专项覆盖同键重放、错误作品／分集／素材、摘要篡改、非法时基与越界区间、前版归属、关闭重开、旧意见不迁移新版、完整文件字节与交付清单。声明的流与时长、技术解码、实际观看和作者认可分别取证。源码测试不代替正式发行或目标系统运行。

随包基础清单检查须拒绝缺失动作、缺失工作面及错误作品类型；可选插件安装目录为空、缺失或存在坏包均不能阻断基础工作面。基础能力完整、专业插件增强和停用后读取导出是三组独立门禁。架构口径见[39](39-Electron与插件优先重构架构.md#无额外插件的基础产品)。

作者要求本对话实测时，实际更新CLI／MCP和所选Skills，再由当前Agent发现Schema、从零创建隔离作品、保存参考稿、回读固定意见并返工。包安装、命令来源、当前连接版本和实际方法读取分别取证；常驻连接未重载时如实记录。自动化夹具不冒充当前对话创作，Agent自查不冒充作者意见。精确作品的媒体交接必须同时验证合法固定引用可达、错误归属及摘要拒绝，以及决定入口无需GUI执行。

精确作品任务读取须验证管理连接及插件回调读取同一固定任务、同根其他作品拒绝、错误范围拒绝、撤权立即生效，并核对读取不增加提交、采纳或定稿权限。当前源码专项的八项 Core 回归及真实山海跨进程正负例见[专项证据](research/evidence/managed-task-read-shanhai-2026-11-17.json)；不将开发制品结论转记为既有安装版通过。

当前桌面执行入口为第14节的Electron、Rust与插件专项。第1至13节中的原生专属夹具与命令保留为历史验收记录，已不参与当前构建；通用业务场景、Core和MCP合同继续适用。历史通过不替代当前制品验收。

以用户行为、失败及恢复验证合同；内核、跨端桥接、原生界面、协议与分发分别提供证据。

## 3. 贯通旅程

默认 AI-first 旅程的业务步骤由真实外部 Agent 经 Skill + CLI/MCP 执行，作者只审阅成果、提供意见和确认必要决定。Computer Use 用于界面、输入法、排版及可访问性验收；不承担正常业务操作。作者 C ABI 驱动可以独立验证审核合同，不能用它预建筹备、填资料和创建作品后声称机器链路从零通过。纯手工旅程验证备用能力，不能代替默认旅程。

- E2E-01 纯手工：断网 → 建项目 → 设定集 → 写小说 → 节点校正 → 骨架 → 手工剧本 → 校验及作者处置 → 对保存修订独立定稿 → 导出。
- E2E-02 Agent：作者主动选择原文范围、修改目标及风格要求并复制 Prompt → 外部客户端对话与 Skill 生成 → 提交独立参考稿 → 原生对比 → 分别验证只读后自行改写、放弃及局部采纳 → 继续编辑 → 独立检查与定稿；软件无生成请求，接收结果不改正文或抢焦点。
- E2E-03 并发恢复：两进程打开 → 同基线写入 → 第二个冲突 → 提交中断 → 重开恢复 → 旧审核不能沿用。
- E2E-04 版本协作：本地快照 → 测试远端 → 两作者改同设定集 → 冲突 → 人工解决 → 重新校验 → 单次推送。
- E2E-05 格式交付：导入中文稿 → 章节／人物人工确认 → Fountain 互换 → DOCX／PDF 制片稿 → Bundle manifest 核验。
- E2E-06 国际化：中文创作 → 切换英文界面 → 读取同一诊断 → 英文帮助与模板 → 核对原文、摘要及批准记录未变；两端分别执行。
- E2E-07 首次建书：软件选客户端 → 无书名筹备 → 对应扩展安装 → 筹备范围只读接入 → 复制 Prompt → 外部构思 → 候选按字段采纳 → 作者创建 → 关联封面任务；创建未知不重复建书。
- E2E-08 Apps：真实支持宿主加载任务 → 选择候选／批注 → 保存并回读 → 原生端显示同一结果 → 切任务不串数据 → 不支持 Apps 的客户端完成原生回退。
- E2E-09 本地浏览器：作者按需启动 → 系统浏览器或外部客户端实际回环可达 → 配对 → 查询和选择 → 原生验收 → 撤权并释放端口；非法 Origin、过期和云端不可达均有明确结果。
- E2E-10 编辑主权：纯手工保存与定稿 → 接收 AI 候选 → 局部采纳、撤销及手工改写 → 定稿保持旧修订 → 作者另行确认新定稿 → 默认交付仅选定稿。

- E2E-11 资料与复用：离线建立纯文字人物／场景／考据 → 关联章节及场次 → 维护两套设计与固定使用 → 更新只提示依赖 → 明确跨作品导入 → 移走原目录仍可读 → 权利撤回阻断新交付，不改历史包。
- E2E-12 图片与 Agent：真实所选客户端发现任务 → 在授权内连续维护设计候选 → 按实际工具生成或官方产品人工操作 → 成图及可用附属文件回传 → 核验与等比预览 → 作者返工及选用 → CAS／迟到／未知恢复／撤权；五类模型的资料与真实调用证据分别记录，不要求付费接口同时可用。
- E2E-13 原创短剧：不建空小说 → 原创项目与多分集 → 中文语义编辑及 Fountain 源文互读 → 场次资料、分镜、模型片段交接 → 分集重排和历史查看 → Agent 候选不能写正式稿 → 独立定稿与第三方格式验收。

- E2E-14 场景创建：分别从首屏创建原创新小说、原创剧本和小说改编项目 → 核对所需字段、可跳过项及默认页面 → 离线写作 → 重开保持作品类型，无冗余空内容。
- E2E-15 原著与权利：自己的小说／授权原著／公版版本三组来源 → 固定引用或独立快照 → 原著对照 → 分别核对改编、Agent 外发与再分发 → 缺项和撤回只影响相关对外操作 → 旧映射与历史包保持。
- E2E-16 用途导入：小说、Fountain 剧本、改编原著及文字资料四类 → 手工纠正识别与结构 → 源文件变化冲突 → 原键恢复 → 在对应工作台继续，不自动定稿或复制既有工作区。
- E2E-17 引导体验：从零、筹备、创建与导入各自执行键盘操作、IME、返回、取消、类型切换、AI 接入回返和迟到候选 → 重启恢复表单与原操作 → 核对未保存内容、焦点和重复创建。
- E2E-18 真实 Codex 小说协作：干净新会话发现实际包和稳定 MCP → 打开无书名筹备 → 与作者讨论方向并交候选 → 作者创建作品并授新范围 → 大纲和资料 → 首章参考稿连续保存 → 作者公开意见 → 原任务返工 → 固定候选及局部采纳；软件不生成，期间不逐任务重配连接。
- E2E-19 协作恢复与上下文：两部隔离作品 → 获权目录／检索／片段 → 请求补资料并由作者确认 → 旧请求写入被拒 → 保存或提交回执丢失 → 新会话按原键及反馈恢复 → 作者正文同时变化 → 三方比较 → 撤权后旧连接读写拒绝，历史可由作者查看。
- E2E-20 真实反馈交互：明确支持消息的宿主实际加载 Apps → 保存公开反馈 → 用户按此修改 → 消息响应与后续成果分别观察；另在无 Apps／无消息能力／普通网页／发送失败下复制相同反馈继续，均不伪报唤醒、不重复保存。
- E2E-21 真实原创剧本与素材：无小说及骨架创建原创任务 → 场景 Skill 组织人物、分集与 Fountain 参考稿 → 保存、反馈和返工 → 提交及作者采纳 → 关联素材设计 → 外部实际生成文件或明确能力缺项 → 核验、比较与作者选用；改编分支再单独核对固定原著和权利。

### 3.2 写入期间浏览

工作区存在写入者时，作者仍能打开作品、切换章节并阅读已提交内容；正文与保存入口显示只读，其他写操作由内核拒绝。写入结束后自动恢复编辑，已有未保存缓冲不得被后台刷新覆盖。读请求在多文件事务发布期间等待完整提交，不读取一半新、一半旧的数据；异常中断的事务先恢复或明确阻断，不把不完整状态显示为成功。

内核用例为 `core/tests/workspace.rs` 的并发打开与恢复测试及 `Store` 的多文件发布、崩溃恢复测试；Mac 状态用例为 `workspaceAccessTests`。界面验收应实际持有隔离作品的写入锁，核对进入、阅读、只读提示、禁用编辑及释放后的恢复，不能只在写入完成后截图。

### 3.3 真实 Agent 协作验收

本专项以作者从软件发起、真实 Codex 执行的协作为验收对象。当前正在工作的 Codex 会话可以按公开 CLI 或实际已连接的 MCP 独立阅读资料、创作和返工；不能因另一套 CLI 未登录而否定当前会话。安装后自动发现、首次连接及新会话恢复另用新会话验证，不借缓存掩盖安装问题。测试驱动可以在隔离作品中执行明确标识的作者操作，但不能代 Agent 提交预制文本。整书夹具和协议测试继续承担其自身覆盖；只有实际执行并保存证据的范围才能标 pass。

| 检查点 | 必需证据 | 失败判断 |
| --- | --- | --- |
| 接入 | 精确客户端版本／表面、安装包及助手摘要、新会话实际工具与 Skill、任务读写回执 | 只看到文件、配置、安装成功或脚本可调用，不能判接入通过 |
| 从想法建书 | 作者意图、Agent 实际准备的资料、必要决定、创建回执与筹备转作品授权 | 测试驱动代填候选或补建书步骤、未获权接管目录、沿旧筹备权限读作品则失败；明确新建意图下的有限受管创建不要求作者重复填表 |
| 资料与首章 | 按需调用的固定引用、工作副本多次保存、正式提交摘要、原生可见结果 | 全书塞进单次工具结果、未保存声明、候选覆盖正文则失败 |
| 反馈返工 | 确切成果及公开反馈、所用继续路径、新稿反馈引用、作者对比 | 测试程序代写返工稿、保存当唤醒、没有后续成果却报完成则失败 |
| 编辑与采纳 | 作者后续修改、三方比较、仅选定范围的 AdoptionRecord、旧定稿指针 | 覆盖未保存内容、越界补丁或采纳即定稿则失败 |
| 恢复与撤权 | 中断前后原键、同 task_id、已有成果和反馈、撤权后的真实拒绝 | 换键重新生成、任务串书或旧连接仍可读则失败 |
| 原创剧本与素材 | 无原著场景、Fountain 修订、设计及实际文件／明确缺项、独立作者选择 | 强制小说／骨架、图片说明冒充成图、回传即选用则失败 |

稳定入口另验完整 TaskRef 的跨层传递：真实 stdio 返回的摘要须进入 Apps 初始化、保存参数及嵌套候选引用；模拟成功回执丢失后，通过窄操作工具恢复同一保存，不能重提或降级到未公布的 URI。协议测试覆盖真实 Core 与传输，浏览器测试覆盖桥接及界面保留意见，两者都不能替代真实 Codex 会话证据。无任务时可读取静态面板代码，但不能取得任务目录或数据；任务关闭后的静态代码可用性不作为仍有业务权限的证据。

证据仅记录必要任务输入、工具调用、结果引用、公开意见和摘要，不收集作者无关聊天、凭据或真实书稿。用原创演示材料和隔离目录，保留中文写作、英文界面、无 Apps 与无消息能力路径。图像或消息能力缺失按对应用例标 blocked／not_run 或验证明确回退，不能把回退通过写成该能力兼容通过。

Mac 本期退出条件为 E2E-18／19／21 及 E2E-20 的已声明宿主路径均有真实证据；不能用原生单测、整书断言、MCP 驱动、模拟 AppBridge 或安装包检查替代。Windows 与其他宿主分别验收，不从 Mac／Codex 结果推导支持。

### 3.4 资料版本影响核对验收

本专项归入 FR-27 与 E2E-11，合同见[35第8.1节](35-资料素材与短剧制作资产.md#81-文字资料的版本影响核对)。范围为已登记的固定使用位置；资料和正文已有新版分别标记，不把版本变化解释为语义错误，也不推断未登记的全书影响。

`tests/native/HetuNativeTests/ResourceImpactTests.swift` 通过真实 Core 验证两类版本变化、固定旧稿及已保存新版、Unicode／Emoji／CRLF 引文、错误摘要与坐标拒绝、合法空锚点、归档过滤、已载入分页摘要，以及作者缓冲和历史关联保持。比较不改变采纳或定稿的合同另以应用调用及界面操作核对。原生构建后运行 `swift run --skip-build hetu-native-tests --resource-impact`；独立 scratch 构建须使用同一 scratch 的执行文件，并记录实际加载的 Core。

同资源 App 的界面验收分别执行：

1. 打开资料详情，在“使用位置”切换全部／待核对，检查两类提示、归档排除、加载更多及读取错误；失败不显示为“没有变化”。
2. 打开“核对变化”，切换资料／正文比较，核对两列标题、版本和旧稿引文定位；新稿不得沿用旧坐标，空锚点不出现空白原文按钮。
3. 保留一份正在编辑的未保存正文，打开、刷新、关闭比较，再返回编辑器，核对内容、光标和脏状态；查看只读作品时仍可比较。
4. 分别使用中文、英文和最小支持窗口，检查阅读、分栏、滚动、键盘及关闭。比较不产生“确认完成”记录，不自动更新关联或覆盖历史。

最终装配须包含 `ResourceImpact.swift`、`ResourceImpactReviewSheet.swift`、`ResourceWorkbenchView.swift`，并核对包内 `NativeStrings.json` 与共享本地化源一致。Swift 与 Core 从同一源码输入统一构建，核验所需 ABI 符号（包括 `hetu_model_service_request`）及实际加载的包内动态库；独立 Core 的链接通过不代表共享目录或安装包已更新。源码被构建目标包含、编译通过及状态测试通过，与安装 App 的实际操作分别记录；中文行为、英文视觉及英文行为分别登记，服务超时后未完成的操作不计为通过。

## 4. 性能与规模目标

以下为性能验收目标。基准分别记录 OS、CPU、内存、磁盘、构建模式、冷／热缓存与 p50／p95；以 macOS arm64 和 Windows x64、16 GB 内存、本地 SSD 的明确机器为基线。

| 场景 | 初始目标 |
| --- | --- |
| 编辑 10 万汉字单章 | 输入到显示 p95 ≤ 100 ms；IME 不丢组合状态 |
| 1000 章、约 1000 万汉字项目 | 冷打开首屏 ≤ 5 s，全文索引异步不阻塞编辑 |
| 10 万汉字规则检查 | ≤ 5 s，结果清楚标识覆盖与预算 |
| 全书后台任务 | UI 可操作，取消请求响应 ≤ 1 s，原子提交阶段单独记录 |
| 1 GB 已选交付材料 | 流式打包，额外峰值内存目标 ≤ 256 MB，不把媒体全部读入内存 |

性能目标未达时先调查瓶颈；任何调整需记录理由与产品影响，不能在失败后静默降低门槛。

## 5. 质量样本与故障注入

核心夹具覆盖中文重名、化名、时间跨期、梦境、插叙、说谎、心理活动、群体角色、未闭合引号及无标点文本。抽取 precision／recall 使用独立作者标注集，M0 先冻结数据与评分方式，再确定数值门槛，不虚构通用 OOC 准确率。

在每个事务阶段注入崩溃、磁盘满、权限撤销、锁竞争、文件替换与进程终止；分别核对未写入、已写入、部分结果和 unknown。网络失败注入测试远端，禁止自动访问真实作者仓库。所有破坏性夹具只操作本次生成的临时项目。

## 6. 证据与发布门禁

证据记录 `requirement_ids, case_id, source_revision, build_digest, os, architecture, toolchains, fixture_digest, steps, expected, actual, status, limitations`。状态为 `pass|fail|skipped|blocked|not_run`；未跟踪工作树使用源码树摘要，不要求为测试自行提交。

V1 P0业务及安全用例双端Electron通过、独立CLI干净系统运行、基础 MCP 至少完成所声明宿主版本验收、标准交付样例第三方可读、无数据完整性关键缺陷，才可声明对应范围完成。MCP Apps、扩展架构和可选插件单独验收。

MCP Apps 资源执行 `npm run test:task-view`：用官方 SDK 桥接渲染受沙箱限制的页面，并经真实原生 stdio 获取资源、保存选择及回读持久化决定；同时覆盖中英浅暗布局、封面比例、候选文本注入、任务切换拒绝、未保存意见、旧修订和未知保存结果沿原键恢复。资源与源码摘要由构建入口核验。该自动化宿主只证明资源、桥接与本机服务的集成，不替代指定 Codex／WorkBuddy／其他客户端版本的实际加载和交互验收。

工作台另覆盖空全局入口不枚举授权、明确作品导航、固定正文与媒体分块摘要、只读专业投影、显式AI交接、恶意深链接及窄窗。连接安装在隔离Codex目录核验准备、作者决定、登记、缓存字节与丢回执原键恢复；指定`HETU_ACCEPT_CODEX_BINARY`时，增加本机官方CLI实际安装测试，不能据此声明GUI会话已加载。草稿受理、上下文替换、消息发送和候选保存各自断言，不把任何桥接回执当成作者采纳。

全局入口发现须另用已安装Codex随包App Server的`mcpServerStatus/list`探测验证，记录真实下游握手，不能只传入自设的UI能力后测试。无UI能力的目录探测仍返回全局／线程元数据、空入口及静态资源；普通客户端保持精简模型目录，读取作品、任务和反馈仍经Core授权。新旧`extensions`／`experimental`能力分别覆盖，并核验新版声明优先。

上述官方客户端验收必须由Core生成连接包，经官方`plugin marketplace add`及`plugin add`后启动同一隔离配置的App Server，断言真实`hetu`服务、正确`pluginId`、入口及HTML；不能直接在`config.toml`添加`mcp_servers`替代插件解析。插件登记、服务加载、入口发现和GUI侧栏分别取证；安装回执与缓存摘要通过不能证明MCP被加载。

共享工作台另验Electron与MCP在相同视口、浅暗外观和固定演示投影下的页头、导航、山水、封面、字号及边框；搜索、类型与状态交集、空结果恢复、布局切换、窄屏键盘和加载／错误分别核对。MCP无授权空入口仍无作品、授权或文件枚举，已绑定作品读取携原精确引用；共享组件不得引入Electron作者桥接。截图只证明对应资料和表面，不把桌面整库权限转授给Agent。

Electron分集阅读覆盖空作者稿与已提交参考稿并存：直接显示最新提交的真实Fountain，切换未提交工作稿和作者稿，参考稿不可触发编辑或自动保存；审阅与意见进入同一固定任务，超过首批分页也能定位。错误分集、跨作品与陈旧固定引用拒绝；保存意见后作者稿仍为空，未采纳或定稿。已有作者内容保留默认展示，刷新及关闭重开仍可阅读参考成果。

同一命令包含本地页面测试：真实任务、原生侧私有 IPC 适配、浏览器请求配对、精确 Host／Origin／CSRF、跨任务与非白名单拒绝、原键恢复、过期及父进程 EOF 后端口释放。撤权流尚未建立时停止任务，也必须清空已显示内容。`python3 "tools/build-native.py" --test` 使用装配后的 Node.js，另验证 Swift 父进程管理、原生批准、真实 Core 保存与关闭任务后撤权。浏览器自动化保存成功不替代作者定稿或实际宿主兼容证据。

完成原生构建后，`swift run --skip-build hetu-native-tests --creation-projects` 单独执行筹备状态集成用例，覆盖空书名持久化、重启恢复、受限任务候选、作者修改及来源、CAS 冲突、非空目录保护和创建回执恢复；`--local-task-view` 单独执行本地 Node 子进程、配对、WebKit 沙箱页面与任务关闭撤权用例。两项也包含在完整原生测试中，单项结果不替代完整用户界面旅程和真实外部客户端验收。

`swift run --skip-build hetu-native-tests --agent-integration` 在隔离目录验证逐作品关联、随包文件与版本、Codex 官方安装及回读、WorkBuddy 方法包安装与配置保留，不使用作者真实客户端缓存。发布前还须比较源包、Swift 资源及 App 内资源的完整文件集和每个文件摘要，并核对签名；隔离安装通过不能代表当前客户端会话已加载扩展。

## 12. 小说批量导入与改编接续

导入 Skill 的范围为不同小说来源与排版；不能以单本书的标题表达式代替通用能力。脚本专项核对 UTF-8／UTF-16／GB18030、中文与英文编号、重新编号与同名标题、正文伪标题、无可靠标题、范围缺口、CRLF／Unicode、Word 段落和 EPUB spine 顺序。转换损失和不支持的输入明确返回，不默默丢正文。

Core 的 `import_authorization` 专项验证批量原稿和一份目录修订同时落盘，逐章原字节和来源保持、重复标题不合并、批准前无正文、原键不重复、非法成员或目录过期无部分章节。Skills 脚本不得具备通用作者批准、采纳和定稿入口；可依据真实用户指令登记受限的整书导入授权。

真实验收由当前对话通过 Skills + CLI/MCP 完成：从作者指定原稿生成可核对计划，导入持久作品，逐章回读修订摘要，比较目录顺序和分卷，再用固定原著引用建立独立改编项目与参考稿。夹具和计划生成不等于全书已导入；实际数量与改编结果写入对应证据。

TXT 转换须分别核对原字节来源摘要和内部 Markdown 修订摘要。不能因合法标点转义判定原文损坏，也不能仅检查转换后的正文而遗漏来源。某批回读不符时不推进持久进度；修复后沿同一方案及执行键恢复，不重复建章。

[《持械入宋》真实验收](research/evidence/novel-import-adaptation-2026-11-15.json)覆盖510章、1篇作品说明及5组目录，511篇逐一回读标题、顺序、分卷、固定修订及来源摘要；章号重置和同名章节均保留。开篇6集 Fountain 参考稿及13份未采用资料已写入独立改编项目，第一集经当前会话实际 MCP 保存、提交和回读。作者分集仍为空稿，原著未改，不将参考稿提交视为采用或定稿。

原生只读复验入口为 `hetu-native-tests --imported-work-review <持久导入记录目录>`。该专项使用隔离书库、偏好与恢复目录，检查全部目录、首／中／尾正文、中英切换、固定提交和资料状态，不填写业务表单、不修改真实正文。启动耗时保留不同负载下的全部样本；SDK 状态通过不替代 GUI 排版或稳定性能结论。[分层导航验收](research/evidence/work-catalog-navigation-2026-11-15.json)另记录安装版的六集逐一打开、真实正文、返回分集保持、原任务意见目标及中英宽窄主题样本。CUA 初始化错误保留，后续实际交互由系统辅助功能与真实窗口截图核对；未执行的完整显示矩阵及返工决定不据此登记通过。

AC-55 的导航检查须区分创作库、项目功能、内容目录、成果模式和按需检查器。分别在窄窗口和宽窗口展开／收起项目导航与卷章／分集目录，核对主要阅读空间、选中对象、原文和未保存缓冲；由搜索、关联或意见进入深层页面时展开对应分组，返回后保持对象及位置。剧本按集进入场次，场次定位准确；不在工具栏平铺全部功能，不以只有一个选项的项目选择器重复要求选择。该检查不能替代单对象授权负例：页面携带当前 WorkRef 时仍须拒绝同根另一对象的内容、交接引用、方案和原操作回执。

窗口关联返回另验完整工作界面：从固定关系详情打开另一作品，使用顶栏返回，恢复原功能页、选中章节／分集与固定关系版本；连续查看可逐次返回，另一作品不显示前一作品的关系状态。打开或返回失败保留当前作品及返回路径；另开作品或返回创作库清理旧路径，多个窗口互不借用。关联返回仍经过统一未保存内容保护，不能以保留页级选择冒充正文滚动、光标或视频播放位置通过。

单作品机器读取与任务接续须覆盖：能力目录返回确切 WorkRef；小说与剧本的正文目录按对象分页，固定正文和历史可回读；同名其他剧本、未归属剧本、错对象及视频读取正文均拒绝。默认目录预算为50条，最多200条，旧作者入口未指定分页时仍完整返回。游标绑定查询、内容与授权，再授权不能复活旧游标。按目标发现原任务返回 TaskLocator，查到任务不等于取得任务执行权；已有独立 TaskGrant 时可沿原任务跨 CLI／MCP 保存参考稿，固定提交不覆盖作者正文。隔离作者通道只登记授权及撤权决定，不能补机器建书或写稿步骤。界面暂停期间，该专项只证明机器合同，不证明 Electron、宿主 Apps 或界面渲染。

AC-56 的关联生命周期另查：列表进入固定版本详情、上一版／下一版与返回列表、已解除关系按需筛选；详情交接固定关联 ID、版本和摘要。显式更新来源后旧关联、旧任务与旧交付保持原引用；CAS 冲突、不同作品冒充新来源、伪摘要及重复恢复必须拒绝。目标精确授权可准备解除／恢复，来源授权不能管理下游，另一端原文不得借 get 或历史读取泄漏。另一端读取失败只影响该关系的可读性，当前性保持未知，不把失败显示为无关联或没有新版。`core/tests/work_links.rs`、真实 stdio 与 `hetu-native-tests --related-works` 分别核验领域、协议和原生状态；GUI 的真实层次、布局与双语行为独立记录。上述同根生命周期通过不代表跨根来源快照或全生命周期交付已经通过。

双端精确读取另验：稳定入口公布 related_management_ref，分别核验当前端与确切另一端；固定历史和摘要正确、正反方向一致。请求结束后任一端不得获得第三方或同根兄弟对象权限；缺省仍只读关系元数据，另一端授权不持久化或回显。错误对象、错误工作区、撤权及再授权后的旧引用拒绝；损坏历史返回 unavailable 与未知当前性，不替换为当前资料。Core、公开 CLI 和实际 stdio 分别执行，不以单次两端读取通过证明新建关联、更新依据或跨根内容快照已获权。

## 14. Electron与插件优先重构验收

本节扩展既有P0旅程，目标见39，插件编号与追踪归[插件15](plugin/15-测试验收与追踪矩阵.md)。原生通过不等于Electron通过；Electron UI/UX 以作者确认的 Mac 工作台截图与历史截图证据对照验收：56px 工具栏、中文170px／英文190px项目导航、210px目录、最大880px正文纸张区、280px检查器和宋体正文；视觉精简遵循[界面风格](10-原生客户端与交互设计.md#界面风格)，使用共享Radix中性色和浅暗主题。覆盖目录折叠／定位、侧栏显隐、窄窗浮层、专注、搜索、编辑保存、固定批注、历史比较和恢复；截图之外还须断言实际尺寸与行为，不由旧原生测试推导通过。

风格验收覆盖桌面、内嵌任务／操作面板和插件：静态文案不含中点分隔与装饰眉题，普通界面只用12／14／20px，文稿默认18px或作者设置，每页最多四档；容器边框0.5px，无装饰左色线、渐变或卡片阴影。实际渲染核对字号集合、浅暗背景、同屏对齐、窄窗无横向溢出和键盘焦点。精简后仍须验证必要授权、采纳、定稿、冲突及原键恢复可达，弹窗Escape只关闭当前弹窗。

独立Rust CLI专项验证中英帮助、无HOME版本查询、完整JSON／BOM／stdin／中文空格路径、16MiB预算、单个AXI结果和退出码；拒绝身份覆盖、相对授权目录与缺任务输入，失败不新建授权状态。公开CLI从零建立作品和任务，再与新启动MCP交叉回读固定工作稿、原操作及撤权结果；同一Core下由CLI与MCP交叉核验语义。仅复制单个可执行文件运行并检查链接依赖，不加载Swift或动态Core。该本机检查不等于目标平台干净系统、签名安装或本机设置Owner委托已完成；精确范围与制品摘要单独记证据。

新宿主本机设置另验证：独立 CLI/MCP 在无窗口时读取、准备、回读与执行固定方案；客户端、摘要、原执行键、期限和完整偏好基线分别核验。公开通道拒绝伪造决定、密钥及任意路径；可信决定丢回执后原键恢复，批准本身不执行。套件固定来源字节、目标客户端及目录，安装只含所选包；官方登记成功后丢回执须只读恢复，不重复安装。并发人工偏好、套件变动、已有目标内容、安装入口不可用与第三方失败分别覆盖；文件安装、官方登记、当前会话加载和 MCP 连通不得混同。桌面核对外观、阅读、人工稿保护和重开。

客户端套件升级补充验证：无关 Codex 市场损坏时，所选市场仍可精确发现、安装及升级；所选市场来源被替换、重复插件、旧缓存改动与同版目标冲突须在写入前拒绝，保留 approved。只读预检失败后可沿原方案继续；写入后丢回执只能原键回读，缓存损坏保留 unknown，随包升级不影响原固定缓存核验。没有阶段证据的历史 executing 不推断为可重试；测试断言官方安装次数及未覆盖的原文件，不能只检查返回状态。

设置以原生六分类截图逐页对照，独立窗口重复聚焦不增开。浅暗主题、520px窄窗、完整滚动内容、渠道浮层、键盘焦点、空方案和恢复状态分别取证；不能截取加载态代替就绪页面。真实开关和步进操作须即时反馈并由Core确认，姓名／邮箱连续失焦及关闭前仍聚焦的输入不得丢失；渠道密钥保存后不回显，Escape只关闭当前浮层。默认套件选择不得覆盖确切作品选择，不等同安装。设置窗口拒绝作品、插件和通用作者通道。

插件生命周期对照Harness源码合同，覆盖并发启用、依赖加载、停用、替换与卸载的串行顺序；不得重复注册或被迟到启用复活。清理倒序尝试全部项，重复清理共享同一完成或失败结果，拒绝晚注册；后端清理失败须返回可诊断且不含私密细节的错误，不静默报告成功。

`core/tests/media_works.rs` 验证素材／线索的不可变作品归属、未归属旧记录、同根对象隔离、固定管理导入和原键恢复、正文／素材引用越权、分页游标与撤权；`core/tests/media.rs` 保留1.0历史及原字节、权利、CAS合同。插件媒体来源另验证真实修订／摘要、同作品约束、旧修订固定及缺插件导出。该机器验收不代替媒体播放、完整解码、音画核对或目标系统性能验收。

`apps/desktop/tests/media.spec.ts` 通过真实CLI准备固定媒体导入、元数据和线索方案，GUI仅驱动作者决定；真实MCP回读同一记录。界面核验来源、历史权利与当前权利、刷新不漂移、线索的固定旧素材、精确交接、作品切换与重开。开发包装配和依赖同一调试可执行文件的桌面测试串行执行，避免重建影响正在启动的机器进程；测试启动失败须记录子进程错误，不将解析空stdout误记为业务失败。

媒体预览另验证固定WorkRef与素材修订／摘要、未归属旧素材和同根越权拒绝、句柄上限与关闭、非法范围、原字节变动、分块预算及未就绪拒绝。真实Electron测试使用可解码图片、WAV与MP4，检查等比显示、播放时间推进、seek后继续、旧地址撤销和插件会话隔离；截断媒体须出现可恢复失败。测试生成的小样本不代替大媒体性能、所有编码、完整音画审阅、作者选用或Windows验收。

导入与交付须验证精确授权的动态发现、inline原字节与目标固定、小说目录CAS、剧本分集原子提交、跨作品正文／设定／素材／线索及未归属旧包拒绝；保留早期工作区合同回归。CLI／MCP准备、作者批准、原Agent执行、原键重放及撤权分别验收。Electron展示完整导入正文、转换损失、固定交付清单与结果，批准不执行；原包核验只证明实际文件完整性。文稿和审阅包不能代替成片或制作工程验收。

文稿版本须在同根小说、多个剧本及旧工作区Git历史下分别验证：独立引用首提交无父、无他作品文件／备注，状态和未选择变更不泄漏兄弟作品；非法路径、旧快照、任意commit和外部替换引用拒绝。提交保留真实HEAD、index、当前正文及未保存稿。作者批准不执行，准备后正文／头变化拒绝；批准与执行丢回执分别沿原键恢复。真实CLI准备、Electron完整差异审核、无窗口执行、稳定MCP历史回读、历史稿接续和重开恢复贯通，保留既有工作区Git回归。

长章节须超过1MiB，含中文和emoji，按UTF-8边界跨页后逐字节一致；两侧长度不等、空侧、非法偏移、分页不前进、摘要变化及完整审核总预算分别覆盖。作者批准不得依据截断差异；历史页固定同一commit、path与摘要，继续阅读不改当前稿。无数据类型及空权限插件须有CLI／MCP和真实桌面闭环：声明的只读计算可用、数据工具不可发现且调用拒绝、重开复用有效绑定、撤权后计算拒绝、重新授权产生独立绑定。

插件数据迁移须覆盖目标Schema校验、完整前后预算、对象CAS、方案摘要、只写权限不能回读旧内容、跨作品拒绝、自报批准拒绝、原键冲突、撤权及再授权不继承批准。普通保存不得跨Schema版本，迁移后旧包只读旧历史；旧来源保持固定。`core/tests/extension_migrations.rs`核验这些事务约束，插件宿主另验证只读动作不能借迁移写入、旧预览token与作品变化拒绝、作者批准丢回执后仍使用同一方案恢复。数据索引重建、批量升级和生态分发单独验收，不由单对象迁移推定完成。

插件标题检索及派生索引须覆盖中文／英文标题、类型筛选、固定分页、查询与授权绑定、同根作品和插件隔离、受限类型集合、撤权及再授权、保存与迁移后的过期状态、缺失与损坏缓存回退、重建不改权威文件、返回对象核验和超预算拒绝。CLI与真实MCP须发现并调用相同检索／状态／重建动作；只读后端动作不能借缓存维护绕过效果限制。JSON元数据投影的通过不表示SQLite、全文检索、批量升级或生态分发已交付。

插件成果工作面另验：超过一页的实际对象、搜索及空结果、继续翻页、搜索变化与迟到响应、旧游标过期、固定版本导出、复制、跨作品切换和停用／卸载后读取。AI交接固定当前插件和所选对象版本，错误摘要及跨作品对象拒绝；不借用通用小说管理动作。开发包须核验同版源码、制品和签名，使用随包CLI／MCP回读确切对象及索引；并行源码变化导致装配拒绝时不能登记为通过。

## 插件大结果传输边界

输入与结果同时超出MCP结果预算时，真实MCP测试必须沿原请求复用说明合成投影，核对原输入与完整结果SHA，并从原规模Unicode文本分块读回；不得缩小输入、提高结果预算或用CLI补读冒充MCP分页成功。恢复说明须完整保留原业务参数和作用域绑定；CLI仅用于独立核对相同完整结果。

- 使用超过MCP双份JSON预算的真实插件读结果，沿摘要提供的动态读取入口恢复Unicode全文及固定引用，核对CLI完整结果SHA。
- 超预算受管写入仅创建一个对象和操作；恢复入口须指向原键与原调用指纹的操作查询，分页、跨CLI/MCP和进程重启均不重放原写动作。
- 对managed_write、未知effect及插件自报read的投影请求须在插件分派前拒绝；不产生Core写回调。
- 新Core接到旧manager缺少投影版本标记、错误能力摘要或不允许的effect时，必须在真实子进程调用前拒绝；用隔离manager记录证明专业分派次数为零。仅测试TS dispatcher不能覆盖新旧资源混装。
- 错结果摘要、同键异输入、错误作品、停用、升级及撤权不得返回成功投影；保留旧回执与原输入，不换键补写。

分派单元、真实manager/runtime、Core路由及稳定MCP集成分别取证。放大传输预算、仅用CLI取全文或静态声明generic invoke为read，均不能替代该门槛。
