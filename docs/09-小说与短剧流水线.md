# 小说与短剧流水线

核心做结构转换，不生成台词、镜头描述或新剧情。节点来自固定源文，作者可人工补标，外部 Agent 只能提交待审补充。

## 1. 剧情节点

节点种类为 `action, dialogue, scene, conflict_candidate, foreshadow_candidate`。共同字段为稳定 ID、类型、原文引用、人物／地点／时间引用、提取方法、确认状态及缺失前提。

原文对话可以作为只读来源证据引用，但骨架不自动把它改写成新台词。因果边只有作者标注或明确结构来源才能进入已确认图；基于模式得到的边仍为候选。

节点集合以不可变提取修订保存，作者校正产生新修订。源文变化后旧集合仍能回溯，但新骨架必须显式选择是否重提取及如何迁移人工校正。

## 2. 分集与分场

输入为节点修订、设定集修订、作者分集锚点及可选目标集长。算法优先保留作者标记，按地点、明确时间变化与场景边界分组，按稳定顺序输出。分集可以依据节点数与原文字数给出候选切点，实际时长和戏剧节奏由作者确认。

机器入口的 `episode_options.episode_start_node_ids` 为按原著顺序排列的分集起始节点。转换按输入文档顺序、原始字节起止和节点 ID 稳定排序；排除 `dismissed` 节点。章节切换、场景节点以及已确认地点／故事时间／日夜的变化建立分场边界。结构字段只消费 `confirmed` 节点，地点的内外景来自固定设定集；词典候选不会自动进入确认字段。片长估算不参与此确定性分场合同。

| 字段 | 语义 |
| --- | --- |
| `episode_id, episode_number` | 稳定身份与展示集号，重排不换身份 |
| `scene_id, scene_number` | 稳定场次与当前顺序 |
| `location_ref` | 已确认地点或 `null` |
| `interior_exterior` | `interior|exterior|mixed|unknown` |
| `time_of_day` | `day|night|dawn|dusk|unknown` |
| `character_refs` | 已确认出场人物，歧义单列 |
| `plot_node_refs, source_refs` | 节点和原著定位 |
| `missing_fields` | 待作者补充的结构信息 |
| `dialogue, shot_description` | 骨架占位固定为空；作者或 Agent 的内容由独立剧本承载 |

未知地点、日夜或人物必须保留未知，不能为了模板完整猜“内景／日”。预计时长标为估计，不声称达到制片方实际拍摄时长。

骨架只存结构，`dialogue` 与 `shot_description` 固定为空字符串；作者或 Agent 的对白与镜头写入独立剧本草稿，不写回这两个占位字段。`status=complete|partial` 继承剧情提取覆盖；结构字段是否完整由 `missing_fields` 单独表达，不能将转换完成理解为制片稿合格。

## 3. 编辑与草稿填充

作者可拖动场次、拆分、合并和修改结构。每次操作记录来源映射与结构修订，不直接改原著。手工编写保存为作者写作稿，不要求提交 Draft；Agent 生成先进入不可变参考稿，由作者采纳后形成写作稿。Agent 提交必须引用 `skeleton_id`、骨架修订及设定集版本，目标结构变化时返回冲突或创建明确的分叉参考稿。二者均由作者针对已保存正文独立定稿，见[15](15-人工审核与审计.md)。

重新生成骨架先预览差异，不覆盖已有剧本或已确认的人工分场。对新源文采用三方比较：旧源文／旧结构、当前作者结构、新提取候选。无法确定的映射留待作者处理。

`build_skeleton` 每次创建新的 `skeleton_id`，不会替换既有骨架。作者编辑以修订和 SHA-256 双重 CAS 写入同一骨架的新修订；历史文件与父摘要链保留。拆分保留左侧集／场 ID，右侧分配新 ID；相邻合并保留左侧 ID，重排只修改展示序号。跨场重复映射同一节点会被拒绝，移出场次后的节点仍在原著和剧情修订中。手工新增空场有明确的 `source_mapping` 缺项。

骨架内容位于 `packages/drama/skeletons/<skeleton_id>/<revision>.json`；`.hetu/skeletons/<skeleton_id>/` 保存修订摘要索引和 `head.json`。读取固定修订核验原文、剧情、设定集及父修订摘要。骨架与索引、回执、审计在同一可恢复工作区事务内保存。

作者通过 `hetu.drama.create_script` 将指定 `skeleton_ref={skeleton_id, revision, sha256}` 建为独立 Fountain 文档。输入还包括作者填写的标题、`language_tag=zh-CN|en` 和原操作键。每次创建新文档，不覆盖已有稿件；读取历史骨架建立文档时保留该历史基线及当前性提示。创建不等于审核通过或定稿。

结构正文只有标题页、分集 section 和场景标题。已知内外景使用 `INT.`、`EXT.` 或 `INT./EXT.`；未知内外景使用 Fountain 强制场景标题的 `.` 前缀。未知地点显示“地点待补充”／`LOCATION UNSET`；未知日夜不写 `DAY` 等词。中英文仅决定模板标签，不翻译作者标题或地点名称。台词、动作、镜头、人物提示、来源摘录和改编批注均不写入结构正文；不能直接表达的换行或控制标记返回 `hetu.format_unrepresentable`，不静默修改字段。

`packages/drama/mappings/<document_id>.json` 保存不可变结构映射，`.hetu/script-mappings/<document_id>.json` 保存摘要索引。每场绑定稳定集／场 ID、初始正文修订、标题原文和 UTF-8 半开范围；初稿和固定骨架共同确定来源。`hetu.drama.get_script_mapping` 重新核验内容与映射，正文新修订、骨架 head 或上游变化单列过期原因。旧范围只用于查看固定初稿，不当作新正文的场景定位；不会通过场号或相似文本偷偷迁移映射。

## 4. 反向诊断与回写

差异类别为 `added, omitted, reordered, modified, unmapped, stale_source`。分别显示原著证据、骨架位置、定稿剧本修订和作者已接受的改编说明。

结构对比入口固定 `skeleton_ref={skeleton_id, revision, sha256}` 与按原输入顺序选择的 `source_revisions`。`added` 为没有节点映射的人工场次，`omitted` 为未纳入骨架的原著节点，`reordered` 比较已映射节点的相对顺序，`modified` 比较地点、内外景、日夜和人物与确认标注的差别，`unmapped` 展示尚未形成节点的原文范围，`stale_source` 标明所选原著修订与骨架基线不同。代码、HTML 与 Fountain 标题页排除范围不当作原著删减。

该入口不判断剧本对白语义，不自动把旧节点定位到改写后的原文；三方映射与剧本差异须使用明确映射合同另行处理。报告保存在 `packages/drama/comparisons/<comparison_id>.json`，索引位于 `.hetu/comparisons/`。`save_result=false` 不保存报告、索引或操作回执；保存需原操作键。单份骨架和差异报告均限制为 16 MiB，超预算阻断写入；输入剧情为部分结果时，骨架与差异响应均保留 `partial`。

小说心理描写过重、缺少可见动作、动机线索不足等为影视化候选问题；不能由它们直接推出“应当删掉”或自动补情节。

“回写原著”仅指作者确认后创建原著的新修订，不能把短剧版本覆盖为新的 IP 正典。改变设定集的事实仍须经过设定集解锁与作者编辑流程。改编例外可以保存在对应剧本中，不能静默修改全 IP 规则。

## 5. 最小完整案例

输入两章已有文本，作者确认人物林舟与地点旧宅，第二场日夜未知。抽取保留动作和对话原文范围，生成一集两场；第二场显示“时间待补充”，台词和镜头栏为空。作者手工填写剧本并审核，导出包含所选原著修订、两场骨架、定稿剧本与映射报告。

验证应断言：没有新增无来源剧情、没有自动填台词、未知字段保留、章节改写使旧报告过期、重建不覆盖人工编辑、纯手工路径全程可用。
