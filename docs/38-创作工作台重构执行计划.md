## 1. 目标与范围

新增已采纳的插件优先桌面重构，目标由[39](39-Electron与插件优先重构架构.md)拥有：Electron＋TypeScript插件宿主＋Rust Core，插件使用JS/TS/React。先完成全部受影响文档及检查，再完整开发。原生保留必要维护和业务/数据对照；作者确认的 Mac UI/UX 为完整还原基准，新增工作包为R6。

从“小说内附带短剧”改为“创作库中的小说、剧本、视频独立关联”。外部 Codex 等 Agent 通过 Skills + CLI/MCP 筹备、整理、创作、预演、生成、剪辑与回传，作者在河图阅读、观看、发现细节、提意见、比较、取舍及确认。作品内容、固定来源、历史修订与作者决定可持续接续。

本轮到可交付成片和完整工程包为止，包含音画字幕、局部返工、源工程依赖及接收方核验。原R1～R5不包含发布投放、运营、Windows实施、移动端、云协作或完整桌面三维/多轨台；新增R6包含共同Electron宿主和Windows平台验证，专业界面通过按需贡献接入，仍不扩展为完整DCC/NLE。官网更新包含中英文产品表达、使用文档、博客和截图，不扩大为云作品后台建设。

2026-11-16 的机器接口专项按作者要求先推进共享 Rust Core、CLI、MCP、Skills 和本对话 Codex 的机器交互，该专项不实施界面迁移。作者本轮要求完善文档并完整实现 Electron 重构，按 R6 继续；R2-04 与 R5-02 的目标界面在新宿主验收。已有 SwiftUI 制品与截图保留原版本范围，不作为新宿主证据。

“创作库”是软件总入口；“书库”仅用于小说分类。独立对象不等于强制独立目录或 Git 仓库，不重建已有作品，不因导航改造搬目录、改 ID 或重算历史摘要。修复机器接口和 Skills 是交付的一部分，不能用临时脚本直写受管记录来补验收。

## 6. Skills、MCP 与 CLI 的交付要求

- Skills 唯一源按筹备／导入、小说、剧本、资产、预演、视频、音画剪辑、审阅返工、交付组织，复用通用定位、授权、固定修订及恢复方法。型号技巧是可核查的能力 profile，不把每个模型或场景复制为整套工作流。
- Skills 中间脚本用于格式辨识、分批、编排和验证，通过公开业务动作提交；不能直写 `.hetu`、伪造作者身份或批准、静默扩范围或用固定演示文件硬编码成功。整书原稿导入依据作者在当前会话的真实指令登记固定范围，按原授权连续执行，不要求桌面逐批批准；不扩展为采纳或定稿权限。
- CLI 与 MCP 使用同一应用用例和权限，发现、准备、执行、查询、反馈及恢复均可机器调用。明确对象、完整任务引用与版本，跨对象读取另获权；稳定连接不绑定全局当前项目。
- 已知目标从精确引用恢复，无作品时从公开筹备入口开始；任务回读必要上下文、已有工作稿、候选和意见。缺能力返回准确错误并修复公共入口，不能让模型猜动作名或改用GUI补链。
- MCP Apps 在已支持宿主中局部观看、比较和写意见；保存、请求继续、消息受理与实际返稿独立取证。无Apps或无消息能力时，复制同一引用继续，数据和操作不另建。
- 视频和外部工程不塞进文本Draft；媒体文件走有界上传／inbox与固定清单，MCP返回必要元数据或受管预览。凭据不进Prompt、参数日志、作品和交付包。
- 方法及分发包从唯一源生成；仓库源、安装插件缓存和App随包内容分别核对版本摘要，不以改完源码证明当前Codex已加载新Skill。
