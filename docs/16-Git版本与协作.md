# Git 版本与协作

Rust 内核通过固定版本的 `git2`／libgit2 管理独立的 IP 内容工作区。本地快照动作由 Mac 版本管理页、C ABI 与受控 MCP 工具共用。具体可调用动作以内核 `contracts/actions.json` 为准。

## 1. 仓库范围

用户可将一个 IP 工作区初始化为独立仓库，绑定自己的 GitHub／Gitee 远端。新建项目默认不自动 init、commit 或联网。已有仓库需检查真实根和嵌套关系，不能将上级软件仓库误认成当前 IP 仓库。

快照范围包括根目录 `.heturc.json`、`.gitignore`、`.gitattributes`、`README.md`、`LICENSE`，以及 `shared/`、`packages/` 和持久 `.hetu/` 业务元数据。排除 `.hetu/transactions/`、`.hetu/cache/`、`.hetu/git/`、`.hetu/operations/`、`.hetu/audit/`、`.hetu/deliveries/`、工作区锁、`exports/`、`.git/` 和 `.DS_Store`；新作品的 `.gitignore` 同步排除本机控制记录。交付暂存、意图与恢复回执即使被外部工具暂存，也不进入河图快照；导入原件和来源报告仍属于可版本化资料。未跟踪且被 Git 忽略的文件不纳入快照。原操作回执及本机恢复日志不进入 Git，以免自提交回执持续制造新变更。媒体大文件显示大小并允许用户配置外部存储／Git LFS；V1 不宣称内置 LFS 上传完整支持。

## 2. 本地快照

1. 检查未保存缓冲、正在运行的事务及仓库状态；作者选择保存或取消。
2. 显示本次文件、文本 diff、二进制大小、备注和目标分支，阻止包含凭据的已知字段。
3. 冻结 HEAD、工作树文件摘要、所选路径与提交身份，取得本次作者确认。
4. 在锁内复核后构建独立暂存树，只提交本次所选内容，不污染用户已有 index 暂存选择。
5. 创建 commit 并更新分支引用，保存原操作结果；记录提交 ID 和未纳入的变更。

工作树状态直接比较 HEAD 与磁盘内容，不将仅暂存区差异误报为待提交内容。文本 diff 每侧最多 1 MiB；二进制或超限内容仅返回大小。快照单文件上限 16 MiB，所选读取总量上限 128 MiB；目录枚举上限 100000 项，单次选择最多 10000 项。已保存正文以外的编辑缓冲仍由编辑器单独保护。

Mac 的“待审快照”支持分页、重新打开与固定差异；已执行快照以 Git 提交与执行记录核验后显示原提交；陈旧且未执行的快照保留审阅记录，但不能继续批准。初始分支、提交身份和备注由作者填写；界面说明姓名与邮箱会进入 Git 历史。版本历史按固定 HEAD 分页，HEAD 变化使旧游标失效。

“快照”是 Git 提交，不是自动保存或系统备份。初次提交没有父 commit 时明确展示；提交失败保留工作树，不执行 hard reset 或丢弃编辑。

独立定稿和参考稿采纳不自动创建快照。外部任务的完整 Prompt、候选 inbox、未采用建书筹备和浏览器会话不默认纳入快照；作者需要版本化特定协作资料时先预览外发内容和来源范围。已采纳正文的来源记录及 FinalizationRecord 随对应作品事实保存，配对材料、会话秘密和动态端口始终只留本机。

批准记录位于工作区外的 `~/Library/Application Support/Hetu/Authorizations/`，绑定 workspace ID、工作区与 `.git` 的设备／inode、快照原字节摘要和作者身份，有效期 15 分钟。移动路径不借此提升权限；复制工作区、克隆仓库或复制记录不能沿用原仓库实例批准。仅作者入口可批准，Agent 请求不接受批准布尔值或作者模式。私密审核决定的原始 Git diff 只对作者开放，Agent 读取公共审核投影。

## 3. 分支、切换与合并

分支创建、切换、合并分别预览并确认。切换前处理未保存正文与脏工作树，不能自动 stash 后把内容藏起来；需要 stash 时作为显式独立能力评估，不作 V1 隐式行为。

合并采用三方比较。普通 Markdown 显示 base／ours／theirs；JSON 使用字段视图辅助人工审阅，但禁止数组拼接式自动合并角色、规则、审核状态或设定集锁。合并完成必须执行 Schema、引用与来源完整性检查，冲突未全部解决不得创建完成提交。

原始不可变修订若同 ID 出现不同内容属于完整性冲突，不能选择“最后修改时间较新”自动覆盖。设定集锁和作者例外合并后必须重新确认，不能利用远端解锁扩大本机 Agent 权限。

## 4. 远端与凭据

支持标准 HTTPS 与 SSH 远端 URL，不把 Token 拼进 URL。HTTPS 凭据保存在系统凭据库；SSH 使用用户授权的 agent 与 known-host 校验。首次主机身份与变化需要用户核对，不能自动信任所有 host key。

远端配置显示服务、仓库、方向与分支，不保存完整凭据。首次绑定远端不自动推送，拉取不自动覆盖本地文件；禁止执行仓库携带的 hooks、过滤器、自定义 transport 或任意脚本。

## 5. 同步操作

| 操作 | 预览与确认 | 失败处理 |
| --- | --- | --- |
| fetch | 远端 URL、refs 与联网目的 | 不改工作树，保留已取得对象 |
| pull | fetch 后的实际本地／远端差异、目标 HEAD | 非快进进入显式合并，不自动 rebase |
| push | 远端、目标 ref、确切 commit 与将外发文件 | 默认禁止 force，非快进返回冲突 |
| merge | 当前和来源 commit、影响路径 | 保留冲突与本地改动，支持取消回到原状态 |

本地内容推送就是内容外发，作者需确认范围。绑定远端的长期读取权限不能替代每次 push 的内容确认。V1 不提供受保护分支绕过、强推、远端删除或自动发布。

## 6. 未知与恢复

push 超时或中断后记录目标 ref、期望旧值、新 commit 和原操作 ID，通过重新查询远端 ref 判定结果；本地未收到成功不能推断远端没更新。核对不明时保持 `unknown`，不自动重发。

本地 commit 先写对象并持久化，再保存包含完整原回执的执行日志，最后以引用 CAS 发布；发布后的持久化或回执失败返回 `unknown/result_unknown`。恢复核验提交身份、时间、备注、父提交和完整 tree，并以当前分支／后代关系或准确 reflog 标记确认发布，不能仅相信日志中的 published 字段。批准已经过期但原提交已发布时，仍可沿原键确认原结果，不再创建新 commit。若发现第三方同时操作仓库，返回冲突并保留证据。

## 7. 冲突界面与安全

冲突界面显示文件、类型、各版本及未解决项；接受所选块后保存合并草稿，先校验再完成。用户可保留两份作为分叉文档，但必须分配新 ID 并修正引用。

历史正文不被 UI 渲染为脚本或可执行链接。秘密扫描只能发现已知模式，不能保证没有敏感内容；真正边界仍是精确外发预览与作者确认。Git 功能验收使用专用夹具仓库及显式授权的测试远端，不触碰真实作者仓库。
