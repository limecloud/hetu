# Agent 与 Codex 插件集成设计

本章定义从河图洛书软件发起、由外部 Agent 完成生成、回到河图洛书展示与验收的协作合同。用户旅程见[26](26-用户故事与用例.md)，图示见[23](23-业务流程与MCP时序.md)，数据和动作分别由[29](29-数据字典与Schema设计.md)、[30](30-应用API详细设计.md)维护。

## 1. 职责与入口

河图洛书以作者自主写作为桌面默认流程，外部 AI 协作按需进入。作者主动请求构思、起草或改稿时，从软件选择自己使用的客户端，复制任务提示词，在该客户端与 AI 对话并生成内容。河图洛书负责作品管理、任务准备、上下文约束、参考成果展示、作者编辑、验收与定稿。

既有正文的 AI 改稿固定所选原文、基线和修改目标，Prompt 可包含作者要求保留的语气、视角与表达。结果以独立参考稿返回；作者可只阅读、自行重写或明确采纳所选内容。保存正文、接收候选或完成局部选择均不触发自动改写，也不要求使用 AI 才能继续创作。

| 组件 | 拥有的责任 | 输出 |
| --- | --- | --- |
| 河图洛书原生软件 | 建书表单、任务与 Prompt 模板、作品与版本、展示及作者决定 | 不可变任务、候选对比、写作稿、定稿及交付包 |
| 外部客户端 | 用户与 AI 的对话、模型选择、生成与宿主工具执行 | 参考文本、结构候选、封面候选和完成声明 |
| 专用 Skills | 各创作任务的方法、输入约束、输出格式、工具发现与恢复 | 指导外部 Agent 按河图洛书合同工作 |
| Codex Plugin | 在支持的 Codex 表面分发 Skills 与 MCP 连接定义 | 可安装、可辨识版本的集成包 |
| MCP Server | 当前授权范围内的能力发现、读取、候选提交和回读 | 结构化结果、资源与原操作回执 |
| MCP Apps | Agent 会话内聚焦的候选选择、比较、批注与预览 | 选择记录或待作者确认的意图 |
| 本地交互网页 | 必要时在内置浏览器展示较大的局部任务 | 与 Apps 和桌面共享的任务投影 |
| Rust Core | 权限、修订、事务、独立校验和业务记录 | 唯一可持久化的业务事实 |

河图洛书不实现 Agent Runtime、聊天窗口、模型路由、自动对话循环或生成 API。复制提示词不等于已经发送；安装扩展不等于已经连接；结果收到不等于采纳；采纳不等于定稿；定稿不等于发稿。

## 2. 软件引导与客户端选择

首次进入书库时提供“设置 AI 协作”和“直接开始创作”。未安装 Agent 不阻断建书、编辑或交付。设置中的“AI 协作”页持续可达，保存本机默认客户端；单次任务可改选客户端，切换不会迁移作品事实或丢失历史候选。

引导顺序：选择客户端及实际使用表面 → 查看对应扩展来源、版本和能力 → 用户在客户端完成安装及连接 → 按宿主要求开始新会话 → 执行只读接入检查 → 回河图洛书复制当前任务 Prompt。接入检查可在没有作品时使用有界的建书筹备范围，不要求先编造书名或创建空白正文。

| 客户端 | 河图洛书的接入方式 | 安装与验证边界 |
| --- | --- | --- |
| Codex | 优先 Codex Plugin，包含专用 Skills 与 MCP 连接定义 | 按桌面／CLI 等实际表面给指南；官方插件目录、仓库渠道和本地安装分别验证 |
| WorkBuddy | 适配该产品的 Skills 包与自定义 MCP 连接器 | 不复用 CodeBuddy 的路径或假设相同 transport；按实际版本给引导 |
| Claude Code | 专用 Skills 与 MCP 配置 | 按目标版本验证 Skill 位置、命名空间及 MCP；可选原生封装不改变共享方法 |
| 其他 Agent | 有明确能力和输出约定的兼容适配 | 无 MCP 时使用任务文件交接；不宣称未验收的功能可用 |

安装来源、包版本、启用状态、Skill 发现、MCP 连通和 Apps／浏览器／图像能力分别展示。用户手动勾选“已完成”只记为用户确认，不能显示为技术检测通过。只有作者显式执行安装时才管理所选客户端的套件文件或调用官方安装入口；不隐式修改其他配置、开启浏览器权限或启动生成会话。

### 2.1 作品关联与题材套件

创建作品时选择客户端和题材套件；作品资料中的“AI 协作”可查看和更改。选择作为本机逐作品偏好保存，不写入小说领域资料，也不授予任务权限。“AI 协作”设置中的默认客户端只影响新作品；既有作品未关联时保持手工创作。任务可显式改选，已经准备的任务保留自身客户端和输入。

套件是覆盖整个创作流程的题材分发单位，例如军事、末世、无限、都市日常、古风世情、双主角关系等。每包包含八个任务入口、共用创作工艺及本题材增量；只安装作者为当前作品选定的包，不附带其他题材整库，不要求额外安装通用包。完整平台分类目录留在河图，用于按平台、频道、主子类与标签查找；标签不等同独立 Skill，也不因选择平台而全量安装。套件身份与分类出处见 `integrations/catalog.json`；它的 `pluginName` 定位 `integrations/codex/<pluginName>/`，各包 `plugin.json` 拥有版本事实，`hetu-suite.json` 拥有题材身份。

作者既可手工筛选，也可让 Codex、Claude Code、WorkBuddy 等外部 Agent 引导定位。共用选择器可复制含有限套件目录与作者输入的选型请求；外部 Agent 区分平台、读者频道、主要体验、叙事机制、篇幅与CP约定，返回套件ID和理由。河图校验目录内ID与建议格式，展示理由；作者显式选用后再在共用安装窗口安装。已有建书构思候选可回填题材，并作为目录匹配的依据。目录匹配明确标注未进行AI分析，不自动改选或安装。软件不接入大模型API、不托管模型密钥、不内置模型调用循环。

原生客户端随附完整方法包，并支持查看包目录和安装说明。Codex 检查当前 `CODEX_HOME`（未设置时为 `~/.codex`）中匹配套件的缓存和 `config.toml` 明确启用配置；仅发现缓存时显示“包文件已发现”，多个候选版本要求选择实际目录，不猜当前加载版本。也可为所选客户端和题材指定实际包目录，核对 manifest、题材身份和各 Skill 文件；手选目录只提供文件证据，不证明已安装。WorkBuddy 等客户端不读取 Codex 配置或推测其专有安装路径。

“安装 Skills 套件”在 AI 协作设置、作品资料、创建作品与封面协作入口共用安装界面。安装前显示客户端、题材和目标；作者可以先安装再创建作品，也可以在已有作品按需安装。Codex 经官方 CLI 的 `plugin marketplace add`、`plugin add` 安装，再用 `plugin list --json` 回读安装、启用和版本，并核对完整包文件摘要。套件来源保存在本机应用数据目录，不依赖开发者 checkout。失败保留来源和客户端原登记，不把启动命令当作安装成功。

Codex 自动发现按本机 PATH 和固定客户端位置检查候选入口，并有界读取脚本首行，跳过解释器已不存在或 `env` 无法在 PATH 找到运行时的候选。入口预检不启动 CLI，不证明插件命令或版本兼容；安装仍以作者操作后的官方回执为准，不修改全局 PATH 或系统 Node。

WorkBuddy 文件安装适配依据本机 5.2.6 制品中 `createSkillsService`、`resolveWorkbuddyConfigDir` 和 `scanSkillsDirectory` 的静态核对：使用 `WORKBUDDY_CONFIG_DIR` 或 `~/.workbuddy[-instance]` 下的 `skills/`，支持选择实际配置根目录。仅复制所选包的任务方法、题材方法和许可；题材 Skill 名称按套件区分，避免不同作品使用的题材包重名。安装后回读完整文件，不改账号、其他设置或伪造市场元数据；已有不同内容时保留原文件并报告冲突。文件安装通过不代表 WorkBuddy 当前会话已经加载；对应版本的实际宿主加载与任务 MCP 仍分别验收。

界面分别显示本机包版本、随附版本、Codex 本机启用配置、检测来源和时间，以及 Skills 文件完整性。版本采用当前 manifest，不用旧 lock 或缓存目录名覆盖；版本不同显示差异。当前会话加载和任务 MCP 连通须在对应客户端另外验证，不能由本机配置或文件存在推导成功。连接按任务单独准备，不在随附方法包中固化作品目录、开发者机器路径或全书库授权。

没有选定作品或建书筹备时，可检查扩展是否可见，但 MCP 范围显示“待选择任务”；不为完成连通检查扫描整库或伪造空工作区。首次建书先保存筹备，再按该 project scope 授权和检查；创建作品后重新授予作品范围。

## 3. 建书前的协作

“创建小说”表单允许书名、简介和大纲尚未确定。作者可以只输入题材、一个想法、目标读者或故事偏好，选择“帮我构思”，再复制提示词到所选客户端。

每次建书筹备具有独立 `CreationProject` 身份，保存于本机应用数据目录；它不属于既有小说，也不授予整座书库的读取权限。外部 Agent 只得到这次筹备明确提供的信息。书名、简介、卖点、故事方向和大纲分别展示候选，作者可跨候选选取字段并自行修改。

作者点击“创建小说”时确认目录与最终表单值，内核创建独立作品，记录字段来源与原筹备引用；外部 Agent 不执行创建。失败保留筹备和候选，同键重放不生成第二本书。建书成功后任务关联到确切作品，筹备历史仍可追溯。

封面可以在筹备期探索，正式选用需绑定已创建作品。筹备封面导入时核验原请求、候选摘要及作者确认的书名／笔名；与最终资料不同的图显示差异，不自动成为正式封面。封面专项合同见[34](34-小说封面与Agent协作.md)。

## 4. 专用 Skills 与管理职责

Skills 共享宿主无关的方法正文与结果合同，安装位置、调用语法和宿主工具由适配层提供。按任务分工，不用一个“管理全部小说”的 Skill 获得全书库或任意文件权限。

| Skill 标识 | 触发任务 | 结果与边界 |
| --- | --- | --- |
| `hetu-setup` | 安装后接入、能力检查、恢复已有任务 | 核对实际扩展与范围；不代作者创建作品或开生成任务 |
| `hetu-book-create` | 第一部或新一部小说尚在构思 | 故事方向、书名、简介和初步大纲候选；不写正式作品资料 |
| `hetu-book-profile` | 为已知作品拟书名、简介、卖点 | 逐字段候选与设计理由；不直接更新 Novel |
| `hetu-outline` | 总纲、卷纲、章纲设计与调整 | 带设定及来源引用的大纲候选；不擅自新增正典 |
| `hetu-cover` | 封面设计、候选生成和交接 | 按固定 inbox 提交图片与回执；不能选用封面 |
| `hetu-draft` | 作者主动请求章稿起草或续写 | 独立 AI 参考稿与基线引用；不覆盖正文 |
| `hetu-revise` | 作者主动请求所选原文改稿，或按公开批注返工参考稿 | 固定原文及风格要求，输出独立候选；返工关联父稿，不改正文、旧候选或私密批注 |
| `hetu-drama` | 基于原著及骨架填充短剧草稿 | Fountain 候选与场次来源；不改原著或确认骨架 |

每个 Skill 必须说明：适用任务、已知任务直接继续、窄能力发现、输入基线、候选提交、局部交互、结果未知恢复、交付引用及作者下一步。描述可自动匹配，用户复制的提示词同时明确目标 Skill；不假定各宿主支持同一种 `$skill` 或斜杠语法。

Skill 在外部 Agent 运行。它不包含模型、密钥、动态作品设定或作者授权。无图像能力时输出设计方案和具体缺口，不伪造图片；付费结果未知先查原任务，不自动重复生成。方法更新、插件更新与任务重做是不同操作。

### 4.1 创作方法、题材与来源

中文唯一源位于 `tools/hetu-skills/`：`base/` 维护任务入口、合同、七项工作法和人物、结构、场景、世界规则四项共用工艺，`genres.json` 维护各题材在定位、资料、大纲、起草、改稿、封面与短剧改编中的增量、复核问题和诊断例。独立包自包含，不依赖兄弟包、符号链接或用户另行克隆上游。共享方法只维护一次，分发副本由脚本生成。

平台分类快照与创作方法分开。`platform-snapshots.json` 保留已取证的起点主子类和番茄不同表单字段；`sources.json` 记录固定源码、许可、逐仓取舍及分类证据级别。男频、女频不决定人物性别、视角、CP或剧情套路；末世、无限流等机制有具体资源、规则和连续性方法。复合题材按主要体验选择套件，其他约定随作品与任务保留，不组合安装整个平台所有标签。

起点公开男频分类直接来自官方页面；番茄后台选项为固定commit的公开截图转录，官方说明只用于核对标签维度。起点女生分类页返回挑战页的范围明确记为未核实，不以二手分类表或已有标签数量冒称平台最新全量。来源和需求逐项对照见[写作 Skills 研究](research/10-GitHub写作Skills对照与方法整理.md)。

任务、方法、模板和导航使用中文；协议字段、代码标识、格式语法和原始许可证按需保留原文。外部项目的CLI、自动写回、Git、发布、记忆库和强制多Agent调度不进入河图工作流。方法不能扩大 `input_refs`、`edit_scope` 或候选交付权限；Core仍拥有作品事实，作者决定采纳和定稿。

`tools/sync-writing-methods.py` 离线生成所选题材独立包及软件目录，`--check` 核对可复现结果。`tools/verify-skills.py` 验证入口、来源许可、文件摘要、本地链接、分类映射、可达性、安装预算和典型选型。完整性目录包含任务方法与题材方法，残包不显示完整。方法更新推进包版本，不覆盖同版本不同内容。

## 5. 任务提示词与成果交接

河图洛书通过本地模板和作者输入组装 Prompt，不调用模型生成 Prompt。复制前可预览和编辑外发内容；新增上下文须重新确认范围。

| Prompt 内容 | 要求 |
| --- | --- |
| 客户端与 Skill | 与本次选定宿主适配，显示适用包及版本；不编造安装命令 |
| 任务身份 | 固定 task_id、任务类型、建书筹备或单部作品范围 |
| 作者意图 | 当前要求、候选数量、明确约束及可讨论的问题 |
| 输入上下文 | 作者确认的资料快照、设定／正文固定引用与基线；不默认附全书 |
| 结果合同 | 候选类型、格式、固定提交位置或精确 MCP 动作，以及原任务查询方式 |
| 权限边界 | 只提交参考成果；不创建正式作品、不改设定、不定稿、不 Git 递交 |
| 交互增强 | 有能力时打开该任务的 Apps 或本地页面；缺能力时文本交接 |

同一不可变请求可重复复制。作者修改要求后形成新任务修订或关联的新任务，不覆盖外部正在处理的输入。相同任务可以接受多个可区分的候选批次；每批具有独立 submission_id 和原操作键。

优先通过已发布的 MCP 候选提交动作返回；无相应能力时按任务指定的 inbox 写文件。只使用当前构建实际发现的动作，不能让 Skill 调用文档中的设计动作后假报成功。文件交接须先写完整候选，再原子写完成清单；Core 独立核验身份、格式、路径、摘要和引用后展示。

软件的可观察状态为“任务已准备”“提示词已复制”“等待外部结果”“结果已收到”“部分结果”“需处理”“已关闭”。外部生成中的百分比、开始时间和运行状态不从复制事件推断；如展示宿主自报进度，明确标为外部报告。

## 6. MCP Apps 的局部交互

优先标准 `_meta.ui.resourceUri`、`ui://` 资源与 `text/html;profile=mcp-app`，使用 SDK 桥接及能力协商。App 的 `ui/initialize` 是 UI 桥接握手，与 MCP Server 协议发现分别管理。

| 面板 | 合适的局部操作 | 不产生的效果 |
| --- | --- | --- |
| 建书构思 | 选择故事方向、书名或简介候选，填写补充要求 | 不创建正式小说 |
| 大纲比较 | 比较卷章安排、选择节点、提出修改意见 | 不更改正典或覆盖现有大纲 |
| 封面比较 | 等比看图、放大、比较文字及裁切意图 | 不自动选用正式封面 |
| 参考稿审阅 | 展示固定版本 diff、批注和采纳意图 | 不将模型调用当作者定稿 |

选择需显式保存为 `InteractionDecision`，包括任务、候选、修订、选中项和意见；视图本地状态不充当业务事实。保存经同一 Core 用例重新验证权限与 CAS，Agent 后续回读原任务才能知道实际选择。

App 不读父窗口 DOM、宿主 Cookie 或任意本机目录，不接触供应商凭据。资源 CSP 默认禁止外部加载，按确有用途的来源逐项开放。`visibility`、只在 App 显示按钮或模型看不到 `_meta` 都不能替代服务端授权。

用户点击“回到对话继续”时，只有宿主实际支持且用户明确要求才使用消息桥接；默认提供补充 Prompt 供用户复制。界面保存、消息请求被接受和 Agent 实际继续是三个独立结果。最终定稿、设定变更及正式封面选用在河图洛书可信原生入口完成。

## 7. 按需本地网页与内置浏览器

需要较大画布、多图对比，或宿主不支持 Apps 但具备浏览器能力时，作者可以启动河图洛书随软件提供的 Node.js 本地交互页面。它可在河图洛书的内置 WebView 或外部 Agent 的内置浏览器打开；后者需实际能够访问本机回环地址。云端浏览器不能假定可访问用户本机。

Node.js 仅提供局部任务页面和受限动作代理，调用 Rust 应用用例，不读写业务文件作为第二存储，不运行 AI。Apps 与本地网页复用同一 HTML、数据合同和双语文案；本地页面以官方 AppBridge 承载沙箱 iframe，再经配对 HTTP 与原生私有 stdio 转发，不依赖浏览器自带 `window.openai` 或 MCP 桥接。

本地服务仅在显式启动后监听 `127.0.0.1` 的动态端口；无全网监听、公开隧道、任意文件服务器或通用 Shell。页面入口绑定原任务，普通 URL 不授予业务权限。浏览器首次打开先显示配对等待，作者在原生端确认该浏览器会话和单任务范围后，建立短期会话；敏感凭据不进入 URL、提示词、命令参数或日志。

HTTP 层严格校验 Host、Origin、会话、CSRF 与动作白名单，不开放通配 CORS。跨作品或任务切换清理旧会话。页面只读取当前任务、保存选择和意见、查询原保存结果；候选仍由既有任务提交工具或结果收件箱接收。浏览器不能获得定稿、设定写入、正式封面选用和 Git 权限；浏览器点击也可能由 Agent 自动化完成，不能用 click 事件证明是作者。

Mac 改稿任务面板提供启动、软件内打开、复制页面地址、浏览器打开和停止入口。作者核对浏览器与原生端的六位码后批准配对，配对请求2分钟过期、已批准会话最多15分钟、实例最多30分钟；服务由发起它的原生任务视图持有，关闭该视图、切换任务或作者停止后释放端口。关闭浏览器标签只结束观察。任务由其他进程关闭时，原生管理器每2秒复核并停止旧页面；旧 Core 句柄在每次业务请求时立即重新核验。

随 Mac 开发包装配 Node.js runtime、许可与页面资源，不要求用户全局安装 Node.js；软件不继承 NODE_OPTIONS、NODE_PATH 或 Agent 密钥。重启页面后重新配对，再从 Core 读取原任务，不重做生成。运行时或浏览器不可用时使用原生任务面板和文本结果，核心编辑与验收不受影响。路由和私有 IPC 合同见[30](30-应用API详细设计.md#18-局部选择与页面会话)，安全要求见[18](18-安全与隐私.md)。

## 8. 协议、插件与 AXI

MCP 基线为 `2026-07-28`，采用 `server/discover` 与每请求版本／能力元数据；legacy 协议单独适配验收。stdio 由宿主管理生命周期，Node.js 页面服务不替代或自动升级为 HTTP MCP。官方 Rust SDK 与工程版本以[14](14-MCP与Agent接入.md)及工程锁定文件为准。

Codex 可移植包采用根 `plugin.json`、`mcp.json`、`skills/`；OpenAI 设置位于 `extensions.com.openai`，兼容 overlay 不与内联设置合并。插件、Skills、MCP 二进制、UI 资源分别版本化；安装后按官方要求开始新会话核对实际加载制品。原生软件安装、插件安装、MCP 授权和公共目录发布分别验收。

AXI 0.2.1 草案用于有界发现、固定上下文、回执、原操作键、CAS 与恢复语义，不替代 MCP、业务权限或提供运行时。借鉴 axi 的 Skills／连接／界面分层，源码构建不依赖相邻 checkout。来源与证据边界见[研究资料](research/README.md)。

### 8.1 插件、本机服务与未来云端

插件只分发方法与连接声明，不内置河图洛书业务服务或保存作品副本。本机 `hetu-mcp` 由软件制品提供，宿主以明确范围启动；连接配置使用实际安装路径与经过验收的参数，不依赖开发者 checkout，也不预设公网 MCP 地址。安装包、连接声明、实际二进制和当前会话发现分别核验。

MCP Apps HTML 可由本机 Server 提供，宿主承担隔离和桥接；官网不承担该本机运行链路。按需 Node.js 页面与 stdio MCP 分开启停，不为连接浏览器而引入云代理、账号或公开隧道。云端浏览器不能访问本机时提供明确回退，不显示虚假的连接成功。

远端 MCP 仅在有明确业务需求时另行设计，其身份与资源范围独立于本机。它不能通过同一插件名取得本机目录、整库或作者身份；切换连接必须重新显示资源位置和授权范围。部署边界以[03第8节](03-总体技术架构.md#8-桌面端与-web-服务端职责)为准。Figma 插件的设计方法及部署差异见[研究](research/08-Figma插件与设计协作研究.md)。

## 9. 兼容性与退出

| 验收面 | 必需证据 |
| --- | --- |
| 客户端接入 | 精确客户端、版本、运行表面、扩展来源与摘要、实际可见 Skills 和连接 |
| MCP | 实际协议、当前 scope、工具／资源、错误与原操作恢复 |
| MCP Apps | UI 版本、桥接协商、结果推送、选择保存、失权和无 Apps 回退 |
| 本地网页 | 实际浏览器及回环可达性、配对、Origin／CSRF、跨任务隔离、重连与停止 |
| 外部生成 | 宿主真实能力、实际文件、结果摘要、来源声明及作者预览 |
| 人工决定 | 采纳不定稿、编辑不丢来源、手工可独立定稿、定稿不发稿 |

仅公布通过验收的组合；“支持 MCP”不能替代 Apps、浏览器或图像能力证据。禁用 Skill、卸载插件、断开连接、撤销作品授权和停止本地页面分别处理；都不删除作品或候选，也不声称已停止外部 Agent 的生成任务。
