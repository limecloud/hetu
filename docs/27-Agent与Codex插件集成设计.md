# Agent 与 Codex 插件集成设计

本章定义从创作库、外部客户端或河图桌面对话开始、由所选Agent通过Skills + CLI/MCP操作、在相应入口阅读观看与审核的双入口协作合同。用户旅程见[26](26-用户故事与用例.md)，图示见[23](23-业务流程与MCP时序.md)，数据和动作分别由[29](29-数据字典与Schema设计.md)、[30](30-应用API详细设计.md)维护。

## 1. 职责与入口

本文的Codex Plugin指外部客户端接入包，分发基础Skills、连接定义及经能力协商启用的MCP App入口；河图专业插件安装在河图，由河图TS宿主管理生命周期。二者分别命名、安装和升级。Agent经稳定CLI／MCP动态发现和调用河图插件，不为每个专业包安装Codex插件或新增工具名，详见[插件21](plugin/21-核心格式与动态能力发现.md)。

河图洛书默认由外部 Agent 通过 Skills + CLI/MCP 联动全软件，桌面端第一作用是可视化 review 与审核，第二作用是作者手动编辑优化。作者在所选客户端表达目标，Agent 负责资料填写、结构整理、任务准备、创作参考与操作执行；河图负责确定性规则、成果与差异展示、必要作者决定和事实保存。建书、卷章、导入、版本和交付等周边操作同样适用，不只覆盖文本生成。

既有正文的 AI 改稿固定所选原文、基线和修改目标，Prompt 可包含作者要求保留的语气、视角与表达。结果以独立参考稿返回；作者可只阅读、自行重写或明确采纳所选内容。保存正文、接收候选或完成局部选择均不触发自动改写，也不要求使用 AI 才能继续创作。

| 组件 | 拥有的责任 | 输出 |
| --- | --- | --- |
| 河图洛书Electron工作台 | 成果、差异、操作提案与作者决定，按页交接，按需编辑 | 与 Core 一致的作品、候选、待审事项、决定及交付投影 |
| 外部客户端 | 用户与 AI 的对话、模型选择、生成与宿主工具执行 | 参考文本、结构候选、封面候选和完成声明 |
| 河图桌面会话宿主 | 承载所选 Agent 的对话、执行事件、审批、停止与恢复 | 会话投影、送达回执及关联任务；不另存作品事实 |
| 专用 Skills | 各创作任务的方法、输入约束、输出格式、工具发现与恢复 | 指导外部 Agent 按河图洛书合同工作 |
| Codex Plugin | 在支持的 Codex 表面分发 Skills 与 MCP 连接定义 | 可安装、可辨识版本的集成包 |
| MCP Server | 当前授权范围内的能力发现、读取、候选提交和回读 | 结构化结果、资源与原操作回执 |
| MCP Apps | Agent 会话内聚焦的候选选择、比较、批注与预览 | 选择记录或待作者确认的意图 |
| 本地交互网页 | 必要时在系统浏览器或可达本机的外部客户端展示较大的局部任务 | 与 Apps 和桌面共享的任务投影 |
| Rust Core | 权限、修订、事务、独立校验和业务记录 | 唯一可持久化的业务事实 |

河图支持外部客户端与独立桌面两种 Agent 协作入口。桌面对话由所选 Agent 引擎执行，Core 不自建推理或自主生成循环；模型工具继续通过作者配置的渠道和固定计划提供。复制提示词不等于已经发送；安装扩展不等于已经连接；结果收到不等于采纳；采纳不等于定稿；定稿不等于发稿。

### 1.1 双入口协作

两种入口均是正式产品目标，作者可独立选择，不要求同时打开两套 GUI。

| 入口 | 完整旅程 | 共享事实与边界 |
| --- | --- | --- |
| 外部客户端，如 Codex Desktop GUI | 在宿主表达目标，MCP App 展示当前任务、候选与意见；经支持的消息桥接继续；完整阅读和编辑可回河图 | MCP／CLI 执行同一 Core 用例；界面资源、消息和可信作者决定分别协商，不因能展示面板就视为全部可用 |
| 河图独立桌面 | 在作品旁表达目标、附加固定上下文、查看真实执行状态、处理审批、停止、比较成果、反馈返工及关闭重开 | 会话适配器驱动所选引擎，作品操作仍使用独立 Agent 身份的 CLI／MCP；无需另开外部 GUI、手动终端或复制提示词 |

独立桌面的自洽指上述旅程在河图内闭合，允许引擎要求浏览器认证、安装或升级；不承诺无账号、无网络也能调用在线模型。引擎缺失、登录失效或版本不支持时展示具体恢复入口，保留作品和对话；手工阅读、编辑及交付继续可用。安装、登录及账号切换遵循明确用户选择，不因点击任务入口静默安装、修改全局配置或切换账号。

一个 CreativeTask 可以关联多个经授权的客户端会话；引擎 thread/session ID 不替代 task_id。切换入口先读同一任务、固定请求、工作副本、公开反馈和原操作；不会默认复制全部聊天，也不保证不同引擎继承对方私有会话。任务转交保留已保存成果和必要的公开接续，另核验新客户端授权；跨入口协同不是强制往返流程。

作者决定始终绑定具体结果、修订和摘要。桌面中的 Agent 不获得可信作者通道；外部 MCP App 只有在宿主声明并实测通过可信决定合同后才能承接相应批准，否则保存提案与意见，再由支持的可信通道完成。两端均不得用模型自报、普通按钮点击或通用 approved 字段扩权。

### 1.2 外部宿主的丰富交互

标准 MCP Apps 为可移植基础，OpenAI MCP Extensions 按宿主实际能力增强，不把桌面文档承诺扩展到CLI或其他客户端。参考[官方指南](https://developers.openai.com/plugins/build/extensions)与[扩展协议](https://github.com/openai/mcp-extensions/blob/main/docs/spec.md)。

| 能力 | 河图用途 | 必须保持的边界 |
| --- | --- | --- |
| 内容提及 `openai/mentions` | 在输入框搜索获权章节、人物、场次和成果，返回固定资源引用 | 搜索只读；无作品授权不列整库或隐藏对象；资源引用不授予权限 |
| 对话／全局入口 | 打开原任务的候选比较与意见面板 | 初始空参数展示共享创作库目录，不选择全局当前作品；正文逐作品核验，全局入口有自己的宿主线程 |
| `ui/update-model-context` | 附加固定选区、任务及来源引用 | 只更新当前 App 实例上下文；不默认传全书，不触发执行，不将隐藏元数据当模型已读内容 |
| `ui/message` | 预览修改请求，准备当前或新对话草稿，或在作者请求后发送 | `target` 和 `send:false` 需扩展能力协商；不能向任意已打开对话注入消息；受理不等于执行或交稿 |
| 插件深链接 | 从河图定位外部宿主内的指定任务面板 | 链接只含非秘密定位；不带 management_ref、凭据或全文；打开后重新核验授权，不因 URL 自动发送或创建任务 |
| 文件查看器 | 查看明确交接的剧本、报告或成果包 | 宿主文件URI为不透明引用；不注册内部 `.hetu` 目录为任意编辑入口，不通过文件写入绕过Core |

资源支持、上下文附加、消息草稿、作者决定及实际返稿分别验收；旧宿主保留标准工具和复制回退。WebMCP、浏览器批注和Appshots可作为可选增强，不能成为两种入口的业务前置。Hooks仅补充上下文或执行观察；云端Work的MCP Events不等于本地Codex会话回调。独立桌面适配器合同由[39](39-Electron与插件优先重构架构.md#43-agent-会话宿主)拥有，实施范围由[38](38-创作工作台重构执行计划.md#双入口协作工作包)跟进。

## 2. 软件引导与客户端选择

首次进入创作库时提供“设置 AI 协作”和“直接开始创作”。未安装 Agent 不阻断建书、编辑或交付。设置中的“AI 协作”页持续可达，保存本机默认客户端；单次任务可改选客户端，切换不会迁移作品事实或丢失历史候选。

引导先选择外部客户端或河图内使用。外部分支：选择或沿用客户端 → 交接适配的接入提示词 → 外部Agent在获权范围内安装并检查扩展 → 按宿主要求开始新会话 → 发现实际能力 → 发起筹备或恢复已知任务。桌面分支：选择引擎 → 核验安装、认证、协议和方法加载 → 建立独立Agent身份的机器连接 → 在作品旁直接讨论与发送；不以安装外部GUI接入包代替桌面适配验收。用户仅在需要选择、权限或安装决定时确认，不负责转抄配置与任务表单；没有作品时不要求先编造书名或创建空白正文。下表描述外部客户端接入，桌面引擎适配另由39维护。

| 客户端 | 河图洛书的接入方式 | 安装与验证边界 |
| --- | --- | --- |
| Codex | 优先 Codex Plugin，包含专用 Skills 与 MCP 连接定义 | 按桌面／CLI 等实际表面给指南；官方插件目录、仓库渠道和本地安装分别验证 |
| WorkBuddy | 适配该产品的 Skills 包与自定义 MCP 连接器 | 不复用 CodeBuddy 的路径或假设相同 transport；按实际版本给引导 |
| Claude Code | 专用 Skills 与 MCP 配置 | 按目标版本验证 Skill 位置、命名空间及 MCP；可选原生封装不改变共享方法 |
| 其他 Agent | 有明确能力和输出约定的兼容适配 | 无 MCP 时使用任务文件交接；不宣称未验收的功能可用 |

安装来源、包版本、启用状态、Skill 发现、MCP 连通和 Apps／浏览器／图像能力分别展示。用户手动勾选“已完成”只记为用户确认，不能显示为技术检测通过。只有作者显式执行安装时才管理所选客户端的套件文件或调用官方安装入口；不隐式修改其他配置、开启浏览器权限或启动生成会话。

### 2.1 作品关联与题材套件

创建作品时选择客户端和题材套件；作品资料中的“AI 协作”可查看和更改。选择作为本机逐作品偏好保存，不写入小说领域资料，也不授予任务权限。“AI 协作”设置中的默认客户端只影响新作品；既有作品未关联时保持手工创作。任务可显式改选，已经准备的任务保留自身客户端和输入。

套件是覆盖整个创作流程的题材分发单位，例如军事、末世、无限、都市日常、古风世情、双主角关系等。每包包含按任务划分的入口、共用创作工艺及本题材增量；只安装作者为当前作品选定的包，不附带其他题材整库，不要求额外安装通用包。完整平台分类目录留在河图，用于按平台、频道、主子类与标签查找；标签不等同独立 Skill，也不因选择平台而全量安装。套件身份与分类出处见 `integrations/catalog.json`；它的 `pluginName` 定位 `integrations/codex/<pluginName>/`，各包 `plugin.json` 拥有版本事实，`hetu-suite.json` 拥有题材身份。

作者既可手工筛选，也可让 Codex、Claude Code、WorkBuddy 等外部 Agent 引导定位。共用选择器可复制含有限套件目录与作者输入的选型请求；外部 Agent 区分平台、读者频道、主要体验、叙事机制、篇幅与CP约定，返回套件ID和理由。河图校验目录内ID与建议格式，展示理由；作者显式选用后再在共用安装窗口安装。已有建书构思候选可回填题材，并作为目录匹配的依据。目录匹配明确标注未进行AI分析，不自动改选或安装。创作分析由外部 Agent 完成；可选模型服务按固定计划执行，作者配置的渠道凭据不向 Agent 返回，不内置模型调用循环。

桌面制品随附完整方法包，并支持查看包目录和安装说明。Codex 检查当前 `CODEX_HOME`（未设置时为 `~/.codex`）中匹配套件的缓存和 `config.toml` 明确启用配置；仅发现缓存时显示“包文件已发现”，多个候选版本要求选择实际目录，不猜当前加载版本。也可为所选客户端和题材指定实际包目录，核对 manifest、题材身份和各 Skill 文件；手选目录只提供文件证据，不证明已安装。WorkBuddy 等客户端不读取 Codex 配置或推测其专有安装路径。

“安装 Skills 套件”在 AI 协作设置、作品资料、创建作品与封面协作入口共用安装界面。安装前显示客户端、题材和目标；作者可以先安装再创建作品，也可以在已有作品按需安装。Codex 以 `plugin list --marketplace <所选市场> --available --json` 核对所选市场来源，经过受管路径、旧缓存与固定目标检查后才开始写入；无关市场损坏不阻断本套件。官方 CLI 的 `plugin marketplace add`、`plugin add` 完成登记，再精确回读安装、启用、版本和完整包文件摘要。空目录不证明同名市场未登记，正式添加仍由官方 CLI 核验来源冲突。套件来源保存在本机应用数据目录，不依赖开发者 checkout。

只读预检失败不进入执行中，可沿原方案继续。开始写入后结果未知时，保留原键，仅回读官方登记与原固定缓存；当前随包升级不阻断旧结果核验，也不允许旧方案改装新字节。无法确认则保留未知，不能换键重试。安装登记与当前会话加载分别验证。

Codex 自动发现按本机 PATH 和固定客户端位置检查候选入口，并有界读取脚本首行，跳过解释器已不存在或 `env` 无法在 PATH 找到运行时的候选。入口预检不启动 CLI，不证明插件命令或版本兼容；安装仍以作者操作后的官方回执为准，不修改全局 PATH 或系统 Node。

WorkBuddy 文件安装适配依据本机 5.2.6 制品中 `createSkillsService`、`resolveWorkbuddyConfigDir` 和 `scanSkillsDirectory` 的静态核对：使用 `WORKBUDDY_CONFIG_DIR` 或 `~/.workbuddy[-instance]` 下的 `skills/`，支持选择实际配置根目录。仅复制所选包的任务方法、题材方法和许可；题材 Skill 名称按套件区分，避免不同作品使用的题材包重名。安装后回读完整文件，不改账号、其他设置或伪造市场元数据；已有不同内容时保留原文件并报告冲突。文件安装通过不代表 WorkBuddy 当前会话已经加载；对应版本的实际宿主加载与任务 MCP 仍分别验收。

界面分别显示本机包版本、随附版本、Codex 本机启用配置、检测来源和时间，以及 Skills 文件完整性。版本采用当前 manifest，不用旧 lock 或缓存目录名覆盖；版本不同显示差异。当前会话加载和任务 MCP 连通须在对应客户端另外验证，不能由本机配置或文件存在推导成功。客户端配置一次稳定的本机 MCP 入口；任务通过精确引用接续，不为每本书或每次返工重写连接。随附方法包不固化作品目录、开发者机器路径或全书库授权。

没有选定作品或建书筹备时，只检查扩展、二进制和协议，不返回作品内容；界面显示“待选择任务”。首次建书先保存筹备，再按该 project scope 授权和检查；创建作品后重新授予作品范围。稳定连接只定位本机已批准的任务，不扫描书库；连接可用与任务获权分别判断，具体合同见第11节。

## 3. 建书前的协作

建书默认从作者与外部 Agent 的对话开始。书名、简介和大纲可以尚未确定；作者只需说出题材、一个想法、目标读者或故事偏好，Agent 发现当前筹备能力，准备资料与创建方案。软件提供当前场景的交接提示，手工新建保留为可选入口。

每次建书筹备具有独立 `CreationProject` 身份，保存于本机应用数据目录；它不属于既有小说，也不授予整座书库的读取权限。外部 Agent 只得到这次筹备明确提供的信息。书名、简介、卖点、故事方向和大纲分别展示候选，作者可跨候选选取字段并自行修改。

Agent 准备完整作品资料、确切目标目录及来源，作者审阅故事方向和创建范围，不重新填写相同字段。Core 固定创建提案，必要决定绑定该提案及当前修订；Agent 在明确授权内通过 CLI/MCP 执行创建，再回读作品身份与回执。失败保留筹备和候选，未知结果沿原目录与原操作键恢复，不生成第二本书。建书成功后任务关联到确切作品；后续读写按新作品范围明确交接，筹备权限不自动扩大。

封面可以在筹备期探索，正式选用需绑定已创建作品。筹备封面导入时核验原请求、候选摘要及作者确认的书名／笔名；与最终资料不同的图显示差异，不自动成为正式封面。封面专项合同见[34](34-小说封面与Agent协作.md)。

## 4. 专用 Skills 与管理职责

Skills 共享宿主无关的方法正文与结果合同，安装位置、调用语法和宿主工具由适配层提供。按任务分工，不用一个“管理全部小说”的 Skill 获得全书库或任意文件权限。

| Skill 标识 | 触发任务 | 结果与边界 |
| --- | --- | --- |
| `hetu-setup` | 安装后接入、能力检查、恢复已有任务 | 核对实际扩展与范围，定位筹备或原任务；不擅自开始创作或扩大权限 |
| `hetu-book-create` | 第一部或新一部小说尚在构思 | 故事方向、书名、简介、初步大纲与完整创建方案；按明确授权创建并回读作品，不自行批准候选 |
| `hetu-book-profile` | 为已知作品拟书名、简介、卖点 | 逐字段候选与设计理由；不直接更新 Novel |
| `hetu-outline` | 总纲、卷纲、章纲设计与调整 | 带设定及来源引用的大纲候选；不擅自新增正典 |
| `hetu-cover` | 封面设计、候选生成和交接 | 按固定 inbox 提交图片与回执；不能选用封面 |
| `hetu-draft` | 作者主动请求章稿起草或续写 | 独立 AI 参考稿与基线引用；不覆盖正文 |
| `hetu-revise` | 作者主动请求所选原文改稿，或按公开批注返工参考稿 | 固定原文及风格要求，输出独立候选；返工关联父稿，不改正文、旧候选或私密批注 |
| `hetu-drama` | 原创剧本或基于固定原著改编，组织分集和场次 | Fountain、分集计划、原著映射及制作依据；骨架可选，视频另关联，不改正式剧本或定稿 |
| `hetu-resources` | 整理人物、地点、物品、灵感与考据并关联使用位置 | 获权资料草稿、来源与引用；不把推测写成正典或修改已采用记录 |
| `hetu-asset-design` | 人物造型、场景、道具和宣传素材设计及外部生成交接 | 固定参考用途、ModelProfile、成组文件候选；仅在任务授权及费用范围内经可发现工具执行固定计划，不替作者选用 |

每个 Skill 必须说明：适用任务、已知任务直接继续、窄能力发现、输入基线、按需读取、工作副本保存、候选提交、反馈接续、结果未知恢复、交付引用及作者下一步。描述可自动匹配，用户复制的提示词同时明确目标 Skill；不假定各宿主支持同一种 `$skill` 或斜杠语法。

任务入口按小说、剧本、视频及本次阶段组织，覆盖原创、改编、已有成果继续和资料设计，共用表中的小型方法。原创剧本可从故事方向、人物和分集计划开始，不要求先有原著、剧情节点或骨架；改编才读取固定原著及来源范围。题材提供创作增量，模型提供能力资料，不按题材、宿主或图片品牌复制整套流程。说明采用渐进加载：入口先说明如何读任务与恢复，具体文体、模型限制和交付模板需要时再读取。

Skill 在外部 Agent 运行。它不包含模型、密钥、动态作品设定或作者授权。无图像能力时输出设计方案和具体缺口，不伪造图片；付费结果未知先查原任务，不自动重复生成。方法更新、插件更新与任务重做是不同操作。

### 4.1 创作方法、题材与来源

中文唯一源位于 `tools/hetu-skills/`：`base/` 维护任务入口、合同、七项工作法和人物、结构、场景、世界规则四项共用工艺，`genres.json` 维护各题材在定位、资料、大纲、起草、改稿、封面与短剧改编中的增量、复核问题和诊断例。独立包自包含，不依赖兄弟包、符号链接或用户另行克隆上游。共享方法只维护一次，分发副本由脚本生成。

平台分类快照与创作方法分开。`platform-snapshots.json` 保留已取证的起点主子类和番茄不同表单字段；`sources.json` 记录固定源码、许可、逐仓取舍及分类证据级别。男频、女频不决定人物性别、视角、CP或剧情套路；末世、无限流等机制有具体资源、规则和连续性方法。复合题材按主要体验选择套件，其他约定随作品与任务保留，不组合安装整个平台所有标签。

起点公开男频分类直接来自官方页面；番茄后台选项为固定commit的公开截图转录，官方说明只用于核对标签维度。起点女生分类页返回挑战页的范围明确记为未核实，不以二手分类表或已有标签数量冒称平台最新全量。来源和需求逐项对照见[写作 Skills 研究](research/10-GitHub写作Skills对照与方法整理.md)。

任务、方法、模板和导航使用中文；协议字段、代码标识、格式语法和原始许可证按需保留原文。外部项目的CLI、自动写回、Git、发布、记忆库和强制多Agent调度不进入河图工作流。方法不能扩大 `input_refs`、`edit_scope` 或候选交付权限；Core仍拥有作品事实，作者决定采纳和定稿。

`tools/sync-writing-methods.py` 离线生成所选题材独立包及软件目录，`--check` 核对可复现结果。`tools/verify-skills.py` 验证入口、来源许可、文件摘要、本地链接、分类映射、可达性、安装预算和典型选型。完整性目录包含任务方法与题材方法，残包不显示完整。方法更新推进包版本，不覆盖同版本不同内容。

## 5. 任务提示词与成果交接

河图洛书通过本地模板和作者输入组装 Prompt，不调用模型生成 Prompt。复制前可预览和编辑外发内容；新增上下文须重新确认范围。

| Prompt 内容 | 要求 |
| --- | --- |
| 客户端与 Skill | 与本次选定宿主适配，显示适用包及版本；不编造安装命令 |
| 任务身份 | 已有任务携带稳定 task_id、确切请求修订与摘要；从零筹备使用实际新建入口，不虚构任务；管理操作携带明确对象或提案引用 |
| 作者意图 | 当前要求、候选数量、明确约束及可讨论的问题 |
| 输入上下文 | 目标、已确定事实、目录与摘要入口、获权固定引用；原文按需读取，不默认附全书 |
| 已有工作 | 工作副本及最新已保存修订、已提交批次、公开反馈、缺项与下一步；没有则明确为空 |
| 结果合同 | 候选类型、格式、固定提交位置或精确 MCP 动作，以及原任务查询方式 |
| 权限边界 | 分别声明读取、草稿维护、操作准备和获权执行；作者采纳、设定采用与定稿需确切决定，不授予通用作者身份 |
| 交互增强 | 有能力时打开该任务的 Apps 或本地页面；缺能力时文本交接 |

同一不可变请求可重复复制。相同目标的讨论、偏好和返工保留 task_id，公开反馈追加记录；作者补充资料、调整基线或授权时发布新的不可变请求修订。改变作品范围或另起创作目标时才建立关联新任务。新修订不覆盖旧输入、工作副本或候选，也不允许旧请求继续写入；版本规则见[30第23节](30-应用API详细设计.md#23-持续协作与任务接续合同)。每个提交批次具有独立 submission_id 和原操作键。

优先通过已发布的 MCP 候选提交动作返回；无相应能力时按任务指定的 inbox 写文件。只使用当前构建实际发现的动作，不能让 Skill 调用文档中的设计动作后假报成功。文件交接须先写完整候选，再原子写完成清单；Core 独立核验身份、格式、路径、摘要和引用后展示。

软件分别展示交接、工作副本保存、候选提交和作者反馈。可观察状态包括“任务已准备”“提示词已复制”“参考稿已保存”“候选已提交”“部分结果”“等待补充资料”“意见已保存”“已关闭”；它们不组成强制线性流程。外部生成中的百分比、开始时间和运行状态不从复制事件推断；如展示宿主自报进度，明确标为外部报告，不混入 AXI 操作状态。

## 6. MCP Apps 的局部交互

优先标准 `_meta.ui.resourceUri`、`ui://` 资源与 `text/html;profile=mcp-app`，使用 SDK 桥接及能力协商。App 的 `ui/initialize` 是 UI 桥接握手，与 MCP Server 协议发现分别管理。

| 面板 | 合适的局部操作 | 不产生的效果 |
| --- | --- | --- |
| 建书构思 | 选择故事方向、书名或简介候选，填写补充要求 | 不创建正式小说 |
| 大纲比较 | 比较卷章安排、选择节点、提出修改意见 | 不更改正典或覆盖现有大纲 |
| 封面比较 | 等比看图、放大、比较文字及裁切意图 | 不自动选用正式封面 |
| 参考稿审阅 | 展示固定版本 diff、批注和采纳意图 | 不将模型调用当作者定稿 |

选择需显式保存为 `InteractionDecision`，包括任务、候选、修订、选中项和意见；视图本地状态不充当业务事实。保存经同一 Core 用例重新验证权限与 CAS，Agent 后续回读原任务才能知道实际选择。

App 不读父窗口 DOM、宿主 Cookie 或任意本机目录，不接触供应商凭据。资源 CSP 默认禁止外部加载，按确有用途的来源逐项开放。`visibility`、只在 App 显示按钮或模型看不到 `_meta` 都不能替代服务端授权。

用户点击“按此修改”时，先保存绑定确切成果的公开反馈，再预览要交给 Agent 的任务、成果和反馈引用。仅在宿主本次实际声明且验收了消息能力时，经标准消息桥接请求继续当前对话；可用的模型上下文更新只传递精简引用，不能代替继续消息。无能力、拒绝或发送失败时提供“复制继续提示词”，不丢意见、不重复保存反馈、不尝试向其他会话发送。普通本地网页没有宿主桥接时直接走复制路径。

“意见已保存”“已请求继续”“收到后续成果”分别由 Core 回执、宿主响应和新成果证明。请求被接受不证明 Agent 已开始或完成；不因一次等待超时再次调用生成。Agent 接续先回读任务当前修订、反馈及已有稿件，再维护原工作副本并提交新候选。最终定稿、设定变更及正式封面选用在河图洛书可信原生入口完成。

### 6.3 与独立桌面共享工作台界面

MCP App与Electron使用同一React表现组件、Radix语义样式、品牌及山水资产。共享层位于`packages/workbench-ui`，承载创作库页头、类型导航、搜索与状态筛选、列表／封面布局及封面预览；组件只消费投影和回调，不读取文件、授权或Electron桥接。桌面适配器使用私有IPC，MCP适配器使用AppBridge和原精确作品引用，不以两份相似CSS维持一致。

全局App入口通过共享Core读取桌面同一`creative-library.json`位置登记中的作品目录投影；尚无桌面登记时，才从当前客户端有效的有限新建记录发现作品。目录只包含作品身份和已缓存的展示资料，不包含正文、任意目录、私密路径或作者权限。选择具体作品后使用该客户端已有的有效`management_ref`重新核验；未授权作品保留在目录中，明确交接精确作品接入，不能因目录可见而授权正文。授权撤销、位置替换、目录损坏与读取失败分别呈现，不把错误或未绑定作品显示成整库为空。已绑定作品和任务入口仍保持原精确范围；宿主缩放、系统选择器和可信作者决定由各端能力承担，不能将Electron的`window.hetuDesktop`直接暴露到MCP页面。消息草稿在作者点击后显示，不占据初始创作库。

完整功能验收按以下旅程核对，不能以通用字段展示或页面入口代替：

| 工作面 | 页面必须完成的往返 |
| --- | --- |
| 创作库与作品资料 | 相同页头、分组导航、山水、封面、筛选及布局；资料与所选作品固定引用一致 |
| 小说与剧本 | 卷章／分集→完整正文→修订／来源；作者稿、已提交参考稿及未提交工作稿分清，旧摘要不套新稿 |
| 视频 | 分集→固定成果→实际媒体预览→前版、意见及交付清单；时间区间按固定time_base交接，不把消息受理显示为已保存 |
| 设定、资料与素材 | 人物／地点等完整内容、版本、资料使用位置、固定图片及原任务审阅；未知专业字段不能静默丢弃 |
| 任务、审核与检查 | 原任务候选、公开意见、返工及原键恢复；审核详情、检查发现和固定依据可打开 |
| 版本 | 当前修改、历史文稿、快照、所选文件差异及分页；历史只读，保留现正文和未保存稿 |
| 导入与交付 | 原固定方案与状态、固定文稿／媒体清单；执行及结果未知在原对话按原操作恢复，作者无需重新录入 |
| 插件与设置 | 安装状态、实际专业能力、非敏感偏好／渠道、固定设置方案；需要内容的专业动作向Agent交接确切能力，不伪造可执行空按钮 |

采纳、定稿、正式版本批准及外发费用继续使用Core的独立作者决定合同。MCP中的交接须携确切对象和范围，不能通过共享UI取得可信桌面作者身份。

## 7. 按需本地网页与外部浏览器

需要较大画布、多图对比，或宿主不支持 Apps 但具备浏览器能力时，作者可以启动河图洛书随软件提供的 Node.js 本地交互页面。它由系统浏览器或外部 Agent 的浏览器打开，均需实际能够访问本机回环地址。河图工作台不提供通用网页浏览入口。云端浏览器不能假定可访问用户本机。

Node.js 仅提供局部任务页面和受限动作代理，调用 Rust 应用用例，不读写业务文件作为第二存储，不运行 AI。Apps 与本地网页复用同一 HTML、数据合同和双语文案；本地页面以官方 AppBridge 承载沙箱 iframe，再经配对 HTTP 与原生私有 stdio 转发，不依赖浏览器自带 `window.openai` 或 MCP 桥接。

本地服务仅在显式启动后监听 `127.0.0.1` 的动态端口；无全网监听、公开隧道、任意文件服务器或通用 Shell。页面入口绑定原任务，普通 URL 不授予业务权限。浏览器首次打开先显示配对等待，作者在原生端确认该浏览器会话和单任务范围后，建立短期会话；敏感凭据不进入 URL、提示词、命令参数或日志。

HTTP 层严格校验 Host、Origin、会话、CSRF 与动作白名单，不开放通配 CORS。跨作品或任务切换清理旧会话。页面只读取当前任务、保存选择和意见、查询原保存结果；候选仍由既有任务提交工具或结果收件箱接收。浏览器不能获得定稿、设定写入、正式封面选用和 Git 权限；浏览器点击也可能由 Agent 自动化完成，不能用 click 事件证明是作者。

局部页面提供启动、复制页面地址、系统浏览器打开和停止入口。作者核对浏览器与原生端的六位码后批准配对，配对请求2分钟过期、已批准会话最多15分钟、实例最多30分钟；服务由发起它的原生任务视图持有，关闭该视图、切换任务或作者停止后释放端口。关闭浏览器标签只结束观察。任务由其他进程关闭时，原生管理器每2秒复核并停止旧页面；旧 Core 句柄在每次业务请求时立即重新核验。

随 Mac 开发包装配 Node.js runtime、许可与页面资源，不要求用户全局安装 Node.js；软件不继承 NODE_OPTIONS、NODE_PATH 或 Agent 密钥。重启页面后重新配对，再从 Core 读取原任务，不重做生成。运行时或浏览器不可用时使用原生任务面板和文本结果，核心编辑与验收不受影响。路由和私有 IPC 合同见[30](30-应用API详细设计.md#18-局部选择与页面会话)，安全要求见[18](18-安全与隐私.md)。

## 8. 协议、插件与 AXI

MCP 基线为 `2026-07-28`，采用 `server/discover` 与每请求版本／能力元数据；legacy 协议单独适配验收。stdio 由宿主管理生命周期，Node.js 页面服务不替代或自动升级为 HTTP MCP。官方 Rust SDK 与工程版本以[14](14-MCP与Agent接入.md)及工程锁定文件为准。

Codex 可移植包采用根 `plugin.json`、`mcp.json`、`skills/`；根清单拥有插件身份与版本。分发包由同一生成源补充 `.codex-plugin/plugin.json`，供使用兼容布局的客户端读取，并明确 `skills: "./skills/"`；两份清单的名称、版本和说明必须一致，不能依靠客户端安装时补出无版本清单。OpenAI 设置位于 `extensions.com.openai`，存在时不与兼容 overlay 合并。插件、Skills、MCP 二进制、UI 资源分别版本化；安装后按官方要求开始新会话核对实际加载制品。原生软件安装、插件安装、MCP 授权和公共目录发布分别验收。

AXI 0.2.1 草案用于有界发现、固定上下文、回执、原操作键、CAS 与恢复语义，不替代 MCP、业务权限或提供运行时。借鉴 axi 的 Skills／连接／界面分层，源码构建不依赖相邻 checkout。来源与证据边界见[研究资料](research/README.md)。

### 8.1 插件、本机服务与未来云端

插件只分发方法与稳定连接声明，不内置河图洛书业务服务或保存作品副本。本机 `hetu-mcp` 由软件制品提供，宿主启动稳定入口；每次业务调用显式携带获权 task_ref，由本机授权映射解析范围。连接配置使用实际安装路径与经过验收的参数，不依赖开发者 checkout，也不预设公网 MCP 地址。安装包、连接声明、实际二进制和当前会话发现分别核验。插件打包规范允许包含 MCP 声明，不代表当前安装的包一定已包含或当前会话已加载。

MCP Apps HTML 可由本机 Server 提供，宿主承担隔离和桥接；官网不承担该本机运行链路。按需 Node.js 页面与 stdio MCP 分开启停，不为连接浏览器而引入云代理、账号或公开隧道。云端浏览器不能访问本机时提供明确回退，不显示虚假的连接成功。

远端 MCP 仅在有明确业务需求时另行设计，其身份与资源范围独立于本机。它不能通过同一插件名取得本机目录、整库或作者身份；切换连接必须重新显示资源位置和授权范围。部署边界以[03第8节](03-总体技术架构.md#8-桌面端与-web-服务端职责)为准。Figma 插件的设计方法及部署差异见[研究](research/08-Figma插件与设计协作研究.md)。

## 10. 资料与制作方法的分发

资料整理、设计与生成交接分别是任务方法，不按 GPT Image、Gemini、Midjourney、Qwen、Seedream 复制五份相同 Skill。共用任务正文与合同放在唯一源目录，模型差异作为按需读取的资料，题材只提供真实增量。封面 Skill 复用图片设计、文件核验和来源方法，封面选用仍走 BookCover。

资料 Skill 先区分已知事实、作者选择与待确认提案，再关联已有设定；设计 Skill 固定人物、造型、场景及参考用途，按外部实际能力选择工具或人工交接。真实输出模型、通道和文件保留，不随默认模型改写。生成未知时查原任务，任何重做需有新的明确需求，不能用重试掩盖未知费用。

任务内可连续维护获权资料草稿和候选；必须读回 CAS 与保存结果。采用资料、选择正式素材、改变设定或正文定稿不由 Skill 自行决定。方法与插件更新分别版本化，并通过生成脚本同步 Codex Plugin 和其他宿主方法包，避免手工编辑分发副本漂移。

## 11. 稳定接入与精确任务定位

一次接入的对象是当前客户端使用的本机 MCP 入口，不是某一本书。入口由随软件安装的二进制与客户端适配器提供；stdio 仍由宿主管理，不要求新增后台服务或公网端口。Codex 手工配置以该版本实际的 `config.toml` 或官方 CLI 为准，不把通用 `mcpServers` JSON 当作 Codex 配置。插件能提供声明时复用同一入口；升级后在新会话重新核验。

作者准备任务后，河图保存私有的范围授权，Prompt 只携带非秘密的交接引用与确切请求摘要。Agent 用引用读取该任务的说明和窄能力，再按需读取获权内容。引用不能作为访问令牌；客户端必须同时具有本机授予的访问能力。服务端不接受调用方提供任意目录，不维护可被其他会话覆盖的全局“当前任务”。并行处理两本书时，每个调用、游标、文件副本和原键均明确归属。

首次交接携带 TaskLocator；`open` 返回当前完整 TaskRef 后，后续读写、嵌套候选引用和恢复均沿用该引用，不在 Skill 或面板中删去摘要。TaskLocator 回答“哪项任务”，TaskRef 回答“哪次请求”；作者发布新请求时，Agent 先重新打开并核对变化，不能自行替换旧引用继续保存。客户端适配标识只区分本机登记，不承担身份认证。

接入检查依次回答：所选包是否完整及启用 → 本机助手及合同是否匹配 → 当前新会话实际看见哪些工具 → 能否读取这项获权任务 → 能否写入测试参考成果并回读。检查不能以缓存目录、用户勾选、安装命令退出码或包版本替代后一项；写回检查只使用隔离筹备或测试任务，不触碰正式正文。

## 12. 持续参考稿与按需上下文

| 内容 | Agent 的工作方式 | 正式结果 |
| --- | --- | --- |
| 创作任务内的参考稿 | 在获权工作副本连续保存、比较、返工；Markdown／Fountain 保持可编辑 | 作者要求提交时固定为不可变候选，可多批比较 |
| 人物、场景、资料和设计草案 | 按既有草稿权限 CAS 维护，引用固定资料 | 已采用版本的修改另交提案，不静默替换 |
| 作者正文与已确认设定 | 按获权固定修订读取，提出范围内补丁或设定建议 | 作者独立采纳；定稿另行决定 |
| 图片及附属工程文件 | 外部生成，按任务 inbox 写回并核验 | 媒体候选不可覆盖，正式选用另行确认 |

工作副本由 Core 管理身份、修订、来源与原键。Agent 可通过 MCP／CLI 保存；只有明确提供文件编辑能力时才检出到任务专属临时目录，编辑后核验并导入新修订。检出文件、编辑器缓冲和未完成清单不等于已保存成果；不能直接修改不可变候选、作者正文或正式资料。作者在河图编辑同一参考稿也走 CAS，冲突保留双方内容。提交固定工作副本修订，后续修改不改变已提交的候选。

上下文读取顺序为任务目标与已确定事实 → 获权目录和摘要 → 范围内检索 → 相关原文片段及固定引用。每次返回覆盖、预算和继续入口；摘要标明作者提供、规则提取或 Agent 声明，不冒充原文。读取更多资料不扩大可改范围。Agent 缺材料时记录具体对象、用途和所需范围；作者可提供、缩小或拒绝，获准后发布同任务的新请求及授权修订。软件不自行扩权、不把全书拼进工具结果。

## 13. 讨论、恢复与完成判断

创作讨论留在作者所选Agent会话中；作品持有任务要求、已保存成果、公开反馈、缺项和作者决定。桌面宿主可按29第22.1节保留本机私有会话记录，但不把整段聊天复制进作品或建立第二份作品记忆；外部宿主的私有聊天不自动同步。作者在对话中临时增加的要求若未写回，应在提交说明标出，不能伪装成已确认设定或扩大授权。

重新打开任务或切换客户端时，先发现实际能力，再读取当前请求、最近工作副本、已提交候选、尚未处理反馈及在途原操作。提交结果未知沿原键回查；没有生成能力就说明缺项；已有成果不因丢失聊天再次生成。任务关闭／撤权后停止后续受管读写，保留作者可见历史。完成声明必须列实际保存引用、未完成项及待作者决定，不能把“我已写好”当作保存回执。

真实协作验收从 Codex 新会话完成建书筹备、方向讨论、大纲与资料、首章参考稿、反馈返工及局部采纳，并验证中断恢复、原文变化、撤权和原创剧本／素材分支，详见[19第3.3节](19-测试策略与验收矩阵.md#33-真实-agent-协作验收)。

## 14. 剧本到成片的方法组织

本节定义待完善的方法职责，不代表同名Skill已经安装；实际目录、版本和可用动作必须现场发现。现有通用定位、持续参考稿、反馈、固定素材及原操作恢复复用，不为视频另造平行任务协议。独立对象和机器入口先于方法分发。

| 阶段方法 | Agent负责 | 河图供作者审阅 |
| --- | --- | --- |
| 剧集开发 | 受众与题材、人物目标、冲突、揭示、兑现、分集和改编取舍 | 全剧方案、分集剧本、原著证据及可纠正建议 |
| 制作资产 | 从具体镜头需要组织人物、服饰、场景、道具和声音资料，复用固定版本 | 对象页单人主图、所需多视图、空间参考、版本及统一库 |
| 镜头与预演 | 按问题选择动态分镜或白模，机器构建并渲染外部工程 | 连续预演、声音时机、空间动作、实际工程及局部意见 |
| 型号适配 | 固定具体模型模式、输入职责、顺序、Prompt、画幅时长声音和费用 | 固定方案及实际结果，不能承诺所有型号通用 |
| 视频执行 | 在授权范围执行、查询原任务、收集实际片段和来源 | 实际媒体、技术核验及内容覆盖，不把成功状态当选用 |
| 音画剪辑 | 机器组织片段、配音、音效、配乐、字幕和混音，保存时间映射并渲染 | 实际成片、连续播放、版本对照、区间意见及可接续工程 |

通用剧本写法与Seedance 2.5专用方法分开。型号profile记录官方来源、核验日期、模式与限制；人物一致性、多人互动、复杂动作、对白、镜头接续、夜景和代理参考等按当前任务加载技巧及bad cases。不同题材／角色／背景的方法可复用，不把供应商旧上限当普遍标准，不将高流量与高留存写成可保证的结果。
