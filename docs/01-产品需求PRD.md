# 产品需求 PRD

## 默认交付要求

作者安装河图后，无需额外创作插件即可完成小说、剧本和视频的基本创作、审阅、返工和交付。共享内核、随包基础模块与可选专业增强分别定义，基础功能不因插件目录为空而消失；详见[默认基础产品](39-Electron与插件优先重构架构.md#无额外插件的基础产品)。实际制作由外部Agent与工具承担，接收、可播放及作者认可分别表达。


版本：V1.0；日期：2026-11-24。产品范围、功能需求与发布判据以本章为准。

## 1. 产品定义

河图洛书 Hetu Luoshu 是面向小说、剧本与叙事视频的本地创作工作台。作者决定作品方向，熟悉的外部 AI 推进具体工作，河图让稿件、设定、素材与创作决定持续接续，直到交付。

对外主张：**让 AI 围绕你的作品持续创作。**

核心价值观：**让越来越强的 AI，围绕作者持续积累的作品工作；让每一次生成，都有机会成为可理解、可选择、可继续创作的成果。**

### 1.1 何时值得使用

价值来自减少重复解释、寻找依据、误改和返工，而不是增加生成次数或管理对象。一次性问答、书名发散、临时对白和普通文件修改，当前 Agent 或编辑器足够时直接完成。作者只读已有作品时按需检索，不创建任务、参考稿或成果记录；必要运行日志沿既有隐私策略管理。需要跨会话接续、固定修改依据、比较多个方案或组织交付时，再使用相应作品能力。

长期创作也不必先导入全部材料。先固定当前需要的章节、场次或素材；原著与外部资料保留各自来源，后续按目标展开。产品必须通过真实任务证明它比现有文件夹、Agent和Skills更省接续与核对成本。

### 1.2 创作原则

| 原则 | 产品要求 |
| --- | --- |
| 从当前需要开始 | 片段、人物、一场戏或已有素材都可成为起点；不强制先建完整设定、大纲或上游作品 |
| 选择性保存 | 保存作者指定、业务恢复必需或值得接续的成果；临时讨论、全部聊天和工具输出不默认进入作品 |
| 保护表达空间 | 区分现实考据、已确认虚构设定、探索方案和有意差异；确定性校验不裁决审美 |
| 允许充分委托 | Agent在明确范围和实际auto／confirm策略内连续推进；已在对话表达的决定不要求桌面重复确认 |
| 保留作品控制 | 参考稿、作者稿、所选素材和定稿各有版本；操作成功不等于作者认可 |
| 能够继续与取回 | 换模型、换Agent或停用插件后，已保存的正式稿件可阅读与导出；恢复能力按引擎实际证据说明 |

“有权限执行”“当前目标需要执行”“结果值得长期保存”分别判断。auto不意味着自动建立作品、创建任务、记住全部对话或认可生成结果。作者明确请求保存的作品材料仍应保存，选择性积累不能成为丢弃已请求内容的理由。

### 1.3 范围与入口

核心场景是小说持续写作与返工、剧本持续创作与改编；叙事视频承接分镜、预演、素材与成片。三类作品独立创建、打开和交付，来源按固定版本关联。专业题材与制作工具按需扩展，插件数量不作为产品价值指标。

AI-first表示外部Agent是主要操作入口，人是软件服务的对象。Agent负责理解、规划、创作与工具循环；Core拥有作品事实、事务、CAS、执行策略与恢复。桌面和MCP App提供连续阅读、观看、比较、编辑与反馈；内嵌终端是可选工作面，能力按适配器真实支持展示，不要求所有作者先进入终端。

正常业务经Skills、CLI／MCP完成，Computer Use用于界面验收和确无机器入口的兜底。作品范围不授予任意本机读取权。参考稿与作者稿分离；采纳、定稿、素材选用和真实费用决定使用确切结果，作者已明确决定时由机器执行，不再要求转填表单。Core不自建通用Agent。

### 1.4 可以跳过的路径

| 目标 | 合适的参与程度 | 交付与停止条件 |
| --- | --- | --- |
| 临时问答、起名、试一句对白 | 当前Agent直接完成 | 回答即可，不自动建作品或保存 |
| 查人物、原文、既有决定 | 只读作品 | 返回固定引用及覆盖，不创建空任务 |
| 探索下一场戏或多个方向 | 按需讨论或独立参考稿 | 作者要求保留或需要可恢复长任务时才保存 |
| 在约束下持续写作与返工 | 固定作品及必要来源 | 保留原文、约束和未改范围，回读新成果 |
| 原著改编、剧本到视频 | 关联相关来源与实际素材 | 分别核验文稿、预演、真实媒体与作者选择 |
| 交付确定版本 | 固定所选修订和依赖 | 文件可核验、可取回，发布另行决定 |

本节拥有产品定位和任务分流。领域与接口沿现有Owner维护，不新增意图分类数据库或内置规划Agent；实现与证据分别见20、38和19。

## 2. 问题、用户与价值

| 用户 | 当前任务与痛点 | 河图洛书提供的结果 |
| --- | --- | --- |
| 小说作者 | 多部作品的封面、卷章、设定与进度散落 | 创作库中的小说分类、独立资料、可引用设定集与证据诊断 |
| 改编编剧 | 小说段落难以转换成可讨论的场次 | 有原文映射、缺失项和冲突提示的分集骨架 |
| IP 工作室 | 素材、草稿与定稿混用，交付版本难追溯 | 审核状态、固定版本及有摘要的交付包 |
| Agent 使用者 | 每轮重复提供人设，生成结果难以约束 | 可发现的设定集、草稿工具、校验反馈与权限边界 |
| 短剧创作者 | 制作昂贵，剧本、资产、片段和剪辑返工互相脱节 | 分级预演、固定制作输入、真实音画、版本意见与局部返工 |

首要用户群体为中国的中文创作者与 IP 工作室，同时支持英文创作及跨语言协作。产品以真实章节维护、改编和交付任务的耗时、误报、返工与作者反馈评价体验。

## 3. 产品红线

| 负责 | 不纳入核心 |
| --- | --- |
| 设定集、规则、内容、版本、审核及所选Agent的双入口协作 | 自建通用LLM／Agent推理引擎、未经授权的模型账号托管 |
| 从已有文本抽取带来源的结构与候选 | 自动续写、自动编对白、补充没有来源的情节 |
| 将确认节点排列成结构骨架，保存外部 Agent 的剧本与镜头方案 | 内核自主编剧、导演或生成循环 |
| 固定模型计划、受管工具执行、媒体接收与来源核验 | 默认联网生成、未经授权外发或付费 |
| 可选插件的导入、结果审核合同 | 核心代收算力费、保证供应商版权或稳定性 |

可选商业插件独立发布、显式启用；其网络与费用行为不进入默认开源安装。具体边界见[22](22-插件生态开源许可与商业化.md)。

桌面创作与随软件提供的本机 MCP 是首要交付范围；官网提供宣传、使用指南及发行入口。服务端业务须由明确的作者需求单独立项，不作为 V1 本机功能的前置。职责与实施顺序见[03第8节](03-总体技术架构.md#8-桌面端与-web-服务端职责)和[20第5节](20-实施路线与里程碑.md#5-服务端演进与准入顺序)。

## 5. 用户主流程

从创作库或外部 Agent 开始，按本次目标选择小说、剧本或视频，可从零、继续已有成果或改编；也可先表达想法再由 Agent 整理方向。来源与授权独立记录，无空小说、空剧本前置；引导和导入见[36](36-创作场景与引导流程.md)。

资料准备、剧本编写、分镜和素材设计可以分别开始，不要求作者先走完线性流水线。作者可一次授权外部 Agent 在指定项目内维护未采用资料和协作候选，设定变更、作者正文采纳、正式素材选用及定稿仍独立确认。完整资料设计见[35](35-资料素材与短剧制作资产.md)。

1. 首次从软件交接到所选外部客户端，安装和能力检查由可发现的机器入口配合完成；已有连接直接恢复。书库持续展示已保存作品与待审成果。
2. 作者给出想法或已有资料，Agent 通过专用 Skill 筹备方向、书名、简介、大纲及保存方案，填好结构化输入。作者比较成果并作必要选择后，Agent 经明确获权的新建动作创建独立作品，回读身份与目录；无需返回建书表单重填。
3. Agent 准备设定建议、分卷章节、分集计划及当前写作任务，软件展示结构、差异与待审事项。作者可以直接编辑，也可提出目标及需保留的表达，由 Agent 在固定范围内维护参考稿；理解、规划和生成由所选外部Agent引擎负责，可在外部客户端或河图内嵌会话继续；本地阅读不依赖会话。
4. 外部 Agent 经稳定 MCP／CLI 或固定 inbox 接续原任务，先读目标、已有成果和获权上下文，保存可持续编辑的参考稿。正式提交经核验后成为固定候选，收到参考稿不改变作者正文。MCP Apps 提供局部比较和意见，较大视图可用本地网页；缺增强能力回到原生界面。
5. 作者保存公开意见后可明确“按此修改”；支持的宿主请求当前对话继续，其他情况复制继续提示词。Agent 回读原任务、具体反馈和已有稿件后返工，不因一次意见另建同义任务。缺材料时由作者确认补充范围；不复制整个聊天到作品。
6. 作者可只将候选作为参考自行撰写，也可预览后明确采纳整稿或所选片段，继续编辑；候选来源与实际采纳记录保留。无需使用参考内容即可继续写作和定稿。
7. 原创剧本可直接从人物与分集创作；小说改编按需抽取并校正节点、整理骨架，再手工或通过外部 Skill 起草剧本。设定建议由作者单独确认。
8. 作者对选定的已保存写作稿执行检查并独立确认定稿。定稿绑定确切修订，后续编辑形成新写作稿，旧定稿保留。
9. 需要视频时，Agent 建立独立制作项目并固定关联剧本或其他依据，组织镜头及所需资产；按问题选择动态分镜或白模，作者观看、反馈后再推进代表性真实生成及分组制作。
10. Agent 回传实际片段、剪辑工程、声音、字幕和渲染成片。作者可连贯审片，沿人物、改动或疑点核对并提出具体意见；局部返工回到对应剧本、预演、素材或剪辑环节，旧版不覆盖。
11. 作者独立确认确切成片版本。可选提交 Git 快照、推送指定远端；导出固定修订的文稿、成片和工程包。范围止于交付，不包含发布、投放或发布后运营。

封面可直接导入，或由河图洛书提供与所选客户端适配的 Prompt、作者在外部 Agent 调用配套 Skill 后写回候选目录，再回到河图洛书选用，详见[34](34-小说封面与Agent协作.md)。建书前可以探索封面方向，正式选用需绑定已创建作品。封面设计与其他小说的设定、正文、审核和版本独立。

Git、远端与 Agent 均不是导出的前置条件。纯手工路径不能因没有 Agent 而中断。完整分支与时序见[23](23-业务流程与MCP时序.md)。

## 6. 非功能需求

- 本地优先：核心任务离线；默认不收集正文、遥测或自动上传。
- 数据可持有：UTF-8 Markdown／Fountain／JSON 与普通媒体文件，不依赖私有数据库才能读取原文。
- 无静默覆盖：并发写入、外部修改和过期审核采用版本与摘要检查。
- 可解释：每个问题具有规则、来源、级别、覆盖及证据，不用一个分数代替结论。
- 可恢复：崩溃保留已保存版本与未完成操作，恢复不重新执行未知推送。
- 跨端一致：业务、Schema、错误、状态与测试夹具共享；文件权限、编辑器与凭据分别原生适配。
- 国际化：zh-CN 为默认语言、en 为完整支持语言，机器字段稳定，内容、界面与交付语言独立，见[31](31-国际化与中文体验.md)。
- 性能与规模按明确硬件、测量方式和门槛验收，见[19](19-测试策略与验收矩阵.md)。

## 7. 发布与成功判据

V1 发布需全部 P0 需求的正向、失败与恢复验收通过，FR-17 独立评估。两端分别验收自主写作至定稿交付的完整旅程，以及作者按需发起外部协作、比较参考稿、选择性采纳和继续编辑的旅程。统一执行模式按1.3及FR-43：auto在明确当前工作区内直接执行，confirm固定本次变更集中确认；作者正文、设定、封面选用、采纳与定稿均核对确切目标、修订及真实指令，不得冒充作者身份或把执行成功当成创作认可。任务和窄作品连接不能绕过其实际范围。Apps 至少在一个明确版本的支持宿主通过；其他所声明客户端的无 Apps 路径也必须通过。本地网页、Electron工作台及宿主特有能力分别验收，不能相互替代。

Mac 本期交付必须在真实 Codex 新会话中走完筹备、方向讨论、大纲资料、首章参考稿、作者反馈、返工与局部采纳，并验证恢复、原文变化、撤权、原创剧本及素材分支。内嵌GUI、TUI与外部MCP按声明范围分别核对。预制整书夹具只证明业务协议和格式链路，不替代真实 Agent 协作。Windows、Linux及其他声明平台各自保留构建、运行和安装验收，不能由Mac或共享源码推导；当前进度归[38](38-创作工作台重构执行计划.md)，实现基线与历史证据归[20](20-实施路线与里程碑.md)。

短剧全生命周期另须以真实一集验证分镜、预演、代表性真实视频、音画字幕、局部返工及工程交付；全剧验证按明确覆盖范围分批推进。API 成功、完整解码或几张抽帧均不替代内容观看与作者确认。创作方法旨在改善故事可理解性、节奏与连续性，不保证高流量或高留存。

小说和剧本采用明确的内部源格式、转换报告与交付 profile；文件标准、行业惯例、制片方模板分别标注。格式范围与规范依据见[25](25-小说与剧本标准格式.md)，不将自定义 JSON 或中文短剧模板称为通行行业标准。

试点记录候选采纳率、确定规则误报、诊断覆盖、数据恢复成功与任务耗时；不得用测试集通过率宣传为所有小说的语义准确率。发布必须同时满足许可证、固定工具链、宿主兼容与签名要求。

## 8. 架构选型背景与设计目标

河图洛书需要长期管理本地目录、正文和媒体、设定集修订、Git 冲突、复杂审核及可交付版本。Electron工作台、独立CLI/MCP与创作插件共用可验证的业务、文件事务和恢复底座；Codex 插件承担方法与连接，MCP Apps 承担聚焦的人类检查。

插件优先意味着专业能力按贡献和套件交付，固定组件、动态组合及自由成果共存。宿主保持作品上下文、可信决定和恢复，Core统一身份、授权与事务；插件按需安装启用，缺失时保留成果读取和导出。技术理由见[02](02-架构选型与设计原则.md)，现有适配审计见[插件19](plugin/19-现有架构审计与插件优先重构.md)。

设计目标是正典与生成解耦、内容独立于模型上下文、核心离线、受管入口校验、作者最终决定、版本可追溯及标准格式交付。生成供应商可选，核心仍承担自身依赖、数据完整性与安全责任；设定集锁不替代 OS 或团队权限。

## 9. 技术架构摘要

共享Rust内核负责领域、规则、存储、libgit2与交付；Electron经JSON-RPC 2.0私有App Server接入，独立Rust CLI目标和MCP直接复用应用层。SwiftUI原生客户端与Swift CLI已退役；Electron沿用作者确认的Mac工作台体验。本地 Rust MCP Server 为外部 Agent 提供标准工具与资源，协议采用范围按官方版本和宿主证据冻结。源码采用一个 Monorepo，作者内容工作区独立存放。

IP 正典和文本使用可读 JSON／Markdown／Fountain，索引可用可重建数据库；业务事实不依赖某个模型对话。插件、MCP、AXI 和 UI 资源各有版本和职责，联合设计见[27](27-Agent与Codex插件集成设计.md)，完整架构见[03](03-总体技术架构.md)，重构决定见[39](39-Electron与插件优先重构架构.md)。

## 全软件机器操作与可审阅能力

所有业务能力均须提供可发现、可执行、可回读、可恢复的机器路径，覆盖新建、资料、正文、设定、审核、导入交付、版本、设置和插件生命周期。作者可在当前外部Agent会话表达目标并作出必要决定；桌面用于可视化审阅与可选手动操作，不能成为机器旅程的强制前置。作者已有明确授权时继续完成，不以重复GUI批准消耗作者精力。

产品与AI共同使用[40机器能力地图](40-机器能力地图与Review清单.md)。每项区分源码入口、安装实际发现、专项测试与真实端到端证据；没有界面时也能逐项Review已有能力、范围和缺口。实现进度仍由38维护，不以生成地图冒充功能完成。

## 10. Agent First的产品边界

写作产品的任务分类、上下文引用、编辑工具箱及技能发现是参考，河图的默认流程围绕“表达目标—机器执行—阅读成果—提出意见—继续创作”。人工表单、模型参数面板、工具市场和专业画布均不作为必经步骤。研究事实归[研究14](research/14-编辑阅读与全局体验研究.md#11-写作产品调研与agent-first取舍)，本体与能力归属归[28第15节](28-领域设计与边界上下文.md#15-agent-first-的本体核心)。

本轮范围是复用已有创作模型与专业扩展，使固定上下文、能力发现、统一执行及双入口审阅成为一条连贯旅程；不包含将竞品所有生成器逐项重做，也不新建通用知识图谱、内置Agent推理循环或新的云作品服务。专业功能仅按实际安装与兼容能力提供，方法可以复用共同任务合同。

作者从创作库打开作品后进入作品资料，可直接点击章节／分集进入内容；资料、结构与协作分组均可按需访问，不强迫依次走完。完整内容进入共同阅读／编辑区，常驻目录和按需Agent面板服务当前任务，专业插件在合适位置出现。字体、主题、字号、行高、行宽、缩放和编辑命令在两种入口共用，显示偏好不改变原稿及交付版式。

默认auto允许明确当前工作区内的确定性业务操作；confirm在一次固定变更前集中确认，不逐章重批。采纳、定稿与成片确认保存真实取舍及确切结果；已在对话作出决定时由机器执行，无需回软件重复操作。操作成功、专业检查、完整阅读及作者认可分别报告。发布、安装系统软件和真实付费外发继续遵守本次明确范围，不从执行模式推断额外目标。

FR-41～44的故事、用例和验收分别由26、19维护；本轮完整实施范围、依赖及状态归[38](38-创作工作台重构执行计划.md#agent-first能力组合工作包)。设计可评审、源码可调用、业务可回读与真实宿主可用是独立门槛。
