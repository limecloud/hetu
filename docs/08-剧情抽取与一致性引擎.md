# 剧情抽取与一致性引擎

核心不用 LLM、NER 模型、向量模型或生成服务；算法只从已有文本、设定集、人工标注与明确结构产生证据和候选。

## 1. 输入与处理链

输入固定为所选文档修订、设定集修订、规则集版本、语言配置及资源限额。处理顺序为：格式解析 → 段落／句子／引号边界 → 名称词典与标注解析 → 节点候选 → 作者确认或结构前提核验 → 规则执行 → 诊断与覆盖报告。

Markdown 标题、明确场景标记及说话人标签优先于启发式。解析后的规范文本必须保留到原始 UTF-8 字节的映射，不能用清洗后偏移定位原文。UTF-8 BOM、CRLF、中文引号、破折号、Emoji 和组合字符均需夹具。

## 2. 提取能力与限制

| 内容 | V1 方法 | 无法确定时 |
| --- | --- | --- |
| 已知人物 | 名称／别名词典、最长匹配、人工关联 | 返回多个候选，不自动消歧 |
| 新人物 | 对话标签、称谓与重复专名模式 | 保留文本证据，由作者确认 |
| 场景 | 章节／场景标题、已知地点及显式标注 | `location_ref=null`，提示补充 |
| 对话 | 成对引号、说话人标签与位置关系 | 可提取文本，说话人保持未知 |
| 动作 | 分句与受限动作词规则 | 返回原句候选，不改写动作 |
| 冲突 | 明确冲突标注、对立目标／否定动作模式 | `conflict_candidate`，不声称完整理解 |
| 伏笔 | 作者标签、明确回指与已登记线索 | `foreshadow_candidate`，不能预测后文 |
| 时间 | 显式时间标签、事件 ID、已知相对关系 | 保持未知，不按章节号推导 |

代词、自由间接引语、反讽、梦境、多层倒叙与隐瞒身份不能仅凭词典可靠解决。工具返回 `needs_author_review` 与缺失前提；外部 Agent 可补充结构化候选，但不能绕过证据和作者确认。

## 3. 一致性检查

| 类别 | 确定性条件 | 非确定性部分 |
| --- | --- | --- |
| 身份与人设事实 | 作者确认的实体、断言及有效期直接矛盾 | 性格是否合理、角色是否说谎 |
| 时序 | 显式事件先后成环、互斥区间重叠 | 没有时间锚的段落关系 |
| 世界规则 | 结构前提完整、命中已声明限制 | 隐喻、例外和未知能力 |
| 引用完整性 | 人物、地点、源修订不存在或类型错误 | 同名实体是否同一人 |
| 影视化 | 可统计的心理／叙述标记密度、缺失动作／场景 | 是否有电影感、动机是否充分 |

心理描写比例等阈值由版本化规则集明确配置，输出命中片段与计算方法，只生成 warning。阈值不是行业标准，也不据此阻止文学表达或承诺改编质量。

## 4. 诊断合同

每个 finding 包含 `finding_id, rule_id, rule_revision, severity, certainty, message_key, source_refs, blueprint_refs, evidence, missing_prerequisites, disposition`。建议给出“核对谁／补充什么标注”，不生成替换段落或台词。

报告覆盖对象包括所选文档、已扫描字节、所启用规则、跳过原因、无法解析的段落与预算终止点。未命中问题只有在相应规则前提成立时才算该项检查通过；未执行、未知与不适用分别统计。

自动校验在草稿保存后进行；设定集更新、源文更新或作者消歧触发相关报告过期提示，按需增量重算。缓存键包括所有输入摘要、规则集及引擎版本，不能只按文件路径缓存。

## 5. 作者反馈与外部 Agent

作者可修正人物、场景、时间、忽略误报或接受具体例外。反馈保留原 finding、理由和证据版本；规则变更需要显式操作，不通过后台“学习”修改正典。

Agent 语义建议标为 `agent_suggested`，保留调用来源并与确定性报告分开展示。Agent 声称“检查通过”不能覆盖内核错误、覆盖不足或过期结果。

## 6. 资源与质量

任务具有字节、节点、运行时间、输出数量与取消预算；预算耗尽返回 `partial` 和已覆盖范围，不自动截断后宣布完成。运行耗时、规则命中和缓存指标不携带正文。

提取质量使用人工标注且与规则开发样本隔离的测试集。分别统计实体候选 precision／recall、场景识别、说话人归属、时间覆盖及确定冲突误报；不能以单一“准确率”替代细项。基准与发布门槛见[19](19-测试策略与验收矩阵.md)。

## 7. 剧情提取运行合同

结构、默认预算及上限以 [Plot Schema](../contracts/schemas/plot.schema.json)、[提取输入](../contracts/schemas/plot-extract-input.schema.json)和[作者校正输入](../contracts/schemas/plot-correct-input.schema.json)为机器合同。提取不执行一致性诊断，`coverage.status=complete` 只表示输入范围完成扫描，不表示候选的语义完整或没有问题。

Markdown 使用 CommonMark 语法边界与原始字节等长掩码；代码、HTML、不能直接映射的转义／实体文本记录为忽略范围，不根据清洗后的文本计算位置。Fountain 场景标题、`@中文人物` 与大写拉丁人物提示形成结构边界；未知人物保留带来源的 `unresolved_names`。普通中文行不推断为人物提示。受限动作词、显式伏笔标记与冲突词只生成待核对候选，不建立事实断言。

自动提取的 `entity_refs`、`location_ref`、`time_ref` 与 `speaker_ref` 保留空值；名称词典仅写入候选字段。作者校正可确认或排除节点、绑定固定设定中的人物／势力、地点、事件与说话人，也可从固定原文选区补标节点。日夜由明确场景标题或作者指定；故事时间不依据章节顺序推导。

覆盖数据区分已扫描范围、已输出节点与未解析范围。`budget_stop.byte_offset` 标记未完成的候选或扫描位置；它可能位于已经扫描过、但没有完整输出的段落内。达到字节、节点、匹配、时间或输出限额时返回 AXI `partial`；如果请求保存，部分结果仍作为不可变修订持久化并返回原操作回执。不能更换操作键把部分结果当作失败重复写入。

单条引文不超过 16 KiB，序列化剧情修订不超过 8 MiB。超大段落记录 `segment_too_large`，不能伪称已理解。自动连线仅为待核对的 `narrative_next`；`causes` 由作者确认且不得成环。两类关系均保留原文证据。

## 8. 结构标注与规则执行合同

节点的可选 `annotation` 包含 `context`、`facts[]` 和 `capabilities[]`。语境区分 `actual`、`dream`、`hypothetical`、`reported`、`unknown`；没有标注不能默认实际发生。事实断言为 `subject_ref, predicate, value`，人物必须已关联该节点，谓词和值类型与设定事实一致。同一人物／谓词只能声明一次。能力名称字面匹配；作者启用标注后能力数组为空，表示本段未使用能力。

只有节点已确认、语境为 `actual`，事实／能力才进入确定性检查。梦境、假设和转述记为该结构规则不适用；未知语境记为缺少前提。事实检查还需已关联故事事件，并能证明事件位于设定事实的半开有效区间；缺少可适用事实不判为通过。仅凭人物词典命中不建立事实。

`story_before` 表达作者明确确认的故事先后，区别于叙述顺序和因果。`event_precedes` 对映射到规则事件对的明确故事先后边检查正反关系；没有明确故事先后边时记为未知，不根据章节顺序、倒叙位置或普通叙述连线推断。复杂但未标注的时间关系仍需作者判断。

禁用词对格式解析后可见正文执行有界字面匹配，包括未形成剧情节点的段落；代码、HTML 与无法直接映射的格式范围单独记录。`case_sensitive=false` 忽略 ASCII 字母大小写，不执行 Unicode 语言相关折叠。例外只排除被完整例外词条覆盖的命中范围，不豁免整段。实体限定范围仅检查已确认关联节点，其余正文归属缺口保留未知。规则的包、文档、实体条件同时满足才适用。

`advisory` 产生 `info` 级作者提示；影视化启发式产生 `warning`。规则集 `1` 的心理标记提示阈值为可见正文至少 3 次且每千个非空白字符不少于 10 次，报告保留标记、字数与原文位置；没有场景候选另作提示。这些统计不能证明动机不足、人物性格冲突或文学质量。

## 9. 报告、预算与处置

[执行输入](../contracts/schemas/validation-run-input.schema.json)以保存的 `plot_revision_id` 固定正文、设定集及其摘要，规则集版本为 `1`。报告由 [Report Schema](../contracts/schemas/validation-report.schema.json)约束，包含原提取覆盖、格式扫描范围、启用／执行规则、逐检查单元结论与统计。`passed`、`finding`、`unknown`、`not_applicable` 分开计数，不把统计总数当作品质量评分。没有可用节点、结构前提或规则范围归属时返回具体缺项。

默认预算为 2 MiB 原文字节、10000 个检查单元、1000 条 finding、20000 次词条匹配和 3000 ms；输入上限分别为 8 MiB、50000、5000、200000 和 10000 ms。单文档格式排除范围最多记录 10000 处，完整报告最多 16 MiB。达到限额或输入剧情本身为部分提取时，报告及 AXI 执行结果均为 `partial`，保留已执行单元及终止原因。保存的部分报告也是原操作键的终态回执。

报告存于 `packages/drama/reports/<report_id>.json`，摘要与输入索引位于 `.hetu/reports/`。读取核验报告、剧情、正文及设定历史摘要。当前正文、设定变动或输入剧情已有作者校正分支时，另外计算 `stale_reasons`，不改写历史结论。

[问题处置](../contracts/schemas/finding-disposition-input.schema.json)仅作者可执行，要求报告的完整 `expected_inputs`、当前处置修订、非空理由与原操作键。状态为待处理、已知悉、作者标记误报、作者接受例外；规则的 `exception_policy=none` 禁止接受例外。每次记录绑定原 finding 与固定输入，使用 CAS 并保留摘要相连的不可变历史，报告始终保留原 `disposition=open`，当前处置作为独立投影返回。文件完整性错误阻止操作，不作为可豁免的普通 finding。
