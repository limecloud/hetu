# 架构选型与设计原则

## 架构判断起点

先确认当前任务是否需要作品状态。临时讨论由外部Agent完成；只读、选择性保存和持续返工复用同一Core，不为每条路径另建框架。架构价值用接续、核验与维护成本验证。

产品定位与任务分流见[01](01-产品需求PRD.md#1-产品定义)。

河图洛书采用插件优先的Electron工作台、共享Rust内核和开放Agent接口，围绕作者对内容的持有权、创作自由、离线工作及可追溯交付设计。已采纳的重构决定与迁移边界见[39](39-Electron与插件优先重构架构.md)，实际进度归20／38。

## 1. 设计目标

1. 作者掌握设定集、正式采纳与定稿；外部 Agent 在授权范围内读取资料、维护协作稿及未采用资料、提交候选。
2. 核心写作、规则校验、审核、本地版本和导出不依赖网络、模型或第三方账号。
3. GUI、CLI、MCP 共用应用用例、事务和权限，平台只保留原生交互差异。
4. 文件透明可读、引用稳定、修订可追溯，作者内容与软件源码分离。
5. 简体中文为默认体验，英文具有同等功能覆盖；语言不影响内容身份和版本。
6. 软件引导安装与交接，作者在所选外部客户端对话；专用 Skills 约束回传方式，候选采纳和定稿由作者分别决定。
7. 创作库登记独立小说、剧本和视频；来源关系不成为强制父子层级，工作区不等于小说，跨对象关联不扩权。
8. 人持续参与品味、创意和细节判断；用适合问题的预演降低昂贵试错，用实际音画验证成片，不以模型状态代替结果。

### 1.1 核心价值的设计判据

[产品核心价值](01-产品需求PRD.md#1-产品定义)要求 AI 能围绕持续积累的作品工作。评审功能和接口时，检查以下结果：

- **可积累**：作品事实、固定来源、修订与作者决定保存在作者持有的工作区；模型或会话变化后，可从已有记录接续。
- **可理解**：候选说明所用来源与基线，作者能够查看差异、适用范围及需要重新核对的依据。
- **可选择**：收到候选、反馈、采纳和定稿分别记录；作者可自行重写、局部采用或放弃，既有正文与未保存编辑受到保护。
- **可继续创作**：反馈绑定具体成果，返工沿原任务接续；失败或未知结果按原操作恢复，历史候选与定稿保持可查。

授权、修订一致性、采纳、定稿及恢复属于共享内核的确定性责任，创作方法由 Skills 提供，理解、规划与生成由外部 Agent 执行。桌面界面优先呈现阅读、比较、意见与决定，其次提供作者编辑；结构化资料由 Agent 准备，不要求作者维护内部模型或重新填写对话已有信息。

### 1.2 全软件联动的设计判据

1. **机器入口先于页面流程**：先定义应用动作、范围、输入输出、预览及恢复，再投影到 CLI/MCP、Skills 和界面。建书筹备也可从无作品、无桌面窗口的状态发起，不能要求先在 GUI 制造任务。
2. **操作与决定分开**：建书、整理卷章、导入解析、资料填写、检查和交付准备由 Agent 执行；涉及采纳、定稿或外部副作用时，Agent 准备确切提案，作者只审阅所需决定。需要批准不意味着每一步都要作者操作。
3. **全页上下文交接**：书库、详情、编辑器、资料、审核、版本、交付、设置及异常状态都提供与当前对象绑定的 AI 入口。上下文引用不是授权；交接不自动外发整部作品。
4. **不依赖视觉操控**：Skills + CLI/MCP 完成正常业务。Computer Use 只验证界面或在其他入口均不可用时兜底；机器接口缺失列为缺陷并修复，不能靠点击 UI 通过业务验收。
5. **共享一个状态**：外部 Agent、原生端、Apps 和局部页面读写同一内核事实；界面能看到机器操作的成果、待审项和失败恢复，Agent 能读回作者公开意见与决定。
6. **宿主复用独立引擎**：河图内承载Codex GUI／TUI对话、执行与恢复，推理和工具循环由Codex提供；Core仍组织作品、权限和确定性事务，不自建通用Agent循环。默认使用AI不强迫作者使用AI，手动编辑独立可用。

权限按读取、草稿维护、操作准备、明确授予的执行及作者决定分别建模，不用单一“Agent 一律禁止正式操作”覆盖全部业务，也不提供通用作者提权开关。跨对象、扩大范围、覆盖原文及外部副作用的规则由 Core 检查。合同见[30第25节](30-应用API详细设计.md#25-全软件联动与操作提案合同)，实现准入见[20](20-实施路线与里程碑.md)。

## 2. 技术选择与代价

| 选择 | 设计理由 | 工程代价与约束 |
| --- | --- | --- |
| Rust Core与薄入口 | 复用身份、规则、文件事务、libgit2与交付实现 | 权限、CAS与恢复集中，桌面以私有stdio接入 |
| Electron＋TypeScript/React | 共同Chromium、Web专业组件、跨端宿主与隔离插件容器 | 中文编辑、包体、资源、系统集成和安全更新需实测 |
| Rust App Server＋JSON-RPC 2.0私有stdio | 分离桌面系统与业务内核，避免Electron原生扩展ABI绑定 | 有界消息、握手、错误、生命周期与unknown恢复 |
| 独立Rust CLI | 无GUI复用Core及CollaborationHub，减少Windows运行时链路 | 公开命令、JSON、退出码、授权与恢复回归后才替换 |
| 独立 stdio MCP Server | 宿主按需启动；业务记录独立于窗口和连接生命周期 | 协议库维护、版本协商和宿主兼容需单独验收 |
| Codex内嵌GUI／TUI＋外部MCP App＋专用Skills | 内嵌两表面优先复用受管App Server和固定任务；外部入口继续可用 | Codex优先，其他引擎延后；PTY、输入权交接、协议版本和同版装配须独立验证 |
| MCP Apps＋按需 Node.js 局部页面 | 对话内聚焦选择与必要的大画布比较共用业务记录 | 两种桥接分别适配；回环页面需配对和会话隔离，不增加必装后台服务 |
| 文件为权威，索引可重建；插件首期为JSON标题投影，SQLite待规模评估 | 支持直接备份、Git 审阅与标准交付 | 多文件一致性依赖进程锁、CAS 和恢复日志 |
| 规则提取与可解释校验 | 核心不依赖生成服务，问题可回到明确证据 | 中文自由文本存在歧义，候选、未知与覆盖必须可见 |
| 独立可选多媒体插件 | 网络、费用和供应商适配与核心隔离 | 结果仍需来源、审核和权利状态管理 |

Rust 用于共享内核，利用所有权、类型与 Result 管理内存和失败；unsafe 限制在经过审计的 ABI 边界。系统调用、文件事务、FFI 和业务授权仍需独立验证。文件权威是数据持有与版本审阅的选择，不否认嵌入式数据库的适用性。

## 3. 工作台宿主与创作插件的分工

宿主提供作品上下文、布局、贡献发现、可信决定和恢复状态；小说、剧本、视频及专业工具贡献导航、工作面、动作和方法。第三方Web包进入隔离容器，普通网页、自由HTML成果与可信作者页使用不同会话和桥接。A2UI组合已实现组件，不替代组件、数据和授权。现有原生版保留作业务与数据对照，旧页面与操作步骤不直接成为新产品要求。

默认协作路径由河图内Codex对话操作、作者在作品旁审阅构成，外部Agent经相同机器用例协作。作者可自行改写或明确采纳所选内容；采纳只形成写作稿，独立定稿固定作者确认的修订。基础编辑、保存和定稿仍能独立使用，不要求作者先使用 AI。具体交接与回退见[27](27-Agent与Codex插件集成设计.md)。

选型依据是创作能力的独立交付、共同渲染环境和受管系统接入，不以浏览器不能访问文件或所有动态UI都昂贵作为理由。现有架构审计见[插件19](plugin/19-现有架构审计与插件优先重构.md)，成本推导见[插件01](plugin/01-背景与第一性原理.md)。

## 4. CLI与迁移边界

目标Rust CLI直接调用共享应用层，不调用Electron或桌面作者RPC。CLI分别适配终端、信号和凭据，保持公开命令、JSON、退出码和Agent权限语义。

先更新全部受影响文档，再开发公共贡献闭环与作者旅程，不能只复刻原生页面。切换与退役须取得独立机器入口、插件生命周期、中文编辑和平台制品证据，不长期维护两套完整产品。详见[39](39-Electron与插件优先重构架构.md)和[13](13-内核ABI与CLI合同.md)。

## 5. 工程原则

- KISS：采用本地模块化单体，以完整人工闭环为最小业务切片。
- YAGNI：不预建云账号、实时协作、消息代理、移动端或插件市场。
- DRY：领域规则、Schema、错误、文案键与语义资源各有唯一来源。
- SOLID：领域判断、应用编排、存储、平台与表现职责清晰，接口围绕实际用例建立。

## 6. 创作对象、预演与审阅的取舍

小说、剧本、视频按事实拥有者拆分：正文与对白由各自文稿持有，镜头制作、预演及剪辑由视频项目持有，来源关系固定版本。导航可以独立，不要求新建三个仓库或复制三份正文。旧项目投影到创作库，保留身份与路径；显式迁移另行预演，不将界面改名做成数据搬迁。

动态分镜用于节奏、揭示及声音时机，白模用于空间、遮挡与调度，真实生成用于身份、表演、动作与质感；选择最小能回答当前问题的材料，不强制逐镜白模。作者可随时查看完整成果和未标记位置，不限于 Agent 摘要。桌面提供观看、比较和位置反馈；复杂建模、渲染及剪辑由外部 Agent 的机器工具执行。

预演认可、媒体选用、文稿定稿与成片确认分别记录。媒体生成是有费用且可出现未知结果的外部副作用，不能用本机事务宣称撤销或退款。固定计划、原调用查询和实际媒体核验先于自动重试；适配器能力不足时明确阻断。具体设计见[37](37-创作库与小说剧本视频设计.md)，研究边界见[research/13](research/13-短剧预演视频与人工审阅研究.md)。

参考工程资料见[参考项目设计研究](research/05-参考项目设计研究.md)，架构决策与变更规则见[24](24-文档治理架构决策与风险.md)。

## Agent First的核心准入与复用

优先判断“这是什么作品事实、由谁拥有、已有对象能否表达”，再选择组件或插件。跨工具共同需要且必须保持统一身份／修订的事实归Core；专业规划与分析归插件；提示方法归Skills；布局、字体和可访问交互归宿主。完整准入与反例以[28第14～15节](28-领域设计与边界上下文.md#14-核心准入与用例论证)为准。

KISS要求复用既有固定引用和应用用例；DRY要求正文、设定与作者决定各有唯一Owner；SOLID要求入口依赖公开用例和专业Schema；YAGNI要求不为每个提示词、新模型或菜单名称新增Core实体、万能执行器或平行存储。CAS、事务和恢复是技术保障，不是本体中的创作对象。

借鉴外部产品时先区分人工作流和可机器执行的领域动作。界面分类只能作为发现投影，不能成为写作流程的强制表单。可选插件不阻断基础创作，算法报告不代替真实作者取舍，默认auto不等于自动认可所有生成内容。
