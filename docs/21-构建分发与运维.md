# 构建分发与运维

本章定义独立制品、工具链、构建、签名、安装与升级要求。精确工具链和依赖摘要随发行清单锁定。

## 1. 工具链与独立产物

| 产物 | 工具链路线 | 运行依赖 |
| --- | --- | --- |
| C++ Core／C ABI | C++20、CMake 3.28+、Clang／MSVC | 固定 native 依赖 |
| macOS App | Swift 6 系列、Xcode 与 macOS SDK | 系统框架及随包内核 |
| Windows App | C#、WinUI 3、.NET 10 LTS | 明确的 .NET／Windows App SDK 分发模式及内核 |
| 跨平台 Swift CLI | SwiftPM、共享 Swift Bridge | 必需 Swift runtime、C ABI 与 native 依赖 |
| C++ MCP Server | 与 Core 相同 native 工具链 | Core 及选定协议库，无 GUI 要求 |
| MCP Apps／Codex 插件资源 | P1 前端构建及声明式插件 | 宿主支持，不是核心运行依赖 |

软件 release 清单记录每个产物版本、源修订／树摘要、合同／ABI 版本、OS、架构、依赖和最终 SHA-256。同一发行组合必须兼容，但不强迫用户同时安装 GUI、CLI、MCP 与插件。

## 2. 构建入口设计

先由 CMake 构建 Core、C ABI 和 MCP，再 staging 头文件、module map 与库；SwiftPM 和原生 App 消费固定产物。共享内核不得由不同入口各自下载不同 libgit2 或使用不同构建选项。

工程入口必须提供明确的本地构建、合同检查、资源生成、内核测试、Swift CLI、双端原生测试和打包入口；每个入口说明可运行平台及副作用。使用指南直接引用真实构建入口。

## 3. 支持矩阵

V1 目标 macOS 14+ arm64、Windows 11 x64；Intel macOS、Windows ARM64 和 Linux CLI 在实际依赖与原生验收后单独声明。二进制按 OS／架构分别构建，不能把“Swift 跨平台”当作单包通用或免运行时部署。

Windows Swift CLI 必须在未装 Swift 工具链、.NET 或桌面 App 的环境启动，验证 runtime DLL、native 库路径、Unicode、Ctrl+C 和 JSON 重定向。macOS CLI／MCP 不依赖 Xcode 安装或桌面应用私有资源路径。

## 4. 安装渠道

优先提供签名的原生独立下载包；macOS App 公证，Windows 验证发布者和依赖。安装／卸载只处理软件与用户选择的偏好，不删除作者工作区。

可选 npm 启动器作为便捷渠道：按 OS／CPU 选择精确版本原生产物，以参数数组转发并保留终端、输出、退出码和取消；启动器不承载业务，不执行 postinstall 网络下载或在用户机器编译。npm 不是使用核心功能的必装条件。

Codex 插件是宿主侧的 skills／MCP／Apps 声明与资源，不能代替 native CLI 的安装和 ABI 兼容检查，也不在插件安装时静默获得文件与 Git 权限。

## 5. 升级与数据兼容

应用升级与内容格式升级分开。新程序先读取 Schema 版本，只在支持范围内写入；未知主版本只读。内容升级由作者确认、备份、预演后执行，失败保留原项目。

回退旧程序不能自动降级内容。CLI、GUI 或 MCP 发现正在运行的不兼容写入口时阻止同时写入，提示用户完成／关闭旧任务。运行时授权与凭据不得通过内容迁移传播到其他机器。

## 6. 发布门禁与诊断

固定源输入 → 合同／资源检查 → 测试 → 分平台构建 → 签名 → 干净系统安装 → 完整旅程 → 最终摘要与发布说明。签名后摘要才作为最终制品摘要。

CI 规划先做只读构建与测试，实际外部发布需单独授权。无证书、宿主或目标 OS 时明确 `blocked`，不能以开发包替代正式签名验收。默认不设置自动更新和正文遥测；诊断遵循[18](18-安全与隐私.md)。
