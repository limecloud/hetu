# 总体技术架构

技术选择见[02](02-架构选型与设计原则.md)，总体图见[23](23-业务流程与MCP时序.md)，领域边界见[28](28-领域设计与边界上下文.md)。

## 1. 架构决定

采用本地模块化内核，共享 C++20 业务与应用用例。macOS 使用 SwiftUI/AppKit，Windows 使用 WinUI 3；原生客户端通过 C ABI 调用内核。独立 CLI 采用跨平台 Swift 薄入口，MCP Server 采用 C++，复用同一内核，不要求桌面进程常驻。

核心没有模型推理、提示词生成服务或第三方生成 API 适配器。小说抽取与诊断采用明确结构、词典、规则与作者标注，语义不足时返回候选或未知。

## 2. 分层与模块

| 层／模块 | 责任 | 依赖限制 |
| --- | --- | --- |
| Domain：Blueprint | 设定集、实体、有效期、锁与约束 | 不依赖 UI、网络、Git 或平台 API |
| Domain：Narrative | 源引用、节点、场次与改编映射 | 不直接访问磁盘 |
| Domain：Review | 草稿状态、定稿资格与证据失效 | 不信任调用方自报作者身份 |
| Application | 工作区、校验、改编、审核、导出用例 | 协调事务与小型存储／授权接口 |
| Engine | 文本切分、候选提取、规则执行与覆盖 | 确定性输入输出，不编造内容 |
| Format Adapter | Markdown／Fountain 解析、DOCX／TXT 导入、DOCX／PDF 导出 | 转换为带来源的结构，不把版式类型传入领域 |
| Infrastructure | 文件、进程锁、哈希、libgit2、ZIP | 实现用例所需接口 |
| Platform | Keychain／Credential Manager、文件选择与原生权限 | 平台实现，不复制领域规则 |
| Entry | 原生 App、CLI、MCP | 参数、身份、呈现、任务调度 |

普通数据结构和算法不增加无用途的接口层。只对文件访问、凭据、确认、时钟及外部副作用建立所需窄接口。

## 3. 运行单元

- 桌面 App：持有编辑缓冲、原生窗口、审核身份与会话确认能力。
- `hetu` CLI：统一 Swift 源码，通过 C ABI 独立执行同一用例，提供交互和 JSON 输出；无 GUI 时可手工管理全部核心任务。
- `hetu-mcp`：原生 stdio MCP Server，绑定启动时明确授权的单一工作区与工具权限。
- 可选 MCP Apps 资源：只负责审核呈现，经受管桥接返回审核意图；不访问工作区或凭据。

不引入必须常驻的本地后台服务。跨进程通过工作区进程锁、版本检查与操作记录协调。发现已占用时返回 `workspace_busy` 或只读状态，不抢锁。需要作者确认的 MCP 请求可进入桌面审核队列；CLI 可提供独立交互审批入口，不自动拉起程序或模拟点击。

## 4. 唯一事实源

| 内容 | 唯一拥有者 | 派生物 |
| --- | --- | --- |
| 已确认 IP 事实 | `shared/blueprint.json` | 搜索索引、Agent 上下文与可视化 |
| 正文与剧本 | 文档修订及文档清单 | 剧情候选、检索、差异报告 |
| 草稿与审核 | 草稿记录与审核记录 | 待办计数、审核面板 |
| 分场结构 | 经作者校正的骨架修订 | 可读剧本模板、交付排版 |
| 版本与交付 | Git 对象、Bundle manifest | 历史列表、校验结果 |

派生节点、报告与镜像缓存不能反向覆盖设定集或原著。SQLite 若使用，仅作可重建索引；删除索引不得丢正文、审核或溯源。

## 5. 关键不变量

1. 角色名称可变，稳定 ID 不变；同名与别名歧义必须显式处理。
2. Agent 永远不能直接修改设定集、解锁或自批定稿；解锁也不会扩大 Agent 权限。
3. 草稿持久化与自动诊断分别有结果；诊断失败时草稿仍可查，但不能显示“校验通过”。
4. 定稿绑定确切草稿、设定集、源文、规则与报告版本，输入变化使旧审核证据过期。
5. 所有入口共用路径检查、CAS、事务和权限；绕过 UI 不能绕过用例约束。
6. 已有文件权限的外部工具可以绕过河图 API；产品提供检测，不声称实现操作系统级内容隔离。

## 6. 同仓与扩展边界

原生 App、CLI、MCP、合同与测试同仓，分别产出制品。软件仓库不存用户小说、供应商密钥或商业插件源码。可选插件独立进程、独立授权，结果通过草稿／素材导入入口进入审核。

V1 不为远期插件市场设计热加载 ABI、云账号或动态代码执行能力；MCP Apps 的嵌入式网页不改变桌面核心界面的原生要求。

## 7. 国际化边界

领域对象保存稳定规则键、消息参数与原文证据，平台按 zh-CN 或 en 呈现。公共资源生成平台语言包，格式适配层消费作者选择的交付 profile。界面、作品和交付语言独立，不通过语言切换改写正文，详见[31](31-国际化与中文体验.md)。
