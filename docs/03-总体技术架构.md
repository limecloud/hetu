# 总体技术架构

技术选择见[02](02-架构选型与设计原则.md)，总体图见[23](23-业务流程与MCP时序.md)，领域边界见[28](28-领域设计与边界上下文.md)。

## 1. 架构决定

采用本地模块化内核，共享 Rust 业务与应用用例。macOS 使用 SwiftUI/AppKit，Windows 使用 WinUI 3；原生客户端通过 C ABI 调用内核。独立 CLI 采用跨平台 Swift 薄入口，MCP Server 采用 Rust，复用同一内核，不要求桌面进程常驻。

核心没有模型推理、Agent Runtime、聊天或第三方生成 API 适配器。任务 Prompt 由本地模板和作者确认的上下文组装；作者复制到外部客户端完成对话和生成。小说抽取与诊断采用明确结构、词典、规则与作者标注，语义不足时返回候选或未知。

## 2. 分层与模块

| 层／模块 | 责任 | 依赖限制 |
| --- | --- | --- |
| Domain：Blueprint | 设定集、实体、有效期、锁与约束 | 不依赖 UI、网络、Git 或平台 API |
| Domain：Narrative | 源引用、节点、场次与改编映射 | 不直接访问磁盘 |
| Domain：Creation | 建书筹备、外部任务、候选和局部选择 | 建书前可独立存在；不运行模型或读整库 |
| Domain：Review | 参考稿审核、采纳记录、独立定稿资格与证据失效 | 来源、审核、编辑和定稿分开；不信任自报作者身份 |
| Application | 工作区、校验、改编、审核、导出用例 | 协调事务与小型存储／授权接口 |
| Engine | 文本切分、候选提取、规则执行与覆盖 | 确定性输入输出，不编造内容 |
| Format Adapter | Markdown／Fountain 解析、DOCX／TXT 导入、DOCX／PDF 导出 | 转换为带来源的结构，不把版式类型传入领域 |
| Infrastructure | 文件、进程锁、哈希、libgit2、ZIP | 实现用例所需接口 |
| Platform | Keychain／Credential Manager、文件选择与原生权限 | 平台实现，不复制领域规则 |
| Entry | 原生 App、CLI、MCP、局部页面代理 | 参数、身份、呈现、任务调度 |

普通数据结构和算法不增加无用途的接口层。只对文件访问、凭据、确认、时钟及外部副作用建立所需窄接口。

### 2.1 依赖规则与组合

入口只调用 Application，Application 编排领域策略、Engine 和所需外部接口；Infrastructure 实现这些窄接口，由入口组合并注入。Domain 不调用文件、Git、MCP、Swift 或 Node.js，Engine 不持有可写工作区句柄。编译依赖图见[23第2节](23-业务流程与MCP时序.md#2-内部组件与依赖)，领域事实消费关系见[28](28-领域设计与边界上下文.md)，两者不能混作同一张调用图。

平台凭据只通过完成当前 Git 操作所需的能力进入适配器，不能进入领域记录或返回给 MCP／网页。格式适配器把输入转换为带来源和损失清单的领域输入；版本、权限和是否定稿由应用用例检查，不能由转换器自行决定。

## 3. 运行单元

- 桌面 App：软件主入口，持有建书表单、客户端适配引导、Prompt 预览、编辑缓冲、审核身份与会话确认能力。
- `hetu` CLI：统一 Swift 源码，通过 C ABI 独立执行同一用例，提供交互和 JSON 输出；无 GUI 时可手工管理全部核心任务。
- `hetu-mcp`：原生 stdio MCP Server，绑定启动时明确授权的单部作品或单项建书筹备及工具权限，二者互斥。
- MCP Apps 资源：在支持宿主内展示建书、大纲、封面和参考稿的局部交互，经受管桥接保存选择及意见；不直接访问工作区或凭据。
- 按需 Node.js 交互服务：为河图洛书 WebView 或外部 Agent 内置浏览器提供单任务局部页面，通过受限本机 IPC 调用应用用例；与 MCP Apps 复用组件和业务合同，不保存第二套作品事实。

不引入必须常驻的后台服务。Node.js 只在用户明确需要网页交互时启动，监听动态回环端口，按会话停止；MCP stdio 与该 HTTP 页面服务分别管理。跨进程通过范围锁、版本检查与操作记录协调，建书筹备锁与作品锁各自作用于明确身份。发现占用时返回忙碌或只读状态，不抢锁。需要作者决定的请求进入原生界面；不自动拉起 Agent、粘贴提示词或模拟作者点击。

### 3.1 进程、通道与生命周期

| 运行单元 | 内核接入方式 | 启停拥有者 | 可观察结果 |
| --- | --- | --- | --- |
| macOS App／Windows App | 进程内 C ABI | 作者与操作系统 | 已保存修订、独立作者决定及原操作回执 |
| Swift CLI | 进程内 C ABI | 本次命令的调用者 | 能力目录及结构化回执；自动化调用保持 Agent 权限 |
| Rust MCP Server | 进程内复用 Rust 应用层 | 外部 MCP 宿主 | stdio 请求结果、工具与资源；桌面退出不等于 Server 退出 |
| MCP Apps 页面 | 经宿主 UI 桥接调用 MCP 工具 | 外部宿主的面板会话 | 固定任务投影及局部选择回执；无本地文件句柄 |
| Node.js 局部页面服务 | 受限本机 IPC，由 Core 校验 scope 和动作 | 发起它的河图洛书应用会话 | 已配对任务的查询与选择；停止后端口释放 |

Node.js 的 IPC 是受限应用调用通道，不是作者 C ABI 句柄的远程转发，也不是可传任意 `action/root/actor` 的通用执行接口。具体传输由实现合同冻结，安全不变量以[18](18-安全与隐私.md)和[30](30-应用API详细设计.md)为准。运行部署及信任边界图见[23第21节](23-业务流程与MCP时序.md#21-运行部署与信任边界)。

### 3.2 事务与可观察结果

| 用例 | 共同提交的业务事实 | 成功回执的边界 |
| --- | --- | --- |
| 保存正文 | 新 Revision、Document 当前指针、Operation 与审计 | 已保存修订，不改变旧定稿 |
| 审核参考稿 | ReviewDecision、Draft 状态、Operation 与审计 | 本次参考稿决定，正文及卷章目录保持 |
| 采纳参考内容 | 新 Revision、AdoptionRecord、当前指针及必要章节目录、Operation 与审计 | 已采纳到写作稿，不新增审核决定或定稿 |
| 独立定稿／撤回 | FinalizationRecord、相应定稿指针、Operation 与审计 | 确切修订的确认或撤回，不改当前正文 |
| 导出交付 | 固定输入计划、已核验新产物与可恢复原回执 | 本次产物可核验，不自动上传或发稿 |

锁只保护短时一致性读取与提交；耗时抽取、格式转换和压缩消费固定输入，在提交前重新核验。原键查询先于首次执行的 CAS，读取原回执仍须重新授权。跨卷创建、文件发布与 Git 网络副作用分别按恢复合同处理，不声称它们属于同一个文件系统原子事务，详见[07](07-工作区与持久化设计.md)、[16](16-Git版本与协作.md)和[17](17-IPBundle与素材交付.md)。

## 4. 唯一事实源

| 内容 | 唯一拥有者 | 派生物 |
| --- | --- | --- |
| 建书筹备与外部协作 | CreationProject、任务请求、候选提交与选择记录 | Prompt、Apps／网页投影和通知 |
| 已确认 IP 事实 | `shared/blueprint.json` | 搜索索引、Agent 上下文与可视化 |
| 正文与剧本 | 文档修订及文档清单 | 剧情候选、检索、差异报告 |
| 参考稿、采纳与定稿 | 草稿、AdoptionRecord 与 FinalizationRecord | 待办、来源标签、定稿指针与审核面板 |
| 分场结构 | 经作者校正的骨架修订 | 可读剧本模板、交付排版 |
| 版本与交付 | Git 对象、Bundle manifest | 历史列表、校验结果 |

派生节点、报告与镜像缓存不能反向覆盖设定集或原著。SQLite 若使用，仅作可重建索引；删除索引不得丢正文、审核或溯源。

### 4.1 书库、作品与改编的层级

源码 Monorepo 是开发者维护的软件工程；作者书库是本机作品登记；单部小说工作区才是正文、设定、素材与版本的业务范围。书库不要求多部作品属于同一 IP，也不为它们创建共享设定集或共同 Git 仓库。

小说内的分卷只组织章节顺序，不持有另一份正文。短剧项目独立管理改编方案、分集分场和剧本引用；它消费固定原著修订，不能因同名角色或相同集号与其他项目合并。项目关系见[29第12节](29-数据字典与Schema设计.md#12-实体关系)，多作品操作见[26](26-用户故事与用例.md)。

### 4.2 修改传播与证据失效

正文、设定、骨架或规则更新后，依赖它们的报告与定稿资格按输入快照重新计算当前性。历史报告和历史定稿仍指向原修订，不能改写为新内容，也不能将“过期”显示为“文件损坏”。界面排版、语言、卷章顺序等变更只影响它们实际依赖的投影，不一律触发全文失效。依赖传播图及处理表见[23第24节](23-业务流程与MCP时序.md#24-依赖变化与证据当前性)。

## 5. 关键不变量

1. 角色名称可变，稳定 ID 不变；同名与别名歧义必须显式处理。
2. Agent 永远不能直接修改设定集、解锁或自批定稿；解锁也不会扩大 Agent 权限。
3. 草稿持久化与自动诊断分别有结果；诊断失败时草稿仍可查，但不能显示“校验通过”。
4. 采纳只更新写作稿，定稿由作者针对确切正文修订、设定集、规则及报告独立确认；纯手工稿不需要先伪造 AI 参考稿。
5. 所有入口共用路径检查、CAS、事务和权限；绕过 UI 不能绕过用例约束。
6. 已有文件权限的外部工具可以绕过河图洛书 API；产品提供检测，不声称实现操作系统级内容隔离。
7. 复制提示词、候选到达、局部选择、写作稿保存、定稿、Git 和交付分别有真实回执；任何一个都不隐含后续效果。
8. 任务只能属于一项建书筹备或一部作品。网页或 Apps 的选择不会扩展到另一作品，普通 URL 和按钮点击不授予作者管理能力。

## 6. 同仓与扩展边界

原生 App、CLI、MCP、局部交互组件、按需 Node.js 页面、宿主适配包、合同与测试同仓，分别产出制品。软件仓库不存用户小说、供应商密钥或商业插件源码。共享 Skill 方法不复制成各宿主独立版本；安装、调用语法与连接定义由适配器提供。可选商业插件独立发布、独立授权。

V1 不为远期插件市场设计热加载 ABI、云账号或动态代码执行能力；MCP Apps 的嵌入式网页不改变桌面核心界面的原生要求。

## 7. 国际化边界

领域对象保存稳定规则键、消息参数与原文证据，平台按 zh-CN 或 en 呈现。公共资源生成平台语言包，格式适配层消费作者选择的交付 profile。界面、作品和交付语言独立，不通过语言切换改写正文，详见[31](31-国际化与中文体验.md)。

## 8. 桌面端与 Web 服务端职责

产品以本机创作工作台为主，本机 MCP 随软件提供；官网承担宣传、使用指南和发行入口。Node.js 本地页面与公网 Web 服务是不同运行单元，前者不构成云后端。服务端业务须有明确需求后单独立项。部署边界图见[23第32节](23-业务流程与MCP时序.md#32-桌面端与未来服务端边界)，先后与准入由[20](20-实施路线与里程碑.md#5-服务端演进与准入顺序)维护。

| 能力 | 本机软件及本机 MCP | 官网 |
| --- | --- | --- |
| 书库与作品 | 管理多部独立作品、卷章、正文、剧本、设定和本地封面 | 提供操作指南与演示数据，无作者作品存储 |
| 中文编辑与稿件状态 | 原生编辑、未保存恢复、本地批注、参考稿比较、采纳及独立定稿 | 说明编辑与验收方法 |
| 外部 Agent 协作 | 用户选择客户端、复制 Prompt；独立 stdio Server 提供获权任务及窄动作 | 提供插件／Skills 接入说明 |
| 局部交互 | 本机 MCP Apps 资源；按需 Node.js 页面、受限 IPC 与浏览器配对 | 提供使用说明，不参与本机任务 |
| 版本与交付 | 本地 Git、标准格式、固定版本 Bundle；远端 Git 操作单独确认 | 提供备份、版本与交付指南 |
| 身份与凭据 | 本机作者会话、作品授权和系统凭据存储 | 静态内容无需创作账号 |
| 素材生成 | 核心不调用模型；外部 Agent 交回候选，作者选用 | 说明外部生成与素材导入方法 |
| 宣传与安装 | 提供已安装制品及连接状态 | 官网提供双语使用指南、品牌素材及经过核验的下载／接入入口 |

### 8.1 数据归属与服务端准入

本地作品以本机修订和记录为事实源，书库、正文、批注、候选和定稿由本机软件管理。插件、MCP Apps 和按需本地页面复用同一业务用例，不保存另一份作品事实。官网的演示数据与作者作品隔离。

服务端立项须先明确用户、场景、业务归属、必要数据和验收条件，再确定存储、身份及接口。涉及作品外发时，逐项确定作者授权、传输范围、保留和删除规则；涉及多端写入时，先确定唯一事实源、修订顺序及冲突处理。共享领域类型不授予本机文件权限，也不等于复用本机存储实现。

### 8.2 MCP 的部署边界

本机 MCP 的启停由连接它的宿主管理，绑定单项筹备或单部作品；本机纯手工创作无须账号、网络或插件。外部 Agent 若无法访问本机 stdio／回环，明确显示不可达，使用固定文件交接或原生界面回退，不默认开公网隧道。

若明确需求需要远端 MCP，须单独冻结传输、身份、资源范围及撤权合同。本机进程不自动升级为公网服务，服务端不能凭远端身份或任意文件路径访问桌面。不同部署共用领域语义时，各自负责存储、身份及副作用适配，不通过新增通用 RPC 扩大动作面。
