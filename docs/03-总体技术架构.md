# 总体技术架构

技术选择见[02](02-架构选型与设计原则.md)，总体图见[23](23-业务流程与MCP时序.md)，领域边界见[28](28-领域设计与边界上下文.md)。

## 1. 架构决定

采用共享Rust业务内核；新工作台使用Electron＋TypeScript/React，主进程以JSON-RPC 2.0私有stdio调用Rust App Server。独立CLI目标采用Rust，MCP继续采用Rust，不要求桌面常驻。SwiftUI/AppKit、Swift CLI及其C ABI桥接退出当前构建；Windows采用共同Electron工作台。目标边界见[39](39-Electron与插件优先重构架构.md)，状态归20／38。

核心没有模型推理、Agent Runtime 或聊天循环。可选模型服务为外部 Agent 提供固定计划封装，支持作者配置的 OpenAI 兼容渠道和 website 服务端 Cloud 渠道。任务 Prompt 由本地模板和作者确认的上下文组装；作者复制到外部客户端完成对话和生成。小说抽取与诊断采用明确结构、词典、规则与作者标注，语义不足时返回候选或未知。

外部 Agent 通过 Skills + CLI/MCP 操作整个软件；桌面端首先呈现成果和操作提案供作者 review、审核与决定，其次提供手动编辑优化。表单是结构化输入的可选人工视图，不能成为正常协作的前置。所有页面交接当前对象和实际能力，不能把“进入 GUI 建任务”作为机器入口的固定第一步。职责判据见[02第1.2节](02-架构选型与设计原则.md#12-全软件联动的设计判据)。

## 2. 分层与模块

工作面、导航、专业动作与方法以贡献注册。第一方套件复用相同合同，第三方代码在独立隔离容器执行；宿主不维护每个插件的业务页面。贡献注册、受限桥接和新旧版边界见39，包及生命周期见[插件10](plugin/10-插件包SDK与生命周期.md)。

```text
外部 Agent + 配套 Skills                 Electron插件工作台（作者）
目标理解 / 填资料 / 整理 / 创作              审阅 / 比较 / 决定
          |                              按需手动编辑优化
       MCP / CLI                                |
          +----------------+--------------------+
                           v
                     Rust Application
       能力发现 / 范围授权 / 操作提案 / CAS / 原操作恢复
                           |
       +----------------+----------------+----------------+
       |                |                |                |
    小说与设定      剧本与来源映射    视频制作与审阅    资料与制作资产
       |                |                |                |
       +----------------+----------------+----------------+
                           |
             文件修订 / Git / 格式转换 / 交付

MCP Apps -> 受限任务工具 -----+
按需本地页面 -> 受限 IPC -----+ 复用相同用例，不保存第二份事实
外部生成工具 -> 固定收件目录 -> 候选核验 -> 作者选用
```

| 层／模块 | 责任 | 依赖限制 |
| --- | --- | --- |
| Domain：Blueprint | 设定集、实体、有效期、锁与约束 | 不依赖 UI、网络、Git 或平台 API |
| Domain：Narrative | 源引用、节点、场次与改编映射 | 不直接访问磁盘 |
| Domain：Drama | 剧本项目、分集身份、语义场次、改编与原著映射 | 不按模型时长重排剧本，不拥有第二份对白 |
| Domain：Video | 视频项目、镜头、预演、生成记录、剪辑版本和成片确认引用 | 消费固定剧本及素材，不自主导演，不把任务成功当成内容认可 |
| Application：WorkLinks | 独立创作对象的固定来源关系及影响查询 | 不复制可写正文，不因关联扩大授权 |
| Domain：Resources | 资料、设计版本、素材候选、作者选用与使用位置 | 不复制正典，不执行生成或跨作品自动共享 |
| Domain：Creation | 建书筹备、外部任务、候选和局部选择 | 建书前可独立存在；不运行模型或读整库 |
| Domain：Review | 参考稿审核、采纳记录、独立定稿资格与证据失效 | 来源、审核、编辑和定稿分开；不信任自报作者身份 |
| Application | 工作区、校验、改编、审核、导出用例 | 协调事务与小型存储／授权接口 |
| Engine | 文本切分、候选提取、规则执行与覆盖 | 确定性输入输出，不编造内容 |
| Format Adapter | Markdown／Fountain 解析、DOCX／TXT 导入、DOCX／PDF 导出 | 转换为带来源的结构，不把版式类型传入领域 |
| Infrastructure | 文件、进程锁、哈希、libgit2、ZIP | 实现用例所需接口 |
| Platform | Keychain／Credential Manager、文件选择与原生权限 | 平台实现，不复制领域规则 |
| Entry | Electron/App Server、CLI、MCP、插件与局部页面代理 | 参数、身份、呈现、任务调度 |

普通数据结构和算法不增加无用途的接口层。只对文件访问、凭据、确认、时钟及外部副作用建立所需窄接口。

### 2.1 依赖规则与组合

入口只调用 Application，Application 编排领域策略、Engine 和所需外部接口；Infrastructure 实现这些窄接口，由入口组合并注入。Domain 不调用文件、Git、MCP、Swift 或 Node.js，Engine 不持有可写工作区句柄。编译依赖图见[23第2节](23-业务流程与MCP时序.md#2-内部组件与依赖)，领域事实消费关系见[28](28-领域设计与边界上下文.md)，两者不能混作同一张调用图。

平台凭据只通过完成当前 Git 操作所需的能力进入适配器，不能进入领域记录或返回给 MCP／网页。格式适配器把输入转换为带来源和损失清单的领域输入；版本、权限和是否定稿由应用用例检查，不能由转换器自行决定。

## 3. 运行单元

- 桌面 App：作者审阅与决定入口，持有成果、差异、待审提案、按页面生成的交接、可选编辑缓冲及审核身份。
- `hetu` CLI：目标Rust薄入口直接复用应用层，向 Agent 提供能力发现、结构化输入输出与原操作恢复；正常业务不要求 GUI 进程存在。
- `hetu-mcp`：宿主管理的原生 stdio MCP Server，提供稳定本机入口；每次请求用显式 task_ref 解析获权单部作品或单项筹备，二者互斥，不依赖全局当前任务。
- MCP Apps 资源：在支持宿主内展示建书、大纲、封面和参考稿的局部交互，经受管桥接保存选择及意见；不直接访问工作区或凭据。
- 按需 Node.js 交互服务：为河图洛书 WebView 或外部 Agent 内置浏览器提供单任务局部页面，通过受限本机 IPC 调用应用用例；与 MCP Apps 复用组件和业务合同，不保存第二套作品事实。

不引入必须常驻的后台服务。独立Node.js局部页面仅按需启动回环服务；Electron已有Chromium/Node运行时，受管内置视图不强制先启动HTTP服务。二者权限与生命周期分别管理；MCP stdio 与该 HTTP 页面服务分别管理。跨进程通过范围锁、版本检查与操作记录协调，建书筹备锁与作品锁各自作用于明确身份。发现占用时返回忙碌或只读状态，不抢锁。需要作者决定时发布完整提案，由实际支持的可信原生端或宿主审阅通道承接，不能要求作者重填输入；未验收通道不签发作者授权。不模拟作者点击。

### 3.1 进程、通道与生命周期

| 运行单元 | 内核接入方式 | 启停拥有者 | 可观察结果 |
| --- | --- | --- | --- |
| Electron工作台 | 主进程经JSON-RPC 2.0私有stdio接入Rust App Server | 作者与操作系统 | 已保存修订、独立作者决定及原操作回执 |
| 独立CLI | Rust直接复用应用层 | 本次命令的调用者 | 能力目录及结构化回执；自动化调用保持 Agent 权限 |
| Rust MCP Server | 进程内复用 Rust 应用层 | 外部 MCP 宿主 | stdio 请求结果、工具与资源；桌面退出不等于 Server 退出 |
| MCP Apps 页面 | 经宿主 UI 桥接调用 MCP 工具 | 外部宿主的面板会话 | 固定任务投影及局部选择回执；无本地文件句柄 |
| Node.js 局部页面服务 | 受限本机 IPC，由 Core 校验 scope 和动作 | 发起它的河图洛书应用会话 | 已配对任务的查询与选择；停止后端口释放 |

Node.js 的 IPC 是受限应用调用通道，不是作者 C ABI 句柄的远程转发，也不是可传任意 `action/root/actor` 的通用执行接口。具体传输由实现合同冻结，安全不变量以[18](18-安全与隐私.md)和[30](30-应用API详细设计.md)为准。运行部署及信任边界图见[23第21节](23-业务流程与MCP时序.md#21-运行部署与信任边界)。

### 3.2 事务与可观察结果

| 用例 | 共同提交的业务事实 | 成功回执的边界 |
| --- | --- | --- |
| 保存正文 | 新 Revision、Document 当前指针、Operation 与审计 | 已保存修订，不改变旧定稿 |
| 审核参考稿 | ReviewDecision、Draft 状态、Operation 与审计 | 本次参考稿决定，正文及卷章目录保持 |
| 采纳参考内容 | 新 Revision、AdoptionRecord、当前指针及必要章节目录、Operation 与审计 | 已采纳到写作稿，不新增审核决定或定稿 |
| 独立定稿／撤回 | FinalizationRecord、相应定稿指针、Operation 与审计 | 确切修订的确认或撤回，不改当前正文 |
| 导出交付 | 固定输入计划、已核验新产物与可恢复原回执 | 本次产物可核验，不自动上传或发稿 |

锁只保护短时一致性读取与提交；耗时抽取、格式转换和压缩消费固定输入，在提交前重新核验。原键查询先于首次执行的 CAS，读取原回执仍须重新授权。跨卷创建、文件发布与 Git 网络副作用分别按恢复合同处理，不声称它们属于同一个文件系统原子事务，详见[07](07-工作区与持久化设计.md)、[16](16-Git版本与协作.md)和[17](17-IPBundle与素材交付.md)。

### 4.1 书库、作品与改编的层级

源码 Monorepo 是开发者维护的软件工程；创作库是本机登记与检索；Workspace 是文件、事务与权限边界，可以持有小说、剧本和视频对象。独立身份和独立工作界面不强制拆成三个目录或 Git 仓库，也不要求同一 IP。按类型过滤小说时可称“书库”，不能用它命名软件总入口。

小说内分卷只组织章节顺序。剧本项目独立持有分集与文稿，视频项目独立持有制作与剪辑；一部小说可关联多套剧本，一套剧本可关联多个视频，也可无上游来源直接开始。WorkLink 固定来源身份及修订，跨根时保存获权必要快照，反向列表从同一关系派生。原目录、ID、任务与历史决定保留，现有嵌套项目仅改变入口投影；迁移另行预演。详见[37](37-创作库与小说剧本视频设计.md)与[29第24节](29-数据字典与Schema设计.md#24-独立创作对象与视频数据)。

同根不自动可读所有对象；既有工作区管理范围不能冒充新对象窄授权。删除登记、删除单个项目和删除整个工作区使用不同用例，单项目删除不移动其他对象的文件。

### 4.2 修改传播与证据失效

正文、设定、骨架或规则更新后，依赖它们的报告与定稿资格按输入快照重新计算当前性。历史报告和历史定稿仍指向原修订，不能改写为新内容，也不能将“过期”显示为“文件损坏”。界面排版、语言、卷章顺序等变更只影响它们实际依赖的投影，不一律触发全文失效。依赖传播图及处理表见[23第24节](23-业务流程与MCP时序.md#24-依赖变化与证据当前性)。

## 5. 关键不变量

1. 角色名称可变，稳定 ID 不变；同名与别名歧义必须显式处理。
2. Agent 永远不能直接修改设定集、解锁或自批定稿；解锁也不会扩大 Agent 权限。
3. 草稿持久化与自动诊断分别有结果；诊断失败时草稿仍可查，但不能显示“校验通过”。
4. 采纳只更新写作稿，定稿由作者针对确切正文修订、设定集、规则及报告独立确认；纯手工稿不需要先伪造 AI 参考稿。
5. 所有入口共用路径检查、CAS、事务和权限；绕过 UI 不能绕过用例约束。
6. 已有文件权限的外部工具可以绕过河图洛书 API；产品提供检测，不声称实现操作系统级内容隔离。
7. 复制提示词、候选到达、局部选择、写作稿保存、定稿、Git 和交付分别有真实回执；任何一个都不隐含后续效果。
8. 任务只能属于一项建书筹备或一部作品。网页或 Apps 的选择不会扩展到另一作品，普通 URL 和按钮点击不授予作者管理能力。

## 6. 同仓与扩展边界

模型能力档案是随软件与方法包分发的声明数据，不是 API 适配器。档案冻结型号、任务、通道、来源和约束；外部 Agent 根据当前可用工具执行。图层、模型参数和参考用途的适配见[35](35-资料素材与短剧制作资产.md)。

Electron宿主、App Server、CLI、MCP、局部交互组件、按需 Node.js 页面、宿主适配包、合同与测试同仓，分别产出制品。软件仓库不存用户小说、供应商密钥或商业插件源码。共享 Skill 方法不复制成各宿主独立版本；安装、调用语法与连接定义由适配器提供。可选商业插件独立发布、独立授权。

首期不以在线交易市场、任意native动态库或完整热更新为前置。Electron提供受管Web插件执行环境，贡献注册与专业工作进程各有合同；MCP Apps继续复用受限业务，不能获得作者通道。

## 7. 国际化边界

领域对象保存稳定规则键、消息参数与原文证据，平台按 zh-CN 或 en 呈现。公共资源生成平台语言包，格式适配层消费作者选择的交付 profile。界面、作品和交付语言独立，不通过语言切换改写正文，详见[31](31-国际化与中文体验.md)。

## 8. 桌面端与 Web 服务端职责

产品以本机创作工作台为主，本机 MCP 随软件提供；官网承担宣传、使用指南、发行入口及可选模型服务的产品接入。Node.js 本地页面与公网 Web 服务是不同运行单元，前者不构成云后端。网站的 Pages Functions 在同源 `/api/hetu/*` 维护服务端会话、客户端连接、模型目录及原操作适配，消费 Cloud 现有身份与 Models 合同；作品事实、作者批准、采纳和定稿仍在 Core。部署边界图见[23第32节](23-业务流程与MCP时序.md#32-桌面端与未来服务端边界)，先后与准入由[20](20-实施路线与里程碑.md#5-服务端演进与准入顺序)维护。

| 能力 | 本机软件及本机 MCP | 官网 |
| --- | --- | --- |
| 创作库与作品 | 登记小说、剧本、视频；持有正文、设定、素材、制作及成片记录 | 提供操作指南与演示数据，无作者作品存储 |
| 中文编辑与稿件状态 | 原生编辑、未保存恢复、本地批注、参考稿比较、采纳及独立定稿 | 说明编辑与验收方法 |

| 版本与交付 | 本地 Git、标准格式、固定版本 Bundle；远端 Git 操作单独确认 | 提供备份、版本与交付指南 |
| 身份与凭据 | 本机作者授权；私密应用目录保存河图连接及自定义渠道凭据 | 静态内容免登录；模型服务用服务端 OIDC 会话接入 Cloud |
| 模型工具 | Core 校验固定任务、输入、作者费用批准与原计划；MCP／CLI 共用自定义及平台渠道；结果进入任务候选 | 服务端接开放平台文字与图片 Models，Console 提供账号与费用入口；不直连供应商 |
| 宣传与安装 | 提供已安装制品及连接状态 | 官网提供双语使用指南、品牌素材及经过核验的下载／接入入口 |

### 8.1 数据归属与服务端准入

本地作品以本机修订和记录为事实源，书库、正文、批注、候选和定稿由本机软件管理。插件、MCP Apps 和按需本地页面复用同一业务用例，不保存另一份作品事实。官网的演示数据与作者作品隔离。

服务端立项须先明确用户、场景、业务归属、必要数据和验收条件，再确定存储、身份及接口。涉及作品外发时，逐项确定作者授权、传输范围、保留和删除规则；涉及多端写入时，先确定唯一事实源、修订顺序及冲突处理。共享领域类型不授予本机文件权限，也不等于复用本机存储实现。

### 8.2 MCP 的部署边界

本机 MCP 的启停由连接它的宿主管理，客户端一次配置稳定入口；任务按本机私有授权和精确引用定位单项筹备或单部作品。连接存在不等于已授任何内容权限，不要求桌面或新增后台服务常驻。本机纯手工创作无须账号、网络或第三方插件，基础工作面随产品提供并保留中性读取。外部 Agent 若无法访问本机 stdio／回环，明确显示不可达，使用固定文件交接或原生界面回退，不默认开公网隧道。

若明确需求需要远端 MCP，须单独冻结传输、身份、资源范围及撤权合同。本机进程不自动升级为公网服务，服务端不能凭远端身份或任意文件路径访问桌面。不同部署共用领域语义时，各自负责存储、身份及副作用适配，不通过新增通用 RPC 扩大动作面。

## 9. 持续协作的结构

```text
作者在河图准备目标和范围                 作者在 Codex 等客户端讨论创作
           |                                         |
    本机私有授权                              场景 Skills + 稳定 MCP / CLI
           |                                         |
           +---------- 精确任务引用 -----------------+
                              |
                 Rust Application：重验授权与请求版本
                              |
       +----------------------+----------------------+
       |                      |                      |
  目录 / 摘要 / 检索     可编辑参考稿工作副本       公开反馈 / 缺项
  获权固定原文片段       CAS 保存不可变修订         同任务接续
       |                      |                      |
       +----------------------+----------------------+
                              |
                    显式提交：固定候选及回执
                              |
                   作者比较 / 局部采纳 / 手工修改
                              |
                        独立确认定稿
```

连接、任务、请求版本、工作副本和提交分别拥有身份；作者补资料或改变基线时追加请求版本，普通返工只追加反馈与工作修订。获权原文按需读取，工作副本不反写正文。检出文件只是任务内临时编辑入口，必须经 Core CAS 导入；候选及定稿仍保持不可变。

Apps 在用户明确“按此修改”时，根据宿主真实能力请求继续当前对话；无能力复制继续提示词。河图持有任务及成果，不持有模型运行循环或全文聊天。架构、调用与恢复图见[23第40～44节](23-业务流程与MCP时序.md#40-持续协作架构与职责)，规范主入口见[27](27-Agent与Codex插件集成设计.md)，精确调用见[30第23节](30-应用API详细设计.md#23-持续协作与任务接续合同)。
