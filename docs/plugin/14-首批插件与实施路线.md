# 首批插件与实施路线

## 1. 实施目标

用差异足够大的真实创作任务验证共同合同：文稿与结构工作、二维/三维空间工作、自由表达。先证明作者收益、机器可操作性和数据接续，再扩大插件数量与分发范围。

本文是新插件体系的实施建议，不登记既有重构的完成状态。当前源码与验收仍看[20](../20-实施路线与里程碑.md)、[38](../38-创作工作台重构执行计划.md)和对应证据。

## 2. 试点能力

| 能力 | 最小任务 | 专业数据 Owner | 主要视图 | 机器操作 | 边界 |
| --- | --- | --- | --- | --- | --- |
| 卷章规划 | 调整一卷冲突与转折并比较 | 规划贡献保存结构候选，正式目录归已有小说 Owner | 目录、连贯规划、差异 | 查询基线、维护候选、准备目录变更 | 不保存第二份正文或卷章目录 |
| 剧本工作面贡献 | 独立剧本按场次阅读并对照固定来源 | 已有剧本及来源 Owner | Fountain、场次、来源对照 | 准备、读取、反馈与返工 | 不要求小说前置，不另造对白存储 |
| 导演调度 | 一个场次的多机位与局部机位调整 | 制作场面专业数据，固定人物与剧本引用 | 二维、三维、镜头表 | 更新相机、站位、镜头覆盖和预览 | 不扩展成完整 DCC 或最终视频生成器 |
| 自由成果 | 一个当前作品专用的比较页面 | 成果自身状态与被引用数据 Owner | Markdown/HTML/图片组合 | 固定提交、受限读取、意见与历史 | 不允许任意系统执行或自动发布包 |

首批不需要新建四套孤立插件平台。现有剧本能力先适配贡献合同；卷章规划验证轻能力；导演验证进程与媒体；自由成果验证开放表达。

技术选型先按[18第7节](18-桌面技术选型与迁移评估.md#7-可推进的验证顺序)验证 Electron＋Rust：贯通桌面容器、包加载、Web SDK 与一次真实保存，再扩大专业能力和动态组合。原生仅作对照，不并行建设该备选方案；文档门禁与独立TS插件闭环先于工作面扩展，准入见[19](19-现有架构审计与插件优先重构.md)。Windows 单独取得实机证据，不能由 Mac 容器通过推导跨端完成。

## 3. 导演场面最小数据范围

场面固定制作对象及依据修订，包含受管实体实例、空间、相机、镜头及局部覆盖。空间约定为米、右手坐标、Y 轴向上；相机方向、角度单位、画幅与传感器信息在正式 Schema 中明确后才能可靠计算视锥。

人物引用固定设定与可选造型，不按“男主”“女主”等名称推断身份。场景中的实例位置属于制作数据，不写回人物设定的世界事实。

镜头默认引用同一场面基线；需要“只改这一镜”时保存有类型的镜头局部覆盖，不能不加区分地改全局站位。预览固定场面与覆盖修订，输出可解码图片或视频，工程可重新打开。

## 4. 工作包与阶段出口

| 阶段 | 工作包 | 依赖 | 出口证据 |
| --- | --- | --- | --- |
| S0 需求与合同 | 用户访谈、等质量任务、贡献与权限边界；启动 A2UI 小型验证 | 本系列评审 | 需求假设、明确样本及协议适配问题 |
| S1 轻能力闭环 | 注册、对象、动作、绑定与基础视图 | S0 | 卷章规划机器旅程、手动冲突、成果回读 |
| S2 工作面接入 | 剧本贡献、自由成果、受限桥接 | S1 | 宿主/插件/机器状态一致、意见与无视图回退 |
| S3 专业操作 | 工作进程、二维/三维、预演与导出 | S1、S2 | 同数据双视图、局部修改、实际预演与工程接续 |
| S4 开发者闭环 | SDK、验证器、开发 Skills、本地包 | S1至S3合同 | 第二位开发者独立实现小能力，不导入内部包 |
| S5 分发生态 | 静态索引、兼容证据、推荐套件 | S4及真实供给 | 固定版本安装、撤回与离线使用 |
| S6 动态组合 | 按早期原型证据扩大领域目录与动态工作面 | 实际组合需求及相关组件、动作成熟 | 与固定视图等质量成本和体验对照、恢复及跨端证据 |

不设置未经团队估算的日历承诺。S5 不以前置完整支付、社交或商店后台为条件；S6 不阻塞基础创作能力。S0/S1 中的 A2UI 小型验证与插件合同并行，用于提前发现架构问题，不代表正式采用必须等到 S5 完成，也不要求早期交付完整动态平台。范围见[11](11-动态渲染与自由成果设计.md#64-验证与采用顺序)。

## 5. 与既有能力的接入

| 现有基础 | 本轮应复用 | 需要新增或核对 |
| --- | --- | --- |
| Rust Application、稳定 CLI/MCP | 授权、能力发现、操作及恢复 | 贡献注册和插件动作映射 |
| 小说与剧本工作面 | 既有文稿、卷章、分集及来源 | 贡献化接入，保持身份与未保存稿 |
| 资料、图片、视频对象 | 原字节、候选、选用和意见 | 新专业工程与已有资产的引用 |
| Skills 套件与安装 | 已有宿主选择及方法来源 | 按插件贡献筛选和版本验证 |
| 本地页面与受限 IPC | 既有范围和配对原则 | 自定义视图的权限与状态桥接 |
| 主22的多媒体插件边界 | 进程、费用、来源与作者决定 | 扩展到更广的创作能力分发模型 |

这些是接入点，不表示所有新用例已经实现。实施应基于当时源码逐项核对，避免重新开发已存在业务。

## 6. 主规范与合同联动

开始发布扩展合同前，同步主01的产品范围、02/03的架构选择、07的目录与恢复、10/37的可选专业工作面、18的隔离、22的生态边界、29/30的数据与动作、19的验收以及20/38的实施登记。

主20中本期不建设桌面画布和三维台的资源范围，与本系列允许未来按需专业插件需在实施计划中明确衔接；禁止专业界面成为作者必经步骤的原则持续保留。不能用一个新文档绕开现有权限、来源和交付不变量。

机器 Schema、CLI/MCP、Skills 和 GUI 同一用例一起交付。新增文档不能自动改变已发布协议修订，也不直接修改现有 Schema 使旧请求获得新语义。

## 7. 发布和回退

先使用示例作品及明确授权测试对象，固定包摘要、Core/CLI/MCP/资源版本和操作引用。开发构建、签名安装包和实际宿主分别验收，不用源码测试代替用户安装。

逐能力开放，保留基本工作面和标准导出。出现权限、数据完整性或无法恢复的问题时停止该贡献的新调用，保留原始数据和原任务。包回退、数据修订恢复、索引重建与外部任务恢复分别记录。

## 8. 阶段决策

只有当插件路线在目标任务中有可验证价值、开发者能独立交付、退出和恢复可用时，扩大供给。若低频需求更适合自由成果，则保留该路径；若动态 UI 更有优势，则在同一动作与作品合同上扩展组合能力。
