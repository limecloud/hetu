# 产品与生态调研

## 1. 研究目标与方法

研究问题是：成熟创作工具如何组织作品；扩展平台如何降低能力制作和组合成本；河图如何在生成式 UI 演进中形成持续价值。

采集日期为2026-11-16。方法为公开官方文档、GitHub README、少量源码及产品网页核对，未登录商业产品、未逐项安装插件、未执行创作者访谈。来源和采集摘要见 [research-sources.json](research-sources.json)。

事实分为三层：来源直接陈述；本轮基于证据的分析；需要试点验证的产品假设。产品官网用于核对公开定位和功能主张，不证明实际易用性、准确率、付费转化或成本收益。来源未出现某项能力，不等于产品没有该能力。

2026-11-16补充核对DSH官方插件索引、参考生成器和包管理源码：其静态JSON发现、npm精确版本／Git固定提交分发、安装再校验和第三方索引声明边界见[24第2节](24-插件目录与分发治理.md#2-deepseek-harness的事实与借鉴)。本轮为源码和文档研究，不代表DSH运行验收。

2026-11-17补充检索DSH社区市场的小说条目，核对固定README、重点源码与许可，候选比较及河图适配见[29](29-小说插件生态调研与复刻路线.md)，检索范围及逐仓证据见[研究记录](research/novel-ecosystem-2026-11-17.json)。该记录不代表上游运行、河图兼容或插件发布验收。

## 5. dsh：插件宿主与组合

固定研究版本为 `39163dd30f703a79079e2d2446545cff3c453738`。README 将其标为开发者预览，存在破坏性变更预期。

直接证据：通过 `inject` 声明服务依赖；通过上下文提供服务；工具、事件与其他贡献可注册并撤销；Profile 组合多个 Bundle；UI 插件进入宿主插槽；显式 Remote 方法向客户端开放。插件管理区分已保存选择与实际加载结果。

借鉴：声明贡献、显式依赖、同一业务服务、多工作面组合、可清理生命周期和实际状态回读。河图保留作品与授权内核，专业能力可扩展，不照搬可替换 Agent loop 或宿主内全权限执行方式。

### 5.1 三万条目的口径

本次采集的 dsh.so 首页显示30,175个收录条目，网站更新标记为2026-11-15。该站说明自己为独立社区项目；生态页区分 DSH 插件、生态插件和生态应用，并指出累计曲线的陡升多来自批量发现。

这说明需要分别研究能力制作、已有工具适配和索引收录。数字为网站自报快照，不能推导三万项能力全部成熟、互不重复、持续维护或被创作者采用。不同页面的冻结时间和统计分母不同，不将首页、周报与验证账本数字拼成一个转化漏斗。

### 5.2 可解释的增长机制

| 机制 | 证据基础 | 河图可采取的方式 |
| --- | --- | --- |

## 6. Pi：能力包和渐进披露

固定研究版本为 `04fd0897e4df737cd8422bc99085d6953da804ec`。原 `badlogic/pi-mono` 已重定向到 `earendil-works/pi`。

经典 Pi Package 可以整体分发 extensions、skills、prompts 和 themes，支持 npm、Git、本地来源与资源筛选。Skills 启动只提供名称、摘要和路径，任务需要时读取完整方法。工具支持自定义结果渲染，模型内容与界面所需详情可分别提供。

借鉴：安装、作品启用与 Agent 暴露分别处理；能力包中的贡献可以任选；给模型的必要内容与作者查看的完整界面分离。摘要和工具发现仍有上下文成本，不能宣称安装多少扩展都零 Token。

同仓库的 P2/Chord 还探索共享合同、多工作面和 HTML artifacts。P2 文档明确其部分加载机制为设计且 API 实验性；本系列只借鉴问题拆分，不把实验方案写成 Pi 的稳定承诺。

### 7.2 机制与成本判断

A2UI 的动态性主要来自运行时组合与更新已实现能力。组件目录描述哪些组件和函数可用，渲染器提供实际实现；Agent 可以选择组织方式。组件可以是通用控件，也可以是插件提供的完整人物关系图、版本比较器或导演视口，后者需要河图自行定义和实现。

`updateComponents` 与 `updateDataModel` 允许分别更新结构和数据，无需每次重建整页。1.0 的 `callAgentFunction` 和 `callRendererFunction` 表达有类型函数调用；名称中的 Agent 不意味着每个调用都需要一次模型推理。是否绕过推理由实现与请求类型决定，不能泛化为所有操作都零 Token。

Agent SDK 还能将紧凑推理格式编译成标准传输消息，因此模型输出、传输消息和渲染开销应分别计量。目录说明进入上下文、选择错误后的纠正、外部请求与数据同步仍有成本。不能只凭使用 A2UI 就宣称便宜或快速。

### 7.3 对河图的结论

A2UI 与河图的插件思路可以互相支持：插件提供专业组件、函数、数据和方法，外部 Agent 按当前问题组织界面，河图执行受管操作并保存作品与作者决定。河图无需内置 Agent 才能接收这种描述，也无需让作者手动搭建工作台。

由此修正机会判断：模型成本与速度影响近期实施顺序；持久创作状态、专业能力和跨任务接续决定长期价值。A2UI 适合优先验证动态组合层，不能替代作品内核、专业图形引擎或完整插件生命周期。

本轮未实测河图接入、中文长文、复杂画布、三维操作和媒体审阅，也未验证作者收益。接入路线及实验见[11](11-动态渲染与自由成果设计.md)和[15](15-测试验收与追踪矩阵.md)。

## 9. 研究结论与缺口

建议采用：持久作品、专业工作面、多种表达、同一动作、多层能力包、开放交付、按需发现和质量证据。

仍需验证：真实作者的操作负担；插件与临时生成的等质量总成本；开发者独立完成插件的难度；跨 Agent 接续质量；专业深度与默认简洁是否兼得。访谈与测量安排由15维护，不能以公开产品的存在替代需求成立。
