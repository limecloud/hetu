# 插件开发与调试指南

## 1. 目标与环境

开发者交付能够独立构建、校验、安装、运行和退出的创作能力。运行包使用JS/TS，视图可用React；Rust只属于宿主内核，插件不编写FFI。无持久数据、无视图或无后端的包均可成立，不为了统一外观强加全部组件。

宿主以固定版本 Cordis 适配内部贡献生命周期，专业插件以河图SDK为公共边界，不强制自行安装Cordis或DSH模块。脚手架复制同版 SDK；框架回归与DSH插件适配分别按[26](26-Cordis采用与DSH兼容边界.md)验证。小说规划独立插件的功能、数据与进度由[插件仓库文档](https://github.com/wordflowlab/hetu-novel-planner/tree/main/docs)拥有。

Node版本、构建与运行前置条件见[根说明](../../README.md#快速上手)。从宿主源码准备开发工具：

```bash
npm ci
npm run build:desktop
node "apps/desktop/dist/plugin-dev.mjs" --help
```

完整宿主运行还需Rust产物；插件自身不继承宿主源码的构建依赖。开发工具当前由桌面构建产出，独立公开SDK发行验收不能由上述源码流程推导。

## 2. 创建到校验

在河图仓库根目录执行，创建目标必须是不存在的绝对路径：

```bash
node "apps/desktop/dist/plugin-dev.mjs" create "$PWD/../hetu-character-notes" --id dev.local.character-notes --title "人物笔记"
cd "../hetu-character-notes"
npm install
npm run build
cd "../hetu"
node "apps/desktop/dist/plugin-dev.mjs" validate "$PWD/../hetu-character-notes/dist"
```

`cd "../hetu"`假定宿主目录名为hetu；使用其他名称时回到实际宿主根目录。`create`不安装依赖、不执行生成代码、不覆盖已有目录。`validate`只读包文件，不执行插件代码；返回身份、版本、包摘要、权限、文件数量和贡献摘要。

```text
独立插件目录/
  plugin.json
  CAPABILITIES.md
  LICENSE
  package.json
  build.mjs
  index.html
  src/view.tsx
  src/backend.mjs
  src/sdk.ts
  dist/
```

脚手架初始动作为显式文字的Unicode字符统计，可省略历史`permissions`字段。这是最小桥接样例，不宣称已经成为持久人物笔记工具。改成自己的能力时同步修改名称、说明、贡献、Schema与功能清单。

## 3. 贡献与数据责任

| 层次 | 插件负责 | 宿主负责 |
| --- | --- | --- |
| 视图 | 专业表达、交互与可访问性、浅暗主题 | 隔离WebContents、受限桥接与导航 |
| 数据 | 自己的数据Schema、版本与迁移说明 | WorkRef隔离、固定修订、CAS、事务与回执 |
| 动作 | 输入Schema、effect、实际计算与明确错误 | 活动包与上下文核验、写入规则和恢复 |
| 功能说明 | `CAPABILITIES.md`与包内验收 | 宿主地图只导航插件发现入口 |
| 作者决定 | 呈现依据和差异 | 正文采纳、定稿及独立授权用例 |

后端按需独立运行，使用公开SDK调用核心服务和专业数据动作，不直接访问`.hetu`或任意文件。Node权限限制属于纵深防护，不能宣称未知代码因此绝对安全。包依赖与内嵌资源必须完整、路径受限，不在用户安装时执行构建脚本。

## 4. 安装与无GUI调试

1. 对最终`dist/`执行固定包校验，保存摘要。
2. 外部Agent调用`hetu.plugins.inspect`发现当前安装基线，再用`hetu.plugins.inspect_package`核对完整包。
3. 按当前Schema提交确切安装选择；`hetu.plugins.apply`与`get_operation`保持原操作键。
4. 绑定隔离演示作品的完整WorkRef；插件无需单独授权。
5. 查询`hetu.plugins.capabilities`，经`invoke`调用本包实际贡献。
6. 回读成果及修订，再由GUI查看同一份数据；GUI不是机器调用前置。

上述是动作导航，参数必须读取当前能力发现，不复制自造的`approved=true`或通用作者身份。稳定CLI/MCP、GUI和独立插件Runtime入口及配置以20、21为准，不新增一套“开发专用直写”入口。

## 5. 断点与故障定位

| 现象 | 先核对 | 避免的处理 |
| --- | --- | --- |
| 校验失败 | 清单字段、Schema、路径、依赖与实际文件 | 关闭校验或临时扩大权限 |
| 安装成功但无能力 | 启用状态、精确包摘要、作品连接和能力刷新 | 重装Codex插件或授权整库 |
| 界面空白 | 本包入口、资源、桥接调用与错误状态 | 让界面获得Node或任意文件权 |
| 后端启动失败 | 受管Node版本、入口、声明依赖和限制 | 退回不受管系统Shell |
| 保存冲突 | 原基线、当前修订与未保存稿 | 覆盖最新数据或丢弃编辑 |
| 结果未知 | 原操作记录和固定输入 | 换键重复执行 |
| 更新后不可读 | 新旧Schema与迁移前后差异 | 用新Schema静默吞字段 |

日志只保留必要的包、贡献、错误及非敏感操作定位。不要提交作品内容、授权原值、账号凭据或本机私密路径。

## 6. 最小验收矩阵

| 用例 | 预期与证据 |
| --- | --- |
| 独立目录构建 | 不依赖宿主私有绝对路径；产物包含许可和功能清单 |
| 坏包 | 越界、软链接、重复贡献、依赖环被拒绝，宿主仍可用 |
| 无数据动作 | 零数据权限包能发现和调用显式输入动作 |
| 受限读写 | 本作品成功，其他作品、撤权与错误包摘要失败 |
| 同连接热插拔 | 安装后重查出现；停用后消失，旧定位不能继续执行 |
| 保存与重开 | CLI/MCP回读与GUI同一修订，关闭重开保持 |
| 冲突与未知 | 保留输入与原键，不静默覆盖、不重复写入 |
| 停用及卸载 | 撤权、清理活动运行时，已保存数据仍可通用读取导出 |
| 数据升级 | 显式差异、确切迁移授权、原键恢复和旧数据保留 |
| 可用性 | 键盘、浅暗、窄窗、长内容与空／错／恢复状态 |

纯计算包明确标注不适用存储用例及原因。自动测试、真实宿主运行和陌生开发者试用分别记录，不能互相代替。完整需求追踪见[15](15-测试验收与追踪矩阵.md)。完成后进入[发布与上架](23-插件发布与上架指南.md)。

## 公开核心服务

```typescript
import {createHostClient, type BackendContext} from './sdk.ts';
export async function inspectNovel(context: BackendContext) {
  const host = createHostClient(context.request);
  const capabilities = await host.capabilities();
  const snapshot = await host.novelSnapshot();
  return {capabilities, snapshot};
}
```

先查询能力及Schema，再组合小说、文稿、大纲、设定及素材服务。领域数据不通过页面导航获取。专业方法和功能清单由插件维护；宿主领域语义见主28，分层、兼容与核心审计见[27](27-开放宿主SDK与核心能力审计.md)。
