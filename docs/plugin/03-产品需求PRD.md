# 产品需求 PRD

## 1. 产品定义

河图洛书是围绕持久作品组织专业能力的本地创作工作台。作者按任务选用小说、剧本、视频等工作环境；插件扩展数据、操作、视图、方法和连接；外部 Agent 在明确范围内准备和执行操作，作者审阅、编辑、表达意见并作出创作决定。

产品的长期目标是形成可组合的创作生态：方法、工具、素材、专业工程与成果能够围绕稳定作品引用协作。近期目标是验证扩展合同和真实创作闭环，不以目录中的插件数量作为阶段目标。

## 2. 用户与核心任务

| 用户 | 希望完成的任务 | 主要困难 | 产品应交付的结果 |
| --- | --- | --- | --- |
| 小说作者 | 组织整部作品并持续写作 | 长文、设定和多线结构分散 | 可阅读、可改动、可接续的作品 |
| 编剧与改编者 | 从构思或原著组织分集和场次 | 对白、结构与来源变化互相影响 | 固定来源的剧本版本与改编取舍 |
| 导演与短剧创作者 | 核对空间、调度、节奏和镜头 | 文字难以表达画面，制作试错昂贵 | 可观看、比较和修改的预演工程 |
| 审阅者 | 查看完整成果并提出具体意见 | 摘要丢细节，意见错绑版本 | 可定位和回读的反馈 |
| 专业方法提供者 | 分发创作方法和模板 | 方法难以进入实际工作流程 | 可与专业工具组合的方法包 |
| 插件开发者 | 提供新的创作能力 | 依赖内部实现、跨端和兼容成本高 | 可独立开发验证的扩展合同 |

团队多人协作、云同步和托管计算为独立机会；本系列先保证单作者本机闭环，不因此新增账号体系和服务器。

## 3. 价值与成功条件

- 深度：能对整部作品及局部对象执行真实操作，不止展示一次性答案。
- 易用：作者可以直接阅读、观看、提意见，无需先学会所有专业工具。
- 自由：特殊需求有自由成果和自定义视图入口，固定模式不穷举全部表达。
- 可接续：换会话、换 Agent 或停用插件后，作品与必要成果仍可理解和交付。
- 可扩展：第三方通过公开合同完成有用能力，无需修改内核或复制正式内容。

## 4. 功能需求

| 编号 | 需求 | 可观察的完成条件 | 优先级 |
| --- | --- | --- | --- |
| PFR-001 | 保留共享内核权威 | 所有入口遵守相同身份、授权、修订、采纳与定稿规则 | P0 |
| PFR-002 | 提供按任务适配的工作面 | 小说、剧本、视频入口独立，专业工作面可按需启用 | P0 |
| PFR-003 | 插件可贡献部分完整能力 | 包可以仅含方法或视图，也可组合数据、动作与适配器 | P0 |
| PFR-004 | 支持自由成果 | Markdown、HTML、图片、媒体及程序输出可固定保存和继续使用 | P0 |
| PFR-005 | 同一事实支持多视图 | 两种视图和 Agent 操作更新同一 Owner；偏好独立保存 | P0 |
| PFR-006 | 提供对等业务入口 | 正常机器旅程不依赖桌面窗口，GUI 消费同一用例 | P0 |
| PFR-007 | 提供精确任务交接 | 各工作面携带对象、固定版本、范围、实际动作与恢复引用 | P0 |
| PFR-008 | 按需暴露能力 | 安装、启用、作品绑定和 Agent 可见性分别管理 | P0 |
| PFR-009 | 支持发现和明确安装 | 可核对来源、版本、摘要、权限、依赖及实际安装结果 | P0 |
| PFR-010 | 管理完整生命周期 | 启停可清理贡献；故障影响限定在当前插件与依赖者 | P0 |
| PFR-011 | 支持兼容和显式迁移 | 旧数据不因代码升级被静默改写，未知字段可保留 | P0 |
| PFR-012 | 版本化扩展数据 | 稳定 ID、命名空间、固定来源、不可变修订和 CAS 均可核验 | P0 |
| PFR-013 | 固定位置反馈 | 文本、图元、图片和视频意见绑定确切成果版本 | P0 |
| PFR-014 | 预览与获权执行分开 | 作者审阅确切差异，首次执行核对 CAS，原操作可恢复 | P0 |
| PFR-015 | 作者决定由内核执行 | 插件或 Agent 不能自报批准，收到成果不自动采纳或定稿 | P0 |
| PFR-016 | 异步及未知结果可接续 | 原计划和原操作查询可恢复，不重复提交付费或外部任务 | P0 |
| PFR-017 | 生成协作保留外部边界 | 外部 Agent 调用可用能力，模型封装只执行获批固定计划 | P0 |
| PFR-018 | 停用后有阅读和交付路径 | 插件缺失仍显示元数据、固定预览和标准导出，不丢原数据 | P0 |
| PFR-019 | 提供TS开发包和验证器 | JS/TS/React独立插件不修改宿主业务路由，验证包、动作、保存、回读与清理；第一方使用相同贡献合同 | P0 |
| PFR-020 | 建立可核验分发目录 | 列出来源和版本，收录、安装、运行与场景验证分别展示 | P1 |
| PFR-021 | 保持中文、英文与辅助功能 | 基础操作可键盘访问，专业画布有结构化对象和阅读替代 | P0 |
| PFR-022 | 保留作者直接操作 | 纯手动可用，Agent 写入冲突不覆盖未保存稿 | P0 |
| PFR-023 | 度量总成本和质量 | 采集经同意的耗时与操作指标，不默认上传正文或提示词 | P0 |
| PFR-024 | 完整来源及工程交付 | 标准文件、原工程、依赖、工具版本、许可与缺项可核验 | P0 |

P0 表示试点闭环需要的合同约束，不表示第一阶段同时交付全部媒介和插件。P1 表示在基础供给与验证流程成立后扩展的分发能力。

## 5. 非功能要求

| 编号 | 方面 | 设计要求 |
| --- | --- | --- |
| PNF-001 | 可用性 | 安装目录或单个插件失败不阻断本地基础阅读、编辑和历史查询 |
| PNF-002 | 性能 | 控制消息有界，列表分页，渲染和生成均不长时持有作品锁 |
| PNF-003 | 数据持有 | 删除可重建索引后能恢复插件对象与历史；撤销授权不删除作品 |
| PNF-004 | 安全 | 通过桥接与进程的输入视为不可信，OS 隔离能力如实声明 |
| PNF-005 | 可维护性 | GUI、CLI/MCP、SDK 不各自实现领域规则或持久层 |
| PNF-006 | 兼容 | 包版本、API 修订、数据 Schema、渲染协议与索引格式独立演进 |
| PNF-007 | 可观测性 | 结果说明已保存、已激活、待重启、失败、部分完成或未知 |
| PNF-008 | 可退出 | 插件卸载和服务订阅结束不剥夺读取、导出已有作品的能力 |

## 6. 范围与排除项

已采纳Electron工作台＋TypeScript插件宿主＋Rust Core；插件无需Rust、FFI或native动态库。宿主/插件交互重新设计，保留原生业务与数据对照；先完成受影响文档再开发，准入见主39与本系列19。

范围覆盖方法包、视图包、带受管数据和动作的能力包、外部适配器、套件、自由成果和分发索引。支持专业工具的深度，默认由 Agent 操作与作者审阅衔接。

本系列不包含内置 Agent Runtime、无限自动循环、发布投放及运营、任意网页执行权、自动安装未知代码、通用本体推理平台、强制云端书库和自建完整 DCC 引擎。

已有小说、剧本、视频类型保持；增加一种专业工作面不自动增加顶层作品类型。新增作品类型必须证明有独立身份、生命周期和交付语义。

## 7. 指标与验证

| 层面 | 指标 | 比较方式 |
| --- | --- | --- |
| 作者价值 | 同等成果质量下的任务完成时间、返工、求助和直接操作量 | 插件路线与临时生成路线配对任务 |
| 接续质量 | 换会话、换 Agent 和插件缺失后的成功接续比例 | 固定作品集与明确检查项 |
| 扩展成本 | 外部开发者到首次通过验证的时间、内部代码依赖和阻塞 | SDK 使用记录与访谈 |
| 生态质量 | 实际使用、作品采用、维护和跨版本存活 | 区分开发者、包、贡献和版本去重 |
| 工程质量 | 冲突拒绝、恢复一致性、故障隔离和导出完整性 | 正负用例与故障注入 |

不在缺少基线时承诺节省比例、用户规模或收入。量化性能实验和证据要求见[15](15-测试验收与追踪矩阵.md)。
