# 领域模型与数据合同

Schema 版本为 `1.0.0`。格式使用 UTF-8 JSON／Markdown／Fountain，时刻使用 UTC RFC 3339，路径使用 `/` 分隔的工作区相对路径。聚合边界见[28](28-领域设计与边界上下文.md)，字段字典见[29](29-数据字典与Schema设计.md)。

## 1. 实体与归属

| 实体 | 核心字段 | 责任 |
| --- | --- | --- |
| Workspace | `workspace_id, schema_version, title, packages` | 项目身份、启用内容包 |
| Blueprint | `blueprint_id, revision, lock, characters, factions, locations, timeline, rules` | 作者确认的 IP 正典 |
| Document | `document_id, kind, title, source_format, current_revision_id, approved_revision_id` | 小说／剧本文档及版本指针，源格式见25 |
| Revision | `revision_id, document_id, sha256, created_at, actor_ref` | 不可变文本修订 |
| Draft | `draft_id, package, target_document_id, base_revision_id, content_sha256, state` | Agent 或人工待审内容 |
| PlotNode | `node_id, kind, source_refs, entity_refs, time_ref, verification` | 从已有文本得到的结构 |
| Skeleton | `skeleton_id, revision, episodes, plot_revision_id, blueprint_revision` | 经过排列与校正的结构骨架 |
| DiagnosticReport | `report_id, input_snapshot, coverage, findings, status` | 对固定输入的校验结果 |
| ReviewDecision | `review_id, draft_id, decision, reviewer_ref, input_snapshot, comments` | 作者决定与证据 |
| AssetCue | `cue_id, kind, narrative_refs, description, asset_refs` | 视觉／配乐线索及既有素材关联 |
| Operation | `operation_id, input_digest, state, result_ref` | 幂等、恢复与副作用跟踪 |
| BundleManifest | `bundle_id, inputs, files, provenance, exclusions` | 固定交付内容与摘要 |

ID 使用带类型前缀的随机 UUID 字符串，例如 `char_…`、`draft_…`；名称、集号、章节号和文件名均不是身份。跨工作区引用必须显式导入并重新映射，不隐式复用同名对象。

## 2. 版本与摘要

- `schema_version`：数据结构的语义版本；未知主版本只读，绝不自动重写。
- `revision`：设定集／骨架等对象的递增整数，由锁内写入分配，禁止调用方指定下一值。
- `revision_id`：不可变修订身份；相同文本的新修订是否复用必须由用例决定，不由路径猜测。
- `sha256`：持久化文件实际字节的 SHA-256，小写 64 位十六进制。原始文本不因展示换行而改变摘要。
- 写入 CAS 同时检查预期版本和原始文件摘要；外部手工修改但未递增版本仍能检出冲突。
- 报告保存源文、设定集、节点、骨架、规则集版本及引擎构建标识；只要相关输入变化即 `stale`。

Git commit 与内容修订不同；一个 commit 可以包含多个修订。未提交工作区可导出，但必须保存输入摘要并标记 `dirty=true`。

## 3. 原文定位 SourceRef

```json
{
  "document_id": "doc_11111111-1111-4111-8111-111111111111",
  "revision_id": "rev_22222222-2222-4222-8222-222222222222",
  "byte_start": 0,
  "byte_end": 18,
  "quote": "林舟推开门。"
}
```

范围为原始 UTF-8 字节的半开区间，边界必须落在完整编码字符上，`quote` 必须等于相应切片。该例五个汉字加句号共六个字符，占 18 字节；实施夹具必须按实际字节计算，不手填偏移。

行列、Swift 字符索引与 Windows UTF-16 索引是表现层换算值，不持久化为权威定位。源文已变时先打开旧修订；可尝试锚点定位当前文本，但必须标记“重新定位候选”，不得将旧诊断直接套到新段落。

## 4. 状态枚举

| 对象 | 状态 |
| --- | --- |
| Draft | `submitted, in_review, changes_requested, rejected, approved, superseded` |
| Report | `complete, partial, failed, cancelled`，另有计算属性 `stale` |
| Task | `queued, running, succeeded, failed, cancelled, unknown` |
| Plot verification | `candidate, author_confirmed` |
| Finding certainty | `deterministic, heuristic, agent_suggested` |
| Finding disposition | `open, resolved, dismissed, accepted_exception` |

报告 `complete` 表示所选检查执行完成，不表示没有问题或整部作品已被完整理解。`unknown` 表示副作用无法确认，不表示失败且可安全重试。

## 5. 来源与身份

`actor_ref` 区分本地作者配置身份、河图发出的会话主体、调用方自报 Agent 名称。自报名称和说明只作展示；不能据此认定真实供应商、模型版本或人类身份。作者身份不是云端实名，V1 不声称具有团队级防抵赖能力。

Agent 输入参数采用允许字段投影：保存工具名、文档 ID、版本、参数摘要及安全的结构参数，正文引用已保存内容；不保存 Authorization、Token、环境变量、凭据或完整秘密参数。审计合同见[15](15-人工审核与审计.md)。

## 6. 兼容与删除

已引用角色、地点、节点不得直接物理移除；作者可归档或迁移引用，再执行明确删除。实体关系必须检查类型、存在性及循环约束。

未知字段的接收策略由各 Schema 明确，写入接口默认拒绝未知字段；阅读未来版本不得“忽略并保存”造成数据损失。升级前备份、预演、校验与恢复见[07](07-工作区与持久化设计.md)。
