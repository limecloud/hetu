# 领域模型与数据合同

各类记录独立声明 Schema 版本，基础格式为 `1.0.0`，参考稿决定为 `2.0.0`；不以文档版本代替记录版本。格式使用 UTF-8 JSON／Markdown／Fountain，时刻使用 UTC RFC 3339，路径使用 `/` 分隔的工作区相对路径。聚合边界见[28](28-领域设计与边界上下文.md)，字段字典见[29](29-数据字典与Schema设计.md)。

## 1. 实体与归属

| 实体 | 核心字段 | 责任 |
| --- | --- | --- |
| CreationProject | `project_id, revision, brief, selected_fields, task_refs, created_workspace_ref` | 建书前的独立筹备，不要求书名或作品目录，不拥有其他作品权限 |
| CreativeTask | `task_id, scope_ref, task_kind, request_revision, input_refs, client_adapter, prompt, output_contract` | 作者准备并复制到外部 Agent 的固定任务；不代表河图洛书正在执行生成 |
| TaskSubmission | `submission_id, task_ref, request_sha256, candidate_refs, provenance` | 外部返回的一批候选，接收后由内核独立核验 |
| InteractionDecision | `decision_id, task_ref, candidate_refs, expected, selected_items, comment, actor_ref` | Apps、网页及原生端共享的局部选择，不充当定稿 |
| LibraryEntry | `workspace_id, location_ref, metadata_projection, last_opened_at` | 本机按作品身份登记目录与资料投影，按最近打开排序 |
| Workspace | `workspace_id, schema_version, title, packages` | 单部作品的内容与权限边界、启用内容包 |
| Novel | `novel_id, workspace_id, revision, metadata, volumes, chapters` | 小说作品资料与独立身份；metadata 保存书名、笔名、简介、类型、语言和状态 |
| Volume／Chapter | `volume_id, title`／`chapter_id, document_id, volume_id` | 可选分卷和章节目录；数组规定顺序，序号不作身份 |
| DramaProject | `drama_project_id, title, source_refs, skeleton_refs, script_refs` | 独立短剧项目、改编来源和剧本引用 |
| BookCover | `revision, asset_ref, source_ref, presentation, previous_sha256` | 作者选用的封面版本；来源和裁切不改原图，见34 |
| Blueprint | `blueprint_id, revision, lock, characters, factions, locations, timeline, rules` | 作者确认的 IP 正典 |
| Document | `document_id, kind, title, source_format, current_revision_id, approved_revision_id` | 小说／剧本文档及版本指针，源格式见25 |
| Revision | `revision_id, document_id, sha256, created_at, actor_ref` | 不可变文本修订 |
| Draft | `draft_id, package, target_document_id, base_revision_id, content_sha256, state` | Agent 或人工待审内容 |
| PlotNode | `node_id, kind, source_refs, entity_refs, time_ref, verification` | 从已有文本得到的结构 |
| Skeleton | `skeleton_id, revision, episodes, plot_revision_id, blueprint_revision` | 经过排列与校正的结构骨架 |
| DiagnosticReport | `report_id, input_snapshot, coverage, findings, status` | 对固定输入的校验结果 |
| ReviewDecision | `review_id, draft_id, decision, reviewer_ref, input_snapshot, comments` | 作者决定与证据 |
| AdoptionRecord | `adoption_id, document_ref, draft_ref, base_revision_id, selected_ranges, input_snapshot, previous` | 作者将参考内容采纳进写作稿的来源记录，document_ref 指结果，不设置定稿 |
| FinalizationRecord | `finalization_id, document_ref, expected_finalization_ref, actor_ref, decision, previous` | 独立确认或撤回确切正文修订；确认额外固定 input_snapshot 与 report_refs，无需存在 AI 草稿 |
| AssetCue | `cue_id, kind, narrative_refs, description, asset_refs` | 视觉／配乐线索及既有素材关联 |
| Operation | `operation_id, input_digest, state, result_ref` | 幂等、恢复与副作用跟踪 |
| BundleManifest | `bundle_id, inputs, files, provenance, exclusions` | 固定交付内容与摘要 |

ID 使用带类型前缀的随机 UUID 字符串，例如 `character_…`、`draft_…`；名称、集号、章节号和文件名均不是身份。跨工作区引用必须显式导入并重新映射，不隐式复用同名对象。

作者书库登记多部独立作品；每部小说的设定、正文、封面和素材归属本作品工作区。设定共享或系列分组由作者显式建立，书库不根据同名角色或题材自动合并。登记项与目录权限留在本机，作品内容继续可随自己的目录持有。

建书筹备以 project scope 存在，正式作品以 workspace scope 存在，二者为互斥授权范围。创建作品通过显式关联保留筹备来源，不修改旧任务的身份或向原筹备 Agent 扩权。

## 2. 版本与摘要

- `schema_version`：数据结构的语义版本；未知主版本只读，绝不自动重写。
- `revision`：设定集／骨架等对象的递增整数，由锁内写入分配，禁止调用方指定下一值。
- `revision_id`：不可变修订身份；相同文本的新修订是否复用必须由用例决定，不由路径猜测。
- `sha256`：持久化文件实际字节的 SHA-256，小写 64 位十六进制。原始文本不因展示换行而改变摘要。
- 写入 CAS 同时检查预期版本和原始文件摘要；外部手工修改但未递增版本仍能检出冲突。
- 报告保存源文、设定集、节点、骨架、规则集版本及引擎构建标识；只要相关输入变化即 `stale`。

Git commit 与内容修订不同；一个 commit 可以包含多个修订。未提交工作区可导出，但必须保存输入摘要并标记 `dirty=true`。

## 3. 原文定位 SourceRef

```json
{
  "document_id": "doc_11111111-1111-4111-8111-111111111111",
  "revision_id": "rev_22222222-2222-4222-8222-222222222222",
  "byte_start": 0,
  "byte_end": 18,
  "quote": "林舟推开门。"
}
```

范围为原始 UTF-8 字节的半开区间，边界必须落在完整编码字符上，`quote` 必须等于相应切片。该例五个汉字加句号共六个字符，占 18 字节；实施夹具必须按实际字节计算，不手填偏移。

行列、Swift 字符索引与 Windows UTF-16 索引是表现层换算值，不持久化为权威定位。源文已变时先打开旧修订；可尝试锚点定位当前文本，但必须标记“重新定位候选”，不得将旧诊断直接套到新段落。

## 4. 状态枚举

| 对象 | 状态 |
| --- | --- |
| Draft | `submitted, in_review, changes_requested, rejected, approved, superseded` |
| Report | `complete, partial, failed, cancelled`，另有计算属性 `stale` |
| Task | `queued, running, succeeded, failed, cancelled, unknown` |
| CreativeTask observation | `prepared, awaiting_result, result_received, partial, needs_attention, closed, cancelled` |
| Plot verification | `candidate, author_confirmed` |
| Finding certainty | `certain, heuristic, unknown, advisory` |
| Finding disposition | `open, acknowledged, false_positive, accepted_exception` |

报告 `complete` 表示所选检查执行完成，不表示没有问题或整部作品已被完整理解。`unknown` 表示副作用无法确认，不表示失败且可安全重试。

Task 为河图洛书自身执行的检查／导出等任务，CreativeTask 为交给外部客户端的创作请求。`copied_at` 只记录复制事件，不推导 Agent 已接收或 running。内容来源采用独立 `origin_kind=author|agent|import` 与修订贡献引用；Draft 的审核状态不充当正文定稿状态，`approved` 不自动更新 `approved_revision_id`。定稿语义见[15](15-人工审核与审计.md)。

## 5. 来源与身份

`actor_ref` 区分本地作者配置身份、河图洛书发出的会话主体、调用方自报 Agent 名称。自报名称和说明只作展示；不能据此认定真实供应商、模型版本或人类身份。作者身份不是云端实名，V1 不声称具有团队级防抵赖能力。

Agent 输入参数采用允许字段投影：保存工具名、文档 ID、版本、参数摘要及安全的结构参数，正文引用已保存内容；不保存 Authorization、Token、环境变量、凭据或完整秘密参数。审计合同见[15](15-人工审核与审计.md)。

## 6. 兼容与删除

已引用角色、地点、节点不得直接物理移除；作者可归档或迁移引用，再执行明确删除。实体关系必须检查类型、存在性及循环约束。

未知字段的接收策略由各 Schema 明确，写入接口默认拒绝未知字段；阅读未来版本不得“忽略并保存”造成数据损失。升级前备份、预演、校验与恢复见[07](07-工作区与持久化设计.md)。
