# 领域模型与数据合同

## 作品内容的语义

已有实体承载确定设定、来源和稿件修订。探索方案保留在参考稿；现实资料的引用不自动成为虚构事实。有意改编差异使用既有来源与决定表达，不凭模型判断新增正典或例外记录。

产品定位与任务分流见[01](01-产品需求PRD.md#1-产品定义)。

本体术语与准入归[28第15节](28-领域设计与边界上下文.md#15-agent-first-的本体核心)，本文只维护身份、固定引用与版本合同。不要把本体概念数量当作新增文件、表或API的数量。

## Agent First 的身份与上下文约束

- 同名章节、同名人物、复制文稿和同根作品均按明确身份区分；展示标题、界面路径和Agent引擎的thread ID不参与业务身份比较。
- `WorkRef`标识当前作品，`DocumentRef`及其他领域固定引用标识具体修订，`SourceRef`标识原文字节范围；`ContextRef`只在所属固定任务清单中解析。它们分别解决归属、版本、位置和任务读取，不能互换。
- “标签、人物、设定、章节、章纲、草稿”是上下文选择器的显示分类。选择后必须解析为原Owner已有固定引用；分类不创建新的正式对象，不以标题匹配代替引用核验。
- 新的正文头不会改变旧任务输入、批注和候选依据；发现新版本时显式选择更新输入或保持原请求。未保存编辑单独显示，未经固定保存不能伪装为已持久化修订。
- 本机执行模式控制如何执行，不改变对象含义。auto读取当前工作区仍须明确目标；confirm批准固定变更后范围内连续执行，不能把批准内容换成另一版本。

视频认可使用独立`MediaDecision`修订链，按确切作品、视频分集和用途维护一个当前头。用途与固定媒体的`previsualization|clip|final`一致，分别表达预演认可、片段选用及成片确认；保存媒体、反馈、技术核验与导出不推进认可。每次确认或撤回固定原媒体、前一决定和作者真实原话，操作执行者保留实际身份。新版视频不继承旧版认可，撤回只能作用于当前已确认的确切媒体；历史记录与文件不被改写。字段归29，动作归30。

上下文的字段映射归[29第27节](29-数据字典与Schema设计.md#27-类型化上下文与能力呈现)，行为与恢复归[30第31节](30-应用API详细设计.md#31-agent-first的上下文与能力协作)。

各类记录独立声明 Schema 版本，基础格式为 `1.0.0`，参考稿决定为 `2.0.0`；不以文档版本代替记录版本。格式使用 UTF-8 JSON／Markdown／Fountain，时刻使用 UTC RFC 3339，路径使用 `/` 分隔的工作区相对路径。聚合边界见[28](28-领域设计与边界上下文.md)，字段字典见[29](29-数据字典与Schema设计.md)。

ID 使用带类型前缀的随机 UUID 字符串，例如 `character_…`、`draft_…`；名称、集号、章节号和文件名均不是身份。跨工作区引用必须显式导入并重新映射，不隐式复用同名对象。

创作库登记独立小说、剧本和视频，同根内容仍按具体对象核验所有权与授权；设定及素材复用固定版本和用途，不按同名或题材自动合并。工作区保存内容与事务，登记项和目录权限留在本机。新对象及媒体字段语义见[29第24节](29-数据字典与Schema设计.md#24-独立创作对象与视频数据)；实现按明确 Schema 修订发布，不向旧记录直接注入字段。

建书筹备以 project scope 存在，正式作品以 workspace scope 存在，二者为互斥授权范围。创建作品通过显式关联保留筹备来源，不修改旧任务的身份或向原筹备 Agent 扩权。

稳定 MCP 连接与任务身份分开。每次调用显式定位已获权任务，不依赖全局“当前作品”。同目标返工保留 task_id；作者补充资料或调整基线时追加不可变请求修订，旧请求不再接受新写入，旧结果不改写。任务、请求、工作副本、提交和反馈的具体字段及版本不变量见[29第22节](29-数据字典与Schema设计.md#22-持续协作上下文与反馈)。

全软件管理用例与单创作任务分别授权。WorkspaceGrant／CreationGrant 限定明确作品或新建范围，TaskGrant 仍限定单任务；页面上下文只提供定位，不能代替授权。操作提案、决定、执行及实际领域结果分别引用，Agent 的填表和执行来源不冒称作者手动创作。字段设计见[29第23节](29-数据字典与Schema设计.md#23-页面交接与操作提案)。

## 2. 版本与摘要

- `schema_version`：数据结构的语义版本；未知主版本只读，绝不自动重写。
- `revision`：设定集／骨架等对象的递增整数，由锁内写入分配，禁止调用方指定下一值。
- `revision_id`：不可变修订身份；相同文本的新修订是否复用必须由用例决定，不由路径猜测。
- `sha256`：持久化文件实际字节的 SHA-256，小写 64 位十六进制。原始文本不因展示换行而改变摘要。
- 写入 CAS 同时检查预期版本和原始文件摘要；外部手工修改但未递增版本仍能检出冲突。
- 报告保存源文、设定集、节点、骨架、规则集版本及引擎构建标识；只要相关输入变化即 `stale`。

Git commit 与内容修订不同；一个 commit 可以包含多个修订。未提交工作区可导出，但必须保存输入摘要并标记 `dirty=true`。

## 3. 原文定位 SourceRef

```json
{
  "document_id": "doc_11111111-1111-4111-8111-111111111111",
  "revision_id": "rev_22222222-2222-4222-8222-222222222222",
  "byte_start": 0,
  "byte_end": 18,
  "quote": "林舟推开门。"
}
```

范围为原始 UTF-8 字节的半开区间，边界必须落在完整编码字符上，`quote` 必须等于相应切片。该例五个汉字加句号共六个字符，占 18 字节；实施夹具必须按实际字节计算，不手填偏移。

行列、Swift 字符索引与 Windows UTF-16 索引是表现层换算值，不持久化为权威定位。源文已变时先打开旧修订；可尝试锚点定位当前文本，但必须标记“重新定位候选”，不得将旧诊断直接套到新段落。

宿主提及资源只编码公开WorkRef、原领域固定引用及可选分页位置，不携带授权。Fountain场次投影绑定DocumentRef及完整场次字节范围，场次序号和分集序号只作展示，不生成持久scene_id；改稿或重排后原引用仍读取原修订。专业成果绑定Owner、对象、修订和摘要，视频分集／媒体分别绑定自己的固定记录；目录、安装状态和作者当前决定不成为来源内容的一部分。实际查询与读取合同归[30第31.4节](30-应用API详细设计.md#314-场次视频与保留专业来源)。

## 4. 状态枚举

| 对象 | 状态 |
| --- | --- |
| Draft | `submitted, in_review, changes_requested, rejected, approved, superseded` |
| Report | `complete, partial, failed, cancelled`，另有计算属性 `stale` |
| Task | `queued, running, succeeded, failed, cancelled, unknown` |
| CreativeTask observation | `prepared, awaiting_result, result_received, partial, needs_attention, closed, cancelled` |
| Plot verification | `candidate, author_confirmed` |
| Finding certainty | `certain, heuristic, unknown, advisory` |
| Finding disposition | `open, acknowledged, false_positive, accepted_exception` |
| ResourceItem／AssetDesign | `draft, adopted, archived`；采用与归档正式资料仅作者可执行 |
| AssetSelection | `selected, withdrawn`；不可变决定链，候选接收不设置选用 |

报告 `complete` 表示所选检查执行完成，不表示没有问题或整部作品已被完整理解。`unknown` 表示副作用无法确认，不表示失败且可安全重试。

Task 为河图洛书自身执行的检查／导出等任务，CreativeTask 为交给外部客户端的创作请求。`copied_at` 只记录复制事件，不推导 Agent 已接收或 running。内容来源采用独立 `origin_kind=author|agent|import` 与修订贡献引用；Draft 的审核状态不充当正文定稿状态，`approved` 不自动更新 `approved_revision_id`。定稿语义见[15](15-人工审核与审计.md)。

工作副本“已保存”、候选“已提交”、反馈“已保存”、宿主“已接受继续请求”与“收到后续成果”分别取证。Agent 自报阶段仅作说明；不能成为 AXI 新状态、正式采纳、定稿或外部费用结果。

## 5. 来源与身份

`actor_ref` 区分本地作者配置身份、河图洛书发出的会话主体、调用方自报 Agent 名称。自报名称和说明只作展示；不能据此认定真实供应商、模型版本或人类身份。作者身份不是云端实名，V1 不声称具有团队级防抵赖能力。

Agent 输入参数采用允许字段投影：保存工具名、文档 ID、版本、参数摘要及安全的结构参数，正文引用已保存内容；不保存 Authorization、Token、环境变量、凭据或完整秘密参数。审计合同见[15](15-人工审核与审计.md)。

## 6. 兼容与删除

骨架的规划分集与写作分集属于不同身份，必须显式映射，禁止因集号相同而共用 ID。资料、素材文件和选用各自修订；故事事实、候选与文件可用性、权利和依赖当前性分别记录，详见[35](35-资料素材与短剧制作资产.md)。

已引用角色、地点、节点不得直接物理移除；作者可归档或迁移引用，再执行明确删除。实体关系必须检查类型、存在性及循环约束。

同根多个创作对象时，单项目删除核对所属内容与被引用位置，可恢复处理，不移走整个工作区。整根移入废纸篓只属于列明所有受影响对象的工作区删除；移除创作库登记不删除内容。旧路径、对象与任务身份保持，导航重构不触发搬迁或重算历史摘要。

未知字段的接收策略由各 Schema 明确，写入接口默认拒绝未知字段；阅读未来版本不得“忽略并保存”造成数据损失。升级前备份、预演、校验与恢复见[07](07-工作区与持久化设计.md)。

## 7. 创作场景与来源

小说、剧本和视频是创作对象类型，从零、继续已有成果、改编是创作方式，导入是输入动作，作者／Agent 是贡献来源，版权与用途是独立声明。这些维度不得合成互斥的“创作模式”枚举。视频可从简述、分镜或素材直接开始，完整场景与原生引导见[36](36-创作场景与引导流程.md)。

SourceMaterial 拥有原著固定文件、只读文本、版本与出处；SourceRights 拥有改编、Agent 外发及原著再分发等独立声明。DramaProject 通过固定引用选择原著或续作依据；普通参考资料仍归 Resources，不自动改变原创／改编判断。缺少原著可以先保存计划，缺少权利声明不阻止打开或手工写作，所选对外材料在动作执行时分别核对。

文稿副本使用新的Document、Revision与章节／分集身份；`copy_source_ref`保留原WorkRef和固定文稿修订，不重绑定旧任务、批注、采纳或定稿。复制只发生在同一作品内，原正文与目录历史保持独立可读，字段与事务合同见[29](29-数据字典与Schema设计.md#开放宿主上下文与小说投影)。

文稿移动记录固定同一WorkRef内的双端前后修订、来源范围及原操作。移除来源、追加目标与记录一次事务提交，不能出现单端成功；恢复也只沿记录并核验双端当前修订，创建新修订而不重写旧历史。批注、任务和定稿继续保留原引用，不因文字位置变化自动转移。

## 插件优先重构的接入边界

插件数据拥有明确命名空间和WorkRef，经Core受管事务保存；既有正文、设定、剧本、媒体与决定Owner不变。插件包、贡献、套件和自由成果不是新的作品类型。 目标分工见[39](39-Electron与插件优先重构架构.md)，详细扩展合同见[插件系列](plugin/README.md)，实际进度归38。

## 本体语义与公开服务

对象语义、关系基数和核心准入以[28](28-领域设计与边界上下文.md)为唯一Owner；不建立独立本体数据库。WorkRef、固定来源、文稿修订及插件对象保持各自格式。插件安装启用后通过公开SDK使用核心应用用例，不新增插件作品授权实体；旧grant字段仅用于历史连接。兼容、Owner与维护顺序见[24](24-文档治理架构决策与风险.md)。
