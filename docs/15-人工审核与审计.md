# 人工审核与审计

作者对候选采纳、写作稿编辑和定稿分别作出决定。河图原生界面承担完整验收，MCP Apps 与本地网页提供局部比较、选择及批注。生成只在外部 Agent 中进行。

作者自主写作、保存和定稿是默认路径，参考稿审核仅在存在候选且作者需要处理时进入。AI 改稿同样保存为独立候选，作者可以只读、自行重写、部分采纳或放弃，不要求为继续写作而先处理全部参考稿。采纳须由作者预览并明确执行。

## 1. 来源与状态

“AI 稿”描述来源，“定稿”描述作者决定，两者不能合并成一个状态字段。

| 维度 | 表达的事实 | 界面示例 |
| --- | --- | --- |
| 内容来源 | 作者书写、Agent 提交、导入，以及采纳修订的来源关联 | AI 参考、作者编辑、含参考稿采纳记录 |
| 候选审核 | submitted、in_review、approved、changes_requested、rejected、superseded | 待审、审阅中、通过参考稿审核、要求修改、驳回、已接替 |
| 文档编辑 | 当前保存修订与未保存缓冲 | 写作稿、未保存、保存失败或外部冲突 |
| 作者定稿 | 对确切文档修订的有效确认及撤回记录 | 当前定稿、写作稿有新修改、已撤回定稿 |
| 对外交付 | Bundle 引用的固定版本及导出结果 | 已导出；不等于已经在平台发布 |

`Draft.state=approved` 只表示参考稿通过审核，不设置文档定稿指针。作者手工书写或导入的正文可以直接执行检查及定稿，无需先制造一份 AI 草稿。来源依据实际提交、采纳和修订记录，不根据文字风格进行“AI 检测”。

参考稿审核状态转移统一使用[23第10节](23-业务流程与MCP时序.md#10-参考稿审核状态)。`withdrawn` 是新增的审核决定，撤回通过后 Draft 回到 `in_review`；它不是新的 Draft 状态，不清除采纳记录或正文定稿。写作稿与定稿的组合显示是修订指针的派生结果，见[23第23节](23-业务流程与MCP时序.md#23-写作稿与定稿的组合状态)。

## 2. 参考稿的保存与审阅

Agent 提交后保存不可变参考稿，正文、目标和基线固定；要求修改时产生新 draft ID，以 `parent_draft_id` 关联。旧稿、原批注与结果保持可读，被新稿接替时标为 `superseded`。接收成功不代表检查已完成。

审阅屏展示：当前作品、任务及客户端来源、候选正文、相对基线的差异、当前写作稿、设定集修订、报告与覆盖。现有正文在作者采纳前保持原样。Agent 自报的模型或身份只作声明，不替代真实连接和授权记录。

审核决定冻结草稿状态修订、内容与提交凭据摘要、目标基线、当前修订、设定及骨架引用。批注绑定固定修订与来源范围，包含作者、时间、内容、可见范围和处理状态。旧批注不静默迁移到相似的新段落。

诊断可使用只读虚拟文档引用访问参考稿，其内容仍指向原候选，不进入正式章节目录。报告页可校正结构前提后生成新报告；历史报告保留，不把最近一页当全部历史。

## 3. 采纳进入写作稿

作者可选择整稿、若干段落或特定字段，预览它们对当前写作稿的修改。界面主操作为“采纳到写作稿”，采纳后可继续编辑；不使用“通过定稿”将两个动作合并。

| 采纳目标 | 结果 | 约束 |
| --- | --- | --- |
| 建书资料候选 | 填入筹备表单的选定字段 | 仍由作者确认创建小说 |
| 既有作品资料候选 | 对选定字段形成作者变更 | 重验 Novel 修订，不能顺带修改正文或设定 |
| 大纲或正文候选 | 保存新的当前文档修订和 AdoptionRecord | 精确目标、基线及选中范围；不改变定稿 |
| 新章节候选 | 作者确认标题和卷组后创建写作稿及章节引用 | Agent 不能决定入卷或创建正式章节 |
| 设定建议 | 进入独立设定变更预览 | 遵守设定锁与作者修改权限 |
| 封面候选 | 在素材页供作者预览选用 | 正式选用遵守34，不由文本采纳动作代办 |

采纳在锁内核对候选摘要、当前目标和作者预览，事务写入新修订、AdoptionRecord、原操作及审计；未选内容不进入正文，不隐式新增参考稿审核决定。待审、审阅中或审核通过的参考稿可由作者明确采纳；已驳回、要求修改或已接替的稿件先走审核／返工流程。基线过期时显示基线／候选／当前三方差异，由作者重新选择，不自动覆盖或重放旧 patch。

输入法组合、未保存缓冲及撤销栈遵守编辑器合同。作者可在编辑器撤销一次采纳，保存时产生后继修订和撤销关联；不删除原候选或历史采纳。手工改写后保留修订级来源，不承诺永久逐字符准确判断作者与 AI 的贡献比例。

## 4. 独立定稿

作者对当前已保存写作稿选择“确认定稿”，查看固定全文、与上次定稿的差异、来源摘要、设定和规则证据。定稿对象是 `Document + Revision`，可关联零个或多个候选／采纳记录；不要求存在 draft ID。

| 情况 | 定稿策略 |
| --- | --- |
| 内容摘要不符、Schema／引用损坏、越权、源文件缺失 | 硬阻断，先修复完整性 |
| 本次输入已变化、诊断失败或取消 | 重新检查／审阅，不沿用旧确认 |
| 规则报告部分覆盖或存在未知前提 | 作者明确记录人工核对范围和理由，不标记完整校验 |
| 确定性业务冲突 | 修复；规则明确允许作者例外时可记录具体例外 |
| 启发式警告和 Agent 语义建议 | 作者可接受、驳回或记录已读，不强迫符合算法偏好 |
| 无阻断且证据有效 | 作者确认确切修订，记录 FinalizationRecord 并更新定稿指针 |

机器报告中 `certainty=certain` 且 `severity=error` 为确定性阻断。仅当该 finding 的 `exception_policy=author_review` 且作者记录 `accepted_exception` 时允许例外。覆盖理由不改变原报告覆盖和确定性。

定稿事务写入不可变 FinalizationRecord、文档定稿指针、原操作与审计，不创建新的不同正文来冒充作者刚才审阅的修订。设定或依赖变化时保留历史定稿，当前交付资格需重新检查。定稿后编辑产生新当前修订，旧定稿仍可查看；新写作稿不会自动继承定稿资格。

定稿不修改设定、不 Git 提交、不推送、不导出、不发稿。定稿只针对作者选定章节／剧本范围，不通过一本书的状态替代每份文档的批准。

## 5. MCP Apps、本地网页与人类决定

Apps 和网页可以展示候选、等比预览图片、比较大纲、保存选择与意见，写入 `InteractionDecision` 后由 Agent 回读。它们不持有独立业务数据库，关闭页面不代表采纳或定稿。

选择偏好可以在对应受限会话中保存；正式正文采纳、设定变更、封面选用及定稿由河图原生作者入口确认。浏览器自动化的点击、模型调用工具或 Agent 传入 `is_author` 均不能取得该权限。Apps 或本地浏览器不可用时完整审阅在桌面继续，复用原任务和记录。

默认作者入口为原生桌面界面；独立人工 CLI 按13取得本机作者会话，并执行相同的固定输入确认。单有终端、工具调用或网页会话不能取得作者能力。

## 6. 驳回与返工

要求修改应说明具体段落、保留项及修改目标。河图基于作者选择的公开批注组装补充 Prompt，用户复制到外部客户端继续对话。软件不自动运行 Agent，不保证一次通知会触发生成。

公开理由与私密批注分别存储；普通 Agent 读取投影隐藏内部批注。新候选与原任务、父稿及基线关联；结果未知先查询原操作和候选，不能换键重复提交。参考稿被驳回不删除正文，也不撤销不相关的定稿。

## 7. 审计与来源

审计事件包括 `event_id, operation_id, scope_ref, actor_ref, action, target_refs, before_digest, after_digest, occurred_at, result, safe_parameters`。建书筹备用其 project scope，作品用 workspace scope。来源记录至少关联任务、候选批次、客户端声明、Skill／扩展版本及实际产物摘要；不以缺失模型名推断某个模型。

作者动作记录本地身份配置与可信入口；外部调用记录会话主体和自报信息并明确区分。只保存允许参数投影、已存正文引用与摘要，不保存 Token、Cookie、密钥或整段正文副本。

审计可追加并校验摘要链以发现缺失与意外改写；它不能抵抗同 OS 权限程序重写整份历史，不宣称监管级防篡改。采纳、定稿或审计未完整提交时不能宣称操作成功。

## 8. 并发、撤回与兼容

并发采纳使用目标当前修订 CAS；并发定稿同时核对已保存修订、当前定稿和证据快照，只接受一个有效决定。后续调用返回冲突及可比较的当前状态，不生成互相覆盖的定稿。

撤回定稿新增撤回记录，仅清除仍属于该 FinalizationRecord 的定稿指针；当前写作稿、参考稿和历史决定保留。旧决定不能撤回另一份新的定稿。已经导出的包不可远程撤销，后续交付需重新冻结输入。

参考稿审核、采纳和定稿使用独立动作与合同版本，入口根据能力目录调用相应动作。历史记录按原合同读取，不将历史定稿重新解释为参考稿；原操作结果保留其动作版本，不借新版重放改变原副作用。数据升级须预演、备份并核验正文、指针及历史记录的一致性。
