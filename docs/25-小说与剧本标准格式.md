# 小说与剧本标准格式

标准文件容器、行业写作惯例与河图数据合同分别管理；交稿要求由明确版本的 delivery profile 表达。

## 1. 格式结论

小说创作与交稿按平台、出版社及出版媒介采用相应格式。TXT／DOCX 常用于交稿，Markdown 便于纯文本创作，EPUB 有正式电子出版规范；它们解决的问题不同。投稿与出版方的明确要求优先于默认版式。

影视剧本普遍区分场景标题、动作、人物、对白、括注和转场；Fountain 是公开的纯文本剧本标记格式，FDX 是 Final Draft 的专有 XML 交换格式，DOCX／PDF 是常见交付载体。中文短剧的“集号、场号、日夜、内外景、地点、人物”可作为制片 profile 的结构要求，不能宣称是已经核实的全国统一强制格式。

河图采用：**小说以 Markdown 为可编辑源，剧本以 Fountain 为可编辑源，内核解析为统一叙事结构；对外按接收方 profile 导出 DOCX／PDF 等文件。** EPUB 与 FDX 分阶段接入。

## 2. 支持矩阵

| 对象／格式 | V1.0 导入 | V1.0 导出 | 定位 |
| --- | --- | --- | --- |
| 小说 Markdown `.md` | 是，声明支持子集 | 是 | 工作区权威可编辑正文 |
| 小说 UTF-8 TXT `.txt` | 是，章节识别预览 | 是 | 网文纯文本兼容，不承诺所有平台自动适配 |
| 小说 DOCX `.docx` | 是，限定正文结构并报告损失 | 是 | 编辑、出版社交稿 profile |
| 小说 EPUB 3.3 `.epub` | P1 | P1 | 标准电子书交换与阅读，不是内部唯一源 |
| 剧本 Fountain `.fountain` | 是，冻结语法版本／兼容子集 | 是 | 剧本权威可编辑正文与纯文本互换 |
| 剧本 DOCX | 是，指定结构样式 profile | 是 | 中文制片稿／编剧协作 |
| 剧本 PDF | 不反推为可编辑源 | 是 | 固定版式阅读与签核 |
| 剧本 FDX `.fdx` | P1，需实测版本与样例 | P1 | Final Draft 互操作，未验证前不宣称兼容 |
| 河图结构 JSON | 是，符合自身 Schema | 是 | 设定集、节点、骨架和溯源；不是行业通用文件标准 |

“是”表示 V1 功能范围，P1 为增强范围。PDF 不是有可靠语义的剧本交换源；OCR 与扫描稿识别不作为 V1 隐式能力。

## 3. 内部权威与格式映射

Document 增加 `source_format=markdown|fountain`；修订保存为 `.md` 或 `.fountain`，字段语义及 ID 按[05](05-领域模型与数据合同.md)。导入外部 DOCX／TXT 时创建新修订和导入报告，原文件可作为来源附件保留，但不成为第二份自动双写正文。

内核中间结构区分：作品元数据、卷／章、段落、场景、动作、说话人、对白、括注、转场、注释及来源。AST 为固定正文与解析器版本的派生物，不与正文独立维护两份事实。设定集与骨架仍分别拥有正典和结构规划。

剧本人物名映射到设定集 ID，Fountain 中继续保留可读名称；映射记录绑定修订和字节范围，不能给标准语法偷偷增加私有 ID 指令。导出文本不能泄露内部批注与隐藏线索。

## 4. 小说写作与交稿 profile

必需结构为书名、作者署名、作品简介、卷／章标题、章节顺序、正文和可选场景分隔。分章主要依靠显式标题和作者确认，不能把所有“第×章”字样一律切成章节。

Markdown 子集先支持标题、段落、强调、分隔和普通链接；正文不执行 HTML／脚本。脚注、图片、表格、注释和其他扩展的支持状态由导入预览说明，禁止静默丢弃。

TXT 导出使用显式编码和换行 profile，默认 UTF-8，章节顺序固定。导入非 UTF-8 文本先识别候选编码并预览，由作者确认，不能用替换字符静默修复。正文缩进、全角空格和标点不在保存时强制清洗。

DOCX 使用作品标题、作者、卷标题、章标题和正文等可追踪样式；纸张、字体、字号、行距、首行缩进、页眉和页码由 profile 定义。中文默认 profile 是河图产品模板，必须标明版本；接收方要求可覆盖模板，不能将英语投稿惯例生搬为中文强制规范。

## 5. 剧本结构与 Fountain

最小场景包含稳定 scene ID、展示场号、地点、内外景、日夜和出场人物。剧本正文由场景标题、动作、人物／对白等元素构成；故事梗概、人物小传与分集大纲作为不同文档类型，不混入对白流。

以下是格式测试样例，示例台词是文档夹具，不表示内核会自动生成台词：

```fountain
Title: 旧宅
Credit: 编剧
Author: 示例作者

# 第1集

INT. 旧宅 - DAY #1#

林舟推开门。

@林舟
有人在吗？
```

中文人物名不具备英语大小写特征，需支持 Fountain 的显式人物标记等规则；不能仅用“大写行＝人物”解析中文稿。中文制片显示名可以渲染为“1-1 日 内 旧宅”，交换稿仍遵守所选 Fountain 语法，不把自定义中文标题约定冒充标准语法。

缺少内外景／日夜时，内部骨架保留 `unknown`；要求完整场景标题的正式交付 profile 应阻止无说明的完成稿，允许作者补充或导出显著标记的审阅稿。不能为了语法有效而猜成 `INT.` 或 `DAY`。

## 6. 制片稿与固定版式

中文短剧 profile 必须给出集号、场号、内外景、地点、日夜、出场人物、动作和对白的样式映射，支持连续场号及作者确认的锁场号。修改剧本时保留稳定 scene ID，展示场号变化可查；彩页修订、锁页与复杂拍摄管理不属于 V1.0 范围。

英语 screenplay profile 可参考 12 pt Courier、场景标题、动作与对白的行业惯例；该字体与“一页约一分钟”的经验不适用于所有中文稿，也不能用它自动判定真实片长。中文字体需核验可分发与 PDF 嵌入许可。

DOCX 和 PDF 应保持一致的标题层级、段落类型、人物／对白关联与页码；PDF 处理中文换行、孤行、对白跨页及字体缺失，禁止截字或把人物名与其对白完全分离。所有制片稿导出后渲染检查；最终排版不是仅靠 JSON Schema 通过即可验收。

## 7. 导入损失与回环

导入先报告格式、章节／场景解析结果、未知样式、批注、修订痕迹、脚注、内嵌对象、损坏字符和遗漏风险，由作者确认再登记。DOCX 中跟踪修订不得默认全部接受；宏、外部实体和自动远程引用不执行。

回环要求保留正文、结构、场景顺序、人物／对白关联和元数据的语义等价，不承诺 DOCX、Fountain 的字节或所有排版完全一致。无法表达的内容列入转换报告；原始导入文件保持可追溯。

## 8. 合规检查与证据

- Fountain：用冻结语法夹具与至少一个独立实现校验解析／回环；中文角色、显式标记、注释、转场和场号分别验证。
- DOCX：核验 OOXML 包结构、关系与支持的语义子集，在 Word 和另一独立阅读器抽样打开；不宣称实现全部 ECMA-376。
- PDF：渲染逐页检查中文、分页和布局，核验文本可选择与字体使用；PDF/A 合规不在未声明时自动附带。
- EPUB P1：按 W3C EPUB 3.3 检查包、导航、阅读顺序、语言与元数据，使用固定版本验证器及独立阅读器，不以 ZIP 可解压代替合规。
- FDX P1：核验目标 Final Draft 版本、文件元素与往返样例；没有实际互操作证据就保持未验证。

## 9. 来源与证据边界

规范来源包括 [W3C EPUB 3.3](https://www.w3.org/TR/epub-33/)、[ECMA-376](https://ecma-international.org/publications-and-standards/standards/ecma-376/)、[Final Draft 格式指南](https://www.finaldraft.com/learn/how-to-format-a-screenplay/)和 [William Shunn 投稿格式指南](https://www.shunn.net/format/story/)。前两者为文件标准来源，后两者分别为厂商与作者给出的行业／投稿惯例。

Fountain 语法以[官方语法说明](https://fountain.io/syntax/)和版本化解析器兼容集为依据，中文人物与强制标记按互操作夹具验收。中文制片模板必须注明接收方、版本及必填项；未提供正式标准编号的模板不标为国家或行业强制标准。
