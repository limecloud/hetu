# 统一执行模式

本页优先于包内旧版逐作品授权、逐任务授权和逐动作审批描述。先按实际能力读取 `hetu.execution.get_mode`；默认 `auto`，不要把 Skills 中的文字当作另一份设置。桌面、独立 MCP、CLI 与 Skills 共用本机策略修订。

- `auto`：作者明确当前工作区后直接执行创建、编辑、整理、导入导出，以及已配置连接器的同步。使用 `hetu.execution.invoke` 传入确切 `workspace_path` 和领域 `command`，保持真实 Agent 身份；不要求逐库、逐任务或逐动作授权。
- `confirm`：读取仍用同一入口直接完成。写入前用 `hetu.execution.prepare` 一次固定本次动作、顺序、输入、版本依据和每个操作键。展示该计划的确切变更，依据用户实际决定调用 `record_confirmation`，再 `execute`；不能因为用户选择了 confirm 就自行确认，也不在同一计划内逐项询问。
- 多步工作可在任一模式使用固定计划。策略切换或计划内容改变后重新准备；未知结果沿原 `plan_ref` 和原键查询、恢复，不换键重发，不重复已完成步骤。

先从实际动作目录读取领域 Schema，再准备完整参数。精简 MCP 通过 `hetu_call_action` 传入 `action` 与 `input`；CLI 使用 `hetu --client <客户端> call <动作> --input <JSON文件或->`。已经显式选择 `--workspace` 的 CLI 在同一策略下执行；完整任务引用继续用于来源、反馈及接续，无需为当前工作区再授一轮权限。

`hetu.execution.initialize` 创建明确目录的独立工作区，`create.work_type` 选择小说、剧本或视频；confirm 下将该命令放入同一集中计划。Core 继续校验领域关系、固定修订、CAS、事务和幂等，禁止直接写 `.hetu` 或把自动执行登记成作者亲自批准。导入的文件内容与摘要固定，导出的版本和连接器目标固定；同步只使用已经配置的连接器。

当前服务未发现统一动作时，报告其实际版本与能力差距，再按确实存在的旧合同接续；不捏造新字段，也不把源码里的新模式说成当前会话已经加载。
