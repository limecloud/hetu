# 河图洛书接入与任务恢复

先读本包的 [任务合同](../../references/task-contract.md)，按固定任务和实际宿主能力继续。

创作时结合[本包题材方法](../../references/genre.md)中对应环节的增量；只使用作者已选题材，不从其他已安装套件拼接规则。

## 本次起点

- 首次接入：按任务关键词查询有界动作摘要，选定后读取Schema和前置条件；需要共同方法时通过methods目录按摘要读取，只在接入或版本有问题时运行只读诊断。
- 继续任务：打开精确TaskLocator，先读摘要、任务接续、已有稿件与公开反馈，核对假设、未决问题和handoff中的已知陷阱，从未完成阶段继续。
- 反馈返工：读取意见所指的固定成果，沿同任务保存新稿；交付后回读成果与意见引用。

精简MCP目录通过实际hetu_call_action调用已登记动作，详细参数从inspect按需读取；CLI使用同一call合同。长任务的接续保存、分块读取和错误恢复见[任务合同](../../references/task-contract.md#发现继续与恢复)。

首次诊断可按实际发现调用`hetu.baseline.inspect`，区分随包基础能力与可选专业插件。小说、剧本和视频基础审阅不要求安装额外河图插件；合同完整不代表业务、桌面装配或当前会话方法已验证。

## 接入检查

核对作者选择的客户端、套件及 manifest 版本。分别报告下列可观察状态：

| 检查项 | 足够的证据 |
| --- | --- |
| 包与方法 | 实际包身份、版本、当前声明的任务入口和配套方法；缺参考文件不能称为完整 |
| 安装与启用 | 当前宿主的真实登记或配置，不能以缓存目录存在代替 |
| 当前会话发现 | 本会话实际可调用的 Skills 与工具；新安装可能需要新会话 |
| 任务读取与授权 | 原任务读取回执及固定输入，不能由插件安装状态推断 |
| 局部视图与图像 | 宿主实际暴露的 Apps、浏览器或图像能力，分别报告 |

## 已知任务恢复

作者选择河图文字或图片模型服务时，按[模型服务](../../references/model-service.md)发现目录、准备固定输入、等待作者批准，并沿原计划恢复。连接不阻断其他获权本地工作，不索取供应商密钥。

已有任务先用实际提供的稳定 open 打开精确 TaskLocator，读取当前完整请求引用，再读取已有参考稿、固定候选和公开意见。查询到已保存稿时沿原稿继续，不把新会话当作新任务。结果未知时按任务合同查询原操作，不另开生成任务、换键提交或重复付费。只完成接入检查时不生成正文或封面。

无任务时区分本次目标：仅检查接入就报告实际可见性；作者要开始小说、剧本或视频时，发现已发布的筹备与新建能力，准备必要资料和明确保存方案。视频交给[视频Skill](../hetu-video/SKILL.md)，不要求先建小说或剧本。不能要求先回 GUI 填表创建任务，不扫描书库。版本未开放所需动作时报告准确缺口，不用 Computer Use 或直接修改受管文件补齐。进入创作后使用相应任务 Skill；方法位置见[创作导航](../../references/writing-methods.md)，无需在接入阶段通读。

发现 `hetu_begin_creation` 或 CLI 动作 `hetu.creation_projects.create` 时，可以直接开始独立筹备，无需预有任务。保留返回的 `management_ref` 和明确的 `target_path`；该路径仅用于本次全新受管作品，不扩大为任意目录权限。创建成功使用新的 `workspace_management_ref` 准备首任务，再以 `task_locator` 打开，后续创作切换到完整 `task_ref`。管理权不能替代作者采纳或定稿。


## 已有作品的页面交接与管理方案

收到页面交接时，按其中明确的作品、对象和固定修订调用实际 `hetu.handoffs.get`，先发现当前 CLI/MCP Schema。界面没有目标时只问作者本次要做什么；不要自行整理全书，不读取未保存稿或私密批注。

发现 `hetu.agent_operations.prepare` 后，可由你填好作品资料、空章节、目录、大纲、设定、分集或任务准备的完整领域输入，保存为固定管理方案。在当前对话展示确切结果、差异与影响；作者已明确要求的范围可以直接如实登记 `hetu.agent_operations.record_decision`，缺少必要决定时在当前对话询问。只在方案已批准、未过期且基线未变时，通过 `hetu.agent_operations.execute` 执行同一方案，再读取原结果。原键恢复，不另准备重复方案。先用 `hetu.agent_operations.catalog` 发现可准备领域动作及完整Schema。采纳、定稿、解锁、封面选用和交付可以在作者确切决定后通过固定方案执行，不能将作品读取授权当作决定。模型费用仍走独立任务费用合同；不能自报作者身份或批准字段。

协作请求可先调用实际任务预览动作，再将完整 `prepare_input` 作为管理方案提交。批准执行后自动登记本客户端派生任务，以返回的 task_locator 打开，按完整 task_ref 继续写作、图片或资料任务。父作品授权撤销或重新授予后，旧派生任务不复活。

已有作品使用作者明确授予的 management_ref，每项请求携带完整授权修订。作品授权与具体操作批准分开，不能借读取范围直接写正文、采纳或定稿。作者已在当前会话明确要求导入指定原稿时，交给[导入 Skill](../hetu-import/SKILL.md)登记完整固定范围并连续执行，不转回桌面批准分卷或批次。机器新建作品由创作库接纳同一作品身份，不要求重新导入或填资料。

整理作品、导入交付、版本或设置时交给[管理 Skill](../hetu-manage/SKILL.md)和[管理工作法](../../references/workflows/management.md)。若实际安装版仍缺动作，准确报告缺口，不用 GUI 自动化或直写受管文件补业务。

## 功能地图

使用河图扩展时先查询 `hetu.plugins.inspect` 的活动Skill摘要，再以精确作品、management_ref和包摘要查询 `hetu.plugins.capabilities`。若实际能力包含 `skills` 及 `resource_actions` 中的 `skills.read`，通过稳定 `hetu.plugins.invoke` 传 `action="skills.read"`、`arguments={"skill_id":"实际ID"}` 按需读完整方法；引用文件以同一skill_id加相对`resource`读取。再按方法发现并执行专业动作，包更新／停用后重新查询。河图包内Skill不等于Codex本地安装的Skill，不新增Codex插件或MCP连接；宿主未提供资源入口时明确报告版本缺口，不猜本机路径。

使用[随包功能地图](../../references/capability-map.json)或已发现的 `hetu_get_capability_map` 按目标定位；需要精确领域参数时再发现实际Schema。在源码工作区使用 `docs/40-机器能力地图与Review清单.md` 与 `contracts/capability-map.json` 定位功能、CLI/MCP入口、Skill与验证证据。地图是导航，当前安装版的 `inspect` 和 `agent_operations.catalog` 是执行时能力依据；源码声明不能替代安装发现和业务回读。
