# 河图洛书 建书构思

## 本次是否需要保存

临时起名、试梗或方向讨论直接回答，不调用筹备、创建作品或首任务动作。作者决定保留、明确要求建立作品或进入持续创作时，才发现并执行最小创建路径；书名、完整大纲和设定未定都不阻断探索。

统一判断见[任务合同](../../references/task-contract.md#参与程度与停止条件)。


先按[统一执行模式](../../references/execution-modes.md)读取实际设置：默认auto直接处理当前工作区，confirm先读后集中确认本次写入。本规则优先于下文旧授权流程，任务引用继续用于定位、来源和恢复。

先读本包的 [任务合同](../../references/task-contract.md)，按固定任务和实际宿主能力继续。 已有任务先恢复阶段、固定成果及公开意见；返工沿原任务，完成后回读实际成果。长任务按[接续方法](../../references/task-contract.md#发现继续与恢复)记录未完成范围。

创作时结合[本包题材方法](../../references/genre.md)中对应环节的增量；只使用作者已选题材，不从其他已安装套件拼接规则。

## 本次构思

没有作品或任务时，先发现当前 CLI/MCP 的筹备入口，按作者意图准备独立筹备及必要字段；不要让作者先去软件填写表单。已有筹备按原引用恢复。只使用实际发布的能力，入口缺失时明确指出缺口，不以 Computer Use 代替机器接口。

实际发现 `hetu_begin_creation` 时，以 brief、locale 和原操作键开始筹备。保存返回的 `management_ref`、筹备身份、修订摘要及预留 `target_path`；保存资料和创建继续携带该管理引用。有限新建只支持这个全新受管目录，不能悄悄改到其他目录；作者明确要求其他路径时准备精确授权方案。创建成功回读 `workspace_management_ref`；作者明确需要章节、分集或持久任务时才准备对应内容，再以真实返回的 `task_locator` 打开。正文写入参考稿，管理权限不能直接填正文或替作者采纳。

1. 读取筹备 brief、selected_fields 和固定快照中的 work_profile，提取作者已确定内容、允许探索的字段与保留要求。按小说／剧本、原创／改编及正文语言开展构思；缺少类型时先核对，不从题名猜测。
2. 读[建书构思工作法](../../references/workflows/creation.md)，把点子拆成人物目标、当前压力、对抗、选择代价与持续推进机制。
3. 按任务数量提供可比较方向；差异应落在人物选择或故事机制，不能只换书名。需要题材或人物专项时，从[方法导航](../../references/writing-methods.md)选择相应资料。
4. 复核作品承诺能否落到具体事件，区分既定事实、新建议和需要作者决定的真相或规则。

## 交付

书名、简介和大纲按 selected_fields 分离，保留已有确定内容。候选带本次来源基线，格式以 output_contract 为准。只讨论方向时不顺带写正文。作者决定方向后，Agent 填好创建资料、提出明确新目录并通过实际机器动作准备和执行；需要作者确认时展示完整方案及影响，复用真实决定引用，不要求作者转填表单，不自报已批准。创建后回读真实身份及原操作，按明确新范围继续首个任务；禁止覆盖既有目录或把筹备权扩大为整库权限。

## 题材定位与套件引导

作者尚未确定方向时，帮助区分目标平台、读者频道、主类型、叙事机制、篇幅和CP约定；只问影响选择的问题，不按性别套剧情。清楚说明定位与理由，由 Agent 准备筹备题材字段。只推荐实际目录中的套件ID，不编造插件名或声称已安装；明确选择后按发现的获权安装入口继续，不要求作者转抄命令，不全量安装分类，不为更换套件重新生成已有任务。
