# 诊断、选区改稿与返工工作法

## 先保存作者要保留的东西

核对固定原文、revision_id、edit_scope 和任务目标；识别原文的视角、时态、叙述距离、句子节奏、人物动机与作者明确要求保留的表达。参考章节只用来理解上下文，不取得修改权。公开批注与实际保存的选择可以作为返工依据，私密意见缺失时不补猜。

## 按症状定位根因

| 症状 | 先查什么 | 优先修复什么 |
| --- | --- | --- |
| 人物突然冒险或失去原则 | 动机是否足以承担风险，转变前发生了什么 | 压力、触发、备选路为什么不可行 |
| 情节推进像巧合 | 关键条件是谁通过什么行动造成的 | 前置铺垫和可追溯的因果 |
| 争吵、战斗后像没发生 | 资源、关系、认知或风险是否改变 | 当前允许范围内可表现的实际后果 |
| 中段拖沓 | 重复信息，目标断裂，尝试没有变化 | 删重复、恢复目标、改变策略或代价 |
| 对白像解说、角色声音一样 | 各自目的、隐瞒、话语权与语言习惯 | 行动性、潜台词和声音差异 |
| 文句“像 AI” | 模板反应、空泛总结、意象和句式重复 | 针对原文问题具体修改，保留作者个人表达 |
| 反转生硬 | 可见线索、知情边界、揭示后的变化 | 当前选区内能补的铺垫或解释；越界问题另提建议 |

场景因果与表达问题可用[场景工艺](../craft/scenes.md)进一步定位；人物知情与关系问题读[人物工艺](../craft/characters.md)。结构问题优先于修辞，但修改范围优先于结构调整；修复需要改前章或新增设定时，说明限制并建议作者另建任务。

## 证据与最小修改

每个重要问题提供原文位置或短引句、读者会遇到的具体困难、修复目的。区分必须处理的事实冲突、收益明确的建议和作者风格选择，不给作品打无依据的精确分数。作者只要求诊断时不提交改写；已明确要求改稿时，在范围内直接完成可确定的修改。

反例：“这一段不够高级，全部换成更有文学性的表达。”

改进：“人物刚承诺保密，下一句就主动透露姓名，选区内没有解释。保留透露结果，补出他用姓名交换证据的条件，让选择与此前动机衔接。”若交换条件不在既定设定中，应提供为候选并说明新增。

## 补丁与验收

- 以任务原文字节计算 UTF-8 byte_start、byte_end；不能把字符数、UTF-16 索引或当前编辑器文本当偏移。
- 每处 replacement 对应原基线，补丁不重叠且完全落在允许范围。保留选区外字节及原换行风格。
- 格式与字段以实际 output_contract 和工具 Schema 为准；不要在补丁外附“顺手修改”的正文。
- 对照补丁后的候选检查人物、因果、指代、时态和前后连接，并重新核对本轮具体修改要求。
- 基线已变化时仍保留原基线候选，不猜新的偏移。返工关联父候选，不覆盖父稿，也不声称已采纳。

交付时简述改了什么、为何改、仍有哪些需要作者决定的事项。词数或禁词扫描只能提示问题，不能证明风格、逻辑或原创性已经通过。
