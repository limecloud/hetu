# 总纲、卷纲与章纲工作法

## 先锁定粒度

| 层级 | 需要解决的问题 | 有用的交付结构 |
| --- | --- | --- |
| 总纲 | 主角为何行动、核心冲突怎样改变他、结局回应什么 | 起始处境、关键选择、局面变化、高潮与结局方向 |
| 卷纲 | 本卷兑现什么、怎样从上一卷抵达、留下什么 | 卷目标、主要对抗、压力升级、中段变化、卷末结果及后续义务 |
| 章纲 | 本章具体发生什么、为何接在此处 | 视角、时间与地点、目标、阻碍、选择、代价、前后状态、结尾承接 |
| 场景卡 | 如何把一个节点演出来 | 入场状态、人物目的、行动反应、转折、离场状态 |

先读当前任务快照中的既定设定、目标节点和作者要求。不因请求“补第十章章纲”而重排整卷；只请求结构讨论时，交讨论结果即可。

## 规划步骤

1. 写出主角当前目标和必须面对的矛盾，区分作者要的故事结果与人物当下知道的事。
2. 建立因果链：前一选择造成下一处境，新的阻力逼出下一选择。不能连续靠巧合投递关键证据或让角色无理由降智。
3. 为请求覆盖的节点标注故事时间、持续时长和相邻节点间隔；倒叙与并行线明确标识。时长未知就说明估计，不能编造精确行程。
4. 使升级改变局面：资源、关系、风险、目标或认知至少有适合本段的变化。平静场景也可承担反应与决定，不强求每场爆点。
5. 对照前文承诺、线索和未解决问题，说明本轮新增、推进、兑现或继续保留什么。暂未提供的全书材料不宣称已检查。

长篇单元、信息回收与中段压力见[结构工艺](../craft/structure.md)，节点细化用下方模板；避免把电影页数机械换成章数。

## 节点模板

~~~text
节点／章节：
来源与承接：
视角、地点、故事时间与跨度：
人物想要什么：
阻力及人物能得到的信息：
选择与为何不选其他路：
具体发生的变化及代价：
需要前置铺垫／本章兑现：
结束状态与下一节点的问题：
既定事实／建议新增／待作者裁决：
~~~

模板用于推演；输出格式、字段和候选数量始终服从当前任务，不能要求 Core 接受模板中的新字段。

弱例：“两人争论后握手，主角得到线索，进入下一章。”

改进方向：说明争论双方各自保什么、线索为何此时能交出、交换条件是什么、得到线索后谁的处境变差。没有后果的争论和无成本得到的证据不能承担本章主要推进。

## 调整与检查

修改既有大纲时列出受影响节点、人物动机、时间与伏笔，优先给最小改动；跨越请求范围的结构问题只提出建议。检查结局能否由前文选择支撑、关键规则是否在使用前建立、人物关系与伤病资源是否承接。产物是大纲候选，不新增正式章节、不改设定、不替作者确认真相。
