# 从小说到短剧

“他终于明白，眼前的人一直在骗他。”小说可以这样写。到了剧本里，你会让他摔杯子、追问一句，还是笑着把门关上？

先用一章原文、一场戏，试出你想要的表达。原著与剧本分别保存，通过确定的原著版本关联；从零写原创剧本或继续旧稿，先看[选择你的创作路径](creative-paths.md)。

## 让 Agent 准备改编，你回来读戏

可以说：“沿已导入的小说继续，先核对已有分集和任务。用第一章试写一集完整剧本，保留秘密，不替换原著。列出压缩、重排与新增的地方。”

Agent 先回读已有稿件与决定，再组织分集、行动和对白。回来先读完整剧本，再看原著对照；骨架只说明结构，完整剧本还需要真正可读的场景与台词。只完成一集时，不把它称为全书改编完成。

指出具体位置，例如：“这句解释太早，只改这一场，保留其他段落。”沿原任务返工，比较新版再选择局部采用与独立定稿。具体见[剧本与分集审阅](screenplays.md)。

## 先找出，这一场究竟发生了什么

让 Agent 从获权原著中整理关键事件，并保留原著版本和引文。先读原文：人物做了什么？谁知道这件事？哪些已经写出，哪些只是推测？

再核对当前稿。正文改了，旧整理结果不会自动变成新分析。[桌面界面预览](/#prototype)可查看当前阅读与剧本工作面；官网不创建本机剧本文件。

## 章节不等于一集，地点也不等于一场

让 Agent 整理场次结构，核对地点、日夜、剧情事件与原著来源。

可以用三个问题检查一场戏：

1. 人物进场时，最想得到什么？
2. 什么让他得不到？
3. 离场时，局面发生了什么变化？

这三个问题是写作练习，不是软件自动打出的分数。你可以合并几章里的事件，也可以把一段关键冲突拆开推敲。桌面客户端提供结构编辑、拆分、相邻合并、重排和来源映射；重新建立候选会保留已有人工结构。

## 把“心里明白”，写成“观众看得见”

结构理顺后，让 Agent 准备独立剧本并保留来源，不必重填已经讨论好的标题与资料。手动从骨架建立可编辑剧本也保留可用，剧本使用独立的Fountain正文。

例如，原文是“她很生气”，先不要只把它换成角色喊“我很生气”。试着写一个动作：她把两副碗筷收成一副，把另一只碗放回柜子。这个动作是否适合你的人物，由你判断。

新增对白、压缩时间、合并场次，都可能是有价值的改编。把变化与原著对照着看，才知道自己保留了什么、又创造了什么。独立剧本有自己的正文与修订，初稿结构映射会保留，正文变化后另行提示映射过期。

## 一场戏之后，顺手记下三类资料

人物穿什么、场景是什么状态、关键道具长什么样，往往会影响后面的画面连续性。让 Agent 整理已有资料、固定所用版本，再按需准备缺少的参考。人物与场景分别归属，具体见[资料更新与影响核对](references.md)。

继续到画面时，先看[从预演到成片](video.md)：用适合当前问题的预演，再核对真实片段、声音、字幕和工程。

完成一次对照后，继续看[检查与草稿审核](review.md)：参考稿里只有半句合意，也可以只采用那半句。
