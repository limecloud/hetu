# Privacy and permissions

Your works are stored by default in local folders you choose. Hetu being open source does not make your novels, scripts, images or videos public.

When using an Agent or generation service, check which works and materials it may process and which operations it may perform.

## Understand where content goes

| Situation | Where content goes |
| --- | --- |
| Reading, editing and saving on Mac | Your work folder and necessary local application state |
| Homepage workbench demo | Sample data in the current page, reset on refresh |
| Sharing with an external Agent | According to the host's authorization and material actually provided |
| Using a model service | Approved fixed inputs are sent to that service |
| Backing up, syncing or delivering | The destination and scope you confirm |

External clients and services have their own privacy policies and terms. Review what the current task really needs before sending material. Revising a few lines need not involve the whole novel.

## A connection does not open the entire library

A stable connection gives the Agent a machine interface. Each task still needs a specific work and scope. Linked novels, scripts and videos do not automatically share permission.

You can say: “Read only episode one and this character profile. Prepare dialogue references without changing the novel or viewing other works.” Ask the Agent to explain its actual access before continuing.

Revoking access prevents old tasks from automatically becoming valid through a new connection. To continue, check the precise scope and valid task again. You retain access to your own historical work records.

## Reference access and editing are separate

Permission to refer to a chapter is not permission to replace it. Identify editable passages, reference-only material and content that must remain.

An Agent can prepare candidates and complete proposals. You review the results and decide on adoption and finalization. Formal story facts, cover selection and final video confirmation have their own decisions rather than a blanket approval.

When using other tools to access folders directly, check the host's permissions too. A story-bible lock is not a replacement for operating-system file protection.

## Provide local files for a specific purpose

For manuscript or asset imports, explicitly select the files or authorize the host to read and submit their contents. Work-management access does not allow the application to read arbitrary local paths.

You can prepare a redacted copy of sensitive material. Confirm the version needed before import and preserve the original. See [Import an existing manuscript](import-manuscript.md).

## Rights and external processing are different

Adaptation rights still require checking whether the source can be sent to an external service and whether its text, reference art or source assets can be included in a delivery.

A public-domain story may use a protected modern translation, illustration or commentary. Keep separate source and rights notes. The software records your declaration rather than certifying copyright.

## Keys, support reports and remote copies

Custom model keys stay in local private storage and are excluded from works and Agent readbacks. For support, provide the app version, error and redacted steps without credentials or private manuscripts.

Before remote synchronization, confirm the destination and visibility. Removing a library registration, deleting work files and deleting a whole workspace have different effects. Review linked works before acting.
