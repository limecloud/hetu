# Troubleshooting and recovery

Preserve the current draft and original task before investigating. A working connection, saved feedback, finished generation and adopted result are different outcomes.

Resume with the original work, task or plan. Creating an identical task rarely explains the old outcome and can introduce duplicates or additional costs.

## The Agent or Skills cannot be found

Check which client is selected for this work and what the client's current session has actually loaded. Installed files do not establish that an active conversation has loaded them.

If Hetu shows an installation but the assistant cannot find the methods, check the exact Agent, suite version and the host's reload procedure. Do not repeatedly install every genre suite.

See [Choose and install Skills](skills.md) and [Work with external agents](agents.md).

## The assistant answered, but no draft appears

A conversational answer does not establish that a result was saved to the work. Have the Agent check whether it returned the result through the tools, which object and task it belongs to, and read it back.

If the author draft is empty, look for an existing reference draft. These remain separate; do not automatically adopt a candidate just to display text.

Likewise, feedback marked as received does not prove that revision is complete. Inspect the original task for new results and errors; see [Give feedback and revise](feedback.md).

## There is a version conflict

Keep unsaved text before refreshing and comparing the current revision. Another window or Agent may already have updated the same object.

Do not overwrite newer work from an old view or delete records to remove the warning. Have the Agent prepare a new comparison against the current saved version and recheck the allowed editing scope.

Feedback about an old passage still belongs to that revision. Select the current text again instead of silently applying old coordinates.

## Generation timed out: should I try again?

Query the original plan and provider job first. An unknown result is not a confirmed failure; the service may still be processing.

| Status | What to do next |
| --- | --- |
| Waiting or processing | Query progress on the original plan |
| Completed but absent locally | Check the handoff, files and original task result |
| Confirmed failure | Retain the error and determine the cause before another proposal |
| Insufficient allowance | Verify account and budget, then continue checking the original plan |
| Unknown outcome | Keep the original reference and avoid another paid task |

Read [Model services and costs](model-services.md). Stopping local tracking does not establish an external cancellation or refund.

## An image or video will not open

Check that the original file exists and is complete, and whether its source URL has expired. A download receipt does not prove the media can be decoded. Have the Agent inspect the actual file, then view it in Hetu.

Retain the currently selected version and evidence of the problem rather than overwriting the only copy. Listen to video audio too; readable frames are not a substitute for full playback.

## A connection expired or a work is inaccessible

Check the current account, work and task scope. Reconnecting should not automatically give an old task new permissions. Linked works require their own authorization; see [Privacy and permissions](privacy-and-permissions.md).

If the model service needs another sign-in, begin in Hetu, verify the website code and account, then return to query the original plan.

## Installation issues and support

Check the Mac system, chip, app version and official release attachment. Do not disable system protection to bypass an installation warning. See [Get Hetu for Mac](install.md).

When opening a [GitHub Issue](https://github.com/limecloud/hetu/issues), include versions, reproduction steps, expected and actual results, and a redacted error. Check screenshots for private text, keys, account details and personal paths.

After recovery, open the affected chapters or media and confirm completeness. Keep an independent backup; see [Your work, versions and backups](data-and-backup.md).
