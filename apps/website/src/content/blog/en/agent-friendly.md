## Three useful contributions, three different versions

You renamed a character on Monday. A script editor revised the scene on Tuesday. On Wednesday, your Agent returns dialogue with the old name and a costume reference from the previous draft.

Everyone contributed something useful. Nobody was working from the same material.

Better generation helps produce alternatives. An independent author moving a manuscript toward a screenplay also needs a way to keep sources, revisions and decisions understandable between those alternatives.

## Where creative software earns its place

In [“Are enterprise applications finished?”](https://mp.weixin.qq.com/s/PL0SOae0-LBzLGE8L0TUDw), Feng Ruohang argues that value may concentrate at two ends: general agents that understand and execute intent, and systems of record that preserve business state. Interfaces and fixed workflows between those ends face pressure.

That is an argument about where software value may move, not proof that every application will disappear. One insight applies directly to creative work: easier generation does not remove the complexity of the work being generated.

For an author, the durable state is concrete. Which version of the novel did the script editor use? Was that character change approved? Which part of a proposed rewrite entered the manuscript? What exactly was delivered?

A local creative workspace can preserve those answers in readable files and revision records. It does not need to become a cloud database or another general Agent runtime.

## A change to the family reveal

Imagine adapting your own mystery novel. In the first draft, the protagonist's sister conceals their family history. Later, you decide the mother should hold that secret instead.

A capable Agent can explore motives and propose new dialogue. The decision also raises questions across the project:

| What changed | What deserves another look |
| --- | --- |
| The keeper of the secret | Who could access the letters, and who had a reason to lie |
| The family relationship | Whether anger, dependence and forgiveness still make sense |
| The medium | Which internal thoughts become actions or visible evidence |
| A collaborator's source | Which draft the script editor has, and what changed since it was sent |

This is a way to examine adaptation work, not a claim that software can infer every consequence automatically. Recorded references can establish definite version relationships. Character motivation and dramatic force need interpretation and judgment.

The workspace should help you return to earlier decisions while making the next one.

## Preserve the relationship, not just the file

“The same jacket” might mean several competing designs. If it belonged to the protagonist's father, its torn sleeve may carry both wardrobe information and emotional weight.

Useful project records distinguish the selected design, the passage or scene using it, and the version each refers to. Those records let a writer and a production collaborator understand why an earlier choice was made.

Hetu separates reference drafts, working manuscripts and author finals. Receiving a candidate offers a possibility. Adopting a passage changes the working manuscript through an explicit author decision. Finalizing confirms a particular saved revision separately.

A later model, client or collaborator can then work with what the author has already saved. An old conversation does not have to be the only place the project makes sense.

## General intelligence, durable project state

General agents require sustained investment in reasoning, context management, tool use and recovery. Products such as Codex and Claude Code specialize in that work.

Hetu concentrates on the creative material they work with. External agents understand, plan and generate; the shared core manages project state and deterministic rules; the native app supports human reading, editing and decisions.

| Entrance | A practical contribution |
| --- | --- |
| MCP | Query authorized sources and tasks, submit candidates and retrieve feedback |
| CLI | Discover capabilities, execute scoped operations and recover an original result |
| Skills | Supply task methods, genre guidance and handoff instructions |
| Native app | Compare text, edit manuscripts, select references and finalize a revision |

These entrances share project facts, permissions and revisions. Host support is verified separately: installed files, session loading, connectivity and an actual creative task establish different things.

Hetu does not call model APIs, hold model keys or run an internal chat-and-generation loop. Its current genre-method packages are written in Chinese; the English catalog explains their scope rather than promising localization for every market.

## Organization should leave room for craft

For a short standalone piece, a file and an Agent may be enough. A workspace earns its place as drafts, references, adaptation choices and handoffs become harder to keep straight.

That is also a design constraint. Authors should not have to complete a database-shaped form before writing a scene. Structure should support continuity and revision, with details appearing where they help someone make a decision.

An Agent can offer several openings, all of which the author may reject. Manual creation remains a complete workflow. Taste, voice and the choice of what to leave unsaid remain part of the author's craft.

## Work you can keep developing

Hetu is free and open source under Apache-2.0. Manuscripts and assets live in the creator's workspace and retain their own rights. External agents and generation services have separate costs, data policies and terms. Managed application permissions cannot constrain other programs with unrestricted access to the same files.

Open source and open interfaces are commitments, not proof of a useful product. The practical test is whether the next revision is easier to understand, choose and continue.

> As AI grows more capable, let it work with the body of work you build over time. Let every generated draft become something you can understand, choose from and continue developing.
