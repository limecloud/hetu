# 工具可以生长，作品始终在你手中

写到第二十章，林乔终于知道了周远的身份。你想请 Agent 重新整理人物关系，却发现它读到的是第八章的笔记。图画得很漂亮，关系也解释得通，只是已经不属于你正在写的故事。

创作工具首先要解决的，是让这次工作接上真正的作品。至于用一段文字、一张关系图，还是一条时间线来理解它，应当由眼前的问题决定。

## 先让作品站得稳，再让工具长出来

小说、剧本和视频可以各自开始，也能沿明确来源联系起来。无论打开哪种工具，作者都需要知道：它读了哪一版，改动了什么，哪些内容只是建议，哪些已经由自己决定采用。

这些规则适合由稳定的软件负责。作品身份、来源、修订、授权、保存与恢复，不该每次重新猜一遍。

但不同作者需要的专业表达差别很大。有人想沿人物关系排查秘密，有人要核对二十年间的事件先后，有人只需要连贯地读完一章。把所有深度工具固定塞进同一套界面，会让作者在开始创作之前，先学习一堆操作。

河图选择保留稳定的作品底座，让专业工具按需加入。

[小说规划](/plugins/novel-planner/)把这条边界落在长篇创作里：各卷的目标、主题、冲突与详细剧情在同一工作面阅读，人物、地点和伏笔按需关联。Agent 整理结构，作者沿卷列表检查和修改；正式目录、正文与设定仍复用宿主能力，不另造一部小说。其开发预览提供固定运行包与具体验收范围。

## 可以有画布，也不必先学会画布

人物关系图可以是一张图，时间线可以是一组事件；其他创作问题也可能更适合图片、表格或专门的视图。表达方式不应只有一种。

自由也不意味着要求作者亲手搭建每个界面。你可以对 Agent 说：“只整理女主目前知道的人物关系，不能确定的先问我。”它发现当前可用工具，在获准范围里读取、整理、保存并回读。你回来检查，指出不对的连线，再接着调整。

[导演布景台](/plugins/director-stage/)把同样的方法用于空间与镜头：Agent 安排人物、家具、机位和关键帧，作者观看真实白模预演，再说“等他走到桌边，再切近景”。场景、意见与新旧版本保留在同一作品中；可接续工程和最终画面仍分别判断。

亲自编辑始终可用，但不成为使用专业工具的门槛。作者承担创作判断，软件和 Agent 承担能够确定执行的操作。

## 每次生成，都不必重新造一套软件

动态生成界面能帮助人理解复杂结果。Google 的 [A2UI](https://github.com/a2ui-project/a2ui)采用 Agent 描述界面、应用使用受控组件渲染的分工，也不等于让模型每次输出任意网页代码。

生成速度、模型费用和正确性会随技术进步变化；没有一种界面天然最省成本。对于反复使用的关系图、时间线或审阅操作，复用经过验证的布局与保存逻辑，可以减少重复生成和反复纠错。Agent 把精力放在这部作品的具体问题上。

河图的价值也不只存在于模型昂贵的时期。模型越强，作者越需要把大量成果接回可理解的作品，保留依据、差异和自己的选择。界面可以动态变化，这些作品规则仍然需要持续存在。

## 河图插件与助手插件，分别解决不同问题

[河图创作插件](/plugins/)安装在河图里，提供视图、专业数据或操作。人物关系图与故事时间线是具体例子。

Skills 和客户端接入包安装在你使用的 Agent 环境里，为它提供方法和连接。一个新的河图插件，不需要再对应一个 Codex 插件。已连接的 Agent 重新发现当前安装与获权能力，就能判断下一步怎么做；模型不会凭空知道刚装了什么。

两者之间的连接依靠清楚的能力与数据合同。可信河图插件启用后使用公开宿主能力；外部 Agent 的作品连接仍独立管理。关系图编辑、正文采纳与作者定稿各有明确规则。

## 开放生态，从可核验的小工具开始

[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)把插件、包分发和索引分开：开发者可以通过 npm 或固定 Git 提交分发，静态索引帮助发现，本机管理器执行安装。值得借鉴的是清楚的边界和较低的参与成本，而非一个看起来庞大的数字。

河图采用 GitHub 源码与收录协作、官网精选目录和本机受管安装的分工。开发者用 JS／TS 和 React 开发，插件自己维护功能清单，目录链接到真实来源、版本和权限。能校验、能运行、能解决一个创作问题，分别提供证据。

一个有用的插件，可以只解决一个反复出现的小问题。先让它在一部作品中可用，再让更多作者选择它。工具可以不断增加，作者不必接触自己用不到的复杂度。

从[插件中心](/plugins/)找一件当前用得上的工具，或沿[开发指南](/docs/plugin-development/)与[发布指南](/docs/plugin-publishing/)把自己的方法做成工具。它最终应该帮作者更清楚地看见作品，并更有把握地决定下一步。
