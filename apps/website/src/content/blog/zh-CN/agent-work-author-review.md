## “保留结尾，只改中间那场争执。”

一章参考稿读下来，你喜欢最后那盏没有熄灭的灯，却觉得人物在雨中的争执太直白。你想说的可能只有这一句话。

接下来，找文件、复制原文、重新说明人物关系、填一张改稿表，再把结果贴回章节，这些操作不该耗掉你刚刚作出的判断。

在河图洛书中，你把意见交给熟悉的 Codex、Claude Code 或 WorkBuddy。Agent 沿原任务读取具体稿件和意见，准备下一版；你回来比较改动，看结尾是否保留，争执是否写出了人物的分寸。

创作可以反复推敲，交接应该顺手。

## 从一个想法开始，资料交给 Agent 整理

“想写一部发生在即将停航的渡口的小说，还没想好书名。”

这就可以是起点。你与 Agent 讨论主角想守住什么、渡口为什么停航、故事靠什么继续推进。它整理方向、拟书名、准备简介与大纲，把讨论变成可以比较的方案。

作品资料需要的字段，由 Agent 填好。你审阅的是故事方向和保存方案，不必把对话中的内容重新输入另一张表。明确本次创建范围后，Agent 完成建书，继续准备卷章和首章参考稿。

小说、原创剧本和小说改编各有合适的起点。编剧可以直接从人物、分集和场次开始；改编则保留原著及所用版本，不必为了建项目先造一本空小说。

## 打开软件，先看值得你判断的内容

河图洛书桌面端首先是一张可视化审稿台。

你可以阅读正文与参考稿，比较两个开场，对照改编与原著，查看人物资料和封面候选。哪些是新建议，哪些是已有设定，哪里沿用了旧版本，放在具体成果旁边理解。

收到一稿，不意味着已经采用；采用一段，不意味着整章定稿。你可以留下结尾，拒绝新增人物，只采用一段，也可以看过之后按照自己的方式重写。定稿是对某个已保存版本的独立决定。

编辑器始终可用。想亲自调整一句话、一场戏，或者独立写完整部作品，都不需要先请求 AI。

## 当前这一页，也能交给 AI 继续

书库、章节、剧本、资料、素材、版本和交付，都属于同一部作品的工作。

| 你眼前的事 | 可以交给 Agent 的目标 | 你回来审阅什么 |
| --- | --- | --- |
| 章节顺序乱了 | “把渡口争执移到第二卷开头，保留正文。” | 新目录与原目录的差异 |
| 人物资料有几份 | “整理这些资料，列出冲突，先保留不同说法。” | 来源、矛盾和采用建议 |
| 封面不合适 | “保留雨夜渡口，人物缩小一些。” | 等比预览、候选差异和选用结果 |
| 想交稿给编剧 | “准备已定稿章节、分集剧本和人物资料。” | 所选版本、材料清单及导出结果 |

页面提供当前对象的 AI 操作提示，已有任务带着原稿、意见和版本继续。Agent 负责把目标整理成软件能执行的操作，你不必先学会每张表怎么填。

## 操作交接清楚，作品才能接着往下写

Agent 通过 MCP 或 CLI 直接操作河图的创作底座，Skills 提供相应的创作方法。正文、资料、任务、版本和作者决定保存在同一套作品记录中，桌面端展示这些成果。

这让不同 Agent 可以使用同样明确的入口，减少反复寻找按钮、搬运内容和核对窗口状态。遇到中断，先找回已有稿件与原操作；不会因为换了一个会话，就理所当然地再建一本书、再交一份稿。

需要你作决定时，Agent 先准备完整方案，河图呈现具体影响。你确认的是这次改动、这份材料或这个版本；它不会因此获得整座书库的权限，也不会替你批准下一次修改。

## 把品味与判断留在作者手里

资料整理、格式转换和交付准备可以交给工具。人物为什么沉默，这个结尾是否过满，哪一句话才像你写的，仍然值得你慢慢决定。

河图洛书不在软件里再放一个聊天助手。你继续使用熟悉的外部 Agent，让它围绕自己持续积累的作品工作；回到河图，把成果看清楚，再决定怎样继续。

> 让越来越强的 AI，围绕作者持续积累的作品工作；让每一次生成，都有机会成为可理解、可选择、可继续创作的成果。

可以先在[首页工作台](/#prototype)比较一份参考稿，试着只采用一段；也可以阅读 [Agent 接入指南](/docs/agents/)，把自己的助手带到作品旁边。
