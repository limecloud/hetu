## 电脑里，是不是也躺着一个“最终版3”？

“剧本最终版”“剧本最终版修改”“剧本最终版3”。旁边还有几张人物图、一份旧设定，以及一段你明明讨论过、却怎么也找不到的聊天记录。

你改掉了人物姓名，Agent 仍在用旧名；改编编剧调整了出场顺序，美术却照着上一稿准备造型。每个人都做了工作，作品却没有顺着往前走。

模型越来越能写，这种麻烦为什么还在？因为写出一个方案，和让一部作品持续成立，是两件都需要认真处理的事。

## 通用 Agent 变强之后，创作软件留下什么

冯若航在[《企业软件要完了吗？》](https://mp.weixin.qq.com/s/PL0SOae0-LBzLGE8L0TUDw)中提出一个值得讨论的判断：软件价值可能向两端集中。一端是理解意图、规划与执行的通用 Agent，另一端是承载真实业务状态的记录系统。大量夹在中间的操作页面和流程包装，会受到挤压。

我们认同其中一个关键提醒：**业务复杂度不会随着生成变容易而消失。** 这不等于所有软件都会消失，也不等于每个创作工具都需要一座云端数据库。

对作者来说，需要长期保存的事实很具体：这条设定是谁确认的，这场戏依据哪一版原著，这份参考稿用了哪里，这次交出去的究竟是哪一稿。

Codex、Claude Code、WorkBuddy 等产品持续投入理解、推理、上下文管理、工具使用和执行恢复。河图选择承接它们工作之后应当留下的东西：作品、来源、修订，以及作者作出的决定。

## 把“姐姐”改成“母亲”，会牵动多少处

设想一部悬疑小说。初稿里，姐姐隐瞒了主角的身世。写到后半部，作者发现让母亲隐瞒更有力量，决定重新组织这条情感线。

Agent 可以提出人物动机、重写争执，也可以给出几种揭晓方式。但作者接着会遇到这些问题：

| 创作中的变化 | 需要重新判断的地方 |
| --- | --- |
| 隐瞒者换了 | 前面谁有机会接触信件，谁有理由撒谎 |
| 亲情关系变了 | 主角的愤怒、依恋和原谅是否仍然成立 |
| 小说改成剧本 | 哪些心理活动要转成动作，哪一集揭晓更合适 |
| 已有一版交给编剧 | 对方看的是什么版本，需要说明哪些新决定 |

这是一组创作问题的例子，不是软件能自动查全全书影响的承诺。明确的来源与版本关系可以由软件维护；人物为什么这样做、哪种处理更动人，需要作者与所选 Agent 继续推敲。

工程化的意义，是让这些讨论有据可依，让你改第十场戏时，仍能找回第一场的决定。

## 保存文字，也保存“为什么是这一版”

一个文件夹可以放下小说、剧本和图片。作品能否继续协作，还取决于它们的关系是否清楚。

一件父亲留下的旧外套，可能同时是人物造型和情感线索。“用旧外套那张图”不够具体：采用哪一版，哪场戏需要它，袖口什么时候破损，后来换衣是不是剧情决定，都值得留在作品里。

河图把参考稿、作者正文和定稿分开管理。收到方案，是多了一种可能；作者采用，是把选中的部分写进自己的稿件；定稿，则是独立确认某个已保存版本。三者有各自的记录。

这样，下一位协作者接到的是可以继续工作的材料。模型换了、会话中断了，作者已经保存的文字和决定仍在。

## 开放入口，让智能围绕作品工作

MCP、CLI、Skills 与桌面客户端，是进入同一创作底座的不同入口。

| 入口 | 放进一次创作任务里理解 |
| --- | --- |
| MCP | 在许可范围内查原文、读资料、交候选、回读作者意见 |
| CLI | 发现可用能力、执行明确操作，结果不明时回查原操作 |
| Skills | 提供题材与创作方法，说明任务应如何完成和交接 |
| 桌面客户端 | 让作者读原文、比方案、改文字、选素材和确认定稿 |

权限、版本冲突、采纳和恢复需要软件执行明确规则。品味、人物理解与创意需要留给人及其选用的智能助手。把责任放清楚，作者才不必每次从聊天里重新拼出整部作品。

插件和 MCP Apps 的支持情况按宿主版本与实际任务核对。安装文件、当前会话加载和实际完成任务，需要分别验证。河图不内置模型调用、模型密钥托管、聊天或自动生成循环。

## 让创作更有秩序，也要让作者更轻松

如果一篇短文，用文件和 Agent 就能顺畅完成，没有必要为了“工程化”先建立一大套表单。

长篇、多稿和改编中的关联越复杂，软件越应当在背后承担版本、来源和交接工作，让作者在需要时看得见，而不是把内部模型一股脑摆到眼前。作者可以自己写完整部作品，也可以只请 Agent 查一条资料、试两个开场，最后全部不用。

[《2024中国网络文学蓝皮书》](https://image.chinawriter.com.cn/n1/2025/0630/c404023-40511500.html)记载，重点网站当年新增微短剧改编授权超过 **{{china.new_drama_licenses}} 部**。它说明故事跨媒介流转已是现实工作，不能据此推算某部小说一定能改编或获得收入。

我们希望补齐的是这种工作中的组织和接续能力。你独有的品味、判断、创意与表达，始终值得尊重。

## 免费开源，让积累留在自己的作品里

河图洛书按 Apache-2.0 免费开源。小说、剧本与素材保存在作者自己的目录，软件开源不代表作品公开。外部 Agent 及生成服务可能另行收费，按各自条款使用。

开放接口与开源代码本身，不能代替可靠的创作体验。每个功能都应当回答同一个问题：它能不能帮助作者把已经做出的工作保存下来、看清楚、作出选择，并继续写下去？

> 让越来越强的 AI，围绕作者持续积累的作品工作；让每一次生成，都有机会成为可理解、可选择、可继续创作的成果。

先在[首页工作台](/#prototype)试着只采用一段参考稿，或者跟着[资料更新与影响核对](/docs/references/)检查一次旧外套的变化。“最终版”应当来自你的决定，而不是文件名里的数字。
