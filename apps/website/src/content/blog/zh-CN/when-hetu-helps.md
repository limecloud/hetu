# 什么时候，一个 Agent 和文件夹就够了

“帮我想三个书名。”这样的问题，在你熟悉的对话里就能完成。为了三个名字先创建作品、填题材、安装插件，省下的时间还不够支付这些操作。

河图应该允许你直接离开，带着名字继续写。一次没有使用河图的任务，也可以是正确结果。

## 先从当前的麻烦判断

真正值得处理的，往往出现在第二次、第五次修改。你已经讨论过为什么不让人物道歉，新会话却又写回道歉；上一稿留下的对白很好，这次调整情节时却被一起换掉；给编剧的版本与自己正在改的版本分不清。

这些问题涉及持续工作的依据。河图要帮助你找回稿件、修改意见和已作出的选择，让下一次创作有起点。

## 三种任务，三种参与程度

| 当前需要 | 可以怎样完成 |
| --- | --- |
| 试一句对白、问一个术语、改普通文件 | 当前Agent与原文件直接处理 |
| 查已有作品中的人物或决定 | 按需只读，回答带引用即可 |
| 接续长篇、比较参考稿、按意见返工与交付 | 固定相关版本和来源，在作品中继续 |

这些路径可以随时切换。讨论中出现值得保留的一场戏，再要求保存；查一条设定后没有修改需求，就在答案处结束。

## 可以委托，也可以亲自写

AI-first意味着你不必逐项录入和操作。你可以让Agent在明确范围内连续整理与创作，软件负责可靠保存。已经在对话选好的版本，无需回到桌面再确认一次。

执行与认可仍有区别。保存了候选，不意味着你喜欢它；定稿对应的是你决定的具体版本。

## 用一个小问题试出收益

选一段你准备继续改的文稿，说明“哪里要变、哪里不变”。比较一次接续前后的寻找、解释和纠错成本。如果原有工具已经够用，继续使用它们。

先看[完整审阅例子](/#review-experience)，或读[判断是否适合这次任务](/docs/when-to-use/)。官网示例演示交互，不连接你的真实作品或自动运行模型。
