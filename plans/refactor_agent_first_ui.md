# 重构方案：以 AI 为中心的创作与审核界面 (Agent-First UI/UX)

## 核心定位
`hetu` 软件作为 Agent 执行任务的“审阅与交互工作台”，主要负责：
1. **可视化审阅**：直观展示 Agent 提交的任务计划、生成成果（文字、图片、视频）。
2. **作者决定权**：提供比较版本、审核依据、提出意见、选择采纳及定稿的操作入口。
3. **工作流辅助**：针对审核结果，提供“让 AI 修改/重做/接续”的入口，将需求带回到外部 Agent 对话中。

## UI/UX 重点
- **去生成表单化**：移除在软件内配置模型参数、填写生成表单、进行重复批准的操作逻辑。
- **任务感知**：界面须直接关联当前任务的对象、固定版本及实际能力，提供明确的 AI 处理入口。
- **差异与对比**：突出展示新旧成果差异，方便作者快速决策。
- **一致性体验**：所有操作入口（如“让 AI 处理”、“重做”）遵循统一的交互规范，并携带上下文。

## 实施策略

### 1. 审阅与审核界面重构 (`apps/task-view/`)
- **任务看板**：将当前任务、已生成成果以“审阅流”形式呈现，而非表单列表。
- **反馈闭环**：为每个任务组件添加“提出意见”和“重做/接续”按钮，点击后自动引导至外部 Agent 对话窗口（提示词预填）。
- **媒体预览**：优化视频、图片、文稿的查看器，支持版本比较和帧级/段落级标注。

### 2. 状态与上下文展示
- **信任与状态条**：展示当前任务执行状态（reconciling, succeeded, failed）、费用预算及策略校验信息。
- **操作溯源**：在界面显眼位置提供“来源依据”和“恢复操作”入口，确保作者能追溯任务源头。

### 3. 数据交互与 CLI/MCP 同步
- 确保 GUI 能够实时回读 CLI/MCP 执行状态。
- 实现 GUI 操作（如审阅意见）向 `core` 的同步，以便 Agent 下一次读取时能够获取作者反馈。

## 验证与验收
- **业务接口核验**：确保所有业务能力均通过 CLI/MCP 机器入口调用，而非 GUI 模拟。
- **端到端流程**：验收从“外部 Agent 执行” -> “hetu 接收成果” -> “作者在 hetu 审阅意见” -> “外部 Agent 获得反馈继续工作”的闭环链路。
