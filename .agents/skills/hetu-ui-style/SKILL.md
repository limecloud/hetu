# 河图界面风格

面向小说作者、编剧与短剧创作者，优先展示作品和待审成果。以简洁、清晰、有序的界面支持阅读、比较、反馈和决定。

## 文案与信息组织

- 不使用中点“·”分隔界面文案。并列信息优先以布局和间距分组，短标签可用空格，连续语句用正常标点；不改作者内容中的中点。
- 删除重复标题、泛化教程、实现解释和常驻的冗余描述。空状态只说明缺什么及下一步；错误、授权、费用、版本冲突与未知操作恢复信息留在发生处。
- 文案符合当前作者任务，准确、简短、易懂，避免随意造词、口语化和技术术语堆叠。按钮描述动作，状态描述已发生的事实。
- 删除只起装饰作用的 Eyebrow／Overline，尤其是重复主标题的英文大写眉题；仅保留主标题未表达的必要分类或上下文。
- 按重要性安排内容，主要任务持续可见，历史、技术详情和次要操作渐进展开。减少无效选择；必要决定放在作者正在比较、选用、授权或定稿的位置，不重复要求填写已有信息。
- 作品首页优先呈现封面、已有基本资料和简介，不常驻空候选库、安装检测、路径、摘要或完整配置表单。封面候选进入更换封面，协作设置、目录和版本信息按需展开；审核页不重复提示进入当前审核页。保留必要的失败和原操作恢复信息，不删除作者内容。

## 视觉约束

- 界面控件与表面的颜色使用 Radix UI Colors，通过共享语义变量消费，浅暗主题同步。1–2级用于基础背景，3–5级用于交互表面及柔和背景色，6–8级用于边框，9–10级用于实心强调，11–12级用于文字。中性色承载主体，强调色只用于操作和选中，警告与错误采用对应语义色；避免手写近似色和大面积强调色。窗口背景的渐变按下节执行，不能被旧版“禁止装饰渐变”的规则还原成实色。
- 优先对齐文字基线、图标视觉中心和内容边缘，检查同屏元素的光学平衡。嵌套圆角按外圆角减内间距处理，不机械套同一数值。
- 需要线条或边框时使用 `0.5px`；键盘焦点轮廓保留足够辨识度。图标和实际图形内容不作为容器边框处理。
- 默认无动画。确有反馈或定位价值时，优先 `250ms ease-out`，支持减少动态效果，不添加位移装饰。
- 每页字号最多四档，优先三档，最小 `12px`。先用字重、文字颜色和间距表达层次。工作台默认 `12/14/20px`，文稿使用 `18px` 或作者明确设置的阅读偏好；不要为了装饰引入额外字号。
- 圆角和阴影仅表达控件、纸面或浮层的功能边界。普通内容通过分组、留白和细线组织，不堆卡片，不使用卡片左侧彩色装饰线。浮层圆角与阴影保持克制。

## 渐变背景与材质

作者已要求具有可见渐变的柔和背景。清理工具截图只参考渐变与透明层次，颜色以[官网](https://hetu.limeai.run/)及其实际[色板](../../../apps/website/src/styles/global.css)、[首页背景](../../../assets/marketing/hetu-river-background.webp)为准：纸色、玉色与山水灰。旧 Mac 截图保留布局和交互参考，实色背景不再是材质目标。

- 应用根容器绘制连续、静止的渐变，顶栏、项目导航与内容区共用它；大面积实色 `main` 或不透明侧栏不能盖住背景。不以仅添加 `backdrop-filter`、依赖桌面壁纸或原生 `vibrancy` 代替应用自身的渐变。
- 渐变使用共享 Radix 色板的低阶色及 `color-mix`，浅暗主题分别可读，不照搬参考图的薄荷绿与浅蓝。工作面采用轻透表面承接渐变；正文纸面、编辑器、输入框与决定弹窗保持稳定实色。
- 顶栏、导航和浮层通过共享半透明语义变量表达层次，必要时使用背景模糊；不叠加装饰光球、强阴影或背景动画。透明度不能让后方文字或图像影响识别。
- macOS、Windows、Linux 使用相同的应用渐变与 Web 表面，不将目标效果绑定某一系统的窗口材质。“减少透明度”和“增强对比度”时回到实色背景及表面并关闭模糊，不修改用户系统偏好来测试。
- 创作库可使用与官网一致的纸页山水插画建立识别，浅暗素材跟随应用所选外观，仅在“跟随系统”时消费系统主题；页头紧凑，不把普通工作页改成营销首页。插画不绘制文字、按钮或伪造作品，不重复铺在同屏多个区块；阅读与审核页以真实内容为主。生成素材保存来源模型、提示词及文件摘要，不保存调用密钥。

## 实施与验收

先读当前页面、[共享 Radix 色板](../../../assets/styles/radix-workbench.css)与[交互设计](../../../docs/10-原生客户端与交互设计.md)，保持文档和实现一致。优先修正共享样式及组件，避免追加重复覆盖或复制色板。样式不得改变作品引用、授权、固定修订、采纳、定稿或原操作恢复规则。

检查实际浅暗主题、正常与窄窗口、键盘焦点以及加载／空／错误／恢复状态。确认渐变实际可见、跨区域连续，正文及输入区域稳定可读，半透明导航、浮层和无障碍降级有效。通过真实渲染核对字号、边框、对齐和溢出；截图用于发现视觉偏差，行为验证覆盖展开、返回、未保存稿和必要决定。报告实际验证范围，不以页面可渲染代替完整业务验收。

桌面构建使用仓库实际的 `build:desktop`，根目录 `build` 仅构建官网。核对源码、桌面产物和正在运行实例的路径及版本后再截图；涉及安装版时还须重新装配并回读随包资源。原生窗口材质另看实际窗口截图，网页截图只能证明 Web 层。

还原原生界面时先核对实际制品、截图和对应源码，逐项登记页头、导航、工作面、控件、空状态、弹窗与交互差异。不能只匹配几项宽度后宣布完成。通用页面撑满剩余窗口，标题与动作同排；空状态只居中剩余内容区。窗口缩放、文稿专注和页面导航保持原有语义。缺少实际业务入口时记录缺口，不添加无效按钮或用技术JSON替代正常阅读界面。

作者要求完整复刻或逐项评分时，按实际页面清单循环执行“截图、对照、修正、复拍”，检查布局、间距与对齐、排版、颜色、控件状态和交互六项，每项达到9/10再结束。首页同时检查首屏、滚动中段和底部，覆盖浅暗与窄窗；使用隔离资料，不在真实作品中制造验收数据。默认书封复用现有资产并明确占位身份，不将其登记成选用成果。截图与尺寸断言支持评分，评分属于有依据的设计判断，不能当作自动化像素认证；缺少参考或工具失效的项目明确记为未验证，不能补写满分。已有REA证据按制品摘要复用，运行与截图失败保留原回执，不反复执行没有改变条件的失败调用。
