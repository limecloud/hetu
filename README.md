# 河图洛书 Hetu Luoshu

> 面向网文作者与创作工作室的多作品写作工作台。设定有据，创作有序。

## 简介

河图洛书以作者书库管理多部独立小说，每部作品分别保存资料、封面、卷章、设定集及关联短剧。工作台提供一致性检查、剧情抽取、Git、MCP 与交付流程的规范和原生实现。核心不内置模型或生成 API，作者负责最终审核。

`0.2.0` 交付 Rust 内核、macOS 原生客户端、Swift CLI、独立 MCP Server、双语官网与首页交互演示的源码。原生源码采用 Rust 内核与 C ABI，Swift Bridge 供 Mac 客户端和 Swift CLI 共用；范围与发布门禁见专项设计和验收矩阵。

本仓库是软件源码 Monorepo，用户创作的 IP 内容工作区独立存放。宣传网站位于 `apps/website/`，产品与工程规范位于 `docs/`，品牌资产位于 `assets/`。交互原型不连接真实工作区，应用安装包独立于设计材料交付。

## 快速上手

### 网站

网站使用 Node.js `>=24.21.0 <26` 与 npm。以下命令在仓库根目录执行：

```bash
npm ci
npm run dev
```

访问 `http://127.0.0.1:4350`。`npm run check` 执行类型检查，`npm run build` 构建静态产物并检查链接、双语资源与文件限制。浏览器验收命令见[网站说明](apps/website/README.md)。

### 原生内核与 CLI

在 macOS 上使用 Rust `1.93.1`、Swift `6.2+` 和 macOS SDK。构建脚本只使用本机已安装且版本匹配的 Rust 工具链，依赖由 `Cargo.lock` 固定。

```bash
python3 "tools/build-native.py" --test
open "build/native/Hetu.app"
".build/debug/hetu" --help
```

Rust 内核位于 `core/`，Swift 桥接位于 `bindings/swift/`，CLI 位于 `apps/cli/`。动作及输入合同由 `contracts/actions.json` 与引用的 Schema 定义，`hetu capabilities` 按当前工作区返回实际实现的能力。

Mac 客户端位于 `apps/macos/`，提供多作品书库、作品资料、分卷与章节顺序管理、Markdown／Fountain 正文编辑、设定集编辑与历史修订查看、草稿审核。书库可搜索、按创作状态筛选，切换封面和列表布局；小说资料与目录采用修订校验，章节重排保留正文及原文引用。编辑缓冲保存在本机恢复目录，正文保存处理多窗口冲突。构建输出的 `.app` 采用本机 ad-hoc 签名，用于开发验证；正式分发按[构建分发规范](docs/21-构建分发与运维.md)验收。

“剧情整理”从已保存正文提取场景、动作、对白、冲突与伏笔候选，支持作者校正、原文选区标注、节点连线和修订查看。“核对原文”显示提取时的固定修订并定位引文；正文与设定更新后保留旧结果并标记过期。覆盖不足与未解析范围单独显示，候选需作者确认。

“一致性诊断”检查固定剧情修订，区分确定命中、启发式提示与缺失前提，按规则、严重程度、确定性及处置状态筛选。作者可标注事实、能力和陈述语境，核对原文并记录处置理由；报告与处置历史分别保存。

“短剧骨架”按固定剧情与作者分集锚点整理场次，支持结构编辑、拆分、相邻合并、重排和来源映射。每次编辑保存新修订，重新建立候选保留既有人工结构；原著结构差异报告单独保存。未知字段保留，台词与镜头描述在独立剧本中编写。

从骨架选择“建立可编辑剧本”，填写标题与模板语言，即可打开独立 Fountain 结构正文。编辑器的“结构来源”可核对初稿标题和原著证据；正文修改后仍保留初稿映射，并显示其过期状态。

“审核工作台”核对参考稿、诊断、原文与差异，记录公开理由、私密批注及覆盖说明。通过参考稿审核只记录决定，不创建正文或定稿；返工保留旧稿和历史。采纳到写作稿、作者独立定稿及撤回的权限和证据见[审核合同](docs/15-人工审核与审计.md)，具体动作及版本由能力目录公布。结果未确认的写请求按原操作恢复。

“版本管理”在作者确认后为当前作品初始化独立 Git 仓库。选择已保存文件、填写身份与备注，准备固定快照后核对差异，再确认提交；原有 Git 暂存区保持独立。待审快照和提交历史可分页读取，文件或 HEAD 变化后需重新审阅，结果未确认时恢复原操作。范围与协作合同见[Git 规范](docs/16-Git版本与协作.md)。

“线索与素材”保存作者录入的乐律／视觉说明、固定原文选区和媒体关联。系统文件面板导入图片、音频或视频，流式复制原文件并核对摘要；来源与权利声明单独修订，默认不允许嵌入未知权利素材。历史线索保留原引用，正文或素材说明更新后显示过期状态。文件签名识别不等同于完整解码或版权验证。

作品资料中的“AI 协作”按作品关联客户端和题材 Skills 套件，设置中的默认客户端只用于新作品。Mac 开发包随附“河图洛书·通用”和“河图洛书·军事”完整方法包，可从设置、新建作品和封面旁打开统一安装窗口。Codex 通过官方 CLI 安装，WorkBuddy 安装到个人 Skills 目录；已有不同内容时保留原文件并提示冲突。界面分别展示本机文件、包版本、启用配置及待验证的会话和 MCP 状态。安装、连接和权限边界见[Agent 集成设计](docs/27-Agent与Codex插件集成设计.md)。

独立 Rust MCP Server 位于 `apps/mcp/`，构建输出为 `build/native/bin/hetu-mcp`，Mac 开发包同时携带 `Contents/Helpers/hetu-mcp`。宿主通过参数数组传入作者选定的工作区绝对路径：

```bash
"build/native/bin/hetu-mcp" --workspace "/绝对路径/我的作品"
```

Server 采用 MCP `2026-07-28` stdio 与固定 Agent 权限，提供设定集读取、草稿提交、剧情整理、短剧骨架、诊断、作者批准后的本地快照和资源查询。工具目录见 `contracts/tools/catalog.json`；协议、恢复与接入要求见[MCP 设计](docs/14-MCP与Agent接入.md)。

原生模块目录按[Monorepo 规范](docs/04-Monorepo与开发规范.md)组织；网站构建不依赖原生工具链。产品功能和平台范围以 PRD 及原生验收规范为准。

## 边界

确定性规则只对有证据的结构与约束给出结论；人物性格、动机与复杂 OOC 问题保留作者判断。MCP 设定集锁约束河图洛书受管入口，不能阻止具有同级文件权限的程序直接改写文件。

CLI 的 `call` 自动化入口固定为 Agent 权限；设定集修改、正文覆盖等作者动作由内核拒绝，不接受业务 JSON 指定作者身份。`capabilities` 与 `call` 均需通过 `--workspace` 明确选择工作区。
